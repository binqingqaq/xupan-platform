# xupan-platform

`xupan-platform` 是一个按正式上线标准建设的虚拟积分娱乐平台。当前包含 8 球番摊玩法、玩家链接登录、虚拟积分钱包、聊天室实时链路、服务端机器人、托自动行为和运营后台。

## 当前状态

- 后端模块：`server/xupan-server`
- 技术基线：Spring Boot `4.0.8`、Java `21`
- 构建方式：Maven Wrapper
- 生产数据库：MySQL `8.4 LTS` + Flyway
- 测试数据库：测试 Profile 使用内存 H2
- 当前已具备：
  - 游戏核心：期号自动轮期、8 球随机开奖、11 类玩法文本解析、赔率快照、注单与 `WIN/DRAW/LOSE` 结算。
  - 身份与玩家：管理员密码登录、普通玩家与托的链接免密登录、7 天默认有效期、拉黑/拉白/刷新/过期、软删除与历史保留；玩家工作台不再提供「停用玩家」入口，日常使用拉黑或删除。
  - 虚拟积分：管理员上下分、聊天上下分申请与后台审批、下注扣分、结算返还、不可变流水和业务日对账。
  - 后台 `/console`：玩家工作台、上下分确认、最近上下分记录、下注榜（普/托/上期/开奖）、赔率与特码赔率自动保存、限额与托风控配置弹窗、报网与线路域名静态区域、封盘与显示控制区域。
  - 玩家前台 `/room`：参考式快捷下注面板（74 项赔率、多选、快捷金额、玩家级偏好）、最近 4 小时聊天历史与新消息提示、`说明`指令（发送后仅本机弹出玩法说明）。
  - 聊天室与机器人：REST 持久化、单实例 WebSocket、outbox 补偿、服务端常驻机器人事件消息。
  - 托自动行为：链接是工作前提、期内随机时间下注、11 类指定玩法、下注范围档位与金额整十、活跃比例 A+B、所有托每期总注单/总积分上限、随机上分申请、余额不足降额、自动模式不发送闲聊。
  - 展示端：PC `/display` 与移动端 `/display/mobile` 首页复刻及外部开奖接入。
- 当前阶段已验证：后端全量 H2/Flyway `285/285`、前端 Vitest `104/104`、TypeScript 检查和生产构建、本机 MySQL `8.4.11` 从 V1 迁移到 V32 并成功启动、下注榜与快捷下注与聊天室 4 小时历史的桌面/375px 浏览器验收、后台赔率限额配置浏览器验收、托自动行为 H2 集成用例与构建产物检查
- 当前仍待补齐：服务器现场部署与生产验收、公网 HTTPS 与 Secure Cookie 刷新恢复、多实例下托全局上限和玩家限额的强一致控制、管理员撤单专项、下注榜「上期」榜单、真实全量 74 项下注演练、玩家工作台新面板的 375px 截图专项、链接元数据清理策略；Redis/MQ、多实例协调和跨节点广播仍不属于当前单服务器开发前置条件
- 当前余额能力：正式用户使用管理员分配的虚拟积分并保留可审计流水；历史 `DEMO-USER` 仅作兼容数据，不代表真实资金系统

## 环境要求

- JDK 21
- 可访问 Maven Central 的网络，或已准备好 Maven 本地依赖缓存
- 生产运行阶段需要 MySQL `8.4 LTS`；当前仓库没有提交任何数据库账号或密码

检查 Java 版本：

```powershell
java -version
```

如果当前终端未配置 `JAVA_HOME`，请先将它设置为本机 JDK 21 安装目录：

```powershell
$env:JAVA_HOME = "C:\path\to\jdk-21"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

## 构建和测试

进入后端模块目录：

```powershell
cd server\xupan-server
```

运行测试：

```powershell
.\mvnw.cmd test
```

当前完整后端测试套件使用 `src/test/resources/application-test.yaml` 中的内存 H2 和 Flyway，最近一次通过 `285` 个测试；前端 Vitest 最近一次通过 `104` 个测试，`typecheck` 和 `build` 均已通过。这些测试和 H2 均不替代真实 MySQL 验证。

## 启动服务

```powershell
cd server\xupan-server
.\mvnw.cmd spring-boot:run
```

默认 `application.yaml` 使用 `XUPAN_DB_URL`、`XUPAN_DB_USERNAME`、`XUPAN_DB_PASSWORD` 注入 MySQL 连接；启动前必须确认本机环境变量或受控配置已提供凭据。启动后访问 `http://127.0.0.1:8080/` 可打开首期演示页面；用户聊天室为 `/room`，实时地址为 `/ws/chat/{roomCode}`，浏览器 WebSocket ticket 由 `/api/auth/ws-ticket` 短期签发。

## 前端开发

进入 `web` 目录后运行：

```powershell
npm install
npm run dev
```

生产构建使用 `npm run build`，构建产物会写入 Spring Boot 的静态资源目录；类型检查使用 `npm run typecheck`。玩家前台地址为 `/room`，正式管理控制台地址为 `/console`；旧 `/admin/*` 地址保留自动跳转兼容。

## 当前开发入口

当前开发接续入口是 [当前文档入口](docs/文档索引.md) 和对应业务模块基线。业务规则已经确认并写入模块基线，后续接续按下面的顺序推进：

1. 先读 [文档索引](docs/文档索引.md) 的「当前仍在执行或待补的专项计划」，确认本次要处理的事项是否已经在计划中。
2. 再读对应 [业务模块基线](docs/业务模块/)，把新规则补进模块文档和跨模块流程。
3. 需要改代码时先更新 `docs/plans/` 计划，再改前后端与迁移。
4. 完成后写 `docs/验收记录/` 并标注证据等级，未执行的检查必须显式列出。

当前不把 Redis、多实例、真实支付或生产高可用作为任何业务模块的隐含前置条件；但多实例部署前必须先补齐托全局上限和玩家限额的强一致控制。
