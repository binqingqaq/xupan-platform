# xupan-platform

`xupan-platform` 是一个正在建立中的平台项目。当前首期目标是完成 8 球番摊玩法演示，后端先提供可控赔率和开奖演示接口。

## 当前状态

- 后端模块：`server/xupan-server`
- 技术基线：Spring Boot `4.0.8`、Java `21`
- 构建方式：Maven Wrapper
- 生产数据库：MySQL `8.4 LTS` + Flyway
- 测试数据库：测试 Profile 使用内存 H2
- 当前已具备：玩法领域模型、自动轮期、结算服务、Flyway/MySQL 持久化、赔率控制/下注/开奖 API、认证授权、正式用户虚拟余额、用户管理后台、聊天室 REST 持久化、单实例 WebSocket，以及服务端常驻机器人基础能力和后台管理 API
- 当前阶段已验证：后端全量 H2 `195/195`、前端 Vitest `21/21`、TypeScript 检查和生产构建、MySQL 8.4.11 单服务器启动、机器人事件发布/持久化/重启恢复/失败重试和资金隔离、8080/5173 页面入口，以及基础运维可观测性代码和配置
- 当前仍待补齐：精确 375px/桌面视口下的机器人管理视觉验收、无 `ROBOT_READ` 账号触发 `/forbidden` 的自动跳转、历史事件批量补发、消息归档、单服务器正式运维演练和公网 HTTPS 刷新恢复；其中精确视口视觉项已按用户确认暂缓，不阻断当前机器人管理交付；管理员登录后的管理页、模板、新增表单、`/forbidden` 页面和聊天室冒烟检查已完成；Redis/MQ、多实例协调、跨节点广播和专门监控平台不属于当前单服务器开发前置条件
- 当前余额能力：正式用户使用管理员分配的虚拟演示余额并保留可审计流水；历史 `DEMO-USER` 仅作兼容数据，不代表真实资金系统

## 环境要求

- JDK 21
- 可访问 Maven Central 的网络，或已准备好 Maven 本地依赖缓存
- 生产运行阶段需要 MySQL `8.4 LTS`；当前仓库没有提交任何数据库账号或密码

检查 Java 版本：

```powershell
java -version
```

如果当前终端未配置 `JAVA_HOME`，请先将它设置为本机 JDK 21 安装目录：

```powershell
$env:JAVA_HOME = "C:\path\to\jdk-21"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

## 构建和测试

进入后端模块目录：

```powershell
cd server\xupan-server
```

运行测试：

```powershell
.\mvnw.cmd test
```

当前完整后端测试套件使用 `src/test/resources/application-test.yaml` 中的内存 H2 和 Flyway，最近一次通过 `195` 个测试；前端 Vitest 最近一次通过 `21` 个测试，`typecheck` 和 `build` 均已通过。这些测试和 H2 均不替代真实 MySQL 验证。

## 启动服务

```powershell
cd server\xupan-server
.\mvnw.cmd spring-boot:run
```

默认 `application.yaml` 使用 `XUPAN_DB_URL`、`XUPAN_DB_USERNAME`、`XUPAN_DB_PASSWORD` 注入 MySQL 连接；启动前必须确认本机环境变量或受控配置已提供凭据。启动后访问 `http://127.0.0.1:8080/` 可打开首期演示页面；用户聊天室为 `/room`，实时地址为 `/ws/chat/{roomCode}`，浏览器 WebSocket ticket 由 `/api/auth/ws-ticket` 短期签发。

## 前端开发

进入 `web` 目录后运行：

```powershell
npm install
npm run dev
```

生产构建使用 `npm run build`，构建产物会写入 Spring Boot 的静态资源目录；类型检查使用 `npm run typecheck`。用户前台地址为 `/room`，演示后台地址为 `/admin`。

## 当前开发入口

当前开发接续入口是运维现场验收、机器人管理浏览器视觉收尾和正式需求确认；机器人管理代码切片、管理员 API、事件发布、重启恢复、失败重试和基础可观测性代码验收已完成。开始后续业务开发前，需要先阅读当前需求基线和最新验收记录，并确认：

1. 目标用户和首期核心业务流程。
2. 首期包含和明确不包含的功能。
3. 用户、角色、权限和数据边界。
4. 首期需要落库的数据及其生命周期。
5. 可执行的验收条件。

确认后，应先更新对应实施计划和验收条件，再修改业务代码。当前不把 Redis、多实例、真实支付或生产高可用作为机器人前端阶段的隐含前置条件。
