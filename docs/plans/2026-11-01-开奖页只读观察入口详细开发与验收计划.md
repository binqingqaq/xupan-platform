# 开奖页只读观察入口详细开发与验收计划

> 状态：2026-11-01 已完成代码实施和专项自动化；使用者已配置并启用本机固定绑定。修复绑定 INSERT 参数数量和 TEST 托观察认证后，绑定、观察会话兑换及核心只读 API 本机检查通过；浏览器最终页面渲染、跨机隔离和视觉体验仍待人工确认。服务器/生产未操作。
>
> 业务依据：[开奖展示页只读玩家观察入口业务方案与使用说明](2026-11-01-开奖展示页只读玩家观察入口业务方案与使用说明.md)。本计划细化开发顺序、工程约束、可执行验收和可留给使用者人工验收的项目；不改变该文档的业务口径。

## 1. 目标与完成边界

完成后，超级管理员可在 `/platform-admin/settings` 独立绑定一台专用机器和该机器下一个**手动**展示托，并复制可外发的只读观察地址。`/display/mobile` 快乐8最近开奖期号保持原样式和末三位文字，绑定有效时点击进入同一地址。观察页显示当前机器可见聊天、快捷内容及展示托自己的账户/注单/流水；浏览者既不能从界面发消息或下注，也不能通过 REST、WebSocket 或其他直接调用写入业务事实。

专用机器仍照常归属一个子账号，可由机器账号登录 `/console` 创建玩家和托，正常执行项目已有虚拟积分下注、结算、内部模拟上报和运营。展示托关闭自动；同机其他托可保持自动，观察页只显示它们已产生的真实可见消息。点击开奖卡片中的最近已开奖期号进入**当前实时房间**，不做历史期聊天筛选。

**交付口径**：可将“代码及本机自动化验收完成”和“使用者浏览器人工验收完成”分别记录。人工点击、手机观感、外发设备体验若当时无法完成，写“待使用者人工验收”并交付可访问地址，不要求为了结项伪造通过。服务端拒写、机器隔离、迁移约束和本机运行安全属于可自动验证的关键门槛，不能只凭页面看起来只读就标为通过。服务器/生产需另行授权与验收。

## 3. 实施任务

### P0. 开工校准

1. 重新检查 `git status`、迁移最高版本、当前 `/display/mobile` 静态源与 Spring Boot 静态副本，以及 `/console`、`/room` 的实际路由；保留工作区现有用户改动。构建静态资源使用隔离输出，核对差异后再合入，避免覆盖已有资源。
2. 按项目规则尝试运行 BY220 对应机器管理、创建托、玩家链接及房间页面，补全“BY220 操作/数据/状态 → Xupan 位置”映射。若参考环境不可用，记录源码证据和未运行原因，不把静态阅读写成运行验收。
3. 盘点当前 `agent`、`agent_group`、`demo_user_account`、`test_player_behavior`、`player_access_link`、会话、聊天室及钱包表的关联和删除路径；确认展示托 MANUAL 的保存入口及其他托自动资格。

**产出**：现状映射和实施前数据/迁移清单。**验收**：对象归属、读取/写入端点、旧链接生命周期明确；无凭据或完整访问 URL 进入文档。

### P1. 固定绑定、地址与审计

1. Flyway 追加一份迁移，建立受约束的全局单例绑定，至少保存机器 ID、展示托 ID、状态、公开地址标识/版本、乐观版本、创建/修改人及时间；单独保存追加式绑定、停用和换链审计。具体表名与下一迁移号以开工时现状定，不改历史迁移。
2. 超级管理员绑定时在事务内确认机器有效、归属子账号、AU8 可用；展示对象是同机有效 BOT 且自动行为为手动。检查同机归属要在服务器做，不能信任浏览器的机器或托参数。并发两次首次绑定只允许一条成功；普通保存/重复提交不得产生第二个公开地址。
3. 绑定期间防止展示托被改为自动；机器或展示托停用、过期、物理删除时立即让入口不可用。删除仍遵守既有物理删除行为，不静默换绑；保留不含可访问地址的审计事实。
4. 公开地址在绑定有效时保持稳定，正常轮期不换。换链/停用应撤销旧地址和旧观察会话，要求确认与审计；不存在绑定时不输出看似可用的地址。地址及随机标识不进入 Git、普通日志和错误消息。

**产出**：迁移、绑定仓储/服务、审计与失效联动。**验收**：MySQL 8.4 从旧版本升级、重复启动、唯一绑定、跨机器托拒绝、并发版本冲突、停用/删除/换链失效均可复现。

### P2. 超级后台“设置”独立管理区

1. 在现有 `/platform-admin/settings` 下新增“开奖页只读入口”区域：机器单选、随机器过滤的展示托单选、状态、绑定确认、复制链接、停用和受控换链。展示托列表只显示同机有效且手动的 BOT；未满足条件给出明确提示。
2. 绑定 API 单独使用后台设置写权限，并在服务层要求超级管理员身份；读取与写入的权限分别校验。普通标题/公告等现有“保存”接口不携带或覆盖绑定字段；浏览者及机器账号不能调用全局绑定接口。
3. 复制按钮只取当前绑定地址，复制失败给可理解的反馈。后台只显示必要的机器账号和展示托信息，不显示其密码或 `PLAYER_FULL` 链接。

**建议接口边界**：在 `/api/admin/settings` 下独立设绑定读取、首次保存、停用、换链端点；公开开奖页另设只返回“当前是否可进入及观察地址”的只读端点。最终路径在实现时与现有 Controller 约定统一。**验收**：权限矩阵、重复保存、普通设置并发保存、跨机器选择、复制/停用/换链状态均覆盖。

### P3. 公开只读观察身份与数据

1. 地址打开后建立独立于 `ADMIN`、机器和 `PLAYER_FULL` 的观察会话，服务端从持久化绑定解析 `agent_id` 与展示托用户 ID。浏览器传入的 `agentId`、`userId`、账号名或期号都不得决定可见范围；同一浏览器已有管理员/玩家会话也不能被覆盖或串用。
2. 逐项列出观察页确需的 GET：当前 AU8 期、机器聊天室历史和实时消息、赔率/快捷信息、展示托钱包、个人注单和流水。可以复用原读取服务，但返回字段须经过公开范围核对；读接口本身不得产生下注、上分或聊天业务事实。
3. 为观察身份建立**显式允许列表和默认拒绝**。拒绝聊天文字/命令发送、读游标保存、下注、快捷金额保存、头像/账户修改、积分操作、玩家/机器/中心后台调用及其他写入；未读位置只保留浏览器本地状态。WebSocket 只允许订阅同机消息，拒绝任何上行消息。现有 `CHAT_ONLY` 能发送消息，不能当观察权限；检查 `SecurityConfig` 的宽泛兜底，确保新身份无法走漏到其他接口。
4. 限制会话有效期和公开读取频率；换链、停用或绑定对象失效时使已签发观察会话失效。公开地址可被外发，应按“持有链接者可见”管理，不把随机地址当作隐私控制。限制聊天历史窗口及账户字段，沿用现有机器可见性和虚拟积分边界。

**产出**：观察会话、认证/授权、只读数据投影与实时订阅。**验收**：直接伪造 REST 写请求和 WebSocket 发言均拒绝且数据库无变化；改 URL/请求参数不能看另一机器或另一玩家；观察访问不影响展示托及其他托的现有完整玩家链接、调度和会话。

### P4. 玩家界面观察模式

1. 为玩家房间增加独立观察路由和只读状态，保留聊天、快捷、账户的主要布局及正常加载、断线、重连和空态。账户始终是固定展示托，聊天室来自固定机器；其他托的真实消息可见，它们的注单不进入展示托个人账单。
2. “快捷”可打开查看赔率与配置，但不得弹出可操作的下注键盘、组合提交或偏好保存；聊天输入/发送及任何触发下注的快捷指令均不可操作。“账户”可查看，不提供积分或链接管理动作。用显著但不打扰的“只读”状态说明当前身份。
3. 观察页失败时显示明确状态和重试入口；不以普通玩家会话、缓存中的旧机器数据或其他机器兜底。普通 `/room`、普通玩家/托的完整链接及后台页面保持原行为。

**产出**：只读玩家视图与数据接入。**验收**：静态组件测试核对关键控件状态；最终仍以服务端直接拒写结果为准，不把按钮隐藏视作权限通过。

### P5. 开奖卡片入口与外发地址

1. 在快乐8“第 xxx 期”文本上增加链接语义，不改变原球色、字号、间距、加号、号码和末三位期号规则；其他彩种不接此观察入口。绑定未启用或对象失效时，文字保持非可点击且不生成无效链接。
2. 每次 AU8 轮期只更新展示期号；同一有效绑定一直指向固定实时观察地址。点击最近开奖期号和从“设置”复制地址，都进入当前房间。轮换地址后开奖页通过服务端配置自动更新，无需手工改脚本或每期重发。
3. 公开页不直接包含机器密码、完整玩家链接或可扩大权限的 Token。外发链接须能在独立浏览器打开；停用/换链后旧链接明确失效。

**产出**：两份页面静态源的同范围修改、公开入口状态读取。**验收**：页面样式回归、期号更新与 href 稳定、复制值与卡片 href 一致、跨浏览器外发打开、旧链接失效。

## 5. 执行顺序、环境与证据记录

1. **源码/静态门槛**：Java 21 编译、Vue 类型检查、相关接口/权限和组件专项、两份开奖静态资源语法/差异检查。前端生产构建先用隔离目录，审阅生成资源差异，再处理当前工作区既有静态文件；不以覆盖旧资源来消除构建差异。
2. **数据库门槛**：用隔离 MySQL 8.4 schema 从当前迁移链应用到新版本；验证唯一绑定、同机 BOT、审计、并发、重复启动、删除联动和换链失效。H2 可跑独立单元/接口测试，但当前全量 H2 曾受 V83 MySQL 专用 SQL 阻断；若重现，记录具体阻断和已完成的 MySQL 结果，不把 H2 失败误报为本功能通过或生产失败。
3. **本机运行门槛**：按受控本地密钥启动服务，检查设置、公开期号链接、观察读取及拒写 HTTP/WS；使用隔离的专用机器和展示托数据。记录期号、机/托数量、观察身份、接口状态和账本前后差异，不记录密码、完整链接或可访问随机标识。
4. **可选人工验收**：桌面与手机检查开奖卡片样式、复制/外发打开、聊天滚动、快捷和账户只读、断线重连。若缺少账号、设备或环境，逐项标“待使用者人工验收”，给出可访问页面及操作步骤，不以截图或模拟数据冒充真人体验。
5. **服务器/生产**：本计划不包含上传、重启或数据库操作授权。将来发布时另做迁移账号权限、备份恢复、HTTPS/Cookie、带鉴权 WS、旧链接失效和数据公开范围现场验收；本机完成不等于已上线。

每次验收记录按“项目/提交或工作区状态、环境、测试对象、执行命令或操作、结果、失败原因、未执行项”写入独立验收文档。功能代码未完成时，不生成虚假的通过清单。
