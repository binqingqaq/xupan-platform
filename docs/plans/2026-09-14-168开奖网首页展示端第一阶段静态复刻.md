# 168开奖网首页第一阶段静态复刻开发计划

## 1. 计划定位

本计划只服务于“先做一个可查看的 168 开奖网页首页样稿”这一阶段，目标是让用户先评审桌面端视觉效果和前端交互，再决定是否继续投入正式业务开发。

本阶段的页面是可推翻、可重写的展示样稿：页面上的图片、文字、期号、号码、倒计时、新闻、推荐彩种和广告内容均使用固定静态内容；交互只在浏览器前端本地完成。

本计划与现有“汇博盈”需求并行，不替换、不删除、不修改汇博盈现有业务范围。

## 2. 已确认结论

### 2.1 可以先做静态首页

当前目标是观察首页布局、颜色、密度、图片比例、导航层级和操作感觉，不是实现真实开奖或投注业务。因此，第一阶段不需要先定义后端接口、数据库表或正式领域数据结构。

### 2.2 本阶段不预留正式接口

本阶段不新增开奖、期号、新闻、广告、用户、登录、投注、钱包、支付、聊天或机器人相关 API，也不新增对应 DTO、数据库表、Flyway 迁移、WebSocket 消息协议或数据适配层。

静态内容可以直接写在页面组件或页面专用的静态配置中。这样做是有意保留推翻空间，不把尚未评审的页面字段误认为后续业务契约。

### 2.3 与当前后台的关系

页面仍放在当前项目的前端工程中，以独立展示路由运行；不改变当前后台接口、权限、数据库和已有业务页面。当前项目的后台可以继续保留，静态首页只是新增的展示入口。

本阶段不要求独立部署。是否拆成独立前端、是否共用后端、是否建立正式接口，全部留到静态样稿评审后重新确认。

### 2.4 桌面端优先

本阶段只实现桌面浏览器效果，优先按参考首页的宽屏布局制作。移动端 `m.16894913.com` 的独立布局、响应式重排和移动导航不纳入本阶段。

## 3. 第一阶段目标

完成一个可通过独立路由访问的桌面静态首页，使用户能够检查：

- 顶部公告条、品牌 Logo、用户入口和辅助链接的相对位置。
- 橙色主导航、菜单层级、`新` 标记、简约版入口和鼠标悬停效果。
- 首页主体的横幅/轮播区域、行业新闻、开奖或活动卡片、推荐彩种区域。
- 左侧主内容与右侧推荐/广告栏的宽度、间距、边框、背景和滚动关系。
- “我的偏好”、彩种分类标签、号码球、状态文案和倒计时等静态展示区域。
- 右侧悬浮的导航、客服、反馈、APP 等工具按钮。
- 页面在桌面尺寸下的整体视觉密度和主要前端交互。

## 4. 实现边界

### 4.1 本阶段包含

- 新增一个独立的桌面展示路由，例如 `/display`。
- 使用当前项目已有的 Vue 3、TypeScript、Vite 和 Vue Router 技术栈。
- 新增页面专用 Vue 组件和页面专用 CSS，尽量隔离现有 `/room`、`/admin` 页面样式。
- 使用本地静态图片或已获授权的占位图片，不依赖参考站点运行时资源。
- 将参考首页中的必要文案、数字、期号、新闻标题、推荐项和广告标题固定写入样稿。
- 实现前端本地的下拉菜单、悬停高亮、轮播切换、指示点切换、标签切换、展开/收起和演示倒计时。
- 对轮播和倒计时等定时器做组件卸载清理，避免离开页面后继续运行。
- 保留当前首页 `/` 到 `/room` 的既有行为，并确保静态展示路由不要求登录。

### 4.2 本阶段明确不包含

- 不新增或修改 Spring Boot Controller、Service、Repository、数据库实体和 Flyway 脚本。
- 不调用 `/api/demo/**`、`/api/admin/**` 或任何现有开奖、钱包、投注、聊天、机器人接口。
- 不新增开奖真实数据、赔率、投注、订单、结算、钱包、支付、用户体系或权限规则。
- 不新增 WebSocket、定时开奖任务、服务端倒计时或后台管理配置。
- 不抓取、代理或依赖 `16894913.com` 的运行时接口、Cookie、Token 或外部资源。
- 不把参考网站的栏目名称、请求参数、响应字段或页面行为直接认定为当前项目业务契约。
- 不实现移动端 `m.16894913.com`，不承诺响应式布局和手机端视觉一致。
- 不在本阶段确定未来正式 API 路径、响应格式、数据库字段、权限模型或部署拓扑。

## 5. 建议文件范围

以下是本阶段的建议变更范围，实际文件名可在实施时按当前前端结构微调：

- `web/src/views/DisplayHomeStatic.vue`：静态首页结构、固定展示内容和本地交互状态。
- `web/src/styles/display-home-static.css`：首页专用桌面样式，避免把样式扩散到现有业务页面。
- `web/public/display/`：本阶段使用的本地静态图片和占位资源。
- `web/src/main.ts`：注册公开展示路由 `/display`，不改变现有 `/room`、`/admin` 路由。
- `server/xupan-server/src/main/java/com/xupan/server/web/SpaController.java`：如当前服务端刷新深链接需要处理，则补充 `/display` 的 SPA 回退。
- `docs/验收记录/2026-09-14-168开奖网首页展示端第一阶段静态验收记录.md`：记录截图、交互检查、构建结果和未执行项。

本阶段不新增 `web/src/api.ts` 中的展示接口，不新增 `web/src/types/` 下的正式业务类型，不新增后端 API 或数据库迁移。

## 6. 分阶段执行步骤

### 阶段 1：锁定桌面参考范围

1. 以用户提供的桌面截图和已记录的参考站点观察结果为视觉依据。
2. 固定首轮检查尺寸：`1366 x 768`，补充检查 `1920 x 1080`。
3. 记录首屏必须出现的区域：顶部条、Logo、主导航、主内容、新闻、推荐区、广告区和悬浮工具。
4. 记录必须具备的前端行为：导航悬停、下拉菜单、轮播切换、标签切换、展开/收起和演示倒计时。
5. 对不确定的内容使用“展示样稿固定内容”标记，不将其写成业务规则。

完成标准：形成一份可供开发和验收使用的桌面页面区域清单；没有把移动端或真实后端行为混入本阶段。

### 阶段 2：搭建静态页面骨架

1. 在现有 Vue 前端中新增独立展示页面和 `/display` 路由。
2. 按桌面版固定宽度和主要列宽搭建页面结构，先保证区域位置和整体比例稳定。
3. 将固定文本、期号、号码、新闻、推荐彩种、广告标题和状态文案直接放入页面专用静态内容。
4. 使用本地资源路径引用 Logo、横幅、缩略图和图标；缺少授权素材时使用尺寸一致的占位图。
5. 为图片、卡片、号码球、按钮、导航项和浮动工具设置稳定尺寸，避免内容变化造成布局跳动。

完成标准：在桌面浏览器打开 `/display` 时，页面主体结构完整，静态内容不依赖接口即可显示。

### 阶段 3：补齐前端展示交互

1. 主导航支持当前页面高亮和鼠标悬停态。
2. 有下拉项的导航支持悬停展开、移出收起，并保证菜单不会被其他区域遮挡。
3. 首页横幅支持自动轮换、指示点切换和手动切换；仅使用本地前端状态。
4. 彩种分类标签支持切换当前展示区域，切换数据仍为预置静态内容。
5. “展开”或“收起”按钮只控制页面本地内容显示，不触发请求。
6. 倒计时只作为视觉演示，允许按本地定时器递减；页面销毁时清理定时器。
7. 所有无法实现真实目标的入口使用当前页面内的占位行为或非破坏性提示，不跳转到投注、支付或未知外部站点。

完成标准：截图中能看到主要交互状态，操作不会引起控制台错误、页面跳转异常或布局错位。

### 阶段 4：桌面视觉和行为验收

1. 在 `1366 x 768` 和 `1920 x 1080` 下分别截图检查。
2. 对照参考截图检查页面宽度、列布局、导航高度、图片比例、文字层级、颜色、边框、间距和悬浮工具位置。
3. 检查首屏是否出现明显横向滚动、内容重叠、文字溢出、图片变形、菜单闪烁和布局跳动。
4. 操作检查下拉菜单、轮播、指示点、标签、展开/收起、倒计时和页面离开后的定时器清理。
5. 检查浏览器网络面板或代码引用，确认页面没有调用参考站点运行时接口和本阶段之外的业务接口。
6. 执行前端类型检查、单元测试和生产构建；测试结果只记录实际执行到的范围。
7. 将截图、检查结果、差异项和未执行项写入验收记录。

完成标准：产出一个可供用户评审的桌面静态首页，并明确列出与参考图仍有差异的地方。

### 阶段 5：用户评审后再决定下一步

第一阶段到此结束，不自动进入后端开发。用户评审结果决定后续方向：

- 继续保留样稿：只根据视觉意见修改静态页面。
- 进入正式业务：另行确认真实字段来源、权限、接口、数据库和部署方式，再新增下一阶段方案和开发计划。
- 推翻重做：删除或重写本阶段展示页面，不需要为静态样稿保留数据库迁移和正式接口兼容。
- 暂停：保留当前静态页面作为演示样稿，不继续扩大范围。

## 7. 验收口径

### 7.1 功能验收

- `/display` 可以直接打开并显示完整首页。
- 首页所有内容在无后端数据时仍能显示。
- 导航、悬停、下拉、轮播、标签、展开/收起和演示倒计时按预期工作。
- 页面离开后不存在持续运行的前端定时器或明显控制台错误。
- 现有 `/room`、`/admin` 和后台接口行为没有因新增展示页面而改变。

### 7.2 视觉验收

- 桌面首屏的主要区域与参考首页的结构和视觉层级一致。
- 图片、文字、号码球和广告区域尺寸稳定，常见桌面尺寸下无明显重叠和溢出。
- 本地资源加载正常，不依赖参考站点在线资源。
- 对照截图发现的未完成项必须记录，不能用“基本一致”代替具体差异。

### 7.3 工程验收

- 前端类型检查、测试和构建结果有实际命令输出作为依据。
- 仅修改本阶段约定的页面、样式、资源、路由和文档范围。
- 没有新增正式后端接口、数据库表、业务 DTO 或未确认的业务规则。
- 不提交密码、Token、Cookie、真实外部接口地址或未授权素材。

## 8. 后续正式化的触发条件

只有在用户完成第一阶段视觉评审并明确要继续时，才重新讨论以下事项：

- 哪些首页内容需要真实数据，真实来源是当前后端、第三方数据还是后台录入。
- 哪些栏目属于正式业务，哪些只是展示广告或静态内容。
- 期号、开奖、倒计时、新闻、推荐和广告分别需要什么字段及更新频率。
- 是否复用当前项目后端，是否新增独立前端部署，是否需要公开接口和权限控制。
- 是否需要移动端独立布局或响应式版本。

在这些问题确认前，不提前提交接口和数据库设计，避免把第一阶段的临时展示字段固化成错误契约。

- 后端状态：不纳入本阶段。
- 移动端状态：不纳入本阶段。
- 下一步：用户评审本计划后，再决定是否执行阶段 1 至阶段 4。
