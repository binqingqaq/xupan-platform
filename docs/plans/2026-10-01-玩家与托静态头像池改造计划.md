# 玩家与托静态头像池改造计划
## 状态

已实施并通过 H2/Flyway、前端测试/构建、本机 MySQL 8.4 V33 迁移与独立端口启动验证。验收边界见 `docs/验收记录/2026-10-01-玩家与托静态头像池改造验收记录.md`。


## 目标

用项目自带的 40 张 Pixabay/Pexels 静态图片替代 DiceBear 自动生成头像。普通玩家和托创建时自动分配未占用头像，管理员可在玩家详情中点击头像更换；头像在活动玩家和托之间不重复，软删除后释放。

## 已确认边界

- 使用 `C:\Users\tbq\Desktop\Pixabay_Pexels_各20_20261001_151028` 中的 40 张原图，不裁切、不转格式。
- Pixabay 20 张映射为 `preset-01` 至 `preset-20`，Pexels 20 张映射为 `preset-21` 至 `preset-40`，保留原扩展名。
- 现有玩家和托头像不迁移、不清理。
- 停用和锁定状态继续占用；只有软删除释放。
- 本次只覆盖普通玩家和 `player_kind=BOT` 的托；聊天机器人和后台账号不受影响。
- 玩家和托不再允许自定义上传。

## 实现

- 静态资源放入 `web/public/avatars/presets/`，Vite 构建复制到 Spring Boot 静态目录。
- Flyway `V33` 新增 `avatar_preset`，预置 40 行；`assigned_user_id` 唯一且可空。
- `AvatarPresetService` 负责随机分配、条件抢占、替换和释放；活动头像不足时抛出 `AVATAR_POOL_EXHAUSTED`。
- 普通玩家和托创建后在同一事务内分配头像并写 `sys_user.avatar_key`。
- 玩家删除时释放 `avatar_preset` 占用，但保留历史头像键。
- 移除 DiceBear 生成方法和 `xupan.avatar.auto-generate` 配置。
- 新增 `GET /api/admin/player-desk/avatar-presets` 和 `PUT /api/admin/player-desk/players/{userId}/avatar`。
- 玩家工作台详情头像改为按钮，打开可选、已占用和当前选中头像弹窗。

## 验证

- 头像分配、耗尽、替换、释放和占用冲突专项测试。

- 本机 MySQL 8.4 应用 V33 并检查表、约束和 40 行种子。
