# 聊天室消息容量与生产边界优化计划

## 1. 目标

将聊天室和机器人结构化消息的容量控制从散落的硬编码改为分层、可配置、按 UTF-8 字节计算的生产边界，避免大消息在数据库、WebSocket 容器、应用广播和浏览器之间出现不一致行为。

## 2. 已确认边界

- 客户端入站 WebSocket 帧限制为 `16 KiB`。
- 服务端出站 WebSocket envelope 限制为 `64 KiB`。
- 机器人 `payload_json` 应用层限制为 `64 KiB`，数据库 `JSON` 类型不作为无限容量保证。
- 用户正文仍使用现有字符数限制；本次不放宽普通聊天内容。
- 超限不截断 JSON，不生成半条消息；机器人投递进入失败/重试链路，已持久化消息不被删除。
- 三类上限均可使用环境变量调整，但必须在服务器现场按代理、容器、浏览器和实际 payload 做端到端验证。

## 3. 实施与验证

1. 增加入站、出站和机器人 payload 的独立配置及合法范围校验。
2. 应用层统一按 UTF-8 字节数校验入站和出站 JSON。
3. 配置 Servlet WebSocket 容器文本缓冲上限，避免使用未审计的默认值。
4. 为机器人 payload 校验、中文字节数、出站超限和现有 WebSocket 协议回归补充测试。
5. 更新生产配置说明，明确本机/H2 测试不能代替服务器 WebSocket 现场验证。

## 4. 未覆盖事项

本阶段不把图片或 Base64 内容放入聊天室 JSON；未来若需要较大媒体，应使用对象存储/资源 ID 和独立 HTTP 读取链路，并另行设计权限、过期、病毒扫描和清理策略。
