# 超级管理后台 Element Plus 界面重构计划

> **计划状态：** 本机前端实施、类型检查、生产构建与服务重启已完成；完整人工交互验收仍待补。业务接口、权限与领域操作不在本次改造范围。
>
> **依据：** 2026-10-21 用户明确要求：现有超级管理后台业务功能已实现，本轮只重构前端界面，统一使用 Element Plus 组件和样式，不再以外部旧系统作为设计或业务对照。
>
> **计划创建时源码快照：** `web` 使用 Vue 3 与 Vue Router，尚未引入 Element Plus；后台有共享顶部菜单、13 个业务页面和一个独立登录页。中心上游是高复杂页面，单独列入迁移和验收。

## 1. 目标

在不改变当前页面所承载业务的前提下，统一 `/platform-admin` 的视觉和交互实现：

- 使用 Vue 3 兼容的 Element Plus 组件承载菜单、表格、筛选、表单、弹窗、状态、反馈和统计摘要。
- 保持顶部横向导航，不改为侧边栏；维持当前页面和菜单入口。
- 把页面自定义样式收敛到布局、开奖结果球号/路字图等确有业务表达需要的内容；不再手写通用表格、输入控件、按钮、弹窗和标签的基础样式。
- 让统计和运营数据易于扫描：先展示已有接口返回的关键汇总，再展示明细表格；只使用当前已有数据，不构造模拟指标或新业务数据。
- 桌面后台优先，同时确保窄屏可操作、表格在自身区域内滚动、弹窗不溢出视口。

## 3. 组件与视觉方案

### 技术方案

- 继续使用现有 Vue 3、TypeScript、Vue Router 和 Vite 工程。
- 在 `web` 引入 Element Plus、`@element-plus/icons-vue`，并配置 `unplugin-vue-components` 的 Element Plus resolver 按组件自动引入组件及对应样式。版本在实施时按当前 Vue/Vite 兼容范围解析并锁定到 lockfile。
- 以 `el-config-provider` 配置简体中文和后台统一尺寸；数据密集页面优先使用 `small`，登录、确认操作仍维持易点击目标。
- Element Plus 的主题变量仅在平台后台主题入口生效。组件样式按后台路由异步加载或做等价隔离，避免全局重置影响其他产品面。
- 使用 Element Plus 图标库提供操作图标；有文字说明的业务命令保留文字，不以无提示图标替代。

### 页面骨架

- 保留现有顶部横向导航和路由结构，采用 Element Plus `el-menu mode="horizontal"`、`el-menu-item` 与账号操作菜单实现。
- `PlatformAdminNav.vue` 继续读取现有 `api.me()` 权限和用户信息；只替换呈现组件，不调整权限过滤逻辑。
- 各页面使用统一后台内容容器、标题区、反馈区、筛选区和表格区。定宽/最大宽度、间距、内容滚动由少量平台后台布局变量控制。
- 视觉风格采用清晰克制的运营后台：浅色工作区、白色内容表面、稳定的标题和数据层级、统一边框与状态色。颜色、字号、间距、圆角和阴影统一通过 Element Plus 变量及平台后台 token 管理。

### 组件映射

| 现有交互/元素 | 统一采用 | 保留要求 |
| --- | --- | --- |
| 顶部菜单与当前菜单项 | `el-menu`、`el-menu-item`、`el-dropdown` | 菜单顺序、路由地址、权限过滤和退出行为不变 |
| 普通列表及嵌套明细 | `el-table`、`el-table-column` | 列、排序/筛选行为、行操作、空结果含义不变；不擅自增加排序或筛选 |
| 页面筛选 | `el-form`、`el-form-item`、`el-input`、`el-select`、`el-date-picker` | 查询触发时机、日期边界、默认值和请求参数不变 |
| 编辑/创建表单 | `el-form`、`el-input-number`、`el-checkbox-group`、`el-radio-group`、`el-switch` | 字段、精度、默认值、校验和提交 payload 不变 |
| 弹窗 | `el-dialog` | 统一设置 `close-on-click-modal="false"`；仅通过明确关闭、取消或既有成功提交关闭，避免误点遮罩丢失内容 |
| 危险操作确认 | `ElMessageBox.confirm` 或 `el-popconfirm` | 确认文案、取消结果、API 调用和防重复提交行为保持一致 |
| 状态和类别 | `el-tag`、`el-badge` | 颜色之外同时保留状态文字，颜色不能成为唯一状态表达 |
| 成功/错误提示 | `el-alert`、`ElMessage` | 保留现有错误语义和操作成功反馈；网络失败仍显示可理解信息 |
| 加载/空/无权限 | `el-skeleton` 或 `v-loading`、`el-empty`、`el-alert` | 空数据、加载失败、权限不足相互区分，不用空表掩盖错误 |
| 后端分页 | `el-pagination` | 沿用现有 page/pageSize/total 契约，不改变页大小和分页边界 |
| 汇总指标 | `el-statistic`，必要时 `el-descriptions` | 只呈现当前 API 已提供的指标，精度、单位和正负含义不变 |
| 开奖球和路字图 | `el-tag`/`el-space` 加少量专属样式 | 保留开奖结果视觉区分；专属样式限定在结果展示，不重新实现通用控件 |

### 统计呈现原则

- 开奖信息页先突出最新期号、开奖时间和号码，再承载历史列表与现有路字图。
- 报表统计按当前页签展示对应总计与明细；使用现有 `report`/`scoreFlow` 返回值，不重算后端业务总计。
- 中心上游总览只把页面已计算的代理余额、冻结、未结和风险汇总做成统一指标区域；订单、账本、风险和对账仍使用现有数据结构与状态。
- 只有当现有响应本身包含可比较的分类数据时才使用图形图表；初始实施优先 `el-statistic` + `el-table`，不为追求视觉效果引入新的图表依赖或虚构趋势。

## 5. 主要风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 只换模板导致按钮、字段或调用时机漏迁 | 阶段 0 建立逐页行为清单；每页迁移前后对照同一清单 |
| Element Plus 全局样式影响其他入口 | 后台路由按需加载组件与样式，并做非后台页面回归；主题变量限定到后台根节点 |
| 表格默认行为改变数据顺序/格式 | 逐列保持现有渲染与排序口径；不添加默认排序、筛选或格式转换 |
| 日期控件时区/格式与请求不同 | 明确 `value-format`，沿用现有本地日期转换函数和参数值 |
| 弹窗遮罩误关闭或键盘关闭行为改变 | 统一关闭遮罩点击；保留显式关闭/取消；对破坏性动作保留确认 |
| 高密度表单迁移后难以扫描 | 机器设置按现有语义分组，不删除字段；桌面多列、窄屏单列并验证滚动 |
| 图表误导或重复实现后端规则 | 只用 API 返回的汇总；无时间序列不画趋势；不加入假数据与新 API |
| 后台路由 CSS/依赖体积扩散 | 组件按需引入，检查异步路由资源和产物体积；非后台页面实测 |

## 6. 验收标准

### 行为保持

- 14 个后台入口（含登录）和当前顶部菜单项均可访问，路由和页面标题保持。
- 权限角色下菜单可见范围和直接访问守卫不变。
- 每个页面当前字段、按钮、默认值、空状态、确认步骤、错误处理、API 请求与轮询周期保持。
- 表单提交的 API、参数和值口径保持；危险操作在未确认时不调用 API。
- 弹窗点击遮罩不会关闭；显式关闭和取消不会意外提交。
- 页面没有新增模拟数据，账务/开奖结果数值仅取当前接口结果。

### 界面一致性

- 所有通用表单控件、按钮、标签、表格、页签、分页、弹窗、消息和空状态使用 Element Plus 对应组件。
- 自定义 CSS 仅用于后台布局 token、开奖结果图形和无法由组件表达的少量语义样式；不再重复实现通用按钮/输入框/表格/弹窗皮肤。
- 1440×900、1280×720 与 768px 窄屏检查通过；无整页横向溢出，长表格在表格区域内滚动，弹窗内容可滚动且关闭区可见。
- 键盘可聚焦并操作菜单、表单、表格操作和弹窗；焦点状态清楚；状态不只靠颜色传达。
- `/room`、`/console`、`/display`、`/hby019-demo` 样式和交互未被后台主题改变。

### 工程边界

- 允许变更 `web/package.json`、lockfile、Vite 组件解析配置、平台后台 Vue 视图/组件和后台专属样式。
- 不应变更 `web/src/api.ts`、后端 Java、Flyway、数据库、权限常量、路由路径和业务类型；若发现确有阻塞，先记录并单独提出，不将其夹带进 UI 重构。
- 构建需确认 Element Plus 组件样式确实出现在当前后台入口资源中；开发态页面更新不能代替 Spring 静态资源构建和实际服务资源刷新。
- 测试、类型检查、构建、HTTP 冒烟及浏览器人工验收分项记录；未执行项不写成通过。
