# 机器人展示名同步历史消息开发计划

## 1. 目标

管理员修改机器人展示名后，历史机器人聊天消息与后续新消息使用同一个名称；已打开的聊天室在事务提交后即时更新，不要求用户手动刷新。

## 2. 实现范围

- 在 `ChatMessageRepository` 增加按机器人 ID 更新历史消息发送者名称的操作。
- 在机器人编辑事务中同步更新历史消息，失败时回滚机器人名称修改。
- 即使展示名没有变化，保存机器人配置时也执行幂等历史消息修复，覆盖功能上线前遗留的旧名称。
- 增加提交后的 `robot.updated` 单实例 WebSocket 事件。
- 前端收到事件后，仅更新相同机器人 ID 的已加载消息。
- 保留用户消息、机器人头像、消息正文、消息序号和审计字段不变。

## 3. 验收口径

- 修改机器人名称后，数据库历史 `ROBOT` 消息全部使用新名称。
- 新生成的机器人消息使用新名称。
- 在线聊天室收到事件后立即更新对应历史消息。
- 非该机器人的消息不被修改。
- 机器人编辑失败时不产生部分更新。

## 4. 验证边界

- 使用 JDK 21、测试 H2 验证仓储与服务事务行为。
- 使用现有前端类型检查和构建验证 WebSocket 事件契约。
- 本计划不修改真实 MySQL 数据，运行态 MySQL 验证另行执行。
