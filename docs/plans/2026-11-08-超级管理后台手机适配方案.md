# 超级管理后台手机适配方案

> 状态：已审核并实施；本机代码与自动化验收完成，手机登录后的手工浏览器验收待确认。实施记录见[开发计划与本机验收](2026-11-08-超级管理后台手机适配开发计划.md)。
> 范围：平台超级管理后台 `/platform-admin/**` 的手机与窄屏展示；不包括代理后台 `/console`、玩家端、后端接口、权限与业务规则。
> 设计原则：桌面版维持现有布局；手机端按屏幕宽度重排信息，不把整张桌面页面压缩成不可读的小画面；BY220 菜单、字段、操作与状态流程不因适配而删减或改义。

## 1. 问题与现状

用户提供的手机截图显示：

- 顶部导航在窄屏下折行并出现更多菜单入口，菜单可达性不直观。
- 子账号与机器账号列表仍在渲染，但列宽超过手机可视宽度；用户名、账号等重要列被挤压，操作区需要横向移动才能完整查看。
- 机器管理表格字段较多，当前使用固定列宽和固定操作区，手机上难以同时理解账号信息与操作。
- 开奖信息截图里球号显示 `null`。这属于开奖数据的空值处理/接口状态问题，不是布局问题，应独立排查，不能通过移动 CSS 掩盖。
- 电脑上显示正常，说明本方案应以窄屏断点内的局部样式和移动呈现为主，避免改动桌面布局。

当前代码依据：

| 区域 | 当前实现 | 手机端问题 |
| --- | --- | --- |
| 公共导航 | `web/src/components/platform-admin/PlatformAdminNav.vue`，Element Plus 横向菜单，`ellipsis` 更多菜单 | 菜单项挤压到更多入口；欢迎信息和退出按钮在窄屏换行 |
| 全局样式 | `web/src/styles/platform-admin-element.css` | 全局表格字体 16px；目前没有统一的后台手机页面结构策略 |
| 子账号 | `web/src/views/PlatformAdminSubAccounts.vue`，8 列表格，固定操作列；新增/编辑用对话框 | 信息列总宽度大于手机；固定操作列占宽，导致用户名等信息被裁切或需横向滚动 |
| 机器管理 | `web/src/views/PlatformAdminMachines.vue`，包含账号、失效、所属子账号、积分、状态、下注开关、托数量、赔率/返水/限额等列及操作列 | 列数量多；账号、所属关系与部分操作不在同一可视范围 |
| 开奖信息 | `web/src/views/PlatformAdminHome.vue`，结果球、历史表和路子图 | 结果区可换行；多列历史表需要专门处理；空值显示需单独修正 |
| 其他后台页 | 路由见 `web/src/main.ts`，统一使用 `PlatformAdminNav` | 各页筛选栏、数据表、弹窗的密度不一致，需逐页套用移动规则并核对 |

项目根页面已有 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`。后续不得添加 `user-scalable=no` 或 `maximum-scale=1` 等禁用缩放设置；浏览器双指缩放应继续可用，但它是辅助能力，不替代页面自适应。

## 2. 业务与页面映射

超级后台对应 BY220 `admin.php`。移动适配仅改变呈现方式，不改变下列入口、角色可见性和操作链：

| BY220 页面/操作 | Xupan 当前实现 | 手机呈现要求 |
| --- | --- | --- |
| 顶部菜单、欢迎信息、安全退出：`application/admin/view/public/head.html` | `PlatformAdminNav.vue` | 菜单收纳到可明确打开的导航抽屉/菜单；保留当前页名称、账号信息、安全退出与权限过滤 |
| 开奖信息 | `/platform-admin`、`PlatformAdminHome.vue` | 当前结果放在首屏；结果球按可用宽度换行；历史与路子图纵向排列 |
| 子账号列表、添加、编辑、启停、解锁、删除：`application/admin/view/sub/list.html`、`sub/form.html` | `/platform-admin/sub-accounts`、`PlatformAdminSubAccounts.vue` | 每条账号改成手机信息块；所有现有字段与操作仍可查看/触发；新增/编辑保留原字段与业务语义 |
| 机器列表、添加、编辑、玩家、复制登录链接、启停、解锁、删除：`application/admin/view/rb/list.html`、`rb/form.html` | `/platform-admin/machines`、`PlatformAdminMachines.vue` | 列表改成账号摘要 + 可展开详情；所有字段与操作仍可访问；长表单在手机全屏编辑 |
| 开奖历史、报表、订单、在线玩家、设置、网盘/游戏配置、修改密码 | `web/src/main.ts` 中对应 `/platform-admin/**` 页面 | 筛选区竖排；记录按页面性质使用信息块或明确的横向表格；表单单列；不合并菜单或减少操作 |

机器账号表格的每一项字段仍归属于同一台机器；子账号与机器管理仍是 BY220 中两个独立菜单，不合并成新页面。用户权限继续由现有 `permission` 和路由门禁决定，移动导航仅展示当前账号有权访问的菜单。

## 3. 推荐交互方案

### 3.1 公共导航

- 桌面端继续使用现有横向菜单和欢迎/退出区域。
- 手机端将导航压缩为一行：菜单按钮、当前页面名称、必要的账号/退出入口。点击菜单后打开侧边抽屉或全屏菜单，按现有顺序列出当前账号有权限访问的全部后台入口。
- 当前页面在菜单中有明确选中态；点击菜单项后关闭抽屉并进入原路由。
- 欢迎信息不得挤占主要内容区。手机可以将完整欢迎文本放入账号菜单/导航抽屉，并在导航栏保留短账号标识。
- 不新增底部导航，不调整 BY220 菜单顺序，不把低频菜单改成不可发现的隐藏入口。

### 3.2 子账号列表

手机每个子账号显示为一张纵向信息块：

- 首行：用户名、状态（正常/停用/已锁定）。
- 次行：积分、失效时间、机器数量。
- 详情区：子账号管理权限、机器人权限；所有当前表格字段必须在卡片或展开区中可见。
- 操作区：编辑、启用/停用、解锁（锁定时）、删除。按钮可换行，删除与常用操作视觉分组；不得因屏幕窄而丢失操作。
- 新增子账号入口保持在页面标题附近；批量创建仍使用英文逗号的既有输入规则。
- 空列表、加载、接口错误和删除确认保持现有状态语义。

### 3.3 机器管理列表

每条机器记录使用“摘要 + 详情 + 操作”：

- 摘要首行：账号用户名、状态、下注开关。
- 摘要次行：所属子账号、积分、失效时间。
- 详情区：密码掩码、托数量、封盘/取消秒数、返水值与口径、赔率、总限额、玩家/托数量，以及代码中当前表格展示的其他配置字段。
- 操作区：编辑、玩家、复制登录链接、启用/停用、解锁（锁定时）、删除。低频危险操作可放入“更多”菜单，但入口必须可见且不改变原操作能力。
- 展开详情不触发额外写操作，不改变机器/子账号的归属或配置权限。
- 玩家列表弹窗在手机上按玩家信息块展示；昵称、会员编号、类型、余额、状态都可查看。

### 3.4 新增与编辑表单

- 手机宽度下，Element Plus 桌面弹窗改为占满可视区域的全屏编辑面板；顶部固定标题/返回，底部固定取消/确认，表单内容区域独立纵向滚动，并处理设备安全区。
- 表单字段单列排列，输入控件宽度充满可用空间，标签在控件上方；点击输入框时页面可随软键盘滚动到当前字段。
- 保留现有新增态与编辑态字段差异、字段顺序、默认值、只读状态、校验和提交行为。机器编辑表单较长，分组标题只用于组织现有字段，不改变字段归属和提交接口。
- 日期时间、下拉选项、开关和积分输入在手机上不能被屏幕边缘裁切；日期选择器弹层必须留在可视区域。
- 删除仍需二次确认；确认弹层在窄屏内完整显示操作对象和后果，不能因布局简化警示内容。

### 3.5 其他管理页面

- 开奖信息：当前期结果和状态优先；球号自动换行；历史记录按期排列。需要横向比较的历史列保留独立滚动容器，不带动整个页面左右移动。
- 开奖历史、未结订单、订单改单、在线玩家：筛选项纵向堆叠；列表在窄屏优先展示记录摘要卡片和原有操作，所有字段通过展开详情访问。若页面场景必须保留表格，表格容器须有清楚的横向滚动边界，首列/操作列按需固定。
- 报表、游戏设置、平台设置、网盘设置、中心上游：筛选与配置表单改为单列；统计项纵向排列；宽数据表独立滚动或使用记录卡片，不把整页设置为固定桌面宽度。
- 修改密码：表单单列、提交按钮易触达；认证规则不变。
- 开奖球号 `null`：列为独立缺陷调查和验收，不在移动适配任务中悄悄改成占位值或伪造数据。

## 4. 断点与技术约束

建议断点：

| 视口宽度 | 布局策略 |
| --- | --- |
| `>= 1024px` | 保留当前桌面菜单、表格和表单布局；不应用手机样式 |
| `768px–1023px` | 平板过渡区；导航允许换行，表单可缩列，宽表只在表格容器内横向滚动 |
| `< 768px` | 启用手机导航、账号卡片、单列筛选/表单、全屏编辑面板 |

实现约束：

- 仅在超级管理后台共享组件和对应页面中新增窄屏规则；禁止对所有后台共用选择器设置固定 `min-width`、`zoom` 或 `transform: scale()`。
- 桌面样式保持当前默认值；移动规则使用局部类名和媒体查询，避免影响 `/console`、玩家端、展示页。
- 数据源、接口、Flyway、认证授权、角色权限、菜单顺序、业务操作、提交顺序和确认语义均不因本任务变化。
- 列表卡片与桌面表格使用同一份加载数据和同一套操作函数；不得为了手机另建不同权限或数据口径。
- 页面整体不应出现横向溢出。确需横向比较的表格只允许在表格自身滚动，并应保留可发现的滚动反馈。
- 保留 viewport 缩放能力，不声明 `user-scalable=no`、`maximum-scale=1`；手机适配优先通过真实布局重排实现，不使用桌面画布整体缩小作为主方案。
- 触控目标建议不小于 `44×44 CSS px`；键盘/浏览器缩放后内容不能重叠，固定底部按钮需考虑 `safe-area-inset-bottom`。

## 5. 实施顺序

1. 实施前再次核对 BY220 菜单、子账号/机器列表字段、表单顺序与操作结果，输出逐项映射；同时截取当前电脑端基准图。
2. 先改 `PlatformAdminNav.vue` 和后台公共样式，建立手机菜单和页面宽度约束。
3. 改造子账号列表为手机信息块，并适配添加/编辑表单。
4. 改造机器管理列表、玩家列表与机器新增/编辑表单。
5. 按路由清单适配开奖信息、开奖历史、报表、订单、在线玩家、设置和密码页，逐页记录字段及操作入口。
6. 对 BY220 有对应页面逐项核对桌面与手机下的菜单/字段/操作映射；独有的 Xupan 页面保持其已确认边界。
7. 完成手机浏览器验收后再更新业务模块基线、文档索引和实施验收记录；未经服务器发布不得写成服务器或生产已适配。

## 6. 验收标准

### 视口与呈现

- 手机基准视口：`360×800`、`390×844`、`430×932`；平板：`768×1024`；桌面回归：`1280×720`、`1440×900`。
- 360/390/430px 下页面本身无横向滚动；子账号用户名、机器账号、所属关系、状态和主要操作无需左右拖动即可看到。
- 机器表格中的每个现有字段都可在摘要或详情中找到；所有既有操作都可触达。
- 菜单能打开并访问当前角色有权限的全部入口；没有权限的入口仍不可见，直接访问路由时原有权限拦截保持有效。
- 对话框/全屏表单不会被浏览器工具栏、软键盘或安全区遮挡；确认/取消固定操作可达。
- 浏览器双指缩放没有被页面设置禁用；缩放后控件、菜单和弹层不发生错位或互相遮挡。

### 功能回归

- 子账号：新增、批量新增、编辑、上/下分、权限开关、启停、锁定解锁、删除与二次确认按原流程工作。
- 机器管理：新增、编辑、所属子账号、机器配置、玩家列表、复制链接、启停、锁定解锁、删除按原流程工作。
- 所有表单保留原有字段、校验、提交请求和成功/失败反馈；卡片切换不能重复提交或触发不同接口。
- `1280×720` 与 `1440×900` 桌面端菜单、表格列、对话框和操作位置相对当前基准无非预期变化。
- 开奖 `null` 数据问题单独记录/修复，不以本方案的布局通过代替数据正确性验收。

### 环境与证据

- 自动化：受影响的导航、子账号和机器管理组件/页面专项测试；全局类型检查与生产构建。
- 浏览器：Android Chrome 与实际使用的内置浏览器至少各验一次；如有 iPhone 使用者，补 iOS Safari。
- 验收记录区分代码静态检查、自动化测试、本机浏览器、服务器和生产；未执行的环境不得写成通过。

## 7. 本方案不包含

- 不改变 `/platform-admin` 与 `/console` 的职责边界，也不将机器代理菜单挪入超级后台。
- 不新增、删除、合并或改名 BY220 菜单、字段或业务流程。
- 不改 API、数据库、权限、报表口径、下注/开奖/结算流程和真实积分语义。
- 不处理开奖结果 `null` 的数据来源；需另行按页面/API/服务/数据链路查明。
- 不把“可以双指缩放”当成移动适配完成；目标是不用缩放也能阅读和完成常用管理操作。

## 8. 评审建议

建议按“公共导航 → 子账号 → 机器管理 → 其他平台管理页”的顺序实施。第一阶段以子账号和机器管理作为验收样板：如果用户能在手机上看到完整账号身份、状态、归属和常用操作，且桌面截图无回归，再将同一布局原则扩展到其他后台页面。
