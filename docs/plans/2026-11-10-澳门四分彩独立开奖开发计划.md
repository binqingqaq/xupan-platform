# 澳门四分彩独立开奖开发计划

> 状态：本机代码和 V113 已实施，V114 控盘迁移后共享库为 V114；8080 已重启并验证健康/路由。登录浏览器、真实开奖周期、服务器和生产验收尚未完成。业务口径来自[澳门四分彩独立开奖业务需求草案](../需求基线/2026-11-10-澳门四分彩独立开奖业务需求草案.md)及使用者 2026-11-10 的确认。

> 本计划只覆盖澳门四分彩后台预设、独立定时开奖、开奖记录及 `/display/mobile` 展示。当前工作树存在未提交的开奖/投注相关源码、文档和静态构建产物修改；实施前必须重新核对 Git 状态和这些文件的差异，不得覆盖或回退既有改动。

## 1. 目标与边界

建设一条独立于 AU8 的澳门四分彩开奖链路：期号从 100 开始，每天北京时间 20:30 开一期；七个球位分别允许管理员预设 1～40 号码；空位在开奖时随机补齐，同期开奖七个号码不重复。开奖结果持久化后转为“已开奖”，并创建次日 20:30 的“待开奖”期。

平台后台新增“澳门四分彩”菜单和专用管理页。表格默认总计 20 条，首行是下一期待开奖记录，后面是最新 19 条历史开奖。仅待开奖行可编辑七球预设。移动开奖页澳门四分彩行改读自己的后端数据；下一期未开奖时继续显示最近一次已开奖的七个号码，20:30 开奖完成后立即刷新为新结果。公开开奖页面的期号只显示末三位。

澳门四分彩仅用于开奖展示，不登记为可下注游戏，不参与投注、结算、机器人消息、代理后台、中心上报或报表。不得让它进入现有 AU8/通用游戏轮期及自动结算链路。

## 3. 数据与后端设计

### 3.1 独立持久化模型

通过新的 Flyway 迁移建立独立的澳门四分彩开奖记录，不复用 `game_issue` 或快乐8展示快照。推荐采用期次主表加七球明细表：

- 期次记录保存完整期号、北京时间计划开奖时刻、实际开奖时刻、状态和创建/更新时间。
- 球位明细固定为位置 1～7，每期预建七行；号码可空表示尚未预设，开奖后七个位置必须全部有最终号码。
- 约束包括期号唯一、计划开奖时间唯一、期次与球位唯一、号码 1～40、同一期号码唯一、期次状态仅 `PENDING`/`DRAWN`。
- FK、索引、字符集、时区转换、迁移命名及 MySQL 8.4 LTS 兼容性按仓库标准实现；数据库保存时间统一按项目现有 UTC/`Instant` 约定核对，业务排期用 `Asia/Shanghai` 计算。
- 不向 `game_definition`、投注表、赔率表、注单表、自动结算或机器人事件表写入澳门四分彩数据。

实际采用主表/子表或单表七列，应在完成迁移和 BY220 核查后定稿；上述唯一性、完整性和可追溯要求不得削弱。

### 3.2 期次初始化和每日调度

- 首次初始化创建期号 100 的一条待开奖记录，计划时间设为部署启动时之后最近的北京时间 20:30；若已过当日 20:30，则设为次日 20:30。初始化和服务重启必须幂等，不能重复创建 100 期。
- 到计划时刻后，专用调度服务锁定当前待开奖记录，校验球位预设并完成开奖。已填号码原样保留；空位通过安全随机源从剩余可用号码中无放回抽取。
- 中奖结果写入、状态转为 `DRAWN`、实际开奖时间落库以及次日期号 `+1` 的 `PENDING` 记录创建，放在同一事务内提交。期号 100 后为 101、102，按天连续递增。
- 以数据库期次锁和唯一约束防止多调度线程/多实例重复开奖或重复建下一期。重试遇到已完成期时保持幂等，不重抽、不改写已公布结果。
- 失败不能静默跳期。事务失败时该期仍为待开奖，由调度重试；记录可排查日志并提供健康/告警信号。公开业务状态仍只有“待开奖”和“已开奖”，不向页面增加“开奖中/失败”等状态。
- 需避免错误预设阻塞到期开奖：重复预设号码在保存阶段拒绝；开奖服务在事务中再次校验完整性，异常时不发布半成品结果。

### 3.3 管理端 API、权限与审计

- 提供分页读取接口：返回待开奖期和已开奖历史，默认 `pageSize=20`。第一页最多为待开奖 1 条 + 历史 19 条；后续页仅含历史。历史不足 19 条时返回现有数据，不制造历史行。
- 提供仅针对下一期待开奖期的七球预设保存接口。请求必须包含目标完整期号和七个可空球号；服务端锁定期次并确认仍为当前 `PENDING` 期，防止页面打开后跨日迟到请求写进新一期。
- 校验每球为 `null` 或 1～40 整数，所有已指定号码互不重复；保存请求对七球整体提交，空值表示清除该球预设，不能因为未填写而错误保存为 0。
- 编辑接口按最新授权策略仅授予超级管理员；使用独立读取/管理权限，菜单和后端接口都执行拒绝优先校验。不得依赖“菜单隐藏”作为授权。
- 每次确认保存记入操作审计：操作者、期号、七球变更前后值、时间、请求结果。开奖本身记录期号、计划/实际时间及最终球号，禁止普通管理接口修改已开奖记录。
- 错误响应区分未授权、期次已开奖/已切期、号码范围非法、重复号码和保存失败，前端显示可理解提示。

API 路径及 DTO 命名在 BY220 映射和现有 REST 约定检查后确定；不得借用 `draw-history/supplement` 或 `force-settle` 语义。

## 4. 后台页面计划

1. 在 `/platform-admin` 菜单中增加“澳门四分彩”，使用独立读取权限；路由加入平台管理员路由守卫与 Spring SPA 回退名单。
2. 页面只显示六列：彩票名称、期号、开奖球号、开奖时间、当前状态、操作。移除筛选区、补期区、下注/待结算列及其他操作。
3. 默认取 20 条并按待开奖行在首、历史最新在后的顺序展示。待开奖行显示已预设号码、空位 `-`、计划开奖时间和“待开奖”；历史行显示七个正式结果、实际开奖时间和“已开奖”。完整期号可在后台管理表中辨识；末三位规则用于公开开奖页。
4. 操作列只出现“编辑”这一种操作；仅待开奖行启用。历史行不提供编辑入口。
5. 点击“编辑”打开 7 个球位的号码表单，加载当前预设；允许逐球指定或清空。点击“确认”只保存，不触发开奖、不创建下一期。弹窗/抽屉形式按现有后台组件约定选择。
6. 保存成功后刷新该期数据；并发切期时服务端返回冲突，页面重新拉取当前 20 条记录，不覆盖新一期预设。
7. 覆盖桌面和手机：表格可在窄屏读取关键字段；不得让操作列遮挡期号/号码。移动卡片样式沿用超级后台现有手机适配组件模式。

## 5. 开奖页 API 与显示计划

- 新增公开只读接口，例如 `GET /api/display/mobile/macau-four-minute`。响应至少区分 `latestDraw` 与 `nextDraw`，提供服务端当前时间、下一期开奖计划时刻、最新完成期完整期号/七球和下一期待开奖期号/状态；绝不返回下一期管理员预设号码。
- 没有新的澳门四分彩结果时，前端保留最近已开奖期的球号，不将未来期空球渲染成空白，也不以快乐8/其他彩种的号码代填。
- 公开奖页对期号做末三位显示格式化；API、数据库和后台仍保留完整期号，避免期号 `1000` 及以上时丢失真实主键。
- 在下一期开奖时间到达时，页面按服务端时间对齐刷新；接口若因调度事务尚未提交而仍返回旧结果，短间隔重试直到最新完成期号匹配待开奖期。后台接口不得缓存旧响应；保留页面重新进入时的即时加载和现有页面可见状态刷新方式。
- 仅更新澳门四分彩卡片，不调用 `refreshAu8Draw()` 更新其数据；快乐8刷新、倒计时和观察入口保持不变。澳门四分彩刷新按钮（如现有占位行含该按钮）只请求新接口。
- 开奖后页面展示本期开奖球号并切换为下一期的 20:30 计划时间；状态展示“已开奖/待开奖”，不展示“开奖中”。

## 7. 验收标准

### 数据与开奖

- 初始创建期号 100；每天按北京时间 20:30 轮期，后续期号连续递增，计划时刻为次日 20:30。
- 七球全部为空时，开奖得到 7 个 1～40 的不同号码；只预设部分球时，指定位置保持原值，其他位置无放回随机补齐；全预设时原样开出。
- 超范围、非整数或重复预设不能保存；清空预设会让该位置恢复随机。
- 开奖结果、状态和下一期待开奖记录原子提交；并发调度只生成一次结果/下一期。故障重试不跳期、不生成部分结果、不重写已开奖记录。
- 新流程不产生下注、结算、钱包、机器人、代理/中心记录；既有 AU8 开奖行为不变。

### 管理后台

- 菜单在 `/platform-admin`；普通机器账号 `/console` 不出现入口；未授权用户直接调管理 API 也被拒绝。
- 第一页默认 20 条，由 1 条待开奖 + 最多 19 条最新历史组成；记录不足时只展示真实存在的数据；翻页不重复待开奖行或历史记录。
- 列和按钮严格符合需求：六列，操作只含“编辑”；只有待开奖记录可编辑。
- 编辑 7 球、部分保存、清空、重复号/非法号校验成功；保存不开奖；跨日迟到请求不会改下一期；审计可查操作者及变更。
- 桌面/手机列内容均可辨识，操作不会遮挡核心数据。

### 开奖页

- 快乐8数据只更新快乐8；澳门四分彩不再复制其期号、号码、倒计时或刷新结果。
- 20:30 前显示最近已开奖的七球结果而非空白；公开 API 不泄漏后台预设。
- 到开奖时刻，后端完成后前端立即更新为新期结果和七球；遇到提交延迟会继续读取，成功后展示次日计划期。
- 显示期号末三位（包含 100、999、1000 边界）；后端/数据库仍保留完整期号。
- 刷新页面、重新进入、接口临时失败恢复后，显示与后端已持久化结果一致。

## 8. 实施前风险与待定门禁

1. **首次真实历史结果**：目前没有澳门四分彩独立的上一期结果。首次开奖前页面按确认需求要显示上一期号码，但不能拿快乐8镜像或造测试值冒充真实历史。上线前需提供可确认的首条历史结果（例如期号 99 的真实数据），或由使用者明确接受首期开奖前的临时空历史状态。该问题解决前不得宣称首次开奖前页面满足“显示上一期号码”。
2. **起始期安排**：本计划建议首次部署创建期号 100，并排到之后最近的 20:30。正式实施前需确定开通日期与该次首次开奖时刻，避免部署时间决定业务首期而未告知。
