# 玩家积分记录弹窗与业务日对账实施计划

## 目标

在玩家工作台中增加普通玩家积分记录和托积分记录入口，使用同一套按业务日查询的记录结构。业务日按 `Asia/Shanghai` 每天 06:00 切换；统计只使用当前项目已有的虚拟积分、注单、结算和托动作事实，不实现抽水或飞单。

## 已确认规则

- 业务日边界：每天早上 6 点。
- 总盈亏：统计该业务日已结算注单的 `net_profit` 合计。
- 普通玩家和托：共用记录结构，入口名称不同。
- 抽水、飞单：暂不建模、暂不展示、暂不计入统计。
- 数据事实源：MySQL 业务表和钱包流水，不使用前端计算结果作为唯一事实。

## 实施范围

- 后端新增玩家积分记录查询接口，服务端负责业务日边界、日期校验、汇总和明细排序。
- 复用 `game_bet`、`demo_balance_ledger`、托动作表；只有发现查询所需索引缺失时才新增 Flyway 迁移。
- 前端移除详情页中的“最近动作”和“最近注单”展示。
- 创建普通玩家、创建托按钮下增加“积分记录”“托积分记录”，使用弹窗按日期查看汇总和明细。
- 保持 `USER_MANAGE` 权限边界，避免把玩家记录接口开放给普通玩家。

## 验收边界

- 静态检查：接口响应字段、业务日换算、权限和 SQL 参数边界。
- 快速验证：后端相关 H2/Flyway 测试、前端类型检查和现有相关测试。
- 本机 MySQL、服务器和生产环境未执行前，不表述为已完成上线验收。
