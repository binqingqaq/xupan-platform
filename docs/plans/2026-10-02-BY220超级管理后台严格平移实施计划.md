### 子账号登录和范围规则

- Flyway V49 为 `agent_group` 增加 `sys_user_id`，创建子账号时同步创建登录账号并分配 `SUB_ACCOUNT` 角色。
- 子账号使用 `/platform-admin/login` 登录，首页通过开奖历史只读接口展示开奖信息，不再依赖玩家钱包。
- 子账号菜单由权限裁剪：开奖信息、机器管理、报表统计、开奖历史、修改密码和安全退出。
- 机器列表、机器编辑、机器状态和机器玩家查询限制在子账号所属分组。
- 报表统计自动覆盖前端传入的子账号筛选，只允许查看自己的机器和玩家数据。
- 子账号不能访问子账号管理、未结订单、订单改单、在线玩家、设置、网盘、游戏设置和强制结算/补期。

### 子账号过期与动态权限收口（本轮）

- 对齐 BY220 `Login.php`：密码校验通过后，若 `agent_group.expires_at` 早于当前时间，登录返回账号已过期；相等时仍按 BY220 视为未过期。
- 已签发会话在每次请求重新加载用户时再次校验子账号状态和失效时间，过期后立即不能继续访问，不等待 access token 自然到期。
- 对齐 BY220 `x_admin.rbxiugai`：`agent_group.machine_manage` 为关闭时从 `SUB_ACCOUNT` 的有效权限中移除 `MACHINE_MANAGE`，机器菜单和机器 API 均不可用；开通后动态恢复，不签发新角色或硬编码账号。
- 平台管理登录页允许具有 `PLATFORM_HOME_READ` 的子账号进入；`/platform-admin` 的未登录和会话过期跳转固定回 `/platform-admin/login`，不落到代理或玩家登录页。

### 设置页删除全量账号规则

- BY220 页面调用 `Gd.php::userDels`，要求确认文本 `DELETE_ALL_ACCOUNTS`，先预检数量再二次确认；xupan 使用同一流程。
- 预检字段保持 `admins`、`robots`、`players`、`flyers`；执行在一个事务内软删除非保护账号、机器和子账号，保护当前超级管理员和系统直属主机器。
- 玩家/托写入 `DELETED` 状态并撤销非保护会话；钱包、注单、流水和历史审计事实保留。
- BY220 参考 `changed/config.html` 的“清空数据”指向 `index/clearData`，对应控制器 `Index.php::cleardata`，本轮按该方法的时间、预检、`CONFIRM_CLEAR` 和事务删除流程平移。

### 子账号与机器删除规则

- 对齐 BY220 `Users.php::userDel` 和 `Rb.php::UpdatePanStatus(type=del)`，子账号和机器列表恢复“删除”按钮及确认文本。
- 当前项目不物理删除业务事实：`agent_group` 和 `agent` 使用 `deleted_at/deleted_by` 软删除，同步软删除登录账号、撤销会话并写操作审计。
- 子账号仍存在未删除机器时拒绝删除并返回 `SUB_ACCOUNT_HAS_MACHINES`；机器仍存在未删除玩家/托时拒绝删除并返回 `MACHINE_HAS_PLAYERS`，不在超级管理后台级联删除玩家、注单或流水。
- 所有列表、范围校验和代理后台查询排除软删除记录；历史审计仍保留删除人和删除时间。
- MySQL `TIMESTAMP` 的 2038 年边界在服务端写库前校验，避免把数据库错误直接暴露为 500。

## 7. 订单改单页面映射

BY220 来源：

- 页面控制器：`application/admin/controller/Changed.php::changeRecord`
- 改单接口：`Changed.php::resetRecordNew`
- 列表模板：`application/admin/view/changed/record.html`

- 列表数据：`Tongji.php::GetUnCalculate`

- 所属机器人
- 昵称
- 期号
- 时间
- 金额
- 投注内容
- 操作：编辑

编辑字段：

- 订单ID、期号、所属机器人、昵称只读。
- 指令可编辑。
- 球选择 1-8。

xupan 实现：

- 只允许普通玩家、`PENDING` 注单、当前期 `BETTING` 且未到封盘时间。
- 指令由现有 `BetTextParser` 校验，只接受单条合法下注。
- 当前技术基线支持 1 至 8 球；改单保存新旧球号，重复请求校验球号一致。
- 玩法或指令变化时重新校验参数和赔率；玩法不变时保留原赔率快照。
- 投注额增加时扣减差额，投注额减少时返还差额。
- 使用 `game_bet_edit_record` 保存改单前后字段、差额、操作人和幂等键。
- 钱包使用 `BET_EDIT_DEBIT` / `BET_EDIT_REFUND` 专用流水，避免伪装成普通上下分。
- 重复请求按幂等键重放，不重复调整积分；并发改单通过注单行锁和版本号冲突保护。
- 已开奖、已结算、已撤单或封盘后禁止改单。

差异项：BY220 通过自由文本和多条记录联动改单，当前项目使用结构化 `game_bet` 和单条指令；球号已支持 1 至 8。

## 14. 报表双边流水和反水映射

BY220 来源：

- 页面控制器：`application/admin/controller/Tongji.php::GetYingKui`
- 计算函数：`application/common.php::getRecordData`、`getShuang`、`getShuangs`
- 页面模板：`application/admin/view/tongji/index.html`

BY220 口径：

- 总流水为已结算注单的投注额合计。
- 单边流水在获胜时累计 `yingScore`；当前结构化模型映射为普通玩法净收益，特殊玩法按返还额。
- 双边流水在获胜时按玩法折算，失败时累计有效投注额；通/含通类按一半，车类获胜按三分之一。
- 反水按 BY220 `fanshui / 100` 计算，获胜普通玩法以净收益为基数，特殊玩法以投注额为基数并使用 `teFanshui`。
- 输赢使用 `WIN / DRAW / LOSE`；DRAW 不计双边流水和反水。

xupan 实现：

- Flyway V48 为 `game_bet` 增加 `rebate_rate_snapshot`、`special_rebate_rate_snapshot`。
- 新注单在下注时保存机器当前返水和特码返水；存量注单迁移时按所属机器当前配置回填。
- 报表按注单快照计算，后续修改机器返水不会改变历史报表。
- 页面不再显示“待规则确认”，真实展示单边流水、双边流水和反水。

差异项：BY220 使用旧 `x_record` 的 `yingScore/totalYing/Fanshui` 字段；xupan 用结构化 `game_bet`、赔率快照和返水快照按 BY220 函数口径重算。
