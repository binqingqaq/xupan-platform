# 聊天指令、限时撤单与上下分申请实施计划

## 目标

在现有服务端聊天、虚拟积分、期号和下注链路上，增加已确认的玩家指令：`查`、`玩法`、`上金额`、`下金额`、`流水`、`取消`。所有事实继续落库，机器人反馈继续复用聊天室消息、outbox 和实时广播。

## 已确认规则

- `查`不区分期号阶段，始终返回当前玩家剩余粮草。
- `玩法`消息对全员可见，服务端不发布机器人回复；前端说明按钮只弹窗。
- `上金额`、`下金额`建立待审批申请；申请创建时不改变余额。
- `流水`统计当前业务日的下注金额、已结算净盈亏和今日涉及的期号数量。
- `取消`只处理当前期、当前玩家、仍未结算且各自下注时间不超过 10 秒的注单。
- 取消成功后退回下注积分、注单状态改为 `CANCELED` 并记录 `canceled_at` 与取消说明，不再进入结算，用户可以继续下注；多个注单按消息换行返回明细。
- 当前期进入最后 30 秒或 `DRAWING` 后禁止取消。

## 实施顺序

1. 增加聊天指令解析和逐类反馈。
2. 增加待审批上下分申请表、幂等键和后台审批服务入口。
3. 增加注单撤销标记、撤单钱包流水和事务性批量撤单。
4. 增加今日流水和涉及期数查询。
5. 补充 H2/Flyway、服务层和聊天控制器测试，并检查 MySQL 8.4 迁移兼容性。

## 验收边界

静态代码、H2 和本机 MySQL 迁移可以验证状态机、事务、幂等和查询口径；真实多用户 WebSocket、审批人员现场操作、服务重启中的撤单竞争和生产故障恢复仍需单独验收。
