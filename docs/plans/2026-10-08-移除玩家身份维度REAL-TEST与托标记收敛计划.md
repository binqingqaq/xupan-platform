## 1. BY220 事实（唯一依据）

**BY220 没有"身份"这个维度，只有一个布尔标记 `isrobot`。**

| BY220 用法 | 位置 |
| --- | --- |
| 列定义：`x_rbuser.isrobot`（LONGTEXT，0/1） | `sql/schema-base.sql`（`CREATE TABLE x_rbuser`） |
| **普/托 的唯一定义**：`0`=普、`1`=托 | —— |
| 上下分：**只有普扣机器分** | `application/rbt/controller/Index.php:622-623` `if ($isTuo['isrobot'] == 0) { db('robot')->…->setDec('score', …) }` |
| 托的余额校验 | `application/rbt/controller/Index.php:637` |
| 列表按 `type` 在普/托之间切换 | `:489`、`:582` `where('isrobot', $data['type'])` |
| 汇总只算普 | `:1090` `where(['uid' => USER_ID, 'isrobot' => 0])` |
| 在线列表里标"机器人" | `application/admin/controller/Users.php:175` `if($value['isrobot'] == 1)` |
| 托的自动行为只挑托 | `application/chat/…/Websocket.php:442-443,540` `where('isauto',1)->where('isrobot',1)` |
| 玩家自注册写普 | `application/…/Wxlogin.php:44` `'isrobot' => 0` |
| 前端派生 `isTuo` | `application/common.php:1156/1191/1231` `'isTuo' => $value['isrobot'] == 1 ? 1 : 0` |
| 全仓查 `测试玩家|试玩|测试账号|isTest|ceshi` | **零命中**（BY220 无此概念） |

配套字段（同属 `x_rbuser`）：`isauto`（是否自动行为）、`isBlack`、`isVip`、`gid`（彩种）、`uid`（归属代理）。

**结论**：BY220 里"托"就是玩家行上的一个标记；**不存在 REAL/TEST 身份维度**。

## 3. 目标设计（对齐 BY220）

1. **`demo_user_account.player_kind`（`NORMAL` | `BOT`）是玩家类型的唯一标记** —— 即 BY220 的 `isrobot`。
2. **删除 REAL/TEST 维度**：
   - `sys_user.user_type` 列与其 CHECK 约束删除；
   - `demo_user_account.identity_type` 列与其 CHECK 约束删除；
   - 所有 `identity_type IN ('REAL','TEST')` / `user_type = 'REAL'` 谓词消失。
3. **BOT 的"不能以玩家身份登录"这一行为保留**，但**判定依据换成 `player_kind='BOT'`**（BY220 里托没有登录凭据，属隐式；本项目用显式判定更安全）。实现方式由实施 lane 在两种里择一并说明理由：
   - (甲) 认证查询 `JOIN demo_user_account` 取 `player_kind`（无冗余字段，多一次 join）；
   - (乙) 在 `sys_user` 上加一个从 `player_kind` 派生的布尔列（少 join，但有冗余一致性风险）。
   **本计划倾向 (甲)**（单一事实源，符合 BY220"只有一个标记"）。
4. **平台「用户管理」列表**：由"排除 `user_type='REAL'` 之外"改为"排除 `player_kind='BOT'` 的账号"，语义不变、依据换成 BY220 口径。
5. **`TestPlayerAdminService` → `BotPlayerService`**，错误码 `TEST_PLAYER_*` → `BOT_*`（同步前端文案映射与测试）；删除控制器移除后已死的方法（`list/detail/grant/reset/placeBet/betTargetUserId`）与 `VirtualWalletService.reset`。
6. 顺带清理死配置：`SecurityConfig` 的 `/api/admin/test-players` 匹配器（阶段 3 lane 已处理）；`SpaController:44` 的 `/admin/test-players` 白名单**保留**（让该已下线地址落到独立 404 页，符合 Q4=E2）；前端孤儿 `types.ts` 的 `TestPlayer*` 与 `web/src/testPlayerAdmin.ts` 删除。

## 4. 迁移（V77）

```sql
-- 1) 丢弃 CHECK 与列（两者都只服务已废弃的 REAL/TEST 维度）
ALTER TABLE sys_user DROP CHECK <user_type 的 CHECK 名>;          -- 名称以 V15 实际定义为准
ALTER TABLE sys_user DROP COLUMN user_type;
ALTER TABLE demo_user_account DROP CHECK <identity_type 的 CHECK 名>;
ALTER TABLE demo_user_account DROP COLUMN identity_type;
```
- **必须在同一批里先改完所有读取点**（否则编译/运行即失败）。
- 必须先查 `V15__…sql` 拿到两个 CHECK 的**真实约束名**（MySQL 与 H2 语法差异要一并验证）。
- **不得修改任何已应用的迁移文件**（Flyway 校验 checksum）。

## 6. 边界与风险

- **本轮不碰**：`/console` 的玩家/托工作台功能（已恢复且已验证）、托管行为调度（`xupan.test-player.*` 配置名可留待改名，属纯命名）、`TEST_PLAYER_BEHAVIOR`/`TEST_PLAYER_ACTION` 表（托行为表，是活功能，表名改名不在本批）。
- **不得删既有账号数据**；本机库实测无 TEST 行，若在其它环境发现非零，需先报告再定回填策略。
- 迁移与代码必须**同一批**交付；建议在一个干净分支上一次跑通全量。
- 若实施中发现某处 `TEST` **并非**在替"托"做事（即另有独立语义），**停下报告**，不要强行收敛。
