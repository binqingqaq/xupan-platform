# 中心财务流水入口收敛与订单分组展示计划

> 日期：2026-11-04
> 类型：开发计划。
> 范围：仅 `/platform-admin/center` 的中心账号流水入口与流水展示；不改余额计算、账本分录、报网、订单状态、风险、结算或其它后台业务。

## 1. 目标

1. 移除“财务流水”主页签，避免与中心账号行内的“流水”入口重复。
2. 点击某个中心账号的“流水”后，在当前页打开二级界面；关闭后回到原中心账号列表。
3. 默认将同一中心订单产生的多条中心账本分录合并为一条订单摘要；展开摘要可查看全部原始分录。
4. 不属于订单的期初额度、追加额度等账号级流水继续显示，不丢弃、不伪装成订单。

## 2. 当前实现与数据依据

| 项目 | 当前事实 |
| --- | --- |
| 主入口 | `web/src/views/PlatformAdminCenter.vue` 有独立“财务流水”页签；账号行“流水”按钮调用 `loadLedger()` 后切换页签。 |
| 当前查询 | `GET /api/admin/center/agents/{id}/ledger` 对 `center_agent_ledger` 原始分录按 `id DESC` 分页，分页单位是一条账本分录。 |
| 原始字段 | 分录包含额度层、类型、方向、金额、变动前后余额、说明、`reference_type/reference_id`、幂等键和时间；当前前端只展示其中部分字段。 |
| 订单关联 | 订单预留、冻结/未结转移、结算和撤单释放分录使用 `reference_type='CENTER_ORDER'`，`reference_id` 为 `center_order.id`。 |
| 账号级关联 | 期初额度和额度追加等使用 `reference_type='CENTER_AGENT'`，引用账号而非订单；不能按订单合并。 |
| 账本自检 | 现有 `balanced` 标志按中心账号和额度层校验，仍需在新二级界面显示。 |

BY220 没有中心承接侧或中心账号财务流水页；此处属于 Xupan 中心上游扩展的可读性调整。

## 3. 界面方案

### 3.1 入口

- 从中心账号主导航移除“财务流水”页签及其独立页面分支。
- 中心账号列表保留每行“流水”按钮。
- 点击按钮后打开宽屏右侧抽屉；桌面最大宽度建议约 1400px，手机占满屏幕。抽屉标题显示所选中心账号名、关闭按钮和账本自检状态。
- 关闭抽屉返回中心账号列表，保留原列表页签、滚动位置和已有筛选/分页状态；不改变 URL 路由。

### 3.2 订单汇总行

每个至少有一条中心账本分录的中心订单显示一条摘要行，建议字段：

| 字段 | 内容 |
| --- | --- |
| 中心订单 | `agent_order_no` 与中心订单状态 |
| 本地单 | `local_bet_id` |
| 期号/玩法 | 彩种、期号、玩法及必要的玩法参数 |
| 本金 | 中心订单本金 |
| 中心结算 | 代理赢/代理输/流局/退款/撤单及对应结算金额；未结时显示状态 |
| 流水分录 | 此订单关联的中心账本分录条数 |
| 操作 | 展开/收起分录明细 |

一笔订单有多少条底层分录都只占一个摘要位置。不得把冻结额、未结转移额和最终输赢金额相加成一个含义不明的“订单金额”。

### 3.3 展开的原始分录

展开后逐条保留原始账本事实：额度层、中文业务动作、增加/减少、金额、变动前/变动后、说明、时间。可继续提供内部类型码作为次要信息，但默认名称应可读；不重算、不合并、更不改写流水。

### 3.4 非订单账号流水

对于 `CENTER_AGENT` 等账号级引用，没有中心订单可匹配，按一条账号级流水显示；至少包含类型、额度层、方向、金额、变动前后余额、说明和时间。若 `CENTER_ORDER` 引用缺失或无法匹配，显示为“未关联订单”单独记录，并保留原始分录，不能猜测订单归属。

## 4. 后端与接口方案

建议增加面向中心账号页的分组读取接口，不改变当前原始账本 API 的事实语义：

1. `GET /api/admin/center/accounts/{id}/ledger-groups?page=&pageSize=`：按父级汇总记录分页，返回 `balanced`、总数和摘要行。
2. `GET /api/admin/center/accounts/{id}/ledger-groups/{groupType}/{referenceId}/entries`：`groupType=ORDER` 时读取该账号、该订单的全部原始分录；`groupType=ENTRY` 时读取一个账号级或未关联分录。两种类型都必须校验中心账号归属。
4. 父级记录由 `CENTER_ORDER` 分录按订单分组，并与 `center_order` 关联取得订单号、注单号、期号、玩法、本金、状态和结算结果。
5. `CENTER_AGENT` 及其它非订单分录按独立业务记录生成父级项；未知引用不得丢弃。
6. 父级分页必须以分组后的摘要记录为单位，不能先分页原始分录再在浏览器内聚合，否则同一订单可能跨页、摘要条数错误或明细缺失。
7. 保留现有 `/api/admin/center/agents/{id}/ledger` 原始分录接口以兼容内部调用；本轮 UI 主路径改用分组读取接口。新旧接口都只读同一追加式账本。

DTO 仅用于展示订单快照和分组，不创建新余额事实、不写账本、不变更订单。权限继续要求 `CENTER_AGENT_MANAGE`；账号 ID 不能跨账号读到其它流水。

## 5. 数据关联与排序规则

- 订单分组键：`(center_agent_id, reference_type='CENTER_ORDER', reference_id)`。
- 账号级流水键：原始 `ledger.id`，避免将不同额度追加或期初流水错误合并。
- 摘要按该组最新流水 ID 倒序（与追加写入顺序一致），同时返回最新分录时间；组内原始分录按流水 ID 升序。
- 一笔订单若暂时没有中心账本分录，不作为财务流水父级行展示；它仍在“实时订单”中查看。财务流水只负责展示实际写入的账本变化。
- 一笔订单的明细行数是实际账本分录数，不能从订单状态推测或补造缺失分录。

## 6. 实施映射与范围边界

| 页面/接口/数据 | 计划落点 |
| --- | --- |
| 中心账号行内“流水”按钮 | 打开账号范围内的流水抽屉，不再切换主页签 |
| 独立“财务流水”主页签 | 从 `PlatformAdminCenter.vue` 页签集合和内容分支移除 |
| 订单关联分录 | 新分组摘要查询和按订单加载明细 |
| 初始额度/追加额度/其它账号级分录 | 独立账号级父记录，不归入订单 |
| 原始账本 API、余额层、写流水服务、风险/结算/对账 | 保持现状，不改其业务规则 |

不新增 Flyway 表或列，不修改或删除历史分录，不调整额度余额，不改 `CenterAgentService` 写账本路径、接单风险冻结、订单第二层结算、账号编辑、机器会话和删除策略。

## 7. 验收计划

### 前端

- 主导航不再出现“财务流水”；每个账号行点击“流水”打开对应账号的抽屉，关闭后返回原列表状态。
- 订单摘要一订单一行；展开后列出的明细数量、金额、方向、余额快照和流水 ID 与原始 API 一致。
- 多笔同一期订单互不混组；账号 A 的抽屉不能出现账号 B 的分录。
- 期初额度、追加额度等非订单流水仍可查；未关联订单记录醒目标记并保留原始字段。
- 账本自检状态、空数据、加载失败、详情加载失败、分页和窄屏布局均可理解和操作。

### 后端

- 分组父项分页按父项计数，订单的全部分录可通过展开请求取回，不受相邻分页影响。
- 同一订单多个额度层、同一额度层多条记录均归入正确订单组；账号级、异常引用记录不丢失。
- 越权访问、伪造跨账号 orderId/entryId 返回拒绝或不存在，不泄露其它账号数据。
- 读取接口只读；前后对比余额、中心账本分录数、订单状态均不变化。
- 账本原始 API 与原有账本平衡校验不受影响。
