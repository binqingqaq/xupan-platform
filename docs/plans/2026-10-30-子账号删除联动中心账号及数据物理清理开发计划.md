# 子账号删除联动中心账号及数据物理清理开发计划

> 状态：2026-10-30 本机代码已实施，隔离 MySQL 8.4.11、一次双连接并发与前端专项验收通过；真实账号浏览器操作、BY220 运行态、服务器和生产仍待验证。实施证据见[本机验收记录](../验收记录/2026-10-30-子账号删除联动中心账号本机验收记录.md)。

## 1. 目标与依据

- 用户决定：删除代理子账号时，其专属中心账号及该中心账号的上报、订单、额度账本、会话、风控和处置数据一并物理删除。中心账号是临时账号，不应因外键阻止子账号删除。
- 子账号原有删除语义保持：连同名下机器、玩家/托、注单和积分流水一起物理删除；保留操作审计。全部积分仅为虚拟积分。
- BY220 `application/admin/controller/Users.php:231-245` 的 `userDel` 删除子账号及其机器、玩家和相关业务行；BY220 没有 Xupan 的 `center_agent`/中心账本，中心联动属于用户本次确认的 Xupan 扩展。

| BY220 / Xupan 业务对象 | 当前实现 | 本次目标 |
| --- | --- | --- |
| BY220 `admin` 子账号及 `robot` 机器 | `PlatformAdminService.deleteSubAccount` → `AccountPurgeService.purgeSubAccount` | 保持物理删除和现有权限入口 |
| BY220 `rbuser`、`record` 等机器下属数据 | `purgeMachine` → `purgePlayer`，删除玩家/托、注单、积分流水等 | 保持该链路，处理新增中心依赖 |
| Xupan 专属 `center_agent` 及从属数据 | `CenterUpstreamAccountService.deleteAccount` 已有独立物理删除流程 | 子账号删除事务中复用中心域清理核心，不调用带另一权限校验的管理接口 |
| Xupan 中心报网尝试 | `report_upstream_order.center_agent_id` 可空；V94 只回填可证明归属的历史尝试 | 删除整个子账号时，连同其机器删除无法归属的旧尝试；不扩展到其他子账号 |

## 2. 当前问题

1. V89 的 `fk_center_agent_group` 引用 `agent_group(id)`，`agent_group_id` 唯一。`purgeSubAccount` 目前只删机器、组流水和组，不删除绑定的 `center_agent`；组删除会被外键拒绝，事务整体回滚。
2. 中心账号自身还被 `center_order`、`center_agent_ledger`、`center_machine_session`、`center_reconciliation_disposition`、`agent.center_agent_id` 等引用；V94 的中心报网尝试设有级联外键，但不能只依靠数据库级联完成整条业务清理。`center_reconciliation_disposition.bet_id` 没有注单外键，且 `center_agent_id` 可以为空，需另按目标组注单归属清理。
3. 独立中心账号删除会拒绝组内 `center_agent_id IS NULL` 的旧 `CENTER` 报网尝试，以保护仍要保留的机器与本地注单。删除整个子账号时，这些机器、玩家和注单也一并删除，应按机器归属清除旧尝试。
4. `purgeEverythingExcept` 目前先删机器、后删子账号；绑定中心账号的机器会话外键会拦住机器删除。该入口必须同步调整顺序。

## 3. 删除范围与边界

| 数据 | 子账号删除后的结果 |
| --- | --- |
| 目标 `agent_group`、登录账号、组积分流水 | 物理删除 |
| 组内机器及登录账号、机器配置/会话/积分流水 | 物理删除 |
| 机器名下玩家/托、原始注单、玩家积分流水及附属记录 | 按现有 `purgeMachine`/`purgePlayer` 规则物理删除；`report_local_disposition` 随 `game_bet` 外键级联删除 |
| 绑定该组的中心账号、中心订单、中心额度流水、风控命中、订单/对账处置、中心机器会话 | 物理删除，包括未结和已结中心订单 |
| `center_agent_id` 为空但 `bet_id` 指向组内注单的对账处置 | 在删注单前按目标组注单 ID 清理，避免留下无法回查的记录 |
| 属于该组机器的中心报网尝试，包括无法确定中心账号的旧尝试 | 物理删除；先按机器归属限定范围，不按全库 `CENTER` 清空 |
| `sys_operation_log`、`sys_login_log` 等审计记录 | 按现有账号清理规则保留，清除失效的操作者外键；新增删除审计记录账号标识与各类清理数量，不记录凭据 |
| 其他子账号、机器及其中心数据 | 不删除；发现目标中心账号被其他组机器引用时明确报数据归属冲突并整体回滚 |

独立删除中心账号的既有语义仍适用：保留子账号、机器、玩家原始注单和机器账务，对无法归属的旧中心报网尝试继续阻止独立删除。本计划只改变“删除整个子账号”这条链路。

## 4. 实现步骤

1. **复核参考与统一入口**：开工前复核 BY220 `Users.php::userDel` 对应页面的实际删除操作，并更新上方映射的运行态证据；BY220 无中心承接侧，不据此推断中心规则。`PlatformAdminService.deleteSubAccount` 继续检查 `SUB_ACCOUNT_MANAGE` 和目标归属；在同一事务内锁定目标 `agent_group`，随后读取并锁定其唯一的中心账号。中心账号创建当前也锁组，删除与创建须遵守同一锁顺序。缺失中心账号时直接执行现有子账号删除。
2. **抽取中心清理核心**：从 `CenterUpstreamAccountService.deleteAccount` 抽取可复用的内部清理服务/方法，包含中心订单处置、对账处置、风控命中、额度流水、中心订单、中心报网尝试、机器会话与中心账号本体。独立删除入口保留 `CENTER_AGENT_MANAGE`、删除原因、旧尝试阻断以及保留本地数据的处理；子账号联动入口沿用已验证的 `SUB_ACCOUNT_MANAGE` 授权，不另要求中心管理权限。
3. **子账号专属清理**：在删除中心账号前双向核对中心账号与组内机器、会话、订单、报网尝试及对账处置的归属；越界时返回明确冲突，不能删其他组的数据。组内旧 `CENTER` 尝试即使 `center_agent_id` 为空，也在目标机器/玩家删除过程中清除；联动路径不使用独立删除的旧尝试阻断规则。按目标组注单 ID 删除无中心归属的对账处置。由于整组机器和注单随后删除，联动路径无需为这些注单保留防重报标记或机器账务引用；必须确保所有中心外键在删组前解除。
4. **按依赖顺序删除**：先停用目标中心账号、解除组内机器的 `center_agent_id` 配置，清理中心会话和中心域子表，再删中心账号；随后通过 `purgeSubAccount` 清除组内机器、玩家和组积分流水，最后删除 `agent_group` 及其登录账号。删除步骤与审计处于同一事务，任何约束错误都回滚整条链路。若机器报网尝试没有在玩家删除时被级联清除，`purgeMachine` 的显式清理负责收尾。
5. **全量账号与单机器入口**：`purgeEverythingExcept` 先清理各组绑定的中心账号及会话，再执行现有玩家、机器、子账号删除顺序；复用同一内部清理步骤，避免全量删除因中心外键失败或重复清理。单独删除机器时先清理该机器的 `center_machine_session`，再删除机器下属数据；保留同组中心账号和其他机器。
6. **数据库与界面**：优先复用 V89/V94 的外键和现有索引，不为方便删除改成无条件 `ON DELETE CASCADE`；若实施时发现新的约束或索引需求，只通过新的 Flyway 迁移修改。子账号删除确认框应明确提示“将同时删除关联中心账号、上报数据、机器及玩家数据”，成功反馈显示清理完成；失败反馈给出可处理的归属冲突，不能显示删除成功。

## 5. 验收标准与测试计划

- 专项后端用例覆盖：无中心账号、有中心账号但无中心数据、有未结/已结订单和额度流水、中心会话/风控/处置/报网尝试、组内旧无归属 `CENTER` 尝试、无中心账号归属但指向组内注单的对账处置、组内多机器和玩家/托；断言目标组全链路物理删除，其他组原样保留，审计保留。
- 覆盖越组引用、权限不足、删除中途外键/数据库错误；断言返回明确错误，中心账号、机器、玩家和组均没有部分删除。覆盖同时创建中心账号与删除子账号的并发，确认不能留下孤儿账号。
- 独立删除中心账号原有专项仍通过，尤其是“旧无归属尝试阻断”和“保留机器/玩家数据”；全量账号删除入口在绑定中心账号和机器会话的样例下通过。
- 在隔离的 MySQL 8.4 LTS 测试库验证完整迁移后运行专项集成测试；H2 结果只算辅助证据。本机浏览器核对子账号确认框、成功/失败提示及列表结果。服务器/生产验收须单独记录，不能以本计划或本机测试替代。

## 7. 2026-10-30 本机实施结果

- `CenterUpstreamAccountService` 抽取共用物理删除步骤；独立中心账号删除仍检查无归属历史尝试并保留本地机器/注单/账务，子账号联动删除则清掉整组业务数据。`AccountPurgeService` 先锁组并作双向归属检查，再删中心账号、机器、玩家和组；单机器及删除全量账号同步调整外键清理顺序。无需新增 Flyway 迁移。
- 子账号删除确认框明确提示关联中心账号、上报数据、机器和玩家将永久删除；新增越组归属冲突的中文错误提示。Vitest 内联 Element Plus 依赖，修复原有子账号组件测试无法加载 CSS 的问题。
- 隔离 MySQL 8.4.11 从空库迁移至 V99，应用账号执行新链路 9/9 和独立中心账号回归 5/5，均无失败或跳过；覆盖含已接受/已结中心订单与旧无归属尝试的物理删除、审计、双向越组拒绝、权限、单机器会话、全量账号入口、后段异常回滚及一次双连接创建/删除竞争。
- 前端子账号专项 8/8、中心及机器管理 35/35，类型检查及独立目录生产构建通过。真实账号浏览器删除、BY220 实际运行、服务器/生产未验证；双连接竞争已有单次验证，尚非压力验收。详细证据和边界见本节开头的验收记录。
