# 确认玩法文本下注与结算实施计划

## 1. 目标

在现有虚拟余额、期号和开奖基础上，完成一条可测试的下注闭环：用户输入已确认的汇盈博文本格式，服务端按固定第 1 球创建注单，封盘/开奖期间拒绝下注，开奖后按赔率快照结算，并可查询余额、净盈亏和流水。

## 2. 已确认范围

- 固定 `ballNumber=1`，前端不提供球位选择，服务端也拒绝其他球位。
- 支持：`番`、两位 `角`、三位 `车`、`严/念`、`加`、`正`、`通`、三参数 `无`、`单双`、`大小`、单号/多号 `特`，以及两位/三位省略写法。
- 金额、号码和番值沿用当前请求校验与赔率快照约束。
- 单数字 `无`、单数字 `车`、参数缺失、越界和无法唯一判断的写法拒绝，不自动降级为普通投注。
- 已知命令（查询余额、上分、下分、流水、玩法）不进入下注解析；疑似下注但格式不合法时返回明确格式错误。

## 3. 实现任务

### 3.1 后端

- 增加可复用的下注文本解析器和结果类型，作为前端契约、机器人识别和下注服务的共同规则来源。
- 下注服务强制固定第 1 球，封盘和开奖阶段返回可区分的业务错误。
- 保留幂等键、赔率快照、扣款、开奖结算和正数派彩逻辑。
- 提供或补齐当前用户下注、净盈亏和余额流水查询，避免重复账表。
- 为所有已确认格式、非法格式、封盘和重复结算增加测试。

### 3.2 前端

- 移除球位选择交互，开奖号码只做展示，并明确显示默认第 1 球。
- 下注输入使用白名单解析；不支持的疑似下注显示错误，不作为普通聊天发送。
- 开奖期间显示“下注无效”提示；展示当前注单、结算状态、净盈亏和流水摘要。

### 3.3 机器人

- 机器人接收用户消息时复用同一文本解析结果。
- 合法下注进入下注服务；疑似下注的非法格式返回格式指令；已知业务命令进入命令处理。
- 不改变已完成的开奖结构化图片/消息输出链路。

## 4. 验证

- 后端：`server/xupan-server/./mvnw.cmd test`。
- 前端：`npm run test`、`npm run typecheck`、`npm run build`。
- 手工检查：默认第 1 球、封盘拒绝、下注扣款、开奖后 WIN/DRAW/LOSE、净盈亏和流水可见；不执行真实支付或生产投注。

## 5. 边界

本阶段不支持单数字 `无` 和单数字 `车` 的推断规则，不把外部页面的未确认赔率、本金口径或统计口径写成新规则；具体结果以当前代码、测试和数据库验证为准。
