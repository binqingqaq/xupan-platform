# AU8 机器账号玩家固定球位控制开发计划

> 状态：代码已实施并部署到服务器；本机定向验收和 MySQL V111 迁移完成，浏览器行为及完整管理写入/下注流程待补。服务器发布证据见 §9.4 和[部署验收记录](../验收记录/2026-11-08-AU8机器固定球位控制服务器部署验收记录.md)。
>
> 使用者确认日期：2026-11-07。业务规则以本文和[业务模块 09](../业务模块/09-代理组织与代理后台.md)、[业务模块 03](../业务模块/03-期号玩法下注与结算.md)为准。

## 1. 目标

在超级管理后台“机器管理”中编辑机器账号时，增加 AU8 玩家球位模式设置。每台机器分别使用“默认”或“固定球位”模式，控制该机器名下玩家 AU8 下注使用的球位。配置只在编辑已有机器时出现；创建机器账号时不出现该项。

## 2. 已确认业务规则

- 配置归属单个机器账号，只作用于该机器名下玩家的 AU8 下注；其他游戏不受影响。
- AU8 只有 7 个球位，固定球位允许值为 1 至 7。
- 设置位于编辑机器账号弹窗“所属子账号”字段下一行；创建机器账号时不显示。
- “默认”表示继续走现有玩家球位选择和下注流程；“固定球位”需要选择 1 至 7 中的一个球位。两个模式互斥，选择一个时另一个自动关闭。
- 超级管理员及具有机器管理权限、且在自身子账号数据范围内的管理员可以通过机器编辑表单修改。
- 切换设置不修改或重算已有注单。保存后新提交的 AU8 下注按当前机器设置处理。
- 固定模式下玩家 AU8 页面隐藏球位选择控件。保存后向该机器名下在线玩家页面直接发送刷新指令；未发送的输入随刷新清空，不暂存。已提交下注仍按既有请求流程处理。
- 不引入玩家配置版本号机制。断线期间没有在线页面可刷新；玩家后续打开页面时读取当前设置。
- 此功能是 Xupan 的机器级扩展，不声称为 BY220 已有功能。BY220 仅有彩种级 `hasSelect` 开关和玩家自选球位。

## 4. 实施设计

### 4.1 持久化与规则校验

- 在 `agent` 机器记录上持久化 AU8 球位模式和固定球位，避免另造配置事实表。建议模式枚举为 `PLAYER_SELECT` 与 `FIXED_BALL`，固定球位列取值 1–7。
- 新建机器默认 `PLAYER_SELECT`，固定球位为空；既有机器迁移后也默认 `PLAYER_SELECT`，保证升级前后的玩家行为一致。
- 数据库增加模式/球位一致性约束：固定模式必须有 1–7 球位；默认模式不得残留生效球位。具体 MySQL 8.4 CHECK 写法和字段命名在实施前复核迁移风格。
- 服务端请求校验与数据库约束双重保证只接受合法模式和 1–7；拒绝未知枚举、越界值、固定模式缺球位及创建机器设置固定球位。
- 只在 AU8 下注服务使用该设置；不改变非 AU8 游戏，不更改历史注单、不触发补结算。

### 4.2 管理后台编辑

- 在机器编辑弹窗“所属子账号”之后显示“玩家下注球位”区域；新建弹窗隐藏。
- 用互斥单选/分段方式选择“默认”或“固定球位”；固定模式启用时显示 1–7 球位选择器并设为必填。
- 保存时沿用机器更新 API 的权限、子账号范围、配置版本冲突检查和操作审计。审计摘要包含机器、原模式/球位与新模式/球位，不记录敏感信息。
- 页面回显服务器保存值；更新失败时不显示成功提示，不发刷新指令。

### 4.3 玩家下注与页面呈现

- 玩家加载 AU8 页面时读取该机器当前的球位模式。默认模式保留现有玩家球位选择；固定模式隐藏选择控件，并显示当前固定球位，避免玩家误以为可选择。
- 固定球位必须由服务端在下注受理路径执行，不能仅靠前端隐藏控件。所有 AU8 新订单，包括直连/聊天解析/快捷下注入口，都需由已认证玩家会话解析机器归属后强制落到配置球位；不信任客户端传入值。
- 保存时不触碰既有 `game_bet`。已受理请求按其受理时的球位继续；切换完成后的新请求使用新配置。
- 其他下注规则保持原样，包括当前期、限额、玩法解析、幂等、钱包扣分、聊天回执和结算。

### 4.4 直接刷新

- 机器设置成功提交后，通过已有认证 WebSocket 连接向目标机器下在线玩家发送专用刷新事件；服务端按机器 ID 精确筛选，不广播给其他机器或其他 AU8 玩家。
- 玩家端收到事件后直接刷新整个 AU8 页面。未提交输入随页面刷新清空，不做本地暂存；已发出的下注仍由既有服务端请求处理，不增加下注暂停、撤单或重试机制。
- 刷新事件不得携带令牌、密码或其他敏感数据。无在线连接时不保存待补发刷新任务；后续新开的玩家页面直接读取当前设置。
- 现有连接注册表为实例内存索引。实施时需核对单实例部署约束和连接中的机器身份；若支持多实例，刷新覆盖范围须补跨实例投递设计，不能宣称单实例广播已覆盖其他节点。

## 5. 权限、审计与安全边界

- 写入接口必须服务端要求 `MACHINE_MANAGE`；子账号管理员只能修改其授权范围内的机器，超级管理员按现有权限范围管理。
- 机器归属或子账号字段不得由前端声明来决定授权范围；以服务端加载的机器记录和操作者范围为准。
- 固定球位是虚拟积分下注参数，不产生现实资金能力，不改变积分、赔率或结算资金语义。
- API 返回只包含当前机器的模式和球位，不暴露玩家身份列表或认证数据。
- 管理表单更新沿用既有机器 `configVersion` 处理过期写入；该字段不用于玩家配置版本轮询或刷新。

## 6. 测试与验收计划

### 后端

- 新建默认机器、升级既有机器后均为玩家自选模式。
- 写入固定球位 1、7 成功；0、8、空球位、未知模式和无权限写入失败。
- 超级管理员可更新；子账号管理员只能更新本组机器，跨组机器拒绝。
- 默认模式下注保留现有合法球位；固定模式忽略客户端伪造球位并记录配置球位。
- AU8 以外游戏不受设置影响；已有注单不变；新旧下注并发与设置提交按数据库事务提交顺序验收。
- 设置保存后刷新事件只发给目标机器的普通玩家会话，不发给其他机器、托会话或观察连接。

### 前端与持久化

- 创建机器无设置项；编辑机器字段位置正确、模式互斥、固定模式校验和回显正确。
- 玩家默认模式保留现有可选控件；固定模式显示固定球位且隐藏选择控件；收到刷新事件后页面实际重新加载，未发送输入清空。
- Flyway 迁移和约束在 MySQL 8.4 验证，不把 H2 结果代替 MySQL 证据。
- 覆盖控制器/服务、下注策略、WebSocket 协议/注册表及前端组件的定向自动化测试，随后运行相关类型检查和构建。

### 运行验收

- 本机 MySQL 8.4：迁移、数据约束、管理端保存/回读、AU8 实际下注球位和其他游戏不受影响。
- 浏览器角色验证：超级管理员、子账号管理员、玩家页；至少两个机器的玩家页同时在线，确认仅目标机器刷新。
- 验收保存配置时有未发送输入、正在发送下注、WebSocket 断线以及重新打开页面的行为。
- 服务器发布需按服务器操作边界另行明确授权并备份、核验；本次服务器部署已由使用者于 2026-11-08 明确要求并完成。浏览器级业务验收仍待执行。

## 9. 本机实施与验收状态

### 已实施

- V111 在 `agent` 增加 `au8_ball_mode`、`au8_fixed_ball_number`，既有机器默认 `PLAYER_SELECT`，数据库约束保证固定模式只接受 1–7 球。
