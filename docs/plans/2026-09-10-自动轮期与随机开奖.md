# 自动轮期与随机开奖实施计划

> **给实施者：** 按任务顺序执行本计划。步骤使用复选框（`- [ ]`）语法跟踪进度。
>
> **当前状态：** 已实施并已提交。未勾选项表示尚未完成的增强验证，不表示核心自动轮期未实现。

**目标：** 将演示大厅改造成由服务端驱动的 5 分钟自动轮期：前 3 分钟开放下注，后 2 分钟封盘并展示随机滚动球号，期末固定最终号码、结算、发布机器人消息并立即开启下一期。

**架构：** Spring Boot 服务端以数据库时间和期号时间字段作为唯一时钟，通过每秒调度推进 `BETTING`、`DRAWING` 和 `SETTLED` 阶段。前端通过当前期接口获取服务端时间、阶段结束时间和球号预览，下注只允许发生在 `BETTING` 阶段；最终开奖在服务端事务中只执行一次。

**技术栈：** Java 21、Spring Boot 4.0.8、Spring JDBC、Flyway、MySQL 8.4 LTS、H2 测试、Vue 3、TypeScript、Vite。

## 全局约束

- 每期总时长固定为 300 秒。
- 每期开始后前 180 秒为 `BETTING`，页面显示 03:00 倒计时并允许下注。
- 第 180 秒进入 `DRAWING`，停止下注，持续 120 秒，页面显示“开奖中”并展示随机变化的临时球号。
- 第 300 秒固定 8 个最终号码，执行结算和机器人结果消息，然后立即创建下一期。
- 8 个球号独立随机生成，允许重复，取值范围为 1～20。
- 首期期号从 `3000000` 开始，后续期号连续加一。
- 最终号码由服务端生成并持久化；开奖中的临时球号不能参与结算，也不能覆盖最终号码。
- 当前项目仍是虚拟演示账户，不实现真实资金、支付或第三方开奖接口。
- 汇博盈前端复刻改动已保留，并与本计划代码一起提交。
- 不在本阶段引入 Quartz、Redis、WebSocket；先使用 Spring 调度、REST 轮询和数据库幂等控制。

## 验收标准

1. 清空演示库后，服务自动创建 `3000000` 期，状态为 `BETTING`。
2. 期号开始后的 0～180 秒允许下注并显示服务端倒计时。
3. 到达 180 秒后下注被拒绝，阶段变为 `DRAWING`，前端显示“开奖中”，8 个球号持续变化。
4. 到达 300 秒后最终 8 个球号固定，注单结算一次，机器人发布开奖结果和获胜名单。
5. `3000001` 期自动创建并立即进入 `BETTING`，历史期号和上一期结算数据保留。
6. 调度器重复执行、应用重启和前端重复轮询均不会重复开奖、结算或发布同一事件。
7. `./mvnw.cmd test`、`npm run typecheck` 和 `npm run build` 全部通过。
