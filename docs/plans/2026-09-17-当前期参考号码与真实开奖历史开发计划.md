# 当前期参考号码与真实开奖历史开发计划

## 1. 目标

完成第一阶段的数据一致性改造：当前期尚未开奖时显示上一期已结算号码并明确语义；历史开奖记录改为读取数据库中的真实结算记录，避免开奖后历史期数和号码随当前期变化。

## 2. 事实与边界

- 已确认：`game_issue` 已保存期号、8 个开奖号码、轮期阶段和 `settled_at`；仓储已有最近已结算期查询。
- 本阶段：复用 `game_issue`，通过当前游戏接口返回最近 10 期完整已结算记录；前端只展示服务端历史，不再合成期号、号码或时间。
- 本阶段：当前期未开奖时保留上一期号码作为参考，并显示“上期结果”标识；当前期结算后显示当前期真实号码。
- 未纳入：历史分页、历史导出、第三方开奖源、投注规则调整和图片化机器人消息。

## 3. 实现任务

1. 后端扩展 `GameView`，返回真实已结算历史，并将每期号码转换为稳定的球位属性。
2. 前端新增历史响应类型，删除按当前号码偏移生成的临时历史逻辑。
3. 当前期参考号码增加可见语义和无结果时的稳定空状态，保留响应式布局。
4. 增加仓储、Controller 和前端纯数据转换测试，验证已结算记录顺序、号码固定和空历史行为。

## 4. 验证标准

- 已结算期写入 `game_issue` 后，当前接口的 `history` 返回相同期号、8 个号码和结算时间。
- 新一期进入下注阶段后，历史首行仍为上一期已结算记录，当前参考号码标记为“上期结果”。
- 前端不再基于当前期号或当前号码计算历史行。
- 后端 Maven 测试、前端 Vitest、类型检查和生产构建通过。
