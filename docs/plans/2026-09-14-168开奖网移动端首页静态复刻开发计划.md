# 168开奖网移动端首页静态复刻实施计划

> **给实施者：** 按任务顺序执行本计划。步骤使用复选框（`- [ ]`）语法跟踪进度。本计划只覆盖移动端首页一页，不自动实现底部菜单对应的其他页面。

**目标：** 在当前 Vue 3 展示端中新增一个独立的移动端首页，通过本地静态资源和固定演示数据，尽量复刻 `m.16894913.com/html/public/home.html` 的移动端视觉结构和首屏内容。

**架构：** 新增独立的 `/display/mobile` 路由、移动端首页组件、移动端专用 CSS、移动端静态数据和资源映射。桌面 `/display` 保持现状；移动端不通过压缩桌面布局实现，也不调用参考站点接口。底部固定菜单只展示图标和文字，点击不跳转、不改变地址、不请求后端。

**技术栈：** Vue 3、TypeScript、Vite、Vue Router、页面专用 CSS、现有 Vitest、系统 Playwright 截图工具和浏览器只读验收。

## 全局约束

- 本阶段只实现移动端首页，不实现“两面推荐”“专家推荐”“长龙提醒”“杀号计划”“购彩计划”等底部菜单对应页面。
- 移动端入口固定为当前项目 `/display/mobile`；桌面 `/display`、`/room`、`/admin` 和既有后端接口保持现状。
- 首页所有期号、号码、倒计时、文案和状态均为静态演示数据，不新增开奖、投注、支付、钱包、用户、权限、预测或机器人业务。
- 页面运行时不得请求 `16894913.com`、`m.16894913.com`、第三方 CDN、外部 API、WebSocket、Cookie 或 Token。
- 参考站点资源只允许定向下载明确用于移动首页的图片；不抓取整站目录、不保存 HTML/JS/CSS 源码、不下载接口响应和第三方外链内容。
- 公开可访问不等于获得版权或商用许可。参考资源统一标记为 B 类，仅用于本地评审；正式部署前必须取得授权或替换为项目自有资源。
- 移动端所有新增 CSS 选择器使用 `display-mobile-` 前缀，不能修改全局 `body`、通用 `button`、`.header` 或桌面页面选择器。
- 固定底部导航必须为稳定高度，并通过页面底部安全区留白避免遮挡最后一张开奖卡片。
- 不因为移动版页面存在外部广告、登录、注册或投注链接，就在当前项目中新增同类跳转。
- 本计划只写实施方案，不代表代码、资源下载、截图或正式部署已经完成。

- [x] **步骤 5：复刻固定底部菜单**

底部菜单使用 `position: fixed; left: 0; right: 0; bottom: 0;`，高度包含安全区；主内容增加相同的底部留白，避免遮挡最后一张卡片。按钮保持稳定宽度，图标和文字不因字体加载或状态变化而跳动。

### 风险处理

| 风险 | 处理方式 |
| --- | --- |
| 移动版资源按设备、Cookie 或接口动态返回 | 只记录浏览器实际加载的公开静态图片；动态资源保留本地静态演示，不接运行时接口 |
| 移动版与桌面版 Logo/彩种图标复用关系不一致 | 下载前比较文件哈希和 natural size，清单标记“复用”或“移动专属” |
| 移动端固定菜单遮挡内容 | 使用 `padding-bottom + safe-area-inset-bottom`，并在窄屏全页截图中验证最后一张卡片 |
| 卡片类型结构不同导致模板变形 | 使用 `cardKind` 联合类型和四类模板，不用一个通用卡片强行覆盖所有数据 |
| 页面存在外部推广链接 | 只复刻视觉区域，所有按钮改成无动作按钮，不保留 href |
| B 类素材未获正式授权 | 仅进入本地评审包，验收记录明确禁止直接正式发布 |
