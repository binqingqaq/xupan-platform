# 用户管理最小可用后台实施计划

> 执行状态（2026-09-11）：用户管理后端、前端登录闭环和本地运行链路已完成；后端定向测试 `29/29`、后端全量测试 `117/117`、前端类型检查和生产构建已通过，当前本机 MySQL 已初始化管理员并验证登录/刷新/管理员接口。双浏览器业务人工验收和独立 MySQL 8.4 回归仍待执行，因此本计划暂不标记为全部完成。

本轮已落地的可验收入口：`/login`、`/room`、`/admin/users`。未认证访问受保护路由会进入登录页，登录成功后回到原目标地址；会话恢复使用内存访问令牌和 HttpOnly 刷新 Cookie，不把 Token 写入浏览器持久化存储。Spring Boot 静态资源已重新构建并引用新资源哈希；开发模式入口为 `http://127.0.0.1:5173/admin/users`，服务托管入口为 `http://127.0.0.1:8080/admin/users`。账号仍由外部 bootstrap 配置或已有管理员提供，不在本计划中写入固定凭据。

> **给实施者：** 按任务顺序执行本计划。步骤使用复选框（`- [ ]`）跟踪进度；本计划先补齐正式用户管理闭环，再进行聊天室双浏览器人工验收，不提前进入 WebSocket 或机器人开发。

**目标：** 在现有认证、角色权限和虚拟钱包基础上，建立管理员可操作的用户管理最小后台，使管理员能够初始化、创建和维护普通用户，完成两名正式用户登录、分配虚拟余额并人工验收聊天室。

**架构：** 选择性参考若依 `ruoyi-admin` 的用户控制器拆分、`ruoyi-system` 的用户服务事务边界、角色授权和操作日志设计；当前项目继续使用 Spring JDBC、Flyway、现有 `sys_user/sys_role/sys_permission` 表和 Bearer Token，不复制若依整套模块、MyBatis、JWT、Redis、部门/岗位/菜单表。后端先提供分页查询、创建用户、详情、状态变更、密码重置、角色授权和角色选项接口，前端在现有 Vue 管理后台增加正式用户管理页面。

**技术栈：** Java 21、Spring Boot 4.0.8、Spring Security、Spring JDBC、Flyway、MySQL 8.4 LTS、H2、JUnit、MockMvc、Vue 3、TypeScript、Vite；参考源码为 `D:\codes\liuhecai\_ruoyi-reference\RuoYi-Vue`，当前参考提交为 `13db1fc`。

## 全局约束

- 当前事实以 `server/xupan-server` 源码、Flyway 迁移、测试和当前 MySQL 8.4 配置为准；若依只作为设计参考，不是当前项目依赖或业务事实。
- 保留当前 `sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`auth_session`、`sys_operation_log` 表；本计划不复制若依的 `sys_dept`、`sys_post`、`sys_menu`、`sys_user_post`、`sys_role_menu` 和 `sys_role_dept`。
- 当前已有 `V1` 至 `V10` 不能修改；本阶段优先复用现有字段，不新增迁移。只有确认现有字段无法满足已确认接口契约时，才允许单独增加 `V11`，并必须先更新本计划和项目方案；本计划的基线实现不需要 V11。
- 访问令牌、刷新令牌、密码明文、密码哈希、数据库凭据和初始化管理员密码不得进入响应、日志、普通文档、Git 或前端持久化存储。
- 管理员初始化使用现有 `BootstrapAdminRunner` 和外部配置 `XUPAN_AUTH_BOOTSTRAP_ADMIN_*`；不在 SQL 中写默认管理员、不使用若依默认账号密码、不把测试密码写入文档。
- 普通用户由管理员接口创建，默认角色固定为 `USER`，默认状态为 `ACTIVE`，同时由 `VirtualWalletService.ensureWalletForUser` 创建 `0.00` 虚拟钱包；创建用户不接受初始余额。
- `ADMIN` 角色只能由受保护的管理员角色授权或 bootstrap 创建；普通用户不能通过请求体指定 `ADMIN`，不能修改自己的管理员权限、状态或密码策略边界。
- 状态变化、密码重置和角色变化必须提升 `security_version` 并撤销该用户现有会话；旧访问令牌不能继续访问接口。
- 用户状态只能使用当前项目语义：`ACTIVE`、`DISABLED`、`LOCKED`、`DELETED`。本阶段不提供物理删除；`DELETED` 只保留为兼容状态，不作为前端新增操作。
- 用户名唯一性由数据库唯一约束和服务层预检查共同保证；列表、详情和钱包接口不得返回 `password_hash`、`failed_login_count`、`security_version`、原始登录 IP 或令牌字段。
- 分页接口必须限制 `pageSize` 为 `1..100`，默认 `20`；不得通过任意 `limit` 查询全表。关键字只匹配 `username` 和 `display_name`。
- 管理前端沿用当前 Vue 工程和视觉体系；不引入若依前端工程，不复制若依默认菜单、默认账号、默认密码或示例业务数据。
- 当前阶段完成标准包括真实可操作页面和人工闭环，不以“后端接口测试通过”单独宣称用户管理完成。

## 2. 固定业务和接口决策

### 2.1 用户管理权限

- 查询、详情、创建、状态、密码重置和角色授权统一要求 `PERM_USER_MANAGE`；当前 `ADMIN` 拥有该权限，普通 `USER` 不拥有。
- 角色选项接口只返回 `ACTIVE` 角色；普通用户创建页面只能提交 `USER`，角色授权页面可选择 `USER`、`MODERATOR`、`OPERATOR`，`ADMIN` 只能由已有 `ADMIN` 操作人显式授权。
- 禁止管理员把自己设置为 `DISABLED` 或 `LOCKED`；禁止移除系统中最后一个 `ADMIN` 的管理员角色；禁止删除用户。
- 状态变更和角色变更成功后立即失效目标用户已有访问令牌；管理员自己的普通查询令牌不因操作其他用户而失效。

### 2.2 后端 REST 合同

| 方法 | 路径 | 请求/查询 | 结果 |
| --- | --- | --- | --- |
| `GET` | `/api/admin/users` | `status`、`keyword`、`page`、`pageSize` | 分页用户摘要，不返回密码和令牌 |
| `GET` | `/api/admin/users/{userId}` | 路径 ID | 用户详情、角色编码、状态、创建/最后登录摘要和钱包摘要 |
| `GET` | `/api/admin/roles` | 无 | 可用角色编码、名称和状态 |
| `POST` | `/api/admin/users` | `username`、`displayName`、`rawPassword` | 创建 `USER` 用户及 `0.00` 钱包 |
| `PATCH` | `/api/admin/users/{userId}/status` | `status`：`ACTIVE`/`DISABLED`/`LOCKED` | 状态更新，安全版本提升，会话撤销 |
| `POST` | `/api/admin/users/{userId}/password` | `rawPassword` | 密码重置，安全版本提升，会话撤销 |
| `PUT` | `/api/admin/users/{userId}/roles` | `roleCodes` 数组 | 替换角色关联，安全版本提升，会话撤销 |

分页响应固定为：

```json
{
  "items": [
    {"id": 2, "username": "member-a", "displayName": "成员 A", "status": "ACTIVE", "roles": ["USER"], "createdAt": "...", "lastLoginAt": null}
  ],
  "page": 1,
  "pageSize": 20,
  "total": 1
}
```

创建请求固定为：

```json
{"username":"member-a","displayName":"成员 A","rawPassword":"由验收人员临时设置的强密码"}
```

角色请求固定为：

```json
{"roleCodes":["USER"]}
```

禁止客户端提交 `userId` 作为操作人、`passwordHash`、`securityVersion`、`walletBalance`、`operatorUserId`、`initialBalance` 或权限编码数组覆盖服务端授权结果。

### 2.3 稳定错误码

| 错误码 | HTTP | 条件 |
| --- | --- | --- |
| `USER_USERNAME_EXISTS` | `409` | 登录名已存在 |
| `USER_NOT_FOUND` | `404` | 目标用户不存在 |
| `USER_STATUS_INVALID` | `400` | 状态不是允许值 |
| `USER_OPERATION_FORBIDDEN` | `403` | 普通用户、越权操作或操作最后管理员 |
| `USER_SELF_OPERATION_FORBIDDEN` | `409` | 管理员尝试停用/锁定自己或移除自己的最后管理员角色 |
| `USER_ROLE_INVALID` | `400` | 角色不存在、停用或不允许授予 |
| `USER_PASSWORD_INVALID` | `400` | 不符合现有密码策略 |
| `USER_QUERY_INVALID` | `400` | 分页或筛选参数越界 |
