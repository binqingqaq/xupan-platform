# 阶段三：玩家软删除与链接生命周期实施计划

> **给实施者：** 本阶段负责把截图中的删除确认变成可审计的软删除流程，并补齐链接撤销、轮换和历史数据保留。

**目标：** 在统一玩家工作台中安全删除普通玩家或托，显示 `wxid`、会员 ID 和昵称，停止新登录与新业务动作，同时保留虚拟积分、下注、中奖流水、聊天和审计历史。

**架构：** 不物理删除 `sys_user`、`demo_user_account`、下注、流水和聊天记录；在事务中将用户和账户置为 `DELETED`，递增安全版本，撤销所有会话和访问链接，并记录带身份快照的操作审计。

**技术栈：** Java 21、Spring Boot 4.0.8、JDBC、Flyway、MySQL 8.4 LTS、H2、Vue 3、TypeScript、Vitest。

## 全局约束

- 删除必须是管理员显式确认后的 POST/DELETE 请求，不能由 GET 触发。
- 删除请求必须使用 `userId` 或不可变 `internalCode` 定位，不使用可变昵称。
- 删除成功后不再出现在默认 ACTIVE 列表，但历史查询和审计仍可按内部编号查询。
- 删除后的账户不得上分、下分、下注、执行托动作、发送托消息或签发链接。
- 被软删除的 `CHAT_ONLY` 会话和链接必须同时失效，不能通过已签发 token 继续访问聊天室。
- 删除确认和审计不得记录完整访问链接或访问 token。
- 软删除必须幂等：重复删除返回已删除状态或明确的幂等结果，不重复扣分、不重复写业务流水。

## 任务 2：实现事务化软删除

**接口：**

```text
DELETE /api/admin/player-desk/players/{userId}
```

请求只需要管理员会话和确认后的调用，不接收昵称作为删除依据。响应返回身份快照和 `DELETED` 状态：

```json
{
  "userId": 12,
  "internalCode": "wxid_atM9Rz1V8q3CF",
  "memberCode": "v1982",
  "displayName": "拔胜侠454",
  "status": "DELETED"
}
```

- [x] **步骤 1：在 Service 中建立事务边界。** 删除按用户身份执行，并拒绝自删和管理员目标。
- [x] **步骤 2：更新用户和账户状态。** 同步写入 `DELETED`、更新时间和安全版本，保留余额及流水。
- [x] **步骤 3：撤销会话和链接。** 删除会话和所有未撤销玩家链接。
- [x] **步骤 4：停止托行为。** 删除后禁止新的托调度和立即执行，执行前再次校验 ACTIVE 状态。
- [x] **步骤 5：记录审计。** 审计只记录身份快照和结果，不写 token、密码或完整 URL。
- [x] **步骤 6：实现幂等结果。** 重复删除返回历史身份详情，不重复执行副作用。
- [x] **步骤 7：写 Controller/Service 测试。** 已覆盖普通玩家删除、访问失效、历史保留和重复删除；并发专项仍待补充。

## 阶段验收标准

- 删除确认准确显示 `wxid`、会员 ID 和昵称。
- 删除后玩家不能登录、不能使用链接、不能下注、不能上分或继续托行为。
- 历史积分流水、下注、中奖流水、聊天和审计记录保留并可查询。
- 重复删除和并发删除不会重复产生业务副作用。
- `chat_robot` 不受玩家软删除接口影响，管理员不能通过玩家接口删除独立服务端机器人。
