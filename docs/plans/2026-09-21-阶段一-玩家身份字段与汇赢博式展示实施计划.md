# 阶段一：玩家身份字段与汇赢博式展示实施计划

> **给实施者：** 按任务顺序执行本计划。步骤使用复选框跟踪进度。本阶段只做身份数据和后台展示，不开放链接登录。

**目标：** 为普通玩家和托补齐不可变 `wxid` 内部编号、稳定会员 ID 和昵称展示，并让统一玩家工作台、详情和删除确认使用一致的身份格式。

**架构：** 在 `sys_user` 增加 `internal_code`；在 `demo_user_account` 增加 `member_code`，保留现有 `user_code` 作为旧接口和历史数据兼容字段。后台 API 同时返回新旧字段，前端统一使用 `@会员ID.昵称`，详情和操作确认显示 `wxid`、会员 ID、昵称三项。

**技术栈：** Java 21、Spring Boot 4.0.8、JDBC、Flyway、MySQL 8.4 LTS、H2、Vue 3、TypeScript、Vitest。

## 全局约束

- 不修改 `sys_user.id`、`sys_user.username` 的语义。
- `internal_code` 使用 `wxid_` 前缀，长度上限 64，唯一且创建后不可变。
- `member_code` 使用 `v` 加十进制数字，长度上限 32，唯一且创建后不可变。
- 不在前端生成正式身份编号；编号必须由服务端事务生成。
- 旧 `user_code` 继续返回并支持旧路径查询；新 UI 不再把它当作主要展示身份。
- 托与普通玩家共用身份模型，但继续保留 `player_kind` 区分。
- 本阶段不开放链接登录；后续 `CHAT_ONLY` 权限必须建立在本阶段稳定的用户身份上。
- 余额、下注、开奖、中奖、流水和结算继续只表示虚拟积分，不新增现实资金能力。


服务必须在数据库唯一约束失败时重试有限次数，超过次数返回业务错误并写审计，不允许返回重复编号。
