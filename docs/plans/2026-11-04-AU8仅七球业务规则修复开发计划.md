# AU8 仅七球业务规则修复开发计划

> 制定日期：2026-11-04
> 状态：本机实施完成；部分验收待补，详见 §7。
> 用户决定：AU8 业务固定为 7 球；8 球不是历史兼容要求，正式 AU8 代码路径、配置入口、数据库默认和初始化结果都不得再启用 8 球。开发数据库和数据可整体重建。其他彩种不在本计划范围。

## 1. 目标与根因

本机 `/room` 显示八球是因为 2026-11-03 全库重建后，代码仍按数据库的 AU8 球数配置生成新期：

- V102 给 `game_definition.next_issue_ball_count`、`game_issue.ball_count` 设默认 8，且约束允许 7/8。
- `GameDataRepository.saveBettingIssue()` 从 `game_definition.next_issue_ball_count` 读取新期球数；空库重新初始化后 AU8 即按 8 球运行。
- V103 的防回退检查只有在数据库已经存在七球期时生效。全库重建清除了七球期和 `game_ball_rule_change` 记录，因此该检查不阻止回到 8。
- 平台设置、玩家/代理展示、开奖结果解析和机器人/聊天室仍保留 7/8 双轨兼容；此前切到七球只改了本机数据库运行值，没有让 AU8 规则在代码和迁移层固定为 7。

2026-11-04 本机 MySQL 8.4 只读证据：AU8 的 `next_issue_ball_count=8`，最新期 `3000125` 快照为 8，规则切换记录为空。目标是从新库初始化、管理员配置、期次创建直到玩家显示，AU8 始终只有七球，不依赖手工补设。

## 2. 最终规则与范围

1. AU8 每期严格 7 球。开奖结果恰含 7 个 1–20 数字；球位只允许 1–7；AU8 `number_8` 永远为空。
2. AU8 所有玩家、托、代理、平台、机器人、开奖、历史与中心结算入口固定 7 球。任何 API、聊天文本、管理表单、过期页面缓存或直接 SQL 写入试图输入第 8 球都拒绝，不截断、不补默认、不映射。
3. AU8 不提供下一期球数设置和球数切换。`game_definition.next_issue_ball_count` 虽仍为其他彩种保留，但 AU8 在服务层和 MySQL 层都只能是 7；AU8 球位串固定 `1,2,3,4,5,6,7`。
4. 其他 `game_code <> 'AU8'` 的彩种继续使用各自当前球数规则，本次不统一改成 7。
5. 不保留 AU8 八球期的玩家展示、内部补结算、中心补结算、聊天室旧八球消息过滤/重放等兼容分支。用户已授权清空本机开发数据，修复后从纯七球新库开始。

## 4. 实施步骤

### P0. 记录当前开发状态

1. 只读盘点当前 AU8 配置、期号、七/八球期、注单和结算状态、中心订单及 Flyway 版本，确认本机目标 schema 为 `xupan_platform`。
2. 用户允许清空本机开发数据；不得更改其他 MySQL schema、服务器或生产。

### P1. 固定服务端业务规则

1. `GameSettingsService` 在创建/编辑 AU8 时强制 `nextIssueBallCount=7` 和 `ballIndexes=1..7`；AU8 不再走球数变更审计/切换逻辑，也不能通过更新其他设置把球数带回 8。其他彩种仍保留其现有 7/8 配置行为。
2. `GameDataRepository` 对 AU8 轮期只接受 7；补期、开奖结果确认、所有球号读取/写入、下注与改单入口按彩种做固定 7 校验。其他彩种继续使用 `ball_count` 快照。
3. `PlatformDrawHistoryService`、`CenterOrderService`/`CenterSettlementService` 及其 repository 对 AU8 只接受 7；已确认结果长度不等于 7 时拒绝结算，不做截断。
4. 删除只用于 AU8 八球切换的机器人事件跳过、聊天旧八球隐藏和 cutover 前后差异处理。新库无八球历史，因此不需要给 AU8 保留这类兼容路径。

### P2. V108 固化初始化和 MySQL 写入门禁

1. 当前最新 Flyway 为 V107；新增 V108 前重新核实版本。V108 先检查 AU8 不存在 `ball_count <> 7` 的旧期；有旧八球数据时失败并要求使用者按本计划重建开发库，不做静默迁移或假装兼容。
2. V108 将 AU8 `game_definition.next_issue_ball_count` 设为 7、`ball_indexes` 设为 `1,2,3,4,5,6,7`。新建 AU8 配置由服务端给出 7，且由 MySQL `BEFORE INSERT/UPDATE` 触发器拒绝非 7 配置。
3. 新增 AU8 期次 `BEFORE INSERT/UPDATE` 触发器：只允许 `ball_count=7` 且 `number_8 IS NULL`。既有通用球位触发器继续校验 `game_bet` 和 `center_order` 不超过该期球数；服务端同时固定 AU8 七球。
4. 代码和迁移准备完成后，先停止本机所有 Xupan 实例及期次/机器人调度，再整体重建本机 `xupan_platform`。不要先对含有八球期的旧库执行 V108：V108 的数据前置检查会按设计拒绝这种状态。随后从 V1 完整启动迁移至 V108；V102 中间阶段的默认 8 会在业务初始化前由 V108 修正。验证新库的 `game_definition` 和第一期都是 7。初始化本机管理员使用本地密钥文件，不将凭据写入仓库或聊天。

### P3. 全端七球显示与输入

1. 玩家前台按 `gameCode` 判定；AU8 的球数只能显示 7，任何缺失/非法响应不得 fallback 到 8。
2. AU8 平台设置页面隐藏 8 球选项并显示固定七球；AU8 下注榜、开奖页、开奖记录、补期、改单和 HBY019 桥统一 7 球。其他彩种仍依据自己的配置和 issue snapshot。
3. 移除 AU8 专用的 `firstSevenIssueNumber`/`isSevenBallCutover` 行为和针对旧八球消息的过滤；不能把其他彩种消息误用 AU8 七球规则。
4. `robotDrawMessage` 在 AU8 调用时必须传 expectedLength=7；直接机器人开奖/历史 payload 不接受 AU8 八球数组。

## 5. 数据库重建与影响

- 重建目标仅为本机 `xupan_platform`，完整删除其中所有账号、机器/子账号、期次、注单、虚拟积分账本、机器人数据、中心账号/订单、聊天记录和配置，再由迁移重新建库。此前同一数据库已于 2026-11-03 被全库重建；本次若再次重建，仍会清除其后创建的本机数据。
- 迁移不会自动删除或转换既有 8 球行；V108 对 AU8 八球期做前置失败保护。服务端/生产库没有本次清空授权，绝不连接或操作。
- V108 应为 AU8 建立固定 7 球；不通过增加一个需人工登录平台再次修改的配置来修复默认值。
