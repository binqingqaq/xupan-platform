# 数据保留与自动清理实施计划

> 状态：本机实现与定向验收完成；服务器/生产未执行。用户于 2026-10-09 确认按本计划保留期执行；BY220 清理五天的结论来自源码静态分析，BY220 运行态不可用。

## 1. 目标

为 Xupan 高频增长数据建立独立、自动、可重复运行的保留清理流程，避免依赖后台“清空数据”按钮。所有操作限定在当前 Xupan 数据库；本任务不连接或修改服务器/生产环境。

## 2. 已确认保留期限

| 数据 | 保留期 | 清理条件 |
| --- | ---: | --- |
| 聊天消息、已完成托动作和机器人投递历史 | 5 天 | 只清理超过房间期限的聊天；托动作仅清理 `SUCCEEDED`/`SKIPPED`；机器人派发只清理 `PUBLISHED`/`SKIPPED`。 |
| 登录/安全日志 | 180 天 | 按创建时间分批删除。 |
| 操作审计 | 1 年 | 按创建时间分批删除。 |
| 玩家虚拟积分流水及已结注单 | 3 年（1095 天） | 只清理已结算 `WIN`/`DRAW`/`LOSE`；关联的玩家账本/改单记录一起清理。 |
| 未完成记录 | 不按期限清理 | `PENDING`、`PROCESSING`、`FAILED`、未结算注单均保留。 |

每日 Asia/Shanghai 03:30 执行；每张表每轮有批次与轮数上限，超量历史跨日继续追赶。多进程通过 `ScheduledTaskLock` 互斥。期限可以由部署环境配置覆盖，默认采用上表数值。

## 3. 关联数据与安全边界

- 删除旧聊天前先删除已发布 outbox、清除已完成派发对消息的引用；仍被待处理/失败 outbox、失败机器人派发或失败托动作引用的聊天消息保留。
- 超过 5 天且尚无派发记录的旧游戏事件不再生成迟到机器人消息；旧的待处理/处理中/失败派发仍继续重试。完成派发与事件源只在超期后清理。
- `game_bet` 仅在 `settled_at` 已超过 3 年、状态为 `WIN`/`DRAW`/`LOSE`，且没有上游上报订单、中心订单、中心对账处置或较新的改单/积分流水引用时清理。被上游或对账引用的注单及关联历史保留。
- `demo_balance_ledger` 随已过期注单删除关联流水；无注单关联的旧玩家积分流水超过 3 年删除。`agent_ledger` 超期删除；`center_agent_ledger` 只清理非中心订单引用的超期流水，中心订单相关账本保留以支持对账。
- `center_reconciliation_disposition` 按既有 V68 基线只追加、不物理删除；其过期语义是处置失效并重新进入待处置列表，不是删除历史。此表不属于通用 `sys_operation_log`。
- 积分流水幂等键随对应流水到期清理；超出保留期限后不再保证旧幂等键永久防重。清理不会改写任何当前余额。
- 不删除账号、期号、开奖结果、上游订单或中心订单，不改变人工“清空数据”按钮语义。
