# 代理积分记录与托积分记录后端适配实施计划

## 目标

补齐 `/console` 普通玩家积分记录与托积分记录所需的后端统计数据，使现有 `GET /api/admin/player-desk/points-records` 按 BY220 业务规则返回可直接展示的业务日汇总、玩家/托明细和记录数据。本阶段只修改后端、测试和对应文档，不调整前端结构或样式，不新增“抽水”业务。

## 现状与依据

- BY220 `robot.php` 代理后台按机器配置的单边/双边显示口径选择流水及返水统计值；这项设置不是积分记录页内的切换按钮。
- BY220 积分记录日期支持自然日和 06:00 切日；当前 Xupan 业务模块已确认采用 `Asia/Shanghai` 06:00 切日，本计划沿用该项目既定规则。
- Xupan 已有机器 `rebate_mode`、`rebate_rate`、`special_rebate_rate`，下注记录保存返水比例快照，并已有单边/双边流水及返水计算器。
- 当前积分记录 API 已查询玩家、下注、钱包流水和托动作；目前汇总字段主要是下注额、结算盈亏、上下分和期初/期末余额，尚未向该报表返回 BY220 单/双边流水与返水统计。
- 当前注单、积分流水、托动作 SQL 分别按 `detailLimit` 截断；服务端又从截断后的注单/账本列表累计汇总，超过上限时会把汇总一并截断。本阶段将拆分全量汇总与限量明细。
- BY220 的积分汇总查询只包含普通玩家；其源码没有找到单独的托积分汇总接口。本项目已有 `kind=NORMAL|BOT`，本阶段按 Xupan 当前分类分别生成普通玩家和托报表，不伪称这是 BY220 已证实的托端行为。
- 虚拟积分、注单和钱包流水仍是事实源；报表不创建第二套余额/盈亏账本，不产生现实资金语义。

## BY220 到 Xupan 映射

| BY220 行为/字段 | Xupan 对应 | 本阶段处理 |
| --- | --- | --- |
| 代理机器的 `ls` 单边/双边口径 | `agent.rebate_mode` | 在机器范围报表读取当前机器配置，并按配置选取生效流水/返水；API 同时返回口径标识，便于审计与核对 |
| 单边、双边有效流水 | `BetFlowMetricsCalculator` 计算结果 | 按业务日、普通玩家/托分别汇总到总计和每个玩家卡片 |
| 单边返水、双边返水 | 注单时保存的返水比例快照及现有计算规则 | 输出两种计算值与按机器口径选出的生效值；不引入抽水字段 |
| 06 点业务日 | `PlayerPointsReportService.resolveBusinessDay` | 保持当前 `Asia/Shanghai` 06:00 至次日 06:00 左闭右开窗口 |
| 上下分 | `demo_balance_ledger` | 保持已存在的管理员积分操作统计和明细，不重复统计待审批申请 |
| 托行为记录 | `test_player_action` | 保持托动作数据和现有机器范围过滤 |

## 实施步骤

1. 完成 BY220 控制器、模板、`get_score_his`、`getRecordData`、`getShuang`/`getShuangs` 与 Xupan `BetFlowMetricsCalculator` 逐项映射，并复核状态过滤、机器隔离、明细上限和注单快照字段。
2. 扩展报表查询所需的注单字段，复用 `BetFlowMetricsCalculator` 按注单返水比例快照计算单/双边流水及返水；读取当前机器 `rebate_mode` 选择生效值。普通玩家与托使用同一结构、分别按 `kind` 查询。
3. 将新增指标纳入玩家卡片和总计响应；改为全量聚合报表数值、仅限制各玩家详情条数。保留期初/期末积分、上下分明细与托动作明细。保持撤单排除规则，明确待结算、已结算与和局对各指标的影响。
4. 复用现有 Flyway 表和索引；只有 SQL 证据显示缺少必要索引时才增加迁移。
5. 更新 API DTO/契约及业务模块文档；前端文件不在本阶段变更范围。
6. 增加/调整服务、仓储与 Controller 测试，覆盖单双边算法、返水快照、普通玩家/托隔离、机器范围、06:00 边界、撤单/未结单和空数据。
7. 执行相关后端测试、编译和 `git diff --check`；验证层级按实际环境如实记录。本阶段不部署服务器或生产环境。

## 验收标准

- 机器账号只能读取自己机器范围内对应类别玩家的报表；普通玩家和托查询不串数据。
- `businessDate` 对应上海时间 06:00 至次日 06:00 的左闭右开窗口，非法日期及未来日期仍被拒绝。
- 对每笔注单按现有 BY220 对齐计算器计算单边/双边流水与返水；报表生效值严格跟随该机器 `rebate_mode`。
- 注单取消、未结算与和局按 BY220 映射及 Xupan 已确认的撤单排除规则处理，不重复计入结算指标。
- 上下分只来自钱包流水；待审批申请不冒充已完成积分操作；托动作保持独立明细。
- 前端源码无本计划引起的修改；不增加名为抽水/佣金/分成的字段、接口或流程。
- 后端定向测试与编译通过；运行环境验证范围单独标记，不把 H2 结果表述为 MySQL/服务器验收。

## 前端接入阶段（2026-10-18 新增）

| HBY019 原区域 | 接入方式 | 数据边界 |
| --- | --- | --- |
| 积分记录、托积分记录的日期列表 | 由报表 `availableDates` 更新原日期节点；保留托记录原有最近三天显示规则 | 日期区间采用 API 返回的上海时区 06:00 业务日 |
| 当前积分对账（Way1） | `summary`/`players` 映射为原汇总行与玩家卡片；展开时映射下注、积分操作明细 | 汇总使用全量聚合；明细服从 API `detailLimit`；昵称历史若报表未提供不伪造 |
| 当前上下对账（Way2） | 从普通玩家 `pointOperations` 合并并按时间倒序显示 | 只展示已落账积分流水；待审批申请不计入；筛选实际上下分操作类型 |
| 当前记录对账（Way3） | 用 `bets` 生成注单列表，按期号统计总注和盈亏 | 开奖结果链、报网状态不在当前报表 API 中，明确显示无可用数据，不猜为已报/未报 |
| 抽水/返水变更流水（Way4） | 暂留原占位 | 返水注单快照不是配置变更审计，不能替代修改历史 |
| 赔率变更流水（Way5） | 暂留原占位 | 注单赔率快照不是赔率配置变更审计，不能替代修改历史 |
