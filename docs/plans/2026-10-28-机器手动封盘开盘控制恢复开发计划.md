# 机器手动封盘/开盘控制恢复开发计划

> 状态：本机已实施。2026-10-28 按用户最新要求恢复 BY220 式机器手动开/封盘控制，取代同日“移除机器开盘控制”的先前决定。MySQL 8.4 本机数据库已迁移 V99，后端重启健康检查 UP；Spring H2 集成测试未能越过既有 V83 MySQL 专用迁移语法。BY220 依据为本地源码静态核查；BY220 运行态操作、服务器/生产、登录后浏览器操作及真实机器切换验收未执行。

## 1. 目标与业务边界

在代理后台 `/console` 恢复机器账号自己的“当前状态：开盘/封盘”手动开关，并将同一状态用于服务端下注准入和该机器托的自动下注。它是机器范围的下注许可，不代表彩种/期次的阶段状态。

## 2. 规则与状态模型

维护两个彼此独立的状态：

- **机器手动下注状态**：`manual_betting_open=true/false`，由代理在 `/console` 手动切换；新建机器和 V99 迁移后的既有机器默认 `true`。
- **彩种/期次状态**：沿用现有启用、`BETTING`/`DRAWING`、`betting_ends_at` 规则，由游戏与期次生命周期推进。

普通下注只有在两类状态、机器有效期、机器封盘秒数、余额、限额、玩法配置及其他现存策略全部允许时才可写入。手动开盘只解除机器手动关闭这一项限制，不能重开已截止期次、启用已停用彩种或绕过机器有效期和封盘秒数。

| 场景 | 规则结果 |
| --- | --- |
| 机器开盘，期次仍在下注窗口 | 通过本开关检查；继续执行其他下注校验 |
| 手动封盘，期次仍在下注窗口 | 拒绝新的普通下注，返回稳定业务码 `GAME_MACHINE_MANUALLY_CLOSED` 和“已停止下注”语义 |
| 手动封盘前已提交的注单 | 保留原记录和钱包流水，按正常开奖流程结算，不退款、不作废 |
| 封盘后取消 | 不因机器手动状态而封禁取消；只有期次未进入禁止取消窗口、注单仍在取消秒数内等现行规则允许时才取消 |
| 封盘后查询、查看前台、聊天 | 不因本开关拒绝；各自继续执行玩家身份、会话、有效期、封禁和聊天室权限校验 |
| 封盘后上分/下分等非下注命令 | 不由本开关拦截，沿用各自授权、机器归属、审批和账本规则 |
| 封盘时托自动下注计划待执行 | 执行前发现关闭则标记为跳过并记录 `MACHINE_MANUALLY_CLOSED`，不在之后开盘时补注 |
| 关盘后重新开盘 | 后续新请求恢复按现有规则判断；已经跳过的旧期托动作不补执行 |
| 机器过期、停用、锁定 | 机器状态/期限规则仍优先；切换为开盘不能解除这些限制 |
| 报网/中心已有处理中订单 | 不撤回、不退款、不重复上报；已受理注单及其已有报网状态继续按各自幂等恢复流程处理。关闭只阻止新的下注进入 |

BY220 的按日程自动切换 `isOpen` 代码在 `application/console/Websocket.php:643-652` 已注释；开关应保持手动，重新开盘须由有权代理显式操作。机器过期时超管列表逻辑会把机器置为关闭（`application/admin/controller/Rb.php:167-171`），账号有效状态仍独立决定能否下注。

### 2.1 并发及切换时点

- 下注事务与开关事务都锁定同一 `agent` 机器行；锁持有到业务事务提交。若下注先取得锁，关盘请求等待该笔已进入事务的下注提交后再落库；若关盘先取得锁，之后取得锁的下注读到关闭状态并拒绝。
- API 仅在状态事务提交后报告成功；重复设置为当前状态按幂等成功处理，不反复写审计事件。
- 前端按钮显示请求中状态并禁止重复点击；超时或断网后重新读取服务端状态，不乐观地长期保留未经确认的开/封盘显示。
- 对锁超时、数据库不可用、未授权及机器状态已变化返回明确错误；错误时不显示切换成功。
- 维持一致锁顺序并检查自动托/聊天下注调用路径，避免仅依赖 Vue 按钮或进程内 `PlayerBetLock`。多实例时数据库锁仍是最终协调机制。

## 3. 数据、接口和页面落点

| 层 | 计划改动 |
| --- | --- |
| Flyway | 在 V98 后新增 V99，给 `agent` 增加 `manual_betting_open BOOLEAN NOT NULL DEFAULT TRUE`。不回改历史迁移；新建机器显式默认开盘，所有现存机器迁移后也保持开盘。V98 已删除的旧状态无法可靠恢复，不根据旧审计或猜测自动封盘 |
| 领域/Repository | 读模型增加机器手动状态；提供机器行加锁读取和状态更新方法；确保机器所有权来自认证主体，不接受客户端任意 `agentId` |
| `/console` API | 增加当前 AGENT 更新本人机器开/封盘的受鉴权接口和读取字段；校验机器 ACTIVE、未过期。状态写入与 `AGENT_PLAYER_MANAGE` 等现有权限边界核对，不允许玩家凭证调用 |
| `/console` 页面 | 恢复“当前状态”开/封盘按钮；显示机器手动状态。期次阶段及倒计时仍使用独立数据，不再把 `board.phase` 映射成机器开关 |
| `/platform-admin/machines` | 列表展示机器开/封盘状态；新建机器仍默认开盘，不在超管创建/编辑表单增加该开关。BY220 超管表单无 `isOpen` 输入，机器表仅展示状态列，本计划不添加超管切换动作 |
| 下单/撤单 | 下注服务事务内读取并锁定机器状态。只对普通下注应用手动关闭拒绝；撤单保留 BY220 顺序语义，不因该字段附加拒绝 |
| 托自动行为 | 候选筛选及到期动作执行前重新校验机器状态；封盘时不创建/不执行新的下注动作，关闭期间跳过动作不可在重开后补发。上分/下分/查询等行为是否受影响维持现有独立规则 |
| 审计/消息 | 记录状态变更前后值、操作者、机器、时间、请求关联标识；不记录秘密。面向玩家的下注拒绝文案统一为“已停止下注”，不要泄露内部机器字段名 |

## 4. 实施阶段

1. **需求与映射冻结**：核对 BY220 代理按钮、接口、`sendMsg`、取消、自动托、开奖结算与超管状态列；核对 Xupan 当前 `/console`、`PlatformAdminMachines.vue`、`DemoGameService`、`AgentBettingPolicy`、托调度、审计设施和数据库版本。本计划已完成静态源码映射；BY220 运行态及页面操作仍未验证。
2. **持久化与读写 API**：V99 新增字段、默认值和迁移测试；加入机器本人受鉴权切换接口、读模型、并发锁、审计以及未授权/过期/停用响应。
3. **服务端下注门禁**：普通文本/快捷/批量下注统一经过同一服务端策略；确认任何备用入口和重试路径都不会漏过机器状态；取消与状态查询按上表独立处理。
4. **托自动行为**：在筛选和最终执行点都检查状态；测试封盘并发、关盘后重开、旧期动作不补跑。
5. **前端**：`/console` 加回手动开封控件，显示独立机器状态；超管机器列表加状态展示和正确默认值；处理等待、失败、刷新、重复点击和失效账号。
6. **专项验证与文档收尾**：针对 MySQL 8.4 Flyway、Spring 服务测试、Vue 测试/typecheck/build、并发验收及本机服务运行逐项记录。通过后更新业务模块基线和文档索引状态；本机验证不得写成服务器或生产验收。

## 5. 验收用例

- 新建机器以及从 V98 升级的机器均为开盘；编辑其他字段不覆盖当前开关。
- 手动封盘后普通玩家仍能进入 `/room`、刷新会话、查看当前期/注单/聊天；普通文本、快捷和批量下注均被服务端拒绝且不产生注单、扣分、下注消息或报网任务。
- 封盘状态下取消仍只由取消秒数与期次封盘窗口决定；查询、上下分及聊天权限仍走其既有规则。
- 关盘前已受理下注仍可撤单（在原取消窗口内）或由期开奖结算；关盘动作不改变其注单和钱包记录。
- 两个并发场景：下注事务先锁定时，关盘成功响应晚于该事务提交；关盘事务先锁定时，随后下注不得落单。使用 MySQL 8.4 多连接验证，不以单 JVM 单元测试替代。
- 自动托关闭时不产生新注单；关闭后再次开盘不补发已跳过期号动作；正常开奖、开奖消息及历史结算不被机器状态阻断。
- 机器过期/停用时，即使开盘请求也不能重新取得下注资格；仅机器本人可切换，跨机器 ID、玩家会话、平台子账号越权均失败。
- 页面在请求中防重复提交；请求失败/超时刷新后显示数据库真实状态；期次 `BETTING` 与机器“开盘”不同步时二者分别正确显示。

## 6. 已知风险与验收限制

- V98 已删除此前 `board_open` 列；任何升级到 V99 的现存机器只可安全默认开盘，无法从已丢弃的列恢复之前状态。这是保留业务连续性的迁移选择，实施日志必须明确记录。
- BY220 `checkUser()` 的封盘分支被禁用，故“封盘禁止玩家进入前台”不是 BY220 现行语义。本计划按 BY220 只限制下注处理；若要把玩家前台入口一起封锁，应作为不同业务规则另行决定，不能混入本开关。
- BY220 源码表现为处理分支中的即时开关校验，没有证明数据库事务级竞态语义；Xupan 计划采用共享行锁将切换/下注顺序明确化，这是可靠性强化，不改变已受理注单的结算语义。
- 本计划不包含服务器发布、真实外部上游接入、清理或退款历史注单。

## 7. 本机实施记录（2026-10-28）

- 新增 V99 `manual_betting_open BOOLEAN NOT NULL DEFAULT TRUE`；现存 V98 机器和新建机器默认开盘。新状态只在代理 `/console` 可切换；超级后台机器列表只读显示。
- `/console` 当前状态读取机器手动状态，不再用 `board.phase` 冒充；切换请求期间禁用按钮，失败时重新读取服务端状态。玩家前台访问不因封盘被阻止。
- 后续点击故障排查发现：8080 实际服务的 classpath 静态副本仍是只读 `<span>`，桥接脚本未登记状态更新路径，首页还引用不含机器状态 API 的旧 Vue bundle；已补齐按钮事件与桥接路由、递增桥接资源版本、单独构建并更新首页资源清单及新 hash bundle，随后重启后端。HTTP 实查确认服务返回可点击按钮、点击处理器、iframe 消息处理器、状态更新 API 和桥接路由；未实际点击，避免未经确认地改变当前机器持久化状态。
