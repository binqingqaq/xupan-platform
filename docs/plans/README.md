# 实施计划目录规则

## 当前计划判定

只有 [当前文档入口](../文档索引.md) 的「当前仍在执行或待补的专项计划」中列出的计划，才可以作为当前开发输入。

其他计划文件即使仍保留在目录中，也只用于历史追溯，不能覆盖当前业务模块基线、源码、迁移、测试或最新验收记录。

约定（2026-09-24 起）：

- 计划完成后**不删除文件**，而是由 [文档索引](../文档索引.md) 把它从「当前仍在执行」移动到「已结项计划」，并在计划自身的「计划状态」章节写明当时的证据与未执行项。
- 只有被当前模块基线完全替代、且不再承担追溯价值的计划才会删除，删除后必须在文档索引的「已删除或被替代的内容」中登记。
- 仍未完成的事项（例如服务器与生产验收、多实例强一致、撤单专项）统一登记在文档索引的「待补」表中，不再为每个小项单独保留一份长期计划。

## 计划结项流程

```text
需求进入模块基线
  -> 创建实施计划
  -> 代码、迁移、测试和运行态验证
  -> 更新模块状态矩阵
  -> 写验收记录并标明证据等级
  -> 从当前入口移除已结项计划
  -> 计划删除或移入明确归档位置
```

计划不应长期承担业务规则的唯一记录职责。规则进入业务模块基线，证据进入验收记录，计划只记录本次实施范围和执行过程。
