# 超级后台报表统计严格对齐 BY220 开发计划

> 日期：2026-11-05
> 状态：代码已实施。前端专项测试、Vite 生产构建、Java 主码/测试码编译通过；后端 H2 集成测试启动被既有 V83 迁移语法阻断。本机 MySQL 8.4 与登录态浏览器验收未执行。

## 1. 目标与范围

将超级管理后台 `/platform-admin/reports` 的“积分流水”“盈亏报表”“飞单记录”逐项对齐 BY220 `admin.php` 报表统计页的实际查询和展示语义。按 BY220 的三类报表口径排除托（BOT）；类型缺失或无法确认的历史注单也不得默认算作普通玩家。所有统计均只读既有持久化事实，不建立第二套余额、注单、报网或报表事实。

本计划只改平台后台报表页面、其只读接口/服务及对应测试/文档。不改 `/console` 机器运营台的报网操作、机器端订单页、下注、钱包写入、结算、报网调度和已有数据。不接入真实外部上游，不保存外部凭据，不引入现实资金语义。

### 2.1 BY220 计算细节

- `getRecordData` 对 `type=3` 的所有下注计入下注流水；已结算注单才贡献已生效盈亏、有效流水及相应反水。单边与双边流水/反水规则按玩法、输赢/和局、赔率和返水字段分别计算。不得把下注本金、有效流水、盈亏或反水互相替代。源码：`application/common.php:4606-4657`；单双边规则还见项目既有对齐材料 `docs/验收记录/2026-10-02-BY220超级管理后台报表双边流水与反水验收记录.md`。
- `type=4` 的上下分操作根据 `sys` 和 `isTy` 归入上分/下分；需按业务来源映射至 Xupan 钱包账本操作类型，避免把与 BY220 无对应关系的中心账务、管理员调账等记录混入。
- 飞单页状态切换值为 `0` 未报、`2` 已飞单、`3` 失败；具体页面日期快捷项和 0 点/6 点模式应在实施前结合该页事件处理完整核对。BY220 子账号/超管数据授权仍须遵守 Xupan 当前服务端权限和数据范围，不复制 BY220 接口缺少 `uid` 条件造成的越权风险。
- BY220 的 `GetScoreHisDetail` 详情 SQL 未重复写 `isTuo=0`。Xupan 必须在父查询与详情查询两层都限定普通玩家，不能照搬这一遗漏。

## 3. Xupan 当前实现与缺口

- 页面 `web/src/views/PlatformAdminReports.vue` 已有筛选区和三个选项卡；“飞单记录”当前为未接入占位。积分流水支持服务端分页（既有计划 `2026-11-05-报表积分流水分页优化计划.md`），这次保留分页能力并调整数据口径。
- `GET /api/admin/reports/score-flow` 目前由 `PlatformReportService.scoreFlow` 查询 `demo_balance_ledger`，无 `player_kind` 条件，只返回单条钱包流水；缺少 BY220 的下注流水、按玩家归并、盈亏/返水/有效单双边流水等汇总。分页、总数、日期和子账号过滤保留并扩展到相同统计数据集。
- `GET /api/admin/reports/profit` 当前对账户余额、注单和积分账本查询无普通玩家过滤；下注指标主要按已结算 `game_bet` 聚合。须显式筛选 `player_kind_snapshot='NORMAL'`，按 BY220 逐字段实现统计；遗漏身份快照的数据不得默认归类普通玩家。
- Xupan 有 `game_bet`、`demo_balance_ledger`、`report_upstream_order` 事实及机器端 `/api/admin/player-desk/report/orders` 查询。该查询只服务机器范围、按派生状态分页，不接受平台报表的日期/子账号范围；不能直接暴露为超管 API。`web/src/views/PlatformAdminReports.vue` 当前没有飞单请求。
- `report_upstream_order` 保存追加式尝试；列表状态取每笔注单最新尝试派生。当前状态有 `NOT_SENT/PENDING/ACCEPTED/REJECTED/TIMEOUT/MANUAL/CANCELLED/REFUNDED/SETTLED` 等。上线前需明确这些状态与 BY220 三个可见状态的映射并固定在测试中，不能丢失本地审计事实。

## 4. 目标查询和状态规则

### 4.1 积分流水与盈亏报表筛选

- 查询参数：`day`、`day3`、可选 `subAccountId`；日期与子账号范围用于积分流水、盈亏报表。飞单记录采用自己的日期快捷范围及 `status`、`page`、`pageSize`，不悄然继承父页的自定义日期区间或下拉值。
- 日期区间采用 `Asia/Shanghai` 半开区间 `[fromInclusive, toExclusive)`。BY220 默认业务日为 06:00 至次日 06:00；若页面支持自然日模式，增加明确的 `cutoffHour=0|6` 参数或等价枚举，不用浏览器本地时区计算事实区间。
- 积分流水/盈亏报表中，平台超管可查全局或所选子账号；子账号只可查自身授权范围。机器归属以 `COALESCE(demo_user_account.agent_id, game_bet.agent_id_snapshot)` 等既有快照归属规则解析。BY220 的飞单父页没有把所选子账号传入弹出页；Xupan 仍需服务端强制执行操作者权限边界，子账号不允许因这一兼容行为读取其他范围。
- 普通玩家范围为账户当前身份或订单 `player_kind_snapshot` 明确为 `NORMAL`；BOT、空值、未知值一律排除。不得因玩家实体被删除导致历史注单失去分类后再错误纳入普通玩家。
- 所有查询服务端执行 `REPORT_READ`、操作者数据范围、机器/子账号约束；参数校验、稳定排序和分页总数必须与当前分页约束一致。只读接口不得触发真实报网或改变订单状态。

### 4.2 积分流水

- 以 `game_bet`（BY220 `type=3`）和可映射的 `demo_balance_ledger` 积分操作（BY220 `type=4`）组成报表视图，按普通玩家归并。不得创建重复 ledger 或把纯计算汇总持久化成新事实。
- 玩家汇总至少包含 BY220 页面使用的玩家标识/昵称、昨余/期初余额、下注流水、单边有效流水、双边有效流水、盈亏、单边/双边反水、上分、下分、上下差，以及可展开的分页明细。依据已有 `BetFlowMetricsCalculator` 复用玩法计算；实现前对它与 BY220 各玩法分支逐项比对，补足遗漏而非另写不一致公式。
- 分页应定义为玩家汇总行分页或明细分页，并保证总计覆盖完整筛选集，不因当前页改变总计。推荐玩家行分页、玩家详情按玩家 ID 单独分页；如果现有接口兼容性要求保留记录分页，增加版本化响应结构并更新调用方，不能静默改变 `items` 语义。
- 日期范围、身份、账本操作类型和订单状态的相同 where 条件必须用于 count、汇总、当前页及详情，防止总数和明细不一致。

### 4.3 盈亏报表

- 机器为行、子账号为归属显示；机器维度聚合其名下 `NORMAL` 玩家注单和对应有效积分操作。
- 对齐昨余、流水、单边流水、双边流水、盈亏、反水、上下分、上下差及机器明细。现有跨机器总计继续由同一组机器行求和产生。
- 下注流水按 BY220 `type=3` 口径纳入日期范围内的所有有效下注（含未结单的本金）；盈亏、已生效有效流水和反水按 BY220 结算条件计算。撤销注单排除；已结算输赢/和局按当前玩法计算器的对应语义处理。
- 余额快照只纳入普通玩家；机器自己的 `agent.score` 按 BY220 昨余组成规则处理。日期内没有注单的有效机器仍应返回零流水行与其余额。
- `ADMIN_GRANT/ADMIN_ADJUST` 不可未经映射就都视为 BY220 上下分；按 BY220 来源判定规则确认哪些操作计入报表，上分/下分分别正向累计为绝对值。

### 4.4 飞单记录

- 在“飞单记录”选项卡实现独立近期日期快捷选择、0 点/6 点模式、状态分组、列表和状态数量，不复用父页开始/结束日期输入。为数据量设置服务端分页，默认 20 条，允许 10/20/50/100。超管查看全局；子账号仍按自身权限范围过滤。
- 列表字段按 BY220 可见业务信息映射：发生时间、玩家编号/昵称、期号、球位、下注内容、下注积分、赔率、报网状态及必要的失败说明。不要展示密钥、令牌、完整外部地址或中心账号凭据。
- 只读 `game_bet` 与最新 `report_upstream_order` 尝试派生状态；历史尝试可按详情展开或查看，不以重试覆盖旧尝试。失败、超时、待处理等 Xupan 状态映射到 BY220 未报/成功/失败三类前，先基于状态机代码、BY220 的发送时机和用户可见行为列出映射表，待计划实施前落实测试断言；`CANCELLED/REFUNDED/SETTLED` 是否仍按其最后一次上报结果显示，按 BY220 订单记录行为核实，不按结算状态代替报网状态。
- `report_upstream_order` 无尝试行的普通下注如何归入“未报”，应核对 BY220 `flyers_status` 初始化与 Xupan `NOT_SENT` 派生语义后采用单一规范状态。按最新上报状态分组时，同一注单只能出现一次；尝试历史详情不得重复计入订单数。
- 新增管理端只读查询服务/控制器及前端 API，不复用需要机器账号会话的 `/api/admin/player-desk/report/orders`。不得开放重报、登录、取消或处置动作。

## 7. 必须通过的验收断言

- 输入同一业务日的 NORMAL、BOT、未知类型记录：三类报表只呈现/汇总 NORMAL，所有总数和分页总计也不含 BOT/未知类型。
- 积分流水的下注额、已结算净盈亏、单双边有效流水、反水、上下分分别与 BY220 公式对齐；未结注单只影响 BY220 应计入的本金流水，不影响未结结算指标；撤单不进入有效统计。
- 对同一玩家有多注、同机器多个玩家、空档机器及跨子账号数据，玩家明细、机器汇总、全局总计的求和关系一致；切分页不会改变筛选范围总计。
- 飞单的每个 NORMAL 注单在任一筛选下最多出现一次；最新状态决定归组，状态计数与列表 total 一致，BOT/未知身份不能通过详情接口旁路显示。
- 06:00 截点边界、次日 05:59:59.999999 和 06:00:00、自然日模式、开始/结束日期以及夏令时无关的 Asia/Shanghai 转换分别有测试。
- 超管全局/按子账号筛选及子账号自身范围均在后端生效；越权子账号、无 `REPORT_READ`、非法日期、越界分页均被拒绝。
- 接口仅 SELECT/只读事务；打开报表不会创建上报尝试、触发重报、撤单、退分或改变任何中心/钱包余额。

- 积分流水已改为服务端按玩家汇总分页，响应含全筛选范围 summary 和玩家展开明细；明细每类最多返回 200 条，汇总不受明细/当前页上限影响。下注从 `game_bet` 读取；钱包上下分仅把可映射到 BY220 操作的 `ADMIN_GRANT/ADMIN_ADJUST` 计入。`NORMAL` 通过注单/账本身份快照优先于当前账户类型判断，BOT 与身份未知记录排除。
- 盈亏报表已排除 BOT/未知身份，未结注单本金进入流水，取消注单排除；单/双边流水、盈亏和反水复用并按 BY220 样例核对 `BetFlowMetricsCalculator`。昨余按有统计记录机器的普通玩家期初余额合计；无普通玩家统计记录的机器按 BY220 空档分支显示机器积分。不能从账本/历史身份快照恢复的余额返回 `null` 并显示 `--`，不伪装成零。

- 状态映射：无上报行、`NOT_SENT`、`PENDING`→未报；`ACCEPTED`、`SETTLED` 及中心明确取消/退款的已报结果→已飞单；`REJECTED`、`TIMEOUT`、由失败/超时重试耗尽的 `MANUAL`→失败。失败自动退单后已标记为 `CANCELED` 且 `REFUNDED` 的订单排除（BY220 会物理删除）；未知恢复错误状态不强行归类。
- 未新增 Flyway 迁移、报表事实表或真实外部上游调用。构建刷新了 Spring Boot 静态前端资源；其哈希资源属于本次构建输出。
