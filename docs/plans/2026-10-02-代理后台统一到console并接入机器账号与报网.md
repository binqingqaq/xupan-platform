## 2. 身份与范围设计（按 BY220 入口区分）

| 登录身份 | 角色/权限 | `/console` 可见范围 | 上下分 | 机器级配置 |
| --- | --- | --- | --- | --- |
| **机器账号**（BY220 `x_robot`） | `AGENT` + `AGENT_CONSOLE_READ` + `AGENT_PLAYER_MANAGE` + 新增 `AGENT_MACHINE_CONFIG` | **仅自己机器名下**玩家/托（`agent_id = 自己`） | 联动代理积分 | 可改自己机器（赔率/特码赔率/特码返水/单边双边/封盘/取消/限额/报网/线路/显示控制） |
| **平台管理员**（BY220 `x_admin.type=1`） | `ADMIN` 全权限 | **全局**（等价 `admin.php` 的玩家/订单视角），并可按机器下钻 | 直接调整玩家钱包（不扣机器积分），保留审计 | 通过超级后台"机器管理"设定；`/console` 顶部只读展示当前机器的值 |
| **子账号**（BY220 `x_admin.type=0`） | `SUB_ACCOUNT` | 自己 `agent_group` 下的机器与其玩家（报表已按 group 隔离；本次把玩家/机器查询也纳入） | 直接调整（同 ADMIN），保留审计 | 通过超级后台"机器管理"设定 |

要点：

- 平台直属玩家（`agent_id = PLATFORM_DIRECT`）**机器账号看不到**，只有 ADMIN/子账号能看；这与 BY220"机器只看自己名下"一致。
- 机器账号登录后固定在自己机器上下文，不提供机器切换；ADMIN/子账号提供机器选择器。
- 所有机器级配置修改都写 `sys_operation_log`（操作人、机器、字段、前后值摘要）。

## 5. 报网状态机与本地模拟适配器（合规强制）

```text
下注（本地事务完成）
  -> report_status = UNREPORTED
  -> 若 report_online=1 且 report_auto=1 且 report_type != 无
       -> 适配器（本地模拟）返回 接受 / 拒绝 / 超时
       -> REPORTED | FAILED | TIMEOUT
  -> FAILED 且 report_withdraw=1
       -> 复用撤单路径：事务内物理删除注单 + 幂等退款 + 审计 + 聊天室取消反馈
  -> FAILED 且 report_withdraw=0 / TIMEOUT
       -> 保留注单并标记，等待人工处理或后续重试（不自动退款）
```

- 适配器接口 `ReportAdapter`：`submit(BetSnapshot) -> ACCEPTED | REJECTED | TIMEOUT`。首发只实现 `LocalReportAdapter`（**不发任何网络请求**，按配置与可注入的确定性规则返回结果，便于测试）。
- 真实外部上游、中心上游、第二层账本**不在本次范围**；适配器留接口，不接实现。
- 页面字段对齐 `robot.php`：报网类型、设置账号、退出/登录、在线状态、自动上报网盘、失败自动退单、超时订单数、押注、网盘余额、刷新。

## 9. 风险与处置

| 风险 | 处置 |
| --- | --- |
| 存量玩家全部归属 `PLATFORM_DIRECT`，机器账号登录后看不到任何玩家 | 这是 BY220 语义；验收时用本机新建机器账号（`localadmin`）创建玩家；同时在验收记录里写明存量玩家的可见性 |
| `/console` 放开 `AGENT` 角色后可能越权访问全局接口 | 服务层强制 `agent_id` 过滤 + 逐接口越权测试；`/api/admin/reports/**`、机器管理、子账号等仍要求管理员权限 |
| 报网字段容易越界成"真实外部接入" | 只实现内部持久化 + 本地模拟适配器；不发起网络请求、不存真实凭据；真实上游一律另行评审 |
| 失败退单退款与撤单并发 | 复用撤单同一事务与幂等键（`CANCEL_REFUND:<betId>`），重复请求不重复退款 |
| 文档再次走偏 | 本次范围变更已写入 [需求基线](../需求基线/2026-10-02-代理后台统一到console与机器账号收敛.md)，并同步修改所有把 `robot.php` 指向 `/agent` 的文档；后续 Agent 必须以此为准 |
| 子账号在部分超级后台菜单无 group 范围校验（子任务发现） | 记录为独立待办，不在本计划内擅自扩大范围 |
