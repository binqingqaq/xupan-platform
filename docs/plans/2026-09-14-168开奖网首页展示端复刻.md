# 168开奖网首页展示端复刻实施计划

> **给实施者：** 按阶段和任务顺序执行本计划。每个任务完成后先通过本任务验收，再进入下一任务。步骤使用复选框（`- [ ]`）跟踪进度。

**目标：** 在当前 `xupan-platform` 中新增一个只面向桌面端的公开展示首页，复刻 `https://16894913.com/` 首页的主要布局、静态内容、鼠标交互和页面状态，并为后续接入当前项目后端保留清晰的数据边界。

**架构：** 第一阶段在现有 `web/` Vue 工程内新增独立的 `/display` 展示路由，使用本地静态数据渲染页面，不改变 `/room` 用户页和 `/admin` 管理后台。页面完成视觉验收并经用户确认展示字段、数据来源和更新方式后，再设计公开只读接口；接口路径和响应结构在确认前均为候选，不作为已确定契约。展示端不调用管理 API，也不抓取参考站点接口。

**技术栈：** Vue 3、TypeScript、Vite、Vue Router、现有 Spring Boot 4.0.8、Java 21、MySQL 8.4 LTS、Flyway；前端测试使用现有 Vitest，页面验收使用桌面浏览器截图和 DOM 检查。

## 分析结论与方案决策

- 可行性：可行。桌面首页可以先使用静态演示数据完成高还原度复刻，鼠标悬停、下拉菜单、轮播、标签切换、展开收起和本地倒计时均可由前端完成。
- 后端时机：不要求第一阶段先实现完整后端交互；但要先确定稳定的数据类型和数据源接口，使 mock 数据可以替换为公开 API。
- 复用方式：展示端与当前 `/room`、`/admin` 保持独立页面和权限边界，共用当前项目后端和数据库，不新建重复后台。
- 第一入口：使用 `/display`，不改变当前 `/`、`/room` 和 `/admin` 行为；后续独立部署需求出现时优先抽离展示端前端，后端仍可共用。
- 业务边界：不复制参考站点后台、真实数据、第三方接口、第三方投注入口或未确认多彩种规则；只接入当前项目确认过的公开展示数据。
- 当前状态：本轮只完成分析和文档方案，未修改业务代码，未新增接口，未执行页面实现。

## 全局约束

- 当前需求只新增桌面端展示首页；移动端页面和 `m.` 子域名适配在桌面端验收通过后另立阶段。
- 汇博盈页面复刻需求继续保留，与本计划并行，不得删除、覆盖或改写为本计划的目标。
- 参考站点只作为视觉、结构和交互参考，不复制其源代码、静态资源、真实数据、账号、外部接口、第三方链接或未确认的业务规则。
- 首页第一阶段使用静态演示数据；静态数据必须集中在数据文件中，不能散落在 Vue 模板和事件处理函数内。
- 页面交互与业务交互分开：菜单、悬停、轮播、标签、展开收起属于前端交互；开奖、投注、余额、登录和实时数据属于后端业务，第一阶段不实现。
- 任何预先提出的 API 路径、响应字段、数据库结构和实时协议都只是候选方案；在静态页面评审前不得实现或视为已确认需求。
- 展示端必须使用独立路由和组件；现有 `/room`、`/admin`、`/admin/users`、`/admin/robots` 路由和权限行为不能被破坏。
- 展示端未来只允许访问公开只读数据，不得直接访问 `/api/admin/**`、钱包写入、开奖控制或机器人管理接口。
- 当前工作区已有未提交的前端、文档和静态构建产物改动；实施时先检查 `git status`，只修改本计划列出的文件，不回退或覆盖其他改动。
- 完成每个阶段后运行对应的类型检查、单元测试或浏览器验收；提交时使用中文或中英文结合的 Git 提交信息。
