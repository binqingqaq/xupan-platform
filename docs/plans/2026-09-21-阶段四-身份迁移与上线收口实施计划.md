# 阶段四：身份迁移与上线收口实施计划

> **给实施者：** 本阶段只在阶段一至三通过后执行，负责把新身份、链接认证和软删除收口到可交付状态，并区分测试环境、本机 MySQL、服务器和生产证据。

**目标：** 完成旧玩家身份数据迁移、管理员/普通玩家/托的认证模式核对、真实数据库验证、运行态验收、备份恢复演练记录和最终交付文档。

**架构：** 采用可前向修复的 Flyway 迁移和分批校验；先备份并统计，再迁移身份映射，最后开启链接认证入口。任何无法回滚的字段改写必须先保留兼容字段和迁移报告。

**技术栈：** Java 21、Spring Boot 4.0.8、MySQL 8.4 LTS、Flyway、H2、Vue 3、Vite、Vitest、PowerShell、Git。

## 全局约束

- 本阶段不把 H2 测试结果写成 MySQL、服务器或生产结果。
- 迁移前必须确认工作区、数据库备份、Flyway 当前版本和应用停止窗口。
- 不在命令、日志、文档、Git 或聊天中输出数据库密码、Token、完整链接和私钥。
- `PLAYER_FULL` 权限边界必须在迁移后继续成立；链接玩家可以使用完整 `/room` 的游戏、虚拟钱包和聊天能力，但不能访问后台、用户管理或机器人管理权限。旧 `CHAT_ONLY` 仅保留兼容范围。
- 余额、下注、开奖、中奖、流水和结算仍然只表示虚拟积分，本阶段不扩大产品资金边界。
- 迁移脚本必须可重复识别已完成记录；失败后可通过前向修复继续，不使用破坏性回滚覆盖用户数据。
- 生产配置与 `docs/本地环境密钥.md` 不进入 Git。
