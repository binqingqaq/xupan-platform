# 阶段四：身份迁移与上线收口实施计划

> **给实施者：** 本阶段只在阶段一至三通过后执行，负责把新身份、链接认证和软删除收口到可交付状态，并区分测试环境、本机 MySQL、服务器和生产证据。

**目标：** 完成旧玩家身份数据迁移、管理员/普通玩家/托的认证模式核对、真实数据库验证、运行态验收、备份恢复演练记录和最终交付文档。

**架构：** 采用可前向修复的 Flyway 迁移和分批校验；先备份并统计，再迁移身份映射，最后开启链接认证入口。任何无法回滚的字段改写必须先保留兼容字段和迁移报告。

**技术栈：** Java 21、Spring Boot 4.0.8、MySQL 8.4 LTS、Flyway、H2、Vue 3、Vite、Vitest、PowerShell、Git。

## 全局约束

- 本阶段不把 H2 测试结果写成 MySQL、服务器或生产结果。
- 迁移前必须确认工作区、数据库备份、Flyway 当前版本和应用停止窗口。
- 不在命令、日志、文档、Git 或聊天中输出数据库密码、Token、完整链接和私钥。
- `CHAT_ONLY` 权限边界必须在迁移后继续成立；链接玩家不能因身份迁移获得后台、下注、钱包或机器人权限。
- 余额、下注、开奖、中奖、流水和结算仍然只表示虚拟积分，本阶段不扩大产品资金边界。
- 迁移脚本必须可重复识别已完成记录；失败后可通过前向修复继续，不使用破坏性回滚覆盖用户数据。
- 生产配置与 `docs/本地环境密钥.md` 不进入 Git。

## 文件边界

- 修改：`docs/项目方案.md`、`docs/项目记忆.md`、`docs/文档索引.md`
- 新建：`docs/验收记录/2026-09-21-玩家身份模型与聊天室链接登录验收记录.md`
- 新建或维护：阶段一至三使用的 Flyway migration、迁移校验测试和运行脚本
- 测试：后端全量测试、前端全量测试和运行态检查

## 任务 1：建立迁移前清单和数据库备份证据

- [ ] **步骤 1：检查 Git 范围。**

运行：`git status --short; git diff --check`

预期：只识别本阶段允许的文档、迁移、测试和代码；用户已有无关改动不被覆盖。

- [ ] **步骤 2：检查 Flyway 版本。**

运行：`.\mvnw.cmd -pl server/xupan-server -DskipTests package`

预期：构建成功，迁移文件命名连续且应用启动时能被 Flyway 识别。

- [ ] **步骤 3：在授权的 MySQL 8.4 环境执行备份。** 使用本机密钥文件读取应用账号，不把凭据写入命令历史；记录备份时间、数据库版本、迁移版本和备份文件校验值。
- [ ] **步骤 4：形成迁移前统计。** 统计用户总数、普通玩家数、托数、已有 `user_code` 数、已删除数、已有登录会话数和历史流水关联数；统计结果只写数量，不写凭据或完整链接。

## 任务 2：执行身份映射迁移和一致性校验

- [ ] **步骤 1：在 H2 执行完整迁移。**

运行：`.\mvnw.cmd -pl server/xupan-server test`

预期：Flyway、Repository、认证、聊天、玩家和钱包测试全部通过。

- [ ] **步骤 2：在 MySQL 8.4 执行迁移。** 启动应用或使用受控迁移命令，确认 `V18`、`V19`、`V20` 版本状态为成功；记录退出码和迁移摘要。
- [ ] **步骤 3：执行一致性查询。** 检查：

```sql
SELECT COUNT(*) FROM sys_user WHERE internal_code IS NULL OR internal_code NOT LIKE 'wxid_%';
SELECT COUNT(*) FROM demo_user_account WHERE member_code IS NULL OR member_code NOT LIKE 'v%';
SELECT COUNT(*) FROM demo_user_account a JOIN sys_user u ON u.id = a.sys_user_id
 WHERE a.display_name <> u.display_name;
SELECT COUNT(*) FROM player_access_link l JOIN sys_user u ON u.id = l.user_id
 WHERE u.status = 'DELETED' AND l.revoked_at IS NULL;
```

预期：第一、第二、第四条为 `0`；第三条只允许有明确记录的历史同步差异，并在验收记录中解释。
- [ ] **步骤 4：执行兼容查询。** 用旧 `user_code` 查询钱包、流水、下注和玩家详情，确认历史数据仍能通过旧接口访问；用新 `internalCode/memberCode` 查询后台列表和详情。
- [ ] **步骤 5：执行前向修复检查。** 模拟一次应用重启和重复迁移，确认不重复生成编号、不重复创建链接、不改变历史流水。

## 任务 3：执行本机运行态验收

- [ ] **步骤 1：启动后端和前端。** 确认 Java 21、MySQL 8.4、本机端口和健康响应，记录地址和进程信息，不记录凭据。
- [ ] **步骤 2：管理员验收。** 使用已有管理员密码登录 `/admin`，确认统一后台、玩家工作台、用户管理和服务端机器人入口仍按权限显示。
- [ ] **步骤 3：身份验收。** 创建一个普通玩家和一个托，确认列表显示 `@v数字.昵称`，详情显示 `wxid`、会员 ID、昵称，编号刷新后不改变。
- [ ] **步骤 4：链接验收。** 为普通玩家生成链接，在独立浏览器上下文兑换，确认只能进入聊天室；分别请求后台、下注、钱包和机器人接口，确认均被拒绝。
- [ ] **步骤 5：托验收。** 确认托没有人工登录链接，自动/手动行为、每期下注、消息和流水仍沿用原有服务端链路。
- [ ] **步骤 6：删除验收。** 删除普通玩家和托，确认提示信息完整；删除后链接、会话、下注和托行为失效，历史记录仍可查。
- [ ] **步骤 7：窄屏验收。** 使用 `375px` 检查统一后台、玩家列表、详情、身份信息和确认弹窗无页面级横向滚动。

运行：`npm run test:run && npm run typecheck && npm run build`

预期：全部退出码为 `0`，构建资源与版本记录一致。

- [ ] **步骤 2：运行后端全量验证。**

运行：`.\mvnw.cmd test`

预期：全部测试通过，失败项必须修复或在验收记录中标为未通过，不能用“计划完成”代替。

- [ ] **步骤 3：执行敏感信息扫描。** 检查 Git diff、构建资源、文档和日志中不存在密码、Token、私钥、完整登录链接和未脱敏外部地址。
- [ ] **步骤 4：更新 `docs/项目方案.md` 和 `docs/项目记忆.md`。** 只写已经由测试或运行态证据证明的内容；把服务器和生产未执行项明确标记为未验证。
- [ ] **步骤 5：写验收记录。** 按静态检查、H2、本机 MySQL、本机浏览器、服务器现场、生产验证六类证据记录结果、命令、时间和边界。
- [ ] **步骤 6：检查 Git diff 并提交。**

建议提交信息：

```text
test: 完成玩家身份与链接登录上线收口
```

提交正文必须说明身份迁移、权限矩阵、软删除、测试范围和未执行的环境验证。

## 阶段验收标准

- 数据库中每个玩家都有唯一 `wxid_...` 和 `v数字` 会员 ID。
- 管理员密码登录、普通玩家链接登录、托服务端行为三条身份链路互不越权。
- 链接玩家只能聊天，删除或撤销后立即失效。
- 历史下注、流水、聊天和审计数据保留且可按身份查询。
- Flyway、H2、MySQL 8.4、本机运行态和浏览器验收证据分层记录。
- Git 中没有密钥、完整链接、Token、日志、构建临时目录或无关用户改动。
