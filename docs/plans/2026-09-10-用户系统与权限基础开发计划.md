# 用户系统与权限基础开发计划

> **给实施者：** 本计划只执行总方案的第一阶段“用户身份与登录会话基础”。按任务顺序完成数据库、领域代码、认证接口、安全配置和测试后，才能进入聊天室 REST、WebSocket 或机器人阶段。

> **本轮执行状态（2026-09-10）：** 认证基础阶段已完成，V1 至 V7、登录/刷新/退出、会话撤销、权限默认拒绝、WebSocket 票据和审计均已通过 H2/Flyway 与 MySQL 8.4 验证。虚拟余额钱包属于独立后续计划，已在 `2026-09-10-虚拟余额钱包与管理员分配开发计划.md` 中完成；本计划不包含聊天室消息、WebSocket 实时聊天和常驻机器人。

**目标：** 为 `xupan-platform` 建立真实用户身份、密码登录、可撤销会话、角色权限、账号状态、登录审计和基础安全边界，使后续每条聊天消息都能绑定到可信的服务端用户。

**架构：** 使用 Spring Security 处理请求认证和方法级授权；使用 Spring JDBC + Flyway 管理用户、角色、权限、会话和审计数据。访问令牌采用安全随机生成的短时不透明令牌，数据库只保存哈希；刷新令牌使用 HttpOnly Cookie。首期支持单实例 MySQL/H2，保留 Redis 会话适配边界，但本计划不实现 Redis、多实例广播、聊天室消息和机器人。

**技术栈：** Java 21、Spring Boot 4.0.8、Spring Security、Spring JDBC、Flyway、MySQL 8.4 LTS、H2 测试、JUnit、MockMvc。

## 2. 固定设计决策

### 2.1 身份和令牌

- 用户登录名使用 `sys_user.username`，昵称使用 `display_name`；两者不能混用。
- 登录成功后生成两个不同的随机值：访问令牌和刷新令牌。
- 访问令牌使用 `SecureRandom` 生成至少 32 字节随机数据，编码为 Base64 URL-safe 字符串，有效期默认 30 分钟。
- 刷新令牌使用至少 48 字节随机数据，写入 HttpOnly、Secure、SameSite 受控 Cookie，有效期默认 30 天。
- 数据库只保存访问令牌和刷新令牌的 SHA-256 哈希，不保存令牌原文。
- REST 请求从 `Authorization: Bearer <access-token>` 读取访问令牌；缺失、格式错误、过期、撤销或用户状态异常均返回未认证。
- 第一版不引入 JWT 依赖，不把角色和权限快照编码进令牌；权限从数据库/会话上下文重新解析。
- 权限或账号状态变化时提升 `sys_user.security_version` 并撤销该用户的现有会话，旧令牌立即失效。

### 2.2 密码和锁定

- 使用 Spring Security `BCryptPasswordEncoder`。
- 密码长度限制为 8 至 72 个字符，至少包含一个字母和一个数字；前后空白不自动裁剪后再作为密码使用。
- 同一用户名连续 5 次密码失败后锁定 15 分钟；成功登录清零失败计数。
- 账号状态为 `DISABLED`、`LOCKED` 或 `DELETED` 时不能登录；`locked_until` 到期后由服务端允许重新尝试，但仍需记录状态变化。
- 登录错误对客户端统一返回 `AUTH_INVALID_CREDENTIALS`，不暴露账号不存在、密码错误或内部状态差异；内部原因写入 `sys_login_log.failure_code`。

### 2.3 角色和权限

首期内置角色和权限编码固定为：

| 角色 | 权限编码 |
| --- | --- |
| `USER` | `CHAT_ROOM_READ`、`CHAT_MESSAGE_SEND`、`GAME_CURRENT_READ`、`GAME_BET_PLACE` |
| `MODERATOR` | `CHAT_MESSAGE_REVIEW`、`CHAT_MESSAGE_RECALL`、`CHAT_USER_MUTE`、`CHAT_USER_KICK` |
| `OPERATOR` | `GAME_CURRENT_READ`、`GAME_ODDS_READ`、`GAME_ODDS_WRITE`、`ROBOT_READ`、`ROBOT_WRITE`、`ROBOT_TEMPLATE_WRITE` |
| `ADMIN` | 继承并拥有本阶段全部 17 个权限编码，后续新增高风险权限也必须显式写入角色权限表 |

权限使用 `GrantedAuthority` 格式 `PERM_<permission_code>`；角色只用于聚合权限，Controller 不直接依赖前端传入的角色名称。`ADMIN` 不通过代码硬编码绕过所有审计，管理员操作仍写入 `sys_operation_log`。

### 2.4 初始管理员

- 不在 Flyway SQL 中写入默认管理员密码或固定 BCrypt 哈希。
- 增加 `BootstrapAdminRunner`，仅当 `sys_user` 为空且配置同时提供管理员用户名和密码时创建首个 `ADMIN` 用户。
- 配置键使用 `xupan.auth.bootstrap-admin.username` 和 `xupan.auth.bootstrap-admin.password`，生产值通过外部环境变量或本地密钥文件注入。
- 初始化成功后只记录用户名和结果，不记录密码；已有用户时不覆盖、不重置、不创建第二个管理员。
- 测试 profile 使用独立测试配置或测试初始化 SQL，禁止把生产密码写入 `application.yaml`。

### 3.1 `V5__创建用户角色权限表.sql`

实现以下表和约束：

```sql
CREATE TABLE sys_user (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(64) NOT NULL,
    display_name VARCHAR(128) NOT NULL,
    avatar_key VARCHAR(255) NULL,
    password_hash VARCHAR(255) NOT NULL,
    status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
    failed_login_count INT NOT NULL DEFAULT 0,
    locked_until TIMESTAMP NULL,
    security_version BIGINT NOT NULL DEFAULT 0,
    last_login_at TIMESTAMP NULL,
    last_login_ip VARCHAR(128) NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_sys_user_username UNIQUE (username),
    CONSTRAINT ck_sys_user_status CHECK (status IN ('ACTIVE', 'DISABLED', 'LOCKED', 'DELETED')),
    CONSTRAINT ck_sys_user_failed_login_count CHECK (failed_login_count >= 0)
);

CREATE TABLE sys_role (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    role_code VARCHAR(64) NOT NULL,
    display_name VARCHAR(128) NOT NULL,
    status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
    description VARCHAR(255) NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_sys_role_code UNIQUE (role_code),
    CONSTRAINT ck_sys_role_status CHECK (status IN ('ACTIVE', 'DISABLED'))
);

CREATE TABLE sys_permission (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    permission_code VARCHAR(128) NOT NULL,
    display_name VARCHAR(128) NOT NULL,
    resource_type VARCHAR(16) NOT NULL DEFAULT 'ACTION',
    status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
    description VARCHAR(255) NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_sys_permission_code UNIQUE (permission_code),
    CONSTRAINT ck_sys_permission_type CHECK (resource_type IN ('API', 'ACTION', 'MENU')),
    CONSTRAINT ck_sys_permission_status CHECK (status IN ('ACTIVE', 'DISABLED'))
);

CREATE TABLE sys_user_role (
    user_id BIGINT NOT NULL,
    role_id BIGINT NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id, role_id),
    CONSTRAINT fk_sys_user_role_user FOREIGN KEY (user_id) REFERENCES sys_user(id),
    CONSTRAINT fk_sys_user_role_role FOREIGN KEY (role_id) REFERENCES sys_role(id)
);

CREATE TABLE sys_role_permission (
    role_id BIGINT NOT NULL,
    permission_id BIGINT NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (role_id, permission_id),
    CONSTRAINT fk_sys_role_permission_role FOREIGN KEY (role_id) REFERENCES sys_role(id),
    CONSTRAINT fk_sys_role_permission_permission FOREIGN KEY (permission_id) REFERENCES sys_permission(id)
);

CREATE INDEX idx_sys_user_status ON sys_user (status, id);
CREATE INDEX idx_sys_user_role_role ON sys_user_role (role_id, user_id);
CREATE INDEX idx_sys_role_permission_permission ON sys_role_permission (permission_id, role_id);
```

迁移还要插入四个角色和以下 17 个权限编码：`CHAT_ROOM_READ`、`CHAT_MESSAGE_SEND`、`GAME_CURRENT_READ`、`GAME_BET_PLACE`、`CHAT_MESSAGE_REVIEW`、`CHAT_MESSAGE_RECALL`、`CHAT_USER_MUTE`、`CHAT_USER_KICK`、`GAME_ODDS_READ`、`GAME_ODDS_WRITE`、`ROBOT_READ`、`ROBOT_WRITE`、`ROBOT_TEMPLATE_WRITE`、`USER_MANAGE`、`ROLE_MANAGE`、`PERMISSION_MANAGE`、`AUDIT_READ`。`MODERATOR` 绑定 `USER` 的 4 个权限和聊天治理 4 个权限，`OPERATOR` 绑定游戏和机器人 6 个权限，`ADMIN` 绑定全部 17 个权限。使用 `INSERT ... WHERE NOT EXISTS` 或固定唯一键保证测试重复启动不会产生重复种子数据。迁移不插入任何用户密码。

实现以下表：

```sql
CREATE TABLE auth_session (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    session_id VARCHAR(64) NOT NULL,
    user_id BIGINT NOT NULL,
    access_token_hash CHAR(64) NOT NULL,
    access_expires_at TIMESTAMP NOT NULL,
    refresh_token_hash CHAR(64) NOT NULL,
    refresh_expires_at TIMESTAMP NOT NULL,
    device_label VARCHAR(128) NULL,
    ip_digest CHAR(64) NULL,
    user_agent_digest CHAR(64) NULL,
    last_seen_at TIMESTAMP NULL,
    revoked_at TIMESTAMP NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_auth_session_id UNIQUE (session_id),
    CONSTRAINT uk_auth_session_access_hash UNIQUE (access_token_hash),
    CONSTRAINT uk_auth_session_refresh_hash UNIQUE (refresh_token_hash),
    CONSTRAINT fk_auth_session_user FOREIGN KEY (user_id) REFERENCES sys_user(id)
);

CREATE TABLE auth_ws_ticket (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    ticket_hash CHAR(64) NOT NULL,
    user_id BIGINT NOT NULL,
    session_id VARCHAR(64) NOT NULL,
    room_code VARCHAR(64) NULL,
    expires_at TIMESTAMP NOT NULL,
    used_at TIMESTAMP NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_auth_ws_ticket_hash UNIQUE (ticket_hash),
    CONSTRAINT fk_auth_ws_ticket_user FOREIGN KEY (user_id) REFERENCES sys_user(id),
    CONSTRAINT fk_auth_ws_ticket_session FOREIGN KEY (session_id) REFERENCES auth_session(session_id)
);

CREATE TABLE sys_login_log (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    username_snapshot VARCHAR(64) NOT NULL,
    user_id BIGINT NULL,
    result VARCHAR(24) NOT NULL,
    failure_code VARCHAR(64) NULL,
    ip_digest CHAR(64) NULL,
    user_agent_digest CHAR(64) NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_sys_login_log_user FOREIGN KEY (user_id) REFERENCES sys_user(id),
    CONSTRAINT ck_sys_login_log_result CHECK (result IN ('SUCCESS', 'FAILURE', 'LOGOUT', 'REVOKED'))
);

CREATE TABLE sys_operation_log (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    operator_user_id BIGINT NULL,
    permission_code VARCHAR(128) NULL,
    http_method VARCHAR(16) NOT NULL,
    request_path VARCHAR(255) NOT NULL,
    resource_id VARCHAR(128) NULL,
    result VARCHAR(16) NOT NULL,
    error_code VARCHAR(64) NULL,
    request_summary VARCHAR(2000) NULL,
    ip_digest CHAR(64) NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_sys_operation_log_user FOREIGN KEY (operator_user_id) REFERENCES sys_user(id),
    CONSTRAINT ck_sys_operation_log_result CHECK (result IN ('SUCCESS', 'FAILURE'))
);

CREATE INDEX idx_auth_session_user ON auth_session (user_id, revoked_at, refresh_expires_at);
CREATE INDEX idx_auth_session_access_expiry ON auth_session (access_expires_at, revoked_at);
CREATE INDEX idx_auth_ws_ticket_expiry ON auth_ws_ticket (expires_at, used_at);
CREATE INDEX idx_sys_login_log_user ON sys_login_log (user_id, id);
CREATE INDEX idx_sys_login_log_created ON sys_login_log (created_at, id);
CREATE INDEX idx_sys_operation_log_operator ON sys_operation_log (operator_user_id, id);
CREATE INDEX idx_sys_operation_log_created ON sys_operation_log (created_at, id);
```

`auth_ws_ticket` 属于本阶段认证基础，WebSocket 连接处理本身不在本阶段实现。票据生成、查询和一次性消费接口必须先完成，后续 WebSocket Handler 直接调用，不在 URL 中传递访问令牌。

### 4.2 领域对象职责

#### `UserAccount`

保存用户数据库字段和状态方法：

```java
public record UserAccount(
        long id,
        String username,
        String displayName,
        String avatarKey,
        String passwordHash,
        String status,
        int failedLoginCount,
        Instant lockedUntil,
        long securityVersion,
        Instant lastLoginAt,
        String lastLoginIp) {

    public boolean canLogin(Instant now) { /* status and lockedUntil check */ }
}
```

禁止在 `UserAccount` 中保存明文密码、访问令牌、刷新令牌或权限修改方法。

#### `AuthenticatedUser`

实现 Spring Security `UserDetails`，至少暴露 `userId`、`username`、`displayName`、`securityVersion` 和 `GrantedAuthority`。`getPassword()` 返回数据库密码哈希只供认证流程使用，不允许被 Controller 序列化。

#### `SessionRecord`

保存会话 ID、用户 ID、令牌哈希、签发时 `securityVersion`、过期时间、撤销时间和最后访问时间。提供 `isAccessTokenValid(now, userSecurityVersion)` 和 `isRefreshTokenValid(now)` 判断，但不保存令牌原文。

### 4.3 Repository 方法契约

`UserRepository` 至少提供：

```java
Optional<UserAccount> findByUsername(String username);
Optional<UserAccount> findById(long userId);
Optional<UserAccount> findByIdForUpdate(long userId);
long insert(String username, String displayName, String passwordHash, String status);
void recordLoginFailure(long userId, Instant lockedUntil);
void clearLoginFailures(long userId, String loginIp, Instant loginAt);
void incrementSecurityVersion(long userId);
boolean existsAnyUser();
```

`findByIdForUpdate` 只能在事务中调用，用于登录失败次数和会话撤销的并发保护。SQL 必须显式列出字段，不使用 `SELECT *`。

`SessionRepository` 至少提供：

```java
void insert(SessionRecord session);
Optional<SessionRecord> findByAccessTokenHash(String tokenHash);
Optional<SessionRecord> findByRefreshTokenHash(String tokenHash);
void rotateTokens(String sessionId, String accessHash, Instant accessExpires,
                  String refreshHash, Instant refreshExpires);
void revoke(String sessionId, Instant revokedAt);
void revokeAllByUserId(long userId, Instant revokedAt);
void touch(String sessionId, Instant lastSeenAt);
```

`revoke` 和 `revokeAllByUserId` 必须重复执行安全；刷新令牌轮换必须在一个事务中完成，旧刷新令牌不能再次使用。

### 4.4 Service 方法契约

`PasswordPolicyService`：

```java
void validateForCreation(String rawPassword);
boolean matches(String rawPassword, String encodedPassword);
boolean shouldLock(int failedCount);
Instant lockUntil(Instant now);
```

`PermissionService`：

```java
Set<String> findPermissionCodes(long userId);
Set<GrantedAuthority> toAuthorities(Set<String> permissionCodes);
boolean hasPermission(long userId, String permissionCode);
```

只查询状态为 `ACTIVE` 的角色和权限；禁用角色或权限不产生 authority。

`TokenService`：

```java
IssuedTokens issue(long userId, String deviceLabel, RequestMetadata metadata);
IssuedTokens refresh(String rawRefreshToken, RequestMetadata metadata);
void revoke(String sessionId);
WsTicket issueWsTicket(long userId, String sessionId, String roomCode);
WsTicket consumeWsTicket(String rawTicket);
```

`IssuedTokens` 不记录 Token 日志；`WsTicket` 只返回一次给调用方，消费后 `used_at` 非空即失效。

`AuthenticationService`：

```java
LoginResult login(String username, String rawPassword, RequestMetadata metadata);
CurrentUser currentUser(long userId);
void logout(long userId, String sessionId);
```

登录流程必须使用事务：加载并锁定用户、校验状态和密码、更新失败计数或最后登录信息、生成会话、写登录日志。密码失败也要写日志，但不能在异常中返回明文数据库信息。

## 5. HTTP 接口契约

### 5.1 `POST /api/auth/login`

请求：

```json
{
  "username": "demo-user",
  "password": "Password123",
  "deviceLabel": "Chrome Windows"
}
```

成功响应 `200`：

```json
{
  "accessToken": "short-lived-opaque-token",
  "expiresIn": 1800,
  "user": {
    "id": 1,
    "username": "demo-user",
    "displayName": "演示用户",
    "avatarKey": null,
    "roles": ["USER"],
    "permissions": ["CHAT_ROOM_READ", "CHAT_MESSAGE_SEND"]
  }
}
```

同时设置刷新 Cookie。响应体、日志和异常不能返回 `refreshToken`。

失败响应：

- `401 AUTH_INVALID_CREDENTIALS`：用户名不存在、密码错误、账号停用/删除或账号仍在锁定窗口内，客户端统一返回以避免账号状态枚举；具体内部原因写入登录审计。
- 当前阶段未实现独立的 `429 AUTH_LOGIN_RATE_LIMITED` 限流响应；分布式登录限流属于 Redis 上线阶段能力。

### 5.2 其他认证接口

| 方法 | 路径 | 成功 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/api/auth/refresh` | `200` | 从 HttpOnly Cookie 读取刷新令牌，轮换访问/刷新令牌 |
| `POST` | `/api/auth/logout` | `204` | 撤销当前会话并清除刷新 Cookie，重复退出仍返回 `204` |
| `GET` | `/api/auth/me` | `200` | 返回当前用户、角色和权限 |
| `POST` | `/api/auth/ws-ticket` | `200` | 返回 60 秒有效、只能使用一次的 WebSocket 票据 |

`/api/auth/refresh`、`/api/auth/logout` 和 `/api/auth/ws-ticket` 的错误必须使用统一 JSON 错误结构：

```json
{
  "code": "AUTH_TOKEN_REVOKED",
  "message": "认证状态已失效",
  "requestId": "server-generated-request-id"
}
```

`requestId` 可用于日志关联，但不能包含 Token、密码或用户敏感信息。

### 5.3 Security 放行和权限规则

修改 `SecurityConfig.java` 后固定为：

```java
http
    .csrf(csrf -> csrf.disable())
    .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
    .authorizeHttpRequests(auth -> auth
        .requestMatchers("/", "/index.html", "/assets/**").permitAll()
        .requestMatchers("/api/auth/login", "/api/auth/refresh", "/actuator/health").permitAll()
        .requestMatchers("/api/auth/logout", "/api/auth/me", "/api/auth/ws-ticket").authenticated()
        .anyRequest().authenticated())
    .addFilterBefore(bearerTokenAuthenticationFilter,
        UsernamePasswordAuthenticationFilter.class);
```

当前 `/api/demo/**` 的匿名放行必须删除。阶段一为了兼容现有演示页面，可以保留 `/api/demo/game/current` 的认证访问，但不能继续全部 `permitAll`；后台开奖、赔率和余额接口至少要求 `OPERATOR` 或 `ADMIN` authority。若现有演示测试依赖匿名访问，必须修改测试先登录并携带 Bearer Token，不得降低安全规则。

## 9. 完成后移交给下一阶段的接口

本阶段完成后，下一阶段聊天开发只依赖以下稳定能力：

- `AuthenticationService.currentUser()`：取得服务端当前用户；
- `PermissionService.hasPermission(userId, permissionCode)`：判断聊天发送和治理权限；
- `TokenService.consumeWsTicket(rawTicket)`：WebSocket 首帧完成身份认证；
- `UserRepository.findById(userId)`：取得展示名称和头像快照；
- `sys_operation_log`：记录聊天撤回、禁言和机器人配置等高风险操作。

下一阶段不得重新设计用户表、重复实现密码登录或从前端昵称建立聊天身份。聊天消息、WebSocket Handler 和机器人调度只能消费本计划的认证接口。

## 10. 风险和处理顺序

1. **现有演示接口原先匿名可用：** 先修改测试使用登录 Token，再收紧 SecurityConfig，避免为了保住旧测试重新放开接口。
2. **演示账户与正式用户不是同一实体：** 认证阶段不强行绑定余额；下一阶段通过 `V8` 把现有演示账户表兼容为正式用户的虚拟钱包，不接入真实支付资金。
3. **H2 与 MySQL 约束差异：** H2 只做快速集成检查，MySQL 8.4 必须另行验证 CHECK、时间字段、外键和索引。
4. **初始化管理员密码风险：** 不用默认账号和迁移哈希，使用外部配置的一次性 bootstrap，并在生产部署记录执行结果。
5. **多实例尚未启用 Redis：** 本阶段只完成可撤销会话接口和适配边界；正式多实例上线前必须实现 Redis SessionStore、限流、广播和调度锁。
