## 4. 阅读约定

- 所有条目都带 `文件:行号`；行号指向**该条目所在的源码行**。
- §1「仅超管」= 该菜单项位于 `{if $Think.session.user_uid == '1'}` 块内（非超管子账号看不到）；「注释掉」= 被 HTML 注释包裹，当前未启用。
- §1 菜单按**模板行号顺序**（即导航栏真实顺序）排列，不按名称排序；其余各表按名称排序。
- §2「前置鉴权」是**字符串存在性**静态检查，只说明文件里是否出现 `_initialize` / `isLogin(` / `isAdmin(`，**不判断调用路径**，也不等于运行期已验证。
- §2「首行注释」：优先取声明前紧邻的注释块；无注释块时回退到函数体内第一条 `//`（会标注「行注释(函数体内)」）。`—` 表示机械上找不到注释，**不等于**该动作没有注释。
- §4 `db()` / `Db::name()` 引用次数是**静态调用点计数**，不是运行期热度；0 次才说明代码完全不碰该表。
- §7「注释掉」与 §1 同义（被 `<!-- -->` 包裹）。**只看 HTML 注释，不看 JS 的 `//` 行注释**，因此 JS 注释掉的重定向在 §7.3.3 里仍标「否」。
- §7 的行号定位用「扫 `\n` 建字符偏移表 + 二分」，与 §1 的「行长 + 1」累加不同；前者对 CRLF 文件也准确，后者只在 LF 文件上准确（§1 的 BY220 文件实测是 LF，结论未受影响）。
- §7.4「表单/字段线索」三列来源固定：模板控件的 `name` / `id`、JS `data:` 对象字面量的键名、控制器里 `$data['x']` / `param('x')` / `input('get.x')` 的键名。`—` 表示该列对这个名字没有命中，**不等于**它不存在。
- §7.3.5「JS 选择器」原样保留（含 `.a .b`、`.a,#id` 这类复合写法）；用于 DOM 定位时只取**最后一个类名 token**，所以 `—` 只说明「该 token 不是以 `class` 属性出现的」，不代表绑定失效。
- §8「常驻进程」是**源码字符串标记判定**（`swoole_server` / `while(...)` + `sleep` / `->tick(`），不是运行期观察结果，也不代表这些进程当前真的在跑。
- §8.2 的「全仓引用次数」含类名在**自身 `class` 声明处**的那 1 次；因此「1」= 全仓除声明外无引用。

### §7.3 导航/入口结构判定（机械检测）

#### §7.3.1 导航模板检测

- `application/chat/view/**` 下是否有 `head.html`：**无** → 玩家前台**无独立导航模板**
- 判定依据①：`application/chat/view/**` 里名为 `head.html` 的文件数 = **0**（对照：admin 的导航模板是 `application/admin/view/public/head.html`，内含 `<ul uk-navbar-nav>` 与 15 条 `{:url()}` 菜单项）
- 判定依据②：整个 chat 模块（`application/chat/**`）里 `head.html` 的文件数 = **0**
- 判定依据③：chat 模板里 `{include file=...}` 命中 **1** 处、`{extend/layout name=...}` 命中 **0** 处、`{block name=...}` 命中 **0** 处

**结论（机械判定）：玩家前台没有像 admin 那样的导航模板，也不存在「导航菜单」概念。** 依据即上面三条计数；
真正的「导航」是 3 类等价物（都有 `file:line` 证据，见 §7.3.5 / §7.3.6）：
  1. **整页跳转**：`index.html` 里 `$(".changeGame").on("click")` → `window.location.href = url + "?cd=" + cd + "&gid=" + gid`（切彩种就是换一张整页 URL，不是局部路由）；
  2. **页内弹出面板**：`uni-popup left/right/top` 三个绝对定位面板，由 `$(".showGame")` / `$(".uInfo")` / `$("#header")` 三个 DOM 元素 toggle；
  3. **彩种列表**：左侧面板里的 `{volist name="rbgame"}` 循环（这是全模块唯一「像菜单」的列表）。

#### §7.4.6 字段清单的取舍标准（机械口径声明）

1. **只抽「控件能承载的字段」**：`<input>` / `<select>` / `<textarea>` 三种标签，不抽纯展示元素（`<div class="money">` 这类）。
2. **模板属性只取 4 个**：`name` / `id` / `type` / `placeholder`。`index.html` 有 32 个 `id=`，但只有 3 个 `<input>`，全抽 id 会把 CSS/JS 锚点混进字段表。
3. **JS 侧只抽请求体**：只解析 `data:` 指向的对象字面量键名，不解析任意 JS 变量（否则无法机械判定哪些是「字段」）。
4. **控制器侧只抽请求读取**：`$data['x']`、`param('x')`、`input('get.x')` 三种形态；不抽数据库列名（那属于 §4）。
5. **不做人工改名/合并**：`qiuIndex` 与 `qiu` 不会合并，`van-field-N-input` 这种前端框架自动 id 也照收，因为「BY220 里叫什么」本身就是对齐依据。

# 抽取过程中踩到的坑（人工维护）

> 这些是「机械抽取为什么不能想当然」的具体证据，做缺口表前必须知道。

## K1 菜单区不能按裸串 `uk-navbar-nav` 定位
`application/admin/view/public/head.html` 里 `uk-navbar-nav` 同时出现在 `<style>` 的 CSS 选择器中
（第 27、36、46、60、64、68、81、105、109、113 行），真正的导航元素在第 172 行。
第一版脚本按裸串匹配，把导航区起点误判为第 27 行。
现改为匹配 `<ul[^>]*uk-navbar-nav` 元素本身，实测定位到 `head.html:172-193`。

## K2 超管块的闭合标签写在 HTML 注释里
`head.html:180` 打开 `{if $Think.session.user_uid == '1'}`，而它的闭合标签是 `head.html:189` 的 **`<!--{/if}-->`**。
`head.html:182`、`185`（两条被注释掉的菜单）里也各有一个 `class="{if ...}uk-active{/if}"` 形态的 `{/if}`。
若只按「哪一行同时含 `{/if}` 和 `<!--`」发提示，会对 182/185 行误报。
现改为按 `{if}`/`{/if}` 配对栈逐 token 计算，并只在该 `{/if}` **自身字符位置**落在注释内时才提示 → 现在只对第 189 行提示。

## K3 有两条菜单被整行 HTML 注释掉
- `head.html:182` 飞单 → `{:url('sub/flyer')}`（注释掉）
- `head.html:185` 日志 → `{:url('changed/loglist')}`（注释掉）

配套证据：`application/admin/view/sub/flyer.html` 全文只有 2 行（89 字节），
内容是 `{include file='public/head'}` + `location.replace("{:url('sub/index')}")`，
即「飞单」在模板层已经被改成跳回子账号列表的占位页；而 `Sub::flyer`（`Sub.php:37`）和
`Changed::loglist`（`Changed.php:26`）两个控制器动作**仍然存在且可达**。
→ 缺口表里这两项要按「控制器存在 / 菜单未启用」分别记录，不能因为有动作就算已对齐。

## K4 `menuli*` DOM id 大量重复
`menuli9` 出现 2 次（176、182）、`menuli11` 2 次（177、183）、`menuli13` **4 次**（185、186、187、188）；
另外 186/187/188 三行的 `<a>` 都叫 `id="menu14"`。
平移前端时**不能**照抄这些 id，否则 DOM 选择器会命中多项。

## K5 `db('admin')` 与表 `x_admin` 的前缀关系
代码里全是 `db('admin')`、`db('rbuser')`、`db('record')`，而 schema 里的表名是 `x_admin`、`x_rbuser`、`x_record`。
前缀定义在 `application/database.php:13` 的 `'prefix' => 'x_'`。
不知道这一层，就会误判成「代码引用的 34 张表在 schema 里都不存在」。
（另注：`application/config.php:196` 也有一个 `'prefix' => 'by220_'`，那是缓存/会话键前缀，**不是**数据库表前缀。）

## K6 schema 文件路径与任务描述不一致
任务描述里写 `sql/schema-base.sql`，实际该目录不存在；真实路径是 `local/schema-base.sql`
（另有 `local/seed-base.sql` 与 `local/migrations/*.sql`）。脚本已按候选路径参数化，不写死。

## K7 schema 里有 6 处疑似 SQL 语法缺陷（未实测）
`local/schema-base.sql` 中下列列定义行以**双逗号**结尾：第 167（`x_game`）、332（`x_rbfly`）、
361（`x_rbgame`）、406（`x_rbuser`）、560（`x_robot`）、667（`x_config`）行；
并且第 671 行 `x_config.errMsg` 后缺逗号、直接接 `PRIMARY KEY`。
按 MySQL 语法这应当直接报 1064。
**本 lane 未用 MySQL 实际导入验证**，因此只能记为「疑似缺陷，需实机确认」，
不能据此宣布「BY220 的 schema 导不进去」。

## K8 迁移脚本新建了一张 schema 里没有的表
`local/migrations/20261001_room_feed_visibility.sql:4` 建的是 `x_record_feed_backup_20261001`，
不在 `local/schema-base.sql` 内。所以「schema 有 34 张表」**不等于**「运行期有 34 张表」，至少是 **35 张**。

## K9 备份/副本文件与源码混放
`application/admin/controller/` 下同时存在 `Index.php`、`Index.php.bak`、`Login.php`、`Login.php_LctL3.tar.gz`；
`application/rbt/controller/` 下有 `Index.php`、`Index.php.bak`；
模板目录里有大量 `.html.bak`、`.html_*.tar.gz`、` - 副本 (1).html`、`web.1html`。

admin 控制器 15 个文件里只有 **13** 个是真 `.php`；`application/rbt/view` 8 个条目里只有 **7** 个是 `.html`。

## K10 `Logi888n.php` 是旧版弱登录 + 免密登录后门（**安全**）
`application/admin/controller/Logi888n.php` 文件名是故意拼错的，但**类名与 `Login.php` 相同**（都声明 `class Login`）：

- `Logi888n.php:21 check()` 用 `md5(md5($password))` 校验（旧弱哈希），而加固版 `Login.php:30` 用 `password_verify`；
- `Logi888n.php:47 imdex()` **完全不需要密码**：直接 `Admin::get(['id' => 1])` 取超级管理员并把
  `user_id` / `user_info` / `user_uid` 写进 session（`Logi888n.php:50-56`）。

`url_convert => true`（`application/config.php:104`）且 `application/route.php` 没有为它设置任何路由，
因此该控制器是**按默认控制器/动作规则可达**的（形如 `/admin.php/logi888n/imdex`）。
它写入的 `user_info` 不含 `login_token`，会被 `Base::isAdmin()`（`Base.php:44`）拒绝，
但只调用 `isLogin()` 的控制器（如 `Index`）不会拦住它。
→ **平移时必须把 `Logi888n.php` 判定为「不得平移的遗留后门」，而不是一个待对齐的页面。**

## K11 `Gd.php` 完全没有登录校验（**安全**）
`application/admin/controller/Gd.php:9` 直接 `class Gd extends think\Controller`，
既没有 `_initialize()`，也没有 `isLogin()` / `isAdmin()`，是整个 admin 目录里唯一这样的控制器。
因此 `/admin.php/gd/index`、`/admin.php/gd/getUnCalculate`、`/admin.php/gd/userDels` 都**没有登录校验**。

`Logi888n.php` 同样没有 `_initialize`。

## K12 大量动作是 ajax 端点，页面动作与接口动作同名空间
例如 `Tongji.php` 一个控制器里 `index`/`ShowDetail` 是页面，`GetYingKui`/`GetWay2Data`/`UpdateFanTanS` 是 ajax。

`Rb::addEdit`（`Rb.php:32`）、`Game::addEdit`（`Game.php:21`）都叫 `addEdit`。
→ 缺口表的主键必须是 `控制器::动作`，不能只用动作名。

## K13 admin 与 rbt 的登录体系不同（同一业务两个入口）
- admin：`Base.php` 用 `USER_ID` 常量 + `login_token`（`password_verify` + `session_regenerate_id`）。
- rbt：`application/rbt/controller/Login.php` 有 `login2` / `check2` / `check3` / `logout2` 四个 public 动作，
  且 `application/rbt/view/login/login2.html` 有 **104,056 字节 / 2,765 行**，与本项目 `AGENTS.md` 里

## K14 同一个脚本里不能再假设「行长度 + 1」= 行首偏移

## K15 对象字面量不能按 `[^{}]*` 取

## K30 `Add-Line '文本' + (...)` 会被 PowerShell 静默吃掉后半段（**本轮真实踩到**）
`Add-Line` 的签名是 `param([string]$Text = '')`。在**参数模式**下写
`Add-Line '前缀 ' + (CodeSpan 'x') + ' 后缀'`，PowerShell **不做字符串拼接**：
第一个实参 `'前缀 '` 绑到 `$Text`，后面的 `+`、`(CodeSpan ...)`、`' 后缀'` 是**额外实参并被静默丢弃**。
症状不是报错，而是**输出行只剩第一个片段**：补抽 §7 时
「§7.3.3 表头」变成 `| 模板:行号 | `、「§7.3.4 入口链」8 条全部只剩 `  1. `～`  8. `。
→ **所有多段拼接必须写成 `Add-Line ('文本' + ...)`**（脚本里已有 21 处因此被修正）。
新增输出代码时必须自查：`Add-Line` 之后紧跟单引号字面量、且这一行里有 ` + ` 的，一律要加外层括号。

## K31 PowerShell 变量名大小写不敏感，局部变量会覆盖同名参数

## K32 过滤 XML 命名空间时，不能拿「只有协议」的匹配值去比 host
§7.5 第一版写的是：
`[regex]::Matches($raw, 'wss?://|https?://')`，然后 `if ($m.Value -match '^https?://(www\.)?w3\.org') { continue }`。
`$m.Value` 只等于 `http://`（正则没捕获 host），这个判断**永远为假**，
于是模板里 29 处 `xmlns="http://www.w3.org/2000/svg"` 全被算成「硬编码外部地址」。
现改为 `(?i)\b(wss?|https?)://([A-Za-z0-9.\-]*)`，把 host 一起捕获再判断。
→ 副作用是好的：host 捕获为空正好标识「只写了协议、主机运行时拼接」，
于是 §7.5 才能机械区分出「`index.html` 拼本机 `:9998`」与「4 份 index 变体写死外部 `wss://` 主机」这件事。

## K33 `BIND_MODULE` 在源码里是带引号的常量名
§8.3 第一版按 `BIND_MODULE\s*,\s*['"]admin['"]` 匹配，结果 `admin.php` / `robot.php` 的模块列全是 `—`。
实际源码是 `define('BIND_MODULE','admin');`（`public/admin.php:7`、`public/robot.php:9`）
—— **常量名本身在引号里**，`BIND_MODULE` 后面先有一个 `'` 再是 `,`。

本轮 §8.3（K33）与 §7.4.2（K15）都是这个形态。
