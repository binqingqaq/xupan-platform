## 1. 目标概述

Xupan 在同一套应用中同时运行代理端和中心上游。代理仍在 /console 使用机器账号管理玩家和下注；代理在报网区域使用超级管理员分配的中心账号登录。订单满足“中心账号在线 + 自动上报开启”后，由 Xupan 后端把已受理的玩家订单交给同一应用内的中心订单服务。中心服务返回受理、拒绝或待核实结果，代理端显示回执。超级管理员管理中心账号、额度和订单，并在开奖后台逐球设置开奖结果；开奖结果确认后，系统使用同一期、同一份结果结算本地玩家订单和中心订单。

中心上游在业务体验上承担 BY220 外部网盘的位置，接收代理提交的订单并返回处理状态；在技术上它是 Xupan 内部业务服务，不连接真实第三方，不调用外部网盘地址，也不拆成第二个服务部署。

“不经过 HTTP”在本文特指代理报单服务到中心上游服务的订单通路不发起外部 HTTP 请求，而是在同一应用进程内调用中心服务。浏览器访问 Xupan 页面仍使用正常的前后端应用接口。

## 2. 已确认的业务决定

以下决定来自使用者 2026-10-23 确认，作为本评审稿的已确认输入：

| 主题 | 已确认规则 |
| --- | --- |
| 中心上游运营者 | 只有超级管理员能创建、管理中心账号和额度，管理中心订单，并控制开奖结果。 |
| 账号归属 | 超级管理员创建中心账号时，选择归属的代理子账号。一个子账号下多个机器账号可以使用该中心账号；不同子账号之间不得共用。 |
| 账号有效期 | 创建时默认有效 7 天；管理员可以自定义到期时间；到期后可续期，也可提前续期；不再使用的账号可删除。 |
| 代理登录 | 代理使用后台分配的中心账号登录报网区域。密码校验成功且账号未停用、未过期时，登录状态显示在线。 |
| 自动报单 | 在线状态和“自动上报”开关必须同时开启才自动上报，沿用 BY220 的两个独立条件。 |
| 额度 | 中心账号额度由超级管理员分配。创建中心账号时设置初始额度。额度全部是虚拟积分。 |
| 代理端形态 | 代理报网流程以 BY220 为第一参考，包括账号登录、在线状态、自动上报开关、订单发送结果、押注/余额查看和失败处理；Xupan 中心服务替代 BY220 外部网盘的接单位置。 |
| 开奖 | 超级管理员需要能够控制指定期号的单个球开奖结果；中心结算使用管理后台确认后的开奖结果。 |
| 开发阶段 | 当前仍处于开发阶段。为达成已审核的闭环，允许重构数据库结构、迁移和代码，也允许清理或重建仅用于开发的旧数据；不得为了兼容旧开发数据而保留错误业务模型。 |

项目金额只表示虚拟积分和内部风险额度，不连接充值、支付、提现、现实资金转账或可兑换资产。

本基线对 2026-10-02 之前中心账号以 Token 登录、中心账号与机器直接绑定、报网需网盘编码和盘口线路等细节作出新的用户级调整。旧方案只用于追溯，不覆盖本文已确认的归属、凭据和代理操作规则。BY220 仅作为代理报网流程第一参考；它没有 Xupan 现在要建设的中心接单与第二层结算服务。

## 3. 参与者、身份和范围

| 概念 | 本基线中的含义 |
| --- | --- |
| 超级管理员 | 使用 /platform-admin 管理中心账号、归属子账号、初始额度、有效期、停用/删除、订单、额度流水和开奖。 |
| 代理子账号 | 超级管理员在子账号管理中分配给一个代理负责运营的组织账号；中心账号创建时绑定此子账号。 |
| 机器账号 | 子账号名下的多个 /console 登录账号。机器负责玩家、下注和本机报网开关；名下机器可以共用该子账号关联的中心账号。 |
| 中心账号 | 由超级管理员在 Xupan 内创建的临时登录身份，具有用户名和密码，归属一个代理子账号，并持有管理员分配的虚拟额度。不是外部网盘账号，也不是机器账号的 /console 登录密码。 |
| 玩家订单 | 玩家在代理机器所属站点中成功受理的本地下注订单。玩家钱包和本地订单是第一层业务事实。 |
| 中心订单 | 中心服务收到代理订单后创建的镜像订单，记录来源子账号、来源机器、本地订单号、玩法、期号、投注额、赔率快照、接单结果和结算结果。 |

### 3.1 身份绑定范围

目标关系：

```text
超级管理员创建中心账号
        │ 选择一个代理子账号
        ▼
代理子账号（共享中心账号、额度和有效期）
        ├── 机器账号 A
        ├── 机器账号 B
        └── 机器账号 C
```

中心账号只能绑定一个子账号；该子账号下多个机器发起的订单归入同一个中心账号和额度账本。每一笔中心订单仍保留来源机器、玩家订单号和玩家标识，不能因为共享额度而丢失机器级追踪信息。不同子账号之间的中心账号、余额、押注和订单相互隔离。

每台机器是否分别输入同一中心账号并独立登录，还是子账号登录一次后名下机器全部在线，目前尚未确认。为保留 BY220 的机器级在线语义，本基线暂按“各机器分别登录；中心账号按有效机器会话汇总在线状态”描述，列入第 13 节审核问题。

## 4. 代理端报网区域

代理端仍在机器账号登录后的 /console 使用报网区域。目标操作顺序如下：

1. 超级管理员已为该代理子账号创建并绑定中心账号。
2. 机器在报网区域显示所属子账号、中心账号标识和有效期；代理使用分配的中心账号密码登录。
3. Xupan 校验中心账号、密码、状态、有效期和机器所属子账号。校验成功后建立该机器的报网登录态，界面显示在线；校验失败显示原因，不得显示在线。
4. 机器登录在线后，代理勾选“自动上报”。开关只表示本机器是否自动发送，不代表账号已登录或订单已被中心接受。
5. 玩家下注后，系统按 BY220 报网资格和状态判断是否发送。中心返回结果后，机器报网记录显示“已接受”“已拒绝”或“待核实”，并可查看返回说明。
6. 代理可退出中心账号。退出后该机器不再自动发送新订单，但已接受订单仍须保留并按最终开奖结果结算。

代理端应保留与 BY220 对应的核心状态区：报网账号/登录动作、在线状态、自动上报开关、当前中心可用额度、当前押注或未结金额、上报结果统计、订单记录和可重试失败单。金额字段可以使用更准确的“中心可用额度”“中心押注/未结金额”，不应把 Xupan 内部额度伪装成真实网盘余额。

中心路径不要求代理选择网盘类型、网盘站点、盘口线路 A/B/C/D 或填写外部网盘账号。Xupan 当前兼容字段是否保留在数据库属于实现选择，不得继续要求代理为中心报单填写外部线路信息。

### 4.1 在线状态

“在线”表示该机器已通过中心账号身份校验，并有一条有效报网登录态。它不表示自动上报已打开、没有失败订单或中心已有订单。

中心管理端至少能查看中心账号状态、所属子账号、到期时间、最近登录时间、在线机器数及各机器在线/离线状态。机器登出、会话失效、账号停用或过期后，该机器不得继续产生新的中心上报。

### 4.2 自动上报状态

报单资格至少同时满足：

    机器所属子账号存在有效中心账号
    AND 机器已通过中心账号登录且在线
    AND 该机器的自动上报开关为开启
    AND 玩家订单符合 BY220 报网资格且尚未封盘/取消

未满足条件时，玩家本地下注是否成功由本地下注规则决定；报网状态说明未发送原因，不能将“未发送”伪装为中心拒绝或中心超时。

BY220 对普通玩家、托、特殊玩法和彩种存在具体报网分支差异，必须以 BY220 梳理文档及相应源码规则逐项映射。不能假定所有玩家、所有玩法都可报。

### 4.3 代理可见的余额、押注和状态

| 显示项 | 业务含义 |
| --- | --- |
| 中心可用额度 | 当前中心账号可用于新订单的虚拟额度。多个机器共用同一中心账号时，此值是共享值。 |
| 中心押注/未结金额 | 中心已接受、尚未按最终开奖结果结算的中心订单投注额汇总；应能按期号、机器和订单下钻。它不是玩家余额，也不等于所有本地下注总额。 |
| 冻结额度 | 中心已接受订单暂时占用的额度。管理后台可显示；代理端可并入“押注/未结”说明，不得把冻结额重复计入可用额度。 |
| 已上报 | 中心已确认接受，能查到唯一中心订单号及受理时间。 |
| 已拒绝 | 中心已明确确认不受理，显示拒绝原因；与状态未知区分。 |
| 待核实/超时 | 本地没有获得可证明的最终接受或拒绝结果。不能因此自动退还、删除订单或按新订单号重报。 |

BY220 模板中的“超时”默认文本不等于真实动态统计。Xupan 应根据未确认订单事实计算数字；同进程服务正常时，网络超时不是日常状态。若内部调用中断、事务结果暂不可确认或处理超过阈值，应显示“待核实”，并使用同一幂等订单号查询/恢复。

## 5. 从玩家下注到中心接单

### 5.1 下注与本地订单

玩家先按 Xupan 本地规则完成下注解析、期号/封盘/玩法/限额/余额校验。通过后产生本地玩家订单并扣减玩家虚拟积分。报网是该订单之后的一条上游处理链，不能把“中心接受”当作玩家下注成功的唯一依据，也不能重复扣玩家余额。

每次发往中心的请求至少包含可追踪的来源子账号、机器账号、本地订单唯一号、彩种/游戏、期号、玩法、号码/参数、投注额、赔率快照和结算规则快照。不能由浏览器自行指定中心账号 ID 或覆盖机器与子账号归属。

### 5.2 中心接单和回执

中心收到调用后，按顺序确认：

1. 机器仍属于请求中的代理子账号，且该子账号绑定中心账号。
2. 中心账号启用、未过期，机器报网会话有效。
3. 彩种、期号、玩法、选号、赔率、投注额和期号状态合法。
4. 同一来源订单是否已处理；重复请求必须返回首次结果，不能重复冻结额度或新增订单。
5. 可用额度和超级管理员设定的中心风险限额是否足够。

校验通过，中心创建 ACCEPTED 订单、写额度流水，并返回中心订单编号及接受状态。中心按账号实时汇总已接受未结投注。校验失败，中心保存可审计的 REJECTED 结果及原因并回给代理。代理页面仍通过 Xupan 正常应用接口操作；代理报单服务到中心的调用本身是同进程调用。

### 5.3 成功、失败和未知结果

| 中心结果 | 代理端展示 | 本地订单处理 |
| --- | --- | --- |
| 明确接受 | 已接受、中心单号、受理时间 | 保留本地订单；等待开奖和第一层结算。中心订单进入对应期号的待结算列表。 |
| 明确拒绝 | 已拒绝、原因和时间 | 是否返还玩家本金由代理“失败退单”开关决定；无论是否退还，都留下订单状态/取消记录供对账。 |
| 处理中或结果未知 | 待核实，不显示成失败 | 不自动退款、不物理删除、不生成新业务单号；后端按同一幂等键查询或恢复处理。 |
| 机器离线或自动开关关闭 | 未发送及具体原因 | 不创建中心订单，不冒充中心拒单；本地订单继续按本地规则处理。 |

BY220 有“失败退单”开关：明确报单失败且开关开启时退还玩家积分并取消本地订单；关闭时保留本地订单并可重试。Xupan 如保留这一交互，必须严格区分“中心明确拒绝”和“结果未知”。目标实现应以可查的取消/退款流水保留事实，不能为模仿 BY220 而删除审计记录。

人工重试仅针对可重试的明确拒绝或未完成请求。对已接受订单重试时必须返回原中心订单及首次结果，不可再次占额度。代理端是否继续保留 BY220 的手动“重报”按钮，见第 13 节待审核。

## 6. 额度和账本口径

中心账号额度是虚拟积分，不是现实资金。玩家钱包和中心账号额度是两套账：

    第一层：玩家下注扣玩家虚拟积分；本地开奖后向玩家结算。
    第二层：代理报单占用代理中心账号额度；同一已确认开奖结果后，中心结算代理与中心之间的镜像订单。

一笔玩家下注不会把玩家钱包余额复制成中心账号余额，也不会再扣一次玩家积分。玩家钱包按本地游戏结果结算一次；中心账号记录代理侧的虚拟积分净输赢，不再次给玩家加分。中心额度变化由中心账本记录，不由代理浏览器直接改余额。

### 6.1 额度展示

初始额度在中心账号创建时由超级管理员设定，并作为账号初始可用额度入账。超级管理员可追加/调整额度，填写原因并产生可查询流水。中心订单受理时可用额度减少、冻结额度增加；结算时释放风险冻结并按实际净输赢更新对应账本。后台应分开显示：

- 可用额度：还能支持新订单的额度。
- 冻结额度：当前已接受、尚未出最终结果的订单占用额。
- 未结押注：以订单为准的当前已接受未结投注汇总。
- 已结算流水：订单输赢、返还、变更前后额度。

管理员设置的“账号额度”是中心侧可用虚拟积分。为避免已接受订单结算时无额度，接受订单时冻结该订单可能产生的最大净赔付风险，而不只是冻结投注本金。若中心可用额度不足，先占用报单机器自己的代理积分 `agent.score` 补足风险冻结；两者合计仍不足时拒绝受理。此处不扣玩家钱包 `demo_balance_ledger`，也不扣多个机器共用的子账号积分 `agent_group.score`。

### 6.2 输赢的业务方向

中心接收的是代理机器提交的同一笔下注镜像。中心订单输赢依照同一个已确认开奖和订单赔率快照计算，不能由代理在代理端自行声明结算输赢。结果分为中奖、未中奖、平局/流局或经授权取消。

已确认的账务方向按代理净输赢处理，不把玩家派彩总额再从中心账户扣一次：玩家下注时本地已扣本金；中奖时本地玩家拿回本金加奖金，中心账户只承担净赢额；未中奖时玩家不再收回本金，该本金计入中心账户；平局/流局时本地退回本金，中心额度不产生输赢。中心接单时对可能产生的最大净赔付做风险冻结，开奖结果确认后按实际净输赢释放或入账。

例：中心可用额度 10,000；玩家余额 1,000；下注 100，赔率 1.95，净赢额 95。接单后玩家余额为 900；中心冻结 95，可用额度为 9,905。若玩家中奖，本地向玩家加 195，玩家余额变为 1,095；中心消耗冻结的 95，结算后可用额度仍为 9,905。若玩家未中奖，玩家余额保持 900；中心释放冻结 95 并将输掉的本金 100 计入中心可用额度，结算后为 10,100。若平局/流局，玩家退回 100，余额回到 1,000；中心释放冻结额度，结算后仍为 10,000。

以上口径已由用户确认。BY220 有本地玩家输赢积分结算和失败退单，但没有与当前 Xupan 中心账号相同的中心额度账本，不能据 BY220 确定中心账方向。当前 Xupan 的 `CenterSettlementService` 使用另一种“冻结投注本金后按现有中心/代理输赢口径处理”的实现，与本基线确认的净输赢及 `agent.score` 补足规则不同；后续实现必须按本基线调整，不能沿用现有公式。

## 7. 完整示例：玩家下注到最终结算

### 7.1 配置

超级管理员创建中心账号 C-A，绑定子账号“代理甲”，设置初始可用额度 10,000 虚拟积分，到期日默认为创建时间后 7 天。机器 M01、M02 属于代理甲，均使用 C-A；订单仍各自标记来源机器。假设每台机器单独登录，M01 登录成功后中心总览显示“在线机器 1/2”，M02 登录后显示“在线机器 2/2”。

代理在 M01 的报网区域登录 C-A，校验成功后 M01 在线。代理打开自动上报开关。登录和开关是两个独立状态；两者都开启后，M01 才会自动提交符合 BY220 报网资格的订单。

### 7.2 正常接受并中奖

玩家小林本地积分 1,000，在 M01 对当前期 Q1001 的第 3 球单双玩法下注 100，赔率快照为 1.95。开奖结果由超级管理员把第 3 球设为 08（偶数）并确认。

1. 本地下注校验通过，玩家积分先从 1,000 扣到 900，Xupan 保存本地订单 B1001。
2. 在线和自动上报均开启，报单服务以 B1001 的稳定来源号调用内部中心服务。
3. 中心检查代理甲账号、机器归属、期号、玩法、赔率、投注额、可用额度和重复请求。
4. 中心接受并创建中心订单 C1001；按已确认规则，95 的最大净赔付风险从可用额度转入冻结额度。中心显示可用 9,905、冻结风险 95、当前押注 100。中心回执返回“已接受”，代理报网列表关联本地 B1001 和中心 C1001。
5. 超级管理员确认 Q1001 开奖结果，中心按 C1001 中的玩法、赔率快照计算中奖。玩家第一层收到本金 100 + 净赢 95，玩家积分变为 1,095；中心第二层按同一结果结算代理净输赢。若中奖，中心消耗冻结风险 95；冻结和本期未结押注归零。
6. 玩家本地订单、代理报网状态、中心订单、中心额度流水和开奖快照均能互相查到。重复触发结算不会重复入账。

### 7.3 正常接受但未中奖

若开奖结果为 07（单数），中心 C1001 先处于已接受/待开奖；开奖确认后结算为未中奖。玩家积分仍为 900；中心释放冻结的 95 风险并把输掉的 100 本金计入中心可用额度，结算后可用额度为 10,100，押注/未结金额归零。代理可查看玩法、金额、结果、结算时间和中心额度流水。

### 7.4 机器未登录或自动上报关闭

若 M01 未登录、中心账号已过期，或自动上报关闭，B1001 不发送到中心，因此中心没有 C1001，也不占中心额度。页面显示“未发送/未登录/自动上报关闭”的具体状态；本地下注是否保留并参与本地开奖按本地下注流程和失败退单设置处理。

### 7.5 中心明确拒绝

若中心账号额度不足或该期已停止接单，中心返回明确拒绝码并留存拒绝单。代理报网状态显示“拒绝 + 原因”，押注额不增加，可用额度不变。

- 失败退单开启：本地玩家下注本金按一次性流水返还，订单标记为已取消/已退，不参加后续本地结算。
- 失败退单关闭：本地订单保留为报网失败，可按规则重试；中心接受之前没有中心订单进入中心开奖结算。

开启失败退单不得把未知结果当作明确拒绝；退款后应保留原注单/取消关系和审计流水。

### 7.6 内部处理未能确认结果

同进程调用通常没有网络超时，但仍可能遇到服务异常或事务结果需要核实。此时本地显示“待核实”，玩家本金不自动返还，注单不删除。恢复任务用同一中心幂等号查询或重放；若中心已接单就回填首次接受结果，若确认没有接单，才可进入重试或拒绝处理。不得用新订单号盲目重报。

### 7.7 账号到期、续期或删除

账号到期后，所有使用它的新登录和新报单停止；已经被中心接受的订单不删除、不退回，也不因账号到期跳过开奖结算。管理员续期后，代理按规则重新登录，之后可以继续报单。

管理员删除不再使用的账号时，执行物理删除，清除该中心账号及归属中心域的机器会话、中心报网尝试、中心订单（包括已接受、已结算订单）、中心额度流水、风控命中和订单处置记录，并解除关联机器的中心账号绑定和中心报网配置。删除后这些中心侧订单不可再查询或参与中心结算；该删除是管理员明确删除账号及关联中心业务数据的结果，不等同于订单正常退款或结算。

删除边界：不删除代理子账号、机器账号、机器用户、玩家账号或玩家原始 `game_bet`/玩家钱包流水；玩家原始注单仍按本地开奖记录完成本地结算。不得删除其他子账号、机器或无关业务记录。中心账号物理删除不隐含删除操作审计；审计记录保留账号名、子账号、操作者、操作原因和清理数量，不含密码或令牌。机器积分曾为中心订单写入的风险冻结/释放流水属于独立机器账务事实：保留流水、金额、余额前后值和机器积分，不补发释放或冲销；只把 `reference_type/reference_id` 从中心订单改为 `CENTER_ACCOUNT_DELETED/<center_agent_id>`，使其不再关联被删除订单。中心账号关联报网尝试需保存 `center_agent_id`；迁移只回填能由中心订单直接证明归属的历史记录，同一注单关联多个中心账号或无法证明归属的旧记录不得猜测。删除前若该子账号当前仍有无法归属的 `CENTER` 报网记录，拒绝删除并要求先核对。删除账号的最后一组中心报网尝试后，保留玩家注单并标记为不再自动报送，避免新中心账号把旧注单重新上报；本地结算不受影响。

## 8. 超级管理员中心上游管理

中心上游管理位于 /platform-admin，只有超级管理员可执行写操作。建议提供以下业务区域：

### 8.1 中心账号

列表至少显示账号标识、绑定子账号、账号状态、在线状态、有效期、初始/当前额度、可用/冻结/押注金额、在线机器数、最后登录和创建时间。

创建账号时填写账号名、初始密码或由系统生成的一次性密码、绑定子账号、初始虚拟额度和到期时间（默认 7 天）。创建成功后凭据只显示一次；后续管理员不可读取原密码，只能重置。重置后旧密码和相关报网会话立即失效。允许管理员提前续期、延长到期时间、停用、恢复或删除/撤销。

### 8.2 中心订单和额度流水

中心订单列表支持按中心账号/子账号、机器、玩家本地订单号、中心订单号、游戏、期号、状态和时间查询。详情显示来源、投注内容、赔率快照、投注额、中心接收/拒绝回执、每次处理时间、开奖结果和结算账。

额度流水至少区分初始发放、追加/调整、订单冻结、订单释放、订单输赢、取消/退回和管理员操作；每笔记录操作人、原因、关联订单/期号、幂等标识和变更前后余额。重试、重结算或页面重复点击不能重复发放或扣减额度。

### 8.3 开奖控制与结算

超级管理员在现有开奖信息/开奖历史业务面选择彩种/游戏和期号，可按球号逐个设置开奖结果。球号和值必须符合该游戏配置范围；每次修改都记录操作人、修改前后值和时间。所有必需球号齐全后，管理员确认该期最终开奖结果。

确认开奖结果后，建议系统以唯一的“游戏 + 期号 + 开奖版本”触发本地玩家结算和同一期所有已接受中心订单结算。中心只结算 ACCEPTED 订单；拒绝、未发送和仍待核实订单不得冒充已接受中心单参与第二层结算。结算记录保存采用的开奖结果快照和赔率快照。

BY220 有开奖历史查询、补期和强制结算入口；Xupan 当前开奖历史可查看开奖结果、补入整组 8 球并强制结算。本需求额外要求单球编辑/控制。开奖结果确认后的改号会影响已发生的玩家和中心账务，不能直接覆盖号码并静默重算；必须先定义受控修正、反向流水和重新结算规则，具体权限和确认门槛列为待审核。

### 8.4 登录在线和风险状态

中心管理端能查看账号分配给哪个子账号、哪些机器登录、最后登录时间、过期/停用情况和报单汇总。超级管理员可停用账号或重置凭据。停用/过期应立即阻止新订单，不破坏已接受订单结算。

## 9. 订单和账号状态

中心订单至少区分：

    未发送（本地状态） -> 待中心处理 -> 已接受 -> 已结算
                                      ├-> 已拒绝
                                      ├-> 待核实（结果未知）
                                      └-> 经授权取消/退款

本地订单结算状态与中心报单状态是两条关联但不同的状态链。某笔本地订单可以尚未本地结算但中心已接受；中心明确拒绝时，本地订单也可能继续保留并参与本地开奖（失败退单关闭时）。中心账号在线、自动上报开启、订单被中心接受、开奖结果确认、订单结算完成，分别是不同事实。

中心账号状态至少为有效、已停用、已过期、已撤销/删除。账号在线状态来自机器登录会话，不等于账号有效状态；账号有效但无人登录时仍是离线。

## 12. 开发期数据和技术约束

- 不要求保留旧开发期间中心 Token、中心代理绑定、演示额度或旧中心订单的兼容能力。审核通过后可按新目标重构表结构和迁移，并清理/重建开发数据。
- 旧数据清理仅限开发环境并明确操作范围；正式环境数据不得在没有备份、确认和恢复方案时删除。
- 新业务事实必须写入受约束数据库并可审计：中心账号归属、有效期、登录会话、报网尝试、中心订单、额度账本、开奖结果版本、开奖确认状态和结算结果。
- 密码只保存安全哈希；明文只在创建/重置时一次性显示。订单记录不保存密码或可复用凭据。
- 订单接收、额度风险冻结、失败退款、结算和开奖确认必须有明确事务与幂等键。
- 不使用外部 HTTP 上游、真实网盘凭据、真实资金或充值/提现能力。正常的 Xupan 页面 API 不属于外部上游接入。

## 13. 评审问题

以下问题不阻止形成流程稿，但进入开发前需要逐条确认：

1. 一个子账号能创建几个有效中心账号？本文暂以一个子账号关联一个有效中心账号描述。若允许多个，机器需要明确选择账号，不能由系统猜测。（对关联一个）

2. 共享账号的登录范围是什么？本文暂按每台机器独立登录相同凭据、中心按有效机器会话显示在线；是否改为代理子账号登录一次后全部机器在线？（每台机器独立登录相同凭据、中心按有效机器会话显示在线）

3. 共享账号展示哪些数据？**已确认：选 A。** 同一子账号下的机器共享中心账号的可用额度和汇总押注；订单明细按机器隔离，每台机器只查看自己上报的订单，不查看同一子账号其他机器的订单明细。

4. 默认 7 天后如何续？到期时间默认创建时间 + 7 天；管理员续期时是明确设置新的到期时间，还是默认再加 7 天并允许修改？（明确设置新的到期时间）

5. 删除的含义是什么？**已确认并实现规则：中心账号和其中心侧关联业务数据物理删除，包括任何状态的中心订单、中心报网尝试、中心额度流水、机器会话、风控命中、订单处置和对账处置，并清除机器的中心账号绑定/中心报网配置。** 不级联删除代理子账号、机器账号、玩家账号、玩家原始注单及玩家钱包流水；本地玩家订单仍照常本地结算。删除不表示中心订单已退款或正常结算。用户选择保留机器账务事实：机器积分余额与 `agent_ledger` 原始金额/余额快照不变；只解除流水到已删除中心订单的引用，并把引用改为删除账号标识。不自动返还尚未释放的机器风险占用。删除操作审计保留。新报网尝试保存中心账号 ID；无法可靠归属的旧 `CENTER` 报网记录不盲删，账号删除会被阻止并要求先核对。若删除了该玩家注单的全部中心报网尝试，该玩家注单仍保留、本地照常结算，并被标记为不再自动报送，防止以后重建中心账号时重复上报。

6. 失败退单是否保留 BY220 开关？**已确认：上报失败需要退还玩家下注积分，按 BY220 保留失败退单开关。** Xupan 的超时/处理中属于结果未知，不立即退款；先用原订单号核实中心是否已受理，确认未受理后再按开关退款，避免中心已有订单而玩家同时拿回下注积分。退单保留原订单及退款流水用于审计，不物理删除订单。

7. 中心结算触发方式？**已确认：选 A。** 超级管理员明确确认开奖结果后，系统自动用该期同一开奖结果结算本地玩家订单和中心已接受订单。开奖历史保留受审计的单期/批量强制结算能力。开奖结果编辑过程中不触发结算。

8. 单球开奖结果何时可以修改？**已确认：开奖阶段可设置某一个球的结果，其余球随机；超级管理员确认整期开奖结果并触发自动结算后，不允许撤回或修改开奖结果，也不进行冲正重结算。**

9. 账号“额度”的余额定义？**已确认：** 玩家本地积分只按游戏结果结算一次；中心额度记录代理净输赢，玩家中奖时中心承担净赢额，玩家未中奖时中心额度增加投注本金，平局/流局不改变中心额度。接单时冻结最大净赔付风险；中心额度不足时由报单机器自己的代理积分 `agent.score` 补足，中心额度与该机器积分合计仍不足时拒绝受理。玩家余额 `demo_balance_ledger` 和子账号共用积分 `agent_group.score` 不作为这笔补足资金。数字示例见第 6.2 节。

10. 中心在线状态展示粒度？管理端是否显示子账号总在线、每台机器在线、最近登录和有效期？代理端是否每台机器看到同一份汇总？

    （按你理解的来）

11. 中心订单撤单/退款后，玩家本地注单怎么处理？**已确认：** 支持两种一次性人工结论：保留本地注单继续结算，或退款给玩家并取消本地注单；两种处理都必须填写原因并记录审计。该动作限定在本机机器范围，不改变中心订单/额度。

## 14. 审核通过后的建议验收闭环

后续实现完成后，至少证明以下业务事实：

1. 超级管理员创建中心账号并绑定代理甲，初始可用额度正确，默认到期时间为 7 天；代理乙不能登录或查看代理甲数据。
2. 代理甲名下 M01、M02 可共用账号；来源机器仍可区分，其他子账号不能使用该账号。
3. 登录密码错误、账号停用、过期和有效登录分别产生正确状态；只有在线且自动上报开启的机器自动发送。
4. 一笔玩家订单只扣一次玩家积分；中心接受后只冻结一次额度；重复请求返回原中心订单。
5. 明确拒绝、失败退单开/关、处理未知、自动恢复和手动重试均不会重复退款、删除必要历史或重复冻结额度。
6. 中心押注/未结只统计接受且尚未结算的订单，按账号、期号、机器和订单可追溯；玩家余额不会与中心额度混用。
7. 管理员逐球录入并确认开奖结果后，本地玩家和中心镜像订单使用相同的期号、结果版本和赔率快照结算；重复执行不会重复结算。
8. 管理员调额度、续期、停用、重置密码、开奖确认前逐球录入/修改和强制结算都有操作者及前后值审计；开奖结果确认后不可修改。
9. 到期后禁止新登录/上报，但已接受中心订单仍可查询和完成结算；物理删除中心账号时，已接受/已结算中心订单随中心账号删除，不再查询或参加中心结算。玩家原始注单和玩家钱包不删除，仍按本地结果结算；其他子账号、机器及其数据不受影响。机器积分和账务流水保持不变，流水对中心订单的结构化引用改为删除账号标识；不对被删除订单自动释放风险占用。删除动作及清理数量保留在操作审计中。无法确认归属的旧报网记录必须先核对，不能按子账号或机器范围盲删。

10. 中心撤单或退款后，代理对自己机器的未结玩家本地注单作一次人工结论：保留本地注单并继续本地结算，或退还玩家下注本金并取消本地注单。必须填写处理原因并保留操作者、时间和审计；退款不得重复，结论不能修改为另一种。该动作限定在机器自身数据范围，不改变中心订单或额度。

本基线已按用户确认进入实施。本文记录的是目标业务决定，不表示未完成的接口、数据库迁移或验收已经实现。
