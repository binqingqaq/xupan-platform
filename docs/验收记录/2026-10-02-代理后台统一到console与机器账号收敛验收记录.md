## 5. 记录在案的差异（必须保留，不得美化）

| 差异 | 说明 |
| --- | --- |
| 报网不接真实上游 | 按用户确认与合规边界，只做内部持久化 + 本地模拟适配器（`LocalReportAdapter`），不发任何网络请求、不保存真实凭据；真实外部上游与中心上游、第二层账本仍不在范围 |
| 上报由独立轮询驱动（不是下注事务内） | **与 objective 原文"同一事务内接入下注链路"有意不同**：核对 BY220 后发现飞单是独立定时轮询（`application/console/Websocket.php:658-673` 的 `Swoole\Timer::tick(2400, ...)`），下注只把订单标为未报，上报与失败退单都在轮询里完成。xupan 照此新增 `ReportDispatchScheduler`（默认 2400ms，`xupan.report.dispatch-interval-ms` 可配）；这样失败退单不会在"刚下注的事务里删掉刚插入的订单"，语义与 BY220 一致。如需改回事务内上报请另行确认 |
| 失败退单 | 照 BY220 `common.php:1627-1641`：`flyers_withdraw=1` 且上报失败时退还玩家本金 + 发"注单取消" + **物理删除注单**；xupan 复用 V55 撤单同一事务与幂等退款路径（`CANCEL_REFUND:<betId>`）+ 审计。BY220 同一列混用"失败/超时"，xupan 拆成 `FAILED`/`TIMEOUT` 以支持超时计数与重报；`TIMEOUT` 一律只标记不退款 |
| 押注 / 网盘余额 | BY220 本地环境登录时就把 `money`/`betting` 写 0（`rbt/Index.php:801-803`），真值只由真实上游返回。本项目不接真实上游，因此 `report_balance` 保持 0（界面标注"本地模拟"），`report_stake` 用"已成功上报的投注额累计"作为可算的本地模拟值 |
| 报网配置完整性校验位置 | `login` 要求配置完整（类型/网盘/盘口/账号）否则 400；`resubmit` 不做完整性前置校验（它就是"再试一次"），配置残缺时由适配器判 `FAILED` |
| 显示控制 | 只落地 BY220 有明确写入点的 `hideMsg`；`dj/kuaisu/ltype` 在源码中没有独立写入点，**不臆造语义** |
| 开放注册 | 本项目没有自助注册业务（玩家由代理创建、凭链接进入），本阶段只落地开关的持久化与展示控制，不新增注册流程 |
| 机器级配置写权限 | 复用 `AGENT_PLAYER_MANAGE` + 范围校验，未单开 `AGENT_MACHINE_CONFIG` 权限码（避免冗余权限） |
| 越权指定机器 | 机器账号显式传别人的 `machineId` 时，`/machine-config` 与 `/report` 统一按 **404 `MACHINE_NOT_FOUND`** 处理（不静默改写目标，也不用 403 暴露别的机器是否存在）；不传时固定操作自己那台（提交 `ccf3afe`） |
| 报网密码加密 | 复用项目既有的 `PlayerLinkTokenCipher`（AES-256-GCM），只加密、从不解密；`report_network.api_key_ciphertext` 目前无读写代码也无专属 cipher，如将来要为报网密码改用独立密钥，需要新增环境变量与 bean（本次未做） |
| 网盘编码校验 | `report_network_code` 只校验长度与格式，**不校验 `report_network` 是否存在或启用**（V56 未建外键）；如需存在性校验会让 `login` 前置多一条依赖，本次未做 |
| 请求体密码字段 | 请求体用 `reportPassword`（非空才覆盖，空值保留原密文），响应只用 `hasPassword` 布尔 |
| 报网整表单替换 | `PUT /machine-config` 与 `PUT /report` 均为整表单替换语义且无乐观锁：两人同改同一台机器会互相覆盖（沿用后端既有语义，本次未加版本号） |
| 子账号机器下拉 | 子账号目前沿用基线只显示"全部机器"，实际走全局配置；`resolveMachineConfigLevel` 已支持"GROUP + 选定机器 → 机器配置"，补下拉即生效 |
| 子账号进 `/console` | 阶段 1 实现范围解析，权限授予在 V56 补齐（`SUB_ACCOUNT` 获得 `AGENT_CONSOLE_READ` 与 `AGENT_PLAYER_MANAGE`） |
| 存量玩家归属 | 存量玩家归属 `PLATFORM_DIRECT`，机器账号看不到需先由超级后台分配机器 |
| 服务器/生产 | 未执行 |
