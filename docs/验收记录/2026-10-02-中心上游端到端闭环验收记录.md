## 1. 闭环判据

《代理报网盘口与结算业务规则说明》§23.10 定义的闭环：

```text
订单已接受 + 开奖已确定 + 玩家已结算 + 代理/上游已结算
+ 流水已写入 + 订单状态已关闭 + 没有超时/退款/对账遗留
```

本次验收逐项核对如下。

| 判据 | 结果 | 证据 |
| --- | --- | --- |
| 订单已接受 | ✅ | 3 笔注单本地 `ACCEPTED`、中心 `ACCEPTED` |
| 开奖已确定 | ✅ | 开奖番 1，号码 `1,2,3,4,5,6,7,8` |
| 玩家已结算（第一层） | ✅ | `WIN/WIN/LOSE`，玩家流水 +770、+385 |
| 代理/上游已结算（第二层） | ✅ | 中心 `SETTLED`，赔出 855、收走 50 |
| 流水已写入 | ✅ | 玩家 `demo_balance_ledger`、中心 `center_agent_ledger`、本地 `agent_ledger` |
| 订单状态已关闭 | ✅ | 玩家注单 `WIN/LOSE`，中心订单 `SETTLED` |
| 无超时遗留 | ✅ | 本地未解决 0、中心未解决 0 |
| 无退款遗留 | ✅ | 本期无退单（3 笔全部受理） |
| 无对账遗留 | ✅ | `balanced=true`，差异 0 |

## 3. 两层账口径自洽性验算

| 项 | 第一层（玩家 ↔ 代理） | 第二层（代理 ↔ 中心） |
| --- | --- | --- |
| 本金 | 350 | 350 |
| 赢家返还 | 1155（含本金） | 855（仅净赔） |
| 输家损失 | 50（本金） | 50（本金归中心） |
| 差额解释 | 300 = 赢的两笔本金回流 | 与第一层净赔部分严格相等 |

验算：
- 第一层：玩家赢返还 = 100×3.85 + 200×3.85 = 385 + 770 = **1155**
- 第二层：中心赔出 = 100×2.85 + 200×2.85 = 285 + 570 = **855**
- 差额 300 = 赢的两笔本金（100 + 200），本金本来就属于玩家，不进"中心赔出"口径 ✅
- 中心可用额度：50000 − 350（接单冻结） + 855（结算赔出） = **50505** ✅

**结论：两层账口径自洽，金额可逐笔验算。**

## 4. 本轮同时修复的缺陷（均为实跑暴露）

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | 代理输时本金被扣两遍 | 资金语义错误 | 结算时不再动可用额度（本金在接单时已离开可用） |
| 2 | 赔率精度契约不一致（`DECIMAL(12,4)` vs 结算侧要求 `scale≤3`） | 整期订单全部结不掉 | 边界处 `normalizeOdds` 归一 |
| 3 | 无法结算的订单抛异常打断整期 | 一期结算整体失败 | 改为跳过留给人工，且不静默赔钱 |
| 4 | 玩法白名单漏 ANGLE/STRICT/POSITIVE、多了不存在的 SPECIAL/FAN_SPECIAL | 合法玩法被误拒 | 从 `PlayType` 枚举派生 |
| 5 | `play_text NOT NULL`（仅 MySQL 暴露） | 代理不传展示文案时 500 | V64 改为可空 |
| 6 | `amount>0 / odds>0` 一刀切 | 拒绝单无法落库，与 §12.4 冲突 | V64 改为只对有效订单成立 |
