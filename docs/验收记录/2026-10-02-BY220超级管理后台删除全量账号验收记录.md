# BY220 超级管理后台删除全量账号验收记录

> 验收日期：2026-10-02
> 对应范围：BY220 `changed/config.html`、`Gd.php::userDels`
> 当前结论：预览和确认契约、事务内软删除、权限与审计已在 H2 验证；本机 MySQL 已迁移并完成非破坏性预览；服务器和生产未验证。

## 1. BY220 行为

- 设置页“删除全量账号”要求输入 `DELETE_ALL_ACCOUNTS`。
- 先预检返回子账号、机器人、玩家/托和飞单数量，再二次确认执行。
- 执行时保留超级管理员和主机器人账号。
- BY220 参考源码中的“清空数据”按钮调用 `index/clearData`，对应 `application/admin/controller/Index.php::cleardata`；该功能后续已由设置验收记录单独完成，不再属于本记录范围。

## 2. xupan 实现

- 新增 `POST /api/admin/settings/delete-all-accounts`，请求体包含 `confirm` 和 `preview`，确认文本固定为 `DELETE_ALL_ACCOUNTS`。
- 预检返回字段保持 BY220 命名：`admins`、`robots`、`players`、`flyers`。
- 执行使用单个数据库事务，软删除全部非保护账号、机器和子账号；保护当前执行超级管理员、系统直属主机器及其绑定账号。
- 玩家/托状态写为 `DELETED`；Flyway V51 扩展玩家状态约束以支持该事实。
- 同步提升用户安全版本并撤销非保护账号会话，写成功审计；不删除钱包、注单、流水和历史审计事实。
- 前端恢复 BY220 操作顺序：输入确认文本、预检、二次确认、执行、刷新设置页。

## 3. 已执行验证

- 后端 H2/Flyway：`316/316` 通过；删除全量账号测试覆盖错误确认、预检、执行、幂等重跑、主机器人保留和当前管理员保留，测试事务回滚，不污染其他用例。
- 前端 Vitest：`30` 个测试文件、`119/119`；设置页专项覆盖预检、确认和执行调用。
- 前端 `typecheck` 和生产构建通过。
