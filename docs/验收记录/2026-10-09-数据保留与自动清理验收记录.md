# 数据保留与自动清理验收记录

> 验收日期：2026-10-09
> 范围：本机代码、H2 与本机 MySQL 8.4；服务器/生产环境未操作。

## 实施结果

- V81 设置聊天室默认保留期为 5 天，并添加清理检索所需索引。迁移已在 H2 全量 Flyway 链和本机 MySQL 8.4 数据库应用；本机数据库当前迁移版本为 V81。
- 新增每日 Asia/Shanghai 03:30 的互斥清理任务，按每表批次与轮数上限分段执行，配置默认值为聊天 5 天、登录日志 180 天、操作审计 365 天、玩家/代理账本与已结注单 1095 天。
- 聊天和机器人动作只清理超期且已完成/无待处理引用的记录；旧未派发机器人事件不再补发。待处理、处理中、失败重试与未结算记录保护。
- 已结 WIN/DRAW/LOSE 注单与相关改单、玩家钱包流水按 3 年策略联动清理；有上游订单、中心订单、中心对账处置或未完成托动作引用的注单保留。当前余额不被清理任务改写。
- 中心订单引用的中心账本、上游/中心订单、center_reconciliation_disposition 仍按现有对账追加式规则保留。幂等键随其账本记录超过期限被清理，超期请求不再获得永久去重保证。

## 运行边界

- 每轮每表最多 batch-size × max-batches-per-table-per-run 条；默认每轮最多 10,000 条，积压跨日继续清理。
- 挂起/失败数据若长期不恢复，会因保护规则继续保留，需要运营或故障处理流程解决。
- 上游订单、中心订单、中心订单关联流水与中心对账处置不受通用清理器删除；容量仍需后续监控。
- 本机 MySQL 迁移验证不代表服务器或生产已迁移；本次没有运行生产服务，也没有执行每日清理任务。
