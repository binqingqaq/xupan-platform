# 统一管理后台与玩家工作台主模块验收记录

## 1. 验收范围

- 统一入口：`/admin`
- 玩家兼容入口：`/admin/test-players`
- 旧运营兼容入口：`/admin/operations`
- 其他兼容入口：`/admin/users`、`/admin/robots`
- 本阶段只验收统一页面壳体、静态占位和玩家工作台嵌入，不验收后续期号开奖、聊天运营或服务端机器人模块迁移。

## 2. 实施内容

- 新增 `web/src/views/UnifiedAdminPanel.vue`，提供统一后台顶部、左侧导航、状态摘要、占位区域和玩家工作台挂载。
- 新增 `web/src/components/admin/PlayerWorkbenchModule.vue`，集中承载原测试玩家页面的玩家列表、创建、详情、积分、托行为、动作和注单能力。
- 新增 `web/src/components/admin/AdminPlaceholderPanel.vue`，统一渲染无业务副作用的后续模块占位。
- 新增 `web/src/adminRoutes.ts`，集中维护后台路由和权限元数据。
- `TestPlayerManagement.vue` 收敛为兼容包装页，避免维护第二套玩家工作台。
- 新增统一后台路由契约测试 `web/src/adminShell.test.ts`。
- 未修改服务端控制器、玩家行为调度、Flyway migration、钱包事实和权限编码。

## 4. 兼容与隔离结论

- `/admin/test-players` 继续可访问，并复用 `PlayerWorkbenchModule.vue`。
- `/admin/operations` 继续承载旧赔率、虚拟钱包、开奖和本期注单能力，权限仍为 `USER_MANAGE`。
- `/admin/users` 权限仍为 `USER_MANAGE`；`/admin/robots` 权限仍为 `ROBOT_READ`。
- 玩家工作台的 `player_kind=BOT` 与服务端 `chat_robot` 在文案、路由、接口和领域数据上保持隔离。
- 统一 `/admin` 页面没有自动触发开奖、赔率更新、钱包上分/下分或其他旧运营写操作。
- 页面上的余额、下注、动作和注单仍按虚拟积分边界展示，没有新增充值、支付、提现、转账或现实资金语义。
