# 玩家与托静态头像池改造验收记录

## 1. 范围

- 使用本地 40 张 Pixabay/Pexels 素材替代 DiceBear 自动生成头像。
- 普通玩家和托创建时自动分配未占用头像；管理员可在玩家详情中更换。
- 停用和锁定继续占用，软删除释放；现有玩家和托头像不迁移。
- 聊天机器人、后台账号和原有自定义上传能力不纳入本次头像池。

## 2. 实现结果

- 素材保存于 `web/public/avatars/presets/`，稳定键为 `preset-01` 至 `preset-40`，原始像素和格式未改变。
- Flyway `V33` 新增 `avatar_preset`，预置 40 行，分配用户唯一，顺序唯一。
- 新增 `AvatarPresetService`，创建时随机抢占空闲头像，替换时释放旧头像，软删除时释放占用。
- 移除 DiceBear 生成、本地兜底生成和 `xupan.avatar.auto-generate` 配置。
- 新增 `GET /api/admin/player-desk/avatar-presets` 和 `PUT /api/admin/player-desk/players/{userId}/avatar`。
- 玩家工作台详情头像改为按钮，弹窗显示头像池的可用、占用和当前选中状态。
- 普通玩家和托创建请求不再接受客户端 `avatarKey`。
- 玩家和托的旧上传接口/入口移除；后台账号和聊天机器人上传保持兼容。

## 3. 验证结果

- 后端：Java 21 + H2 + Flyway 全量 `292/292` 通过，错误 0、失败 0、跳过 0。
- 前端：Vitest `21` 个文件、`109/109` 通过，`vue-tsc --noEmit` 通过。
- 前端生产构建：Vite 构建通过，生成新的 Spring Boot static 资源和 `avatars/presets/` 40 张静态图。
- 后端打包：`mvnw clean package` 成功，生成 `target/xupan-server-0.0.2.jar`，大小约 45.5 MB。
- 本机 MySQL 8.4：Flyway 从 V32 前向迁移至 V33 成功；`avatar_preset` 共 40 行，未分配 40 行，`display_order` 唯一计数 40。
- MySQL 启动验证：独立端口 `18080` 启动成功，`/actuator/health` 返回 `UP`，验证后正常停止。
