## 2. 后端验证

以下集成测试使用本机 MySQL 8.4.11，目标为本轮单独创建的隔离 schema `xupan_robot_reply_20261030_173500`；连接凭据从忽略文件读取，未写入文档或输出。新建 schema 首次启动时 Flyway 校验 101 个迁移并成功应用至 V101。

核心专项命令：

```powershell
.\mvnw.cmd '-Dtest=ChatMessageServiceTest,PlayerPointOperationControllerTest,RobotDispatchServiceTest,RobotNoticeLifecycleTest,AgentScoreLinkageConsoleTest,ReportDispatchTransactionIsolationTest,RobotDrawComponentRepositoryTest' test
```

结果：51 tests, 0 failures, 0 errors。覆盖机器人通知意图幂等派发、AU8 机器封盘提醒与手动封盘静默、积分申请审批、代理机器积分池联动、托行为、结构化开奖四组件、本机总榜、报网事务隔离及消息文案。

聊天业务闭环命令：

```powershell
.\mvnw.cmd '-Dtest=ChatMessageFeedbackIntegrationTest' test
```

结果：7 tests, 0 failures, 0 errors。覆盖并发下注限额、成功与拒绝反馈、批量限额、正式开奖结算、结算余额快照和通知派发。该集成类在单次空隔离库运行；开奖保护触发器禁止删除已确认结果，重跑测试类应换新的隔离 schema。

下分余额不足消息断言追加后单独回归：

```powershell

```

结果：1 test, 0 failures, 0 errors。确认 HTTP 400、余额和流水不变、申请不落库，同时用户原文与同机机器人失败消息均落库。

## 4. 已实现范围

- 玩家下注成功、部分/全量拒绝、余额不足、封盘原因、余额/流水/历史/走势/取消回复格式和积分精度。
- 下分即时预扣保持原账务时点；余额不足不建申请/流水，但在独立事务内记录玩家输入和机器人失败反馈；审批结果区分真实预扣退款与旧申请无预扣。
- 玩家积分申请审批、代理机器账号人工上下分和托自动上下分经持久化通知意图，按机器私有范围异步幂等派发。
- 报网明确失败退单及中心 `REFUND_CANCEL_LOCAL` 本地处置完成后创建通知；`PENDING/TIMEOUT` 不伪装退款成功。
- AU8 机器有效封盘前 60 秒提示、机器停止提示和同机注单核对；全局封盘公告保留。开奖中不发假号码。
- 公开开奖摘要/历史和机器私有获胜名单/本期总榜；主动历史/走势结构化卡片。新增总榜有 Flyway V101 默认配置和兼容缺少组件配置的读取逻辑。
- WIN/LOSE/DRAW 结算通知使用结算事务内的钱包余额快照；派发重试不重做账务。终态通知按现有消息保留期限清理，处理中和失败意图保留。
