# BY220 玩家引擎多彩种维度验收记录

> 验收日期：2026-10-02
> 对应范围：BY220 玩家端 gameType、聊天下注、期号隔离；xupan DemoGame 与 Flyway V53
> 当前结论：玩家当前期、开奖事件、下注和自动轮期已具备 game_code 维度；超级后台开奖信息与开奖历史已按彩种选择。旧演示人工开奖/重置和 WebSocket 下注协议仍待补齐。

## 1. 已实现

- Flyway V53 为 game_issue、game_issue_event、game_bet 增加 game_code，并建立彩种外键和游戏维度索引。
- 保留全局 issue_number 唯一性；非 AU8 彩种使用 `<GAME_CODE>-<期号>` 格式，避免当前存量读取路径产生歧义。
- 新增 `GET /api/demo/game/catalog`，返回启用的彩种目录。
- `GET /api/demo/game/current?gameCode=...` 按彩种读取和初始化当前期；未定义彩种返回 GAME_NOT_FOUND。
- `POST /api/demo/game/bets` 支持 gameCode；AI/测试玩家下注通过同一服务路径。
- 聊天 REST 下注请求支持 gameCode；玩家前台增加彩种选择并持久化选择。
- 非 AU8 玩家前台聊天下注走 REST 通道，避免当前 WebSocket 协议未携带 gameCode 时误下到 AU8。
- `自动轮期服务` 的定时入口遍历所有启用彩种，逐彩种执行当前期推进；新增多彩种自动建期测试。
- 超级后台开奖信息页读取启用彩种目录，切换彩种后重新加载对应开奖结果和历史。
- 开奖历史页按 `gameCode` 查询；补期请求携带 `gameCode`，创建/补录、锁定和结算均使用该彩种。

## 2. 已执行验证

- 后端 H2/Flyway：319/319 通过，覆盖多游戏期号/注单隔离、自动轮期遍历启用彩种、开奖历史按彩种隔离与补期。
- 前端 Vitest：121/121 通过，typecheck 和生产构建通过。
- 本机 MySQL 8.4.11 从 V52 迁移至 V53，Flyway 成功应用 53 个迁移。
- 本机运行态创建临时彩种 `MULTI_RUNTIME`，玩家目录返回该彩种。
- 使用临时测试玩家下注后，注单期号为 `MULTI_RUNTIME-3000000`，数据库 game_issue 和 game_bet 的 game_code 均为 MULTI_RUNTIME。
- 主彩种 AU8 的期号保持独立；运行态临时彩种、期号、注单、钱包流水和临时用户已清理。

## 3. 未完成边界

- 旧演示接口 `/api/demo/game/admin/draw` 和 `/api/demo/game/admin/reset` 仍默认操作 AU8；这些接口不属于当前超级管理后台正式菜单。
- 超级管理后台开奖信息和开奖历史已完成彩种选择；未结订单、订单改单按全部彩种注单读取并保留原 BY220 列表结构。
- WebSocket 聊天下注协议尚未携带 gameCode，当前通过玩家前台 REST fallback 保证非 AU8 下注不串彩种。
- 外部开奖源仍未接入，服务器和生产未验证。
