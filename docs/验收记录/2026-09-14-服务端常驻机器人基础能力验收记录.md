# 服务端常驻机器人基础能力验收记录

## 1. 验收范围

- 代码范围：V11/V12、机器人领域模型、模板渲染、稳定选机、事件扫描、投递重试、聊天室机器人消息入口、后台管理 API。
- 基线：Java 21、Spring Boot 4.0.8、Spring JDBC、Flyway、MySQL 8.4 LTS、H2 测试数据库。
- 明确不在本次范围：机器人后台前端、Redis/MQ、多实例广播、历史批量补发、归档清理、真实支付和生产高可用。

## 2. 自动化验证

在 `server/xupan-server` 执行：

```powershell
.\mvnw.cmd -q test
```

结果：后端全量 `176` 个测试，`0` failures，`0` errors。机器人专项覆盖：

- Flyway V11/V12 和默认机器人/四类模板种子。
- 机器人、模板、dispatch 仓储及唯一约束。
- 模板变量白名单、纯文本安全、渲染长度和 `resultNumbers` 限制。
- 稳定权重选机、SHA-256 幂等键、消息幂等和聊天室序号。
- 无在线连接持久化、重复扫描、禁用机器人、失败重试和管理 API 权限/审计。
- Spring Boot 应用上下文和全量既有业务回归。

## 3. MySQL 8.4 运行态

使用本机 MySQL `8.4.11` 创建日期隔离的临时验收库，不接触现有业务库。使用环境变量注入连接信息，凭据未记录在本文档。

验证结果：

1. Spring Boot 真实启动在独立端口成功连接 MySQL 8.4.11。
2. Flyway 从 V1 连续迁移到 V12 成功。
3. 数据库确认默认机器人 1 个、启用模板 4 个、dispatch 1 条。
4. 自动调度器实际扫描 `ISSUE_STARTED` 游戏事件并完成 `PUBLISHED`。
5. 同一事件形成 1 条 `chat_message`，类型为 `ROBOT/ROBOT`，并形成 1 条 `MESSAGE_CREATED` outbox；机器人消息带有唯一幂等键和事件追踪 JSON。
6. `/actuator/health` 返回健康状态。
7. 验收结束后已停止临时 Spring Boot 进程并删除临时数据库。

## 4. 结论与边界

本阶段服务端常驻机器人基础能力已完成代码实现和指定范围验收，可以作为单服务器上线收尾和机器人管理前端的后端基线。当前目标是单服务器、单实例运行，不承诺多服务器高可用；正式上线后是否扩展多服务器，依据真实用户量、连接数和故障数据再评估。

仍需后续开发：

- 机器人管理前端和模板发布的人工作业流。
- 基于实际运行数据决定是否增加多实例任务领取、Redis/MQ 事件通知和跨节点 WebSocket fan-out。
- 单服务器日志留存、备份恢复和基础故障演练；专门监控告警平台按正式上线后的实际需要评估。
- 正式域名 HTTPS、生产备份恢复和故障演练。
