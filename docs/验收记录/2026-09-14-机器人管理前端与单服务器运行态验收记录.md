# 机器人管理前端与单服务器运行态验收记录

## 1. 结论

本轮已完成机器人管理前端代码切片、前端自动化验证、后端回归、单 Spring Boot 实例启动和 MySQL 运行态验收，并补做了管理员登录后的浏览器冒烟检查。当前结论为：**代码实现完成，管理员 API、机器人事件链路、无在线持久化、重复扫描、跳过分支、人工重试、停机恢复和资金隔离均已通过；管理页、模板、新增表单、`/forbidden` 页面和聊天室页面在当前登录视口下可用。精确 375px/桌面布局以及无 `ROBOT_READ` 账号的自动跳转仍未单独验证，不宣称本计划整体完成。**

本轮没有新增数据库迁移、Redis、MQ、多实例协调或跨节点广播设计。

## 2. 已实现范围

- 新增 `web/src/types/robot.ts`、`web/src/robotAdmin.ts`、`web/src/views/RobotManagement.vue` 和专项测试。
- `web/src/api.ts` 接入机器人分页、详情、创建、编辑、启停、模板、预览、投递查询和失败重试接口。
- 新增 `/admin/robots` 路由和后台条件入口，按 `ROBOT_READ` 控制访问，按 `ROBOT_WRITE`、`ROBOT_TEMPLATE_WRITE` 控制操作。
- `SpaController` 和 `SecurityConfig` 均已覆盖 `/admin/robots`，Spring Boot 8080 可以直接返回 SPA 页面。
- 模板默认选择服务端返回的启用最高版本；投递筛选的 `datetime-local` 值转换为 ISO `Instant` 查询参数。
- 页面未使用 `v-html`，未新增本地假机器人数据；机器人仍不是 `sys_user`，不触碰钱包和下注领域。
- 为保证只读权限拒绝仍可落操作审计，操作审计仓储改为 `REQUIRES_NEW`；机器人只读入口保留 `readOnly` 事务。无 `ROBOT_READ` 用户的真实 GET 请求此前会因审计写入回滚而返回 500，本轮已修复为 403，并增加回归测试。

## 5. 真实 API 验收

以下请求通过本机 `127.0.0.1:8080`、MySQL 8.4.11 开发库完成；账号只记录角色，不记录密码、Token 或 Cookie：

| 场景 | 结果 |
| --- | --- |
| 管理员登录、机器人列表/详情/模板列表/投递列表 | 200 |
| 模板预览 `预览 {{issueNumber}} {{eventMessage}}` | 200，渲染为 `预览 PREVIEW-0001 示例：机器人事件消息` |
| 非法 HTML、未知模板变量、权重 0 | 均为 400 |
| 创建、编辑、停用、启用、再次停用机器人 | 201/200，均成功 |
| `DRAW_RESULT` 模板连续保存 | 版本 1、版本 2 均成功 |
| 无 `ROBOT_READ` 普通用户读取和创建 | 均为 403，错误码 `ROBOT_OPERATION_FORBIDDEN` |
| 机器人管理操作审计 | 成功和失败均落 `sys_operation_log`，不保存模板全文、密码、Token 或 Cookie |
| 游戏事件到机器人消息 | `ISSUE_STARTED` 事件最终为 `PUBLISHED`，生成 `ROBOT/ROBOT` 消息和 `MESSAGE_CREATED` outbox |
| 无在线连接持久化 | `ACCEPT-NO-ONLINE-20260914-1228` 只有 1 条 dispatch、1 条消息和 1 条 outbox，历史接口可查询 |
| 重复扫描唯一性 | 同一事件重复经过调度扫描后仍保持单 dispatch、单消息、单 outbox |
| 停用机器人/模板缺失 | 分别为 `SKIPPED/NO_ENABLED_ROBOT`、`SKIPPED/TEMPLATE_NOT_FOUND` |
| 人工失败重试 | 注入 `FAILED` 后接口返回 `PENDING`，随后变为 `PUBLISHED`，消息 ID 为 4425 |
| 停机后 `PENDING` 恢复 | `ACCEPT-RESTART-PENDING-20260914-1222` 在重启后为 `PUBLISHED`，消息 ID 为 4426 |

预览前后 `chat_message`、`chat_outbox`、`chat_room.next_sequence_no` 快照未变化，证明预览没有发布消息或占用聊天室序号。独立 `ISSUE_STARTED` 事件前后，`game_bet` 均为 22、`demo_balance_ledger` 均为 6；消息 `sender_type=ROBOT`、`sender_id` 指向 `chat_robot.id`，机器人流程没有触碰下注或余额流水。

本轮还修复了自动轮期的下一期创建并发窗口：`saveBettingIssue` 对重复期号按幂等成功处理，并增加 H2 回归测试；服务重启后连续观察无重复键异常，health 保持 `UP`。

## 6. 浏览器登录后冒烟证据

- 管理员登录后访问 `/admin/robots`，机器人列表、详情、模板事件页签、投递记录和分页内容均可加载；当前显示 1 个已启用机器人，投递记录可见 `PUBLISHED` 数据。投递表格保留固定最小宽度并由表格容器承载横向滚动，页面本身 `scrollWidth` 未超出 `clientWidth`。
- 点击模板事件页签后正文随服务端模板切换；执行模板预览可看到期号、事件类型和渲染正文，没有新增消息或聊天室副作用。
- 打开并关闭“新增机器人”表单，字段、权重/延时输入、校验说明、取消和创建按钮在当前视口内未发生明显重叠；未提交新机器人。
- 直接访问 `/forbidden` 可显示“无权访问”和返回聊天室按钮；这证明页面视觉和路由入口存在，不等同于使用无 `ROBOT_READ` 账号触发自动跳转。
- 返回 `/room` 可看到当前期号、聊天室消息、操作区和输入发送区；当前浏览器实际 CSS 视口为 `innerWidth=525`、`innerHeight=920`、`clientWidth=510`，页面 `scrollWidth=510`，未观察到页面级横向溢出。精确 375px 和桌面视口未由当前工具分别控制，仍保留为未完成项。
