# 后台与玩家链接会话共存修复验收记录

## 1. 问题

管理员登录后台后，在同一浏览器的另一个标签页打开普通玩家链接，再刷新管理员标签页，会恢复成玩家身份并进入 `/forbidden`；点击“返回聊天室”后只能看到玩家前台。

## 2. 根因

- 管理员登录和玩家链接兑换共用了同一个 HttpOnly 刷新 Cookie：`xupan_refresh`。
- 玩家链接兑换会覆盖该 Cookie，管理员标签页刷新时只能拿到最新的玩家刷新会话。
- 访问令牌本身按标签页保存在内存，但刷新身份没有按标签页或身份类型隔离。

## 3. 修复方案

- 管理员继续使用 `xupan_refresh`。
- 玩家链接使用独立 `xupan_player_refresh`。
- `/api/auth/refresh` 通过 `X-Xupan-Auth-Audience: ADMIN|PLAYER` 选择对应 Cookie，并校验刷新会话的 `authMode`。
- 前端使用 `sessionStorage` 记录当前标签页使用端，不保存任何 Token。
- 路由进入 `/admin*` 时强制使用管理员使用端；普通前台保持当前标签页使用端。
- 管理员退出只清管理员 Cookie；玩家退出只清玩家 Cookie。
- 旧的错误状态：若 `xupan_refresh` 中混入玩家会话，管理员刷新会返回 401 并清除该 Cookie，不再静默切换成玩家。

## 4. 安全边界

- 两个刷新 Cookie 仍为 HttpOnly、Secure 可配置、SameSite Strict、Path `/api/auth`。
- 刷新 Token 不写入 `localStorage` 或 `sessionStorage`。
- `sessionStorage` 仅保存 `ADMIN` 或 `PLAYER` 使用端提示，不构成认证凭据。
- 管理员和玩家访问令牌仍按标签页内存隔离。

## 6. 浏览器复现验证

1. 管理员标签页正常打开 `/admin`。
2. 在同一浏览器新标签页打开玩家链接，确认进入“测试1”玩家前台。
3. 刷新管理员标签页，仍显示管理员 `admin`、玩家工作台和上下分面板。

以上步骤已通过，未再出现 `/forbidden` 身份串线。

## 7. 兼容说明

- 修复前已经被玩家链接覆盖的 `xupan_refresh` 不再被视为管理员有效会话。
- 受影响的管理员标签页需要重新登录一次，之后管理员与玩家会话可以同时存在。
