## 2. 三题逐条验收

### 2.1 第 1 题：积分精度 = 2 位小数，超精度一律 400

| 项 | 结果 | 依据/证据 |
| --- | --- | --- |
| 全站口径 | 统一 2 位小数；新增 `com.xupan.server.web.MoneyAmounts`（`requireTwoDecimals` 管"调用方传入值"，`rounded(HALF_UP)` 管"减法算出的差额"） | 代码 + 静态不变量 I1-1/I1-3 |
| 超精度 | `0.001` → **400**（`MACHINE_SCORE_INVALID`/`SUB_ACCOUNT_SCORE_INVALID`/`WALLET_AMOUNT_INVALID`），**不再 500、不再静默舍入** | H2 用例；**运行态**：机器积分传 0.001 → 400 且余额不变 |
| 小数可用 | `0.01`/`0.1` 端到端可用（子账号池划出 → 机器 → 上分 → 玩家） | **运行态**：池 0.01→机器 0.01→池 0.00→上分 0.1→池 0.10；流水金额精确到分 |
| 前端体验 | 子账号「上分/下分」补 `step="0.01" min="0.01"`（**原先缺 `step`，浏览器原生 `stepMismatch` 会拦掉 0.1/0.01**——BY220 用 layui+`$.post` 不走原生校验，所以 BY220 反而能提交，这是"照抄表单属性却换了提交机制"的反向差异） | 组件测试 + 产物标记 |
| 与 BY220 的关系 | BY220 的 `x_admin.score`/`x_robot.score` 是 `DECIMAL(30,6)`、`rbUpdown()`/`Users.php:62-72` 无任何取整 → **BY220 支持 6 位；2 位是对 BY220 的收窄** | 使用者 2026-10-08 确认，登记为**有意偏离**（§8） |

## 3. 迁移与数据

| 迁移 | 内容 | 本机 MySQL 实测 |
| --- | --- | --- |
| `V75__会话入口维度.sql` | `auth_session.entry VARCHAR(16) NOT NULL DEFAULT 'PLATFORM'` + `CHECK (entry IN ('PLATFORM','CONSOLE'))` | ✅ 列存在、`NOT NULL`、默认 `PLATFORM` |
| `V76__后台入口权限收敛.sql` | 只删 `ADMIN`/`SUB_ACCOUNT` 的 `AGENT_CONSOLE_READ` 授权行（权限码与枚举保留） | ✅ 撤权后 `AGENT_CONSOLE_READ` **只由 `AGENT` 持有**；`ADMIN`/`SUB_ACCOUNT` 仍持 `AGENT_PLAYER_MANAGE` |

- `DEFAULT 'PLATFORM'` 是**刻意**的：升级前已签发的 30 天老会话没有入口信息，回填会把在用的机器账号会话误标成平台入口；统一按"老会话只对平台入口有效"处理 → **平台入口无需重登，代理入口（`/console`）需重登一次**。
- 玩家链接会话 `entry` 落 `PLATFORM`，但刷新**跳过**入口校验（身份隔离由 `auth_mode=PLAYER_LINK` 承担）→ **老玩家会话不需要重登**。
- 迁移后本机库回到基线且验证数据已清理：`agent 6 / agent_group 2 / sys_user 8 / player_point_request 0`，平台直属机器 `LOCALADMIN` 积分仍为 `1000000.00`。

## 9. 已知遗留与未执行项（如实标注，不得当成已完成）

**未执行的验证**（全部归使用者或后续现场工作）：
- **浏览器人工验收**：机器账号进 `/console` 的真实点击、子账号看到本组机器、菜单可见性（机器账号看不到「玩家工作台」）、404 页视觉、`/forbidden` 两种按钮形态。自动化只覆盖到组件/守卫层与静态产物标记，**不等于浏览器点击验收**。
- **服务器、生产、HTTPS Secure Cookie、多设备、跨域部署**均未验证。
- 审批路径的运行态未单独验证（由 H2 覆盖，见 §5）。

**已知遗留**：
- `R3「全局 404」未做`：后端只对白名单前缀做 SPA fallback，白名单之外的乱路径仍返回 401/403 JSON，看不到前端 404 页。
- `web/src/views/AgentConsole.vue` 与 `agentConsole.test.ts` **本批不删**（`/api/agent/**` 仍在，该文件自带"仅用于追溯"注释）。
- `/console` 每次多打一次 `getBetBoard`（`loadBoardState()` 与 `currentBoard`/`issueStatus`/`phaseLabel` 是**既有死代码**，本批未改变）。
- 审批路径的钱包流水 `reason` 由"审批原因"改为共享服务生成的「代理上分/下分：<玩家名>」；审批原因仍落在 `player_point_request.review_reason`。
- **运维中间态**：重放修复前已落库的 `POINT-REQUEST:<id>` 钱包流水会因 `reason` 不一致返回 409 `AGENT_SCORE_IDEMPOTENCY_CONFLICT`（`PlayerDeskAdminService` 的 grant/adjust 路径同理，reason 由调用方传入改为共享生成）。升级后若出现该 409，按"换幂等键/重新提交"处理即可。
- 一次审批现在会写**两条审计**（原 `USER_MANAGE` 审批行 + `changeScore` 内部 `AGENT_PLAYER_MANAGE` 行，后者 `path` 仍是 `/api/agent/players/{id}/score`，沿用共享逻辑未改）。
- 审批路径的 `PlayerPointRequestService` 与 `PlayerDeskAdminService` 各自保留一份三行的 `ownerMachineId`（同口径同错误码），未把私有方法提升为 public 以避免跨服务耦合。

**开发过程中的失败归因（避免误读为产品缺陷）**：
- 前任积分 lane 中断，留下 ① 测试重复方法导致后端测试编译失败 ② 两处测试期望值算错（漏算"建机器已从池划出 50"）。均由工头修正；产品实现本身正确。
- 运行态脚本自身的 5 个缺陷（凭据解析把括号说明当用户名、级联失败未跳过、池未补足却设大值、`GetCookies` 路径不匹配、退出用了刷新前的 access token）也在过程中定位并修掉——**这些是验收工具的缺陷，不是产品缺陷**。

## 10. 影响范围与回滚

- **影响入口**：`/console`（语义收紧）、`/platform-admin/player-workbench`（新增）、`/platform-admin/{stash,operations,users,players,robots,agents}`（新地址）、`/login` 与 `/platform-admin/login`（按角色互拒）、`/api/auth/*`（会话入口维度）、价格/积分写入口（精度校验与 A1）。
- **回滚**：V75/V76 均为"加列/删授权"，按仓库**前向修复**原则：新增迁移重新 `INSERT` 授权行、保留 `entry` 列但不再校验；代码回滚须**同时**回滚前端门禁，否则会出现"门禁严了但权限没恢复"的中间态。
- 已产生的账本流水按追加式账本原则不删除。

## 11. 请使用者在浏览器确认的清单（我无法代做）

1. 用**超管**登录 `/platform-admin/login` → 应落在 `/platform-admin/player-workbench`，且菜单里**看不到**机器端专属内容。
2. 同一浏览器新开标签敲 `http://127.0.0.1:8080/console` → **应要求重新输入机器账号密码**（这是本次最核心的体验变更；旧行为是直接以超管身份进入）。
3. 用**机器账号**登录 `/login` → 应落在 `/console`；顶部身份显示机器名、无机器选择器。
4. 机器账号敲 `/platform-admin` → 应提示无权限并回**平台**登录页；超管敲 `/console/users` → 应看到**独立 404 页**（不是白屏、不是静默跳转）。
5. 在 `/console` 点退出 → 回 `/platform-admin` 刷新，**不应被踢下线**（反之亦然）。
6. 玩家链接打开后，在后台标签刷新 → **不应**串成玩家身份。

> 注：本机 8080 上当前运行的仍是**旧代码实例**（用户先前启动的），上述第 2/4/5 条需要重启后端与刷新前端产物后才会体现；重建后的产物已就位（§6）。
