## 1. BY220 依据

- 代理写入口：`application/rbt/controller/Index.php:165-174` `UpdatePeiLv`；`176-233` 的 `UpdatePeiLv2/UpdateFanShui/UpdateFanShui2/UpdateFengpan/UpdateCancel` 经全仓库检索**无调用者**，属遗留端点。
- 普通赔率：`application/common.php:4562-4566` `getPeilv() = (PeiLv/100)*num + 1`。
- 特码赔率：`common.php:4568-4571` `getTePeilv()` 原样返回；`4181-4215` 特码 `yingScore = 本金×tePeilv` 且 `$ying=0`（不退本金）。
- 封盘：`common.php:2133-2135`（下注）、`2069-2072`（取消）、`rbt/Index.php:437-438`（删单）。
- 取消：`common.php:2067-2106`：`cancel` 秒内退全额本金并 `DELETE x_record`。
- 结算判定：`common.php:4341-4391`（通类结构为「赢值→赢、输值→输、其余→和退本金」）。
- 报表：`common.php:3906-3922` `getShuang`、`3924-3944` `getShuangs`、`4397-4449` `getRecordData`。

## 2. 实现范围

1. Flyway `V55__增加返水口径与撤单物理删除边界.sql`：`agent.rebate_mode`（单边/双边，默认 `SINGLE`）、`odds_rate/special_odds_rate` 非负约束、解除 `fk_demo_balance_ledger_bet` 与 `fk_game_bet_edit_bet`。
2. 新增 `MachineBettingConfig` 与 `AgentBettingPolicy`：玩法权重、赔率换算（机器优先 + 全局回退）、封盘与取消判定。
3. 下注：按机器赔率写入 `game_bet.odds_snapshot`；`board_open=false` 拒绝下注（`GAME_BOARD_CLOSED`）；进入 `close_seconds` 封盘窗口拒绝下注（`GAME_MACHINE_CLOSED`）。
4. 撤单：按 `cancel_seconds` 取窗口，`cancel=0` 关闭（`禁止取消！`）；进入封盘窗口后禁止取消；**先物理删除注单行**再写幂等退款流水与审计；反馈文案与 BY220 一致。
5. 未结订单删除：改为物理删除注单行，退款流水与 `sys_operation_log` 审计保留，重复删除返回冲突。
6. 报表：单边特码返水去掉 `/100`；双边流水按 `getShuang`；新增双边返水（`totalRebateDouble`/`rebateDouble`）按 `getShuangs`；特码输单双边返水为 0；和单不计双边流水与双边返水；按机器 `rebate_mode` 输出**生效返水**（`effectiveRebate`/`totalEffectiveRebate`），使单边/双边口径真正影响报表结果。
7. 前后端：机器管理支持「单边/双边」与返水单位提示，报表页展示双边反水与生效反水（含口径标记）。

## 3. 结算判定核对结论（未改动结算分支）

逐行复核 `common.php:4341-4391` 后确认：BY220 通类与 `X无Y` 都是「赢值→赢、输值→输、其余→和（退本金）」，与 xupan 现有 `TONG`/两位 `NONE` 分支结构一致，因此**本次不修改 `SettlementService`**，并纠正了先前静态摘要中「第三位判和」的错误表述。`ADD`（加）玩法在 BY220 中只有一个和值，与 xupan 三参数结构存在语法级差异，登记为待确认事项，不在本次范围。

## 6. 偏差与连带影响

| 项 | 说明 |
| --- | --- |
| 撤单/未结订单物理删除 | 用户 2026-10-02 确认按 BY220。注单行删除后不可恢复，金额事实保留在 `demo_balance_ledger`（含原注单号）与 `sys_operation_log`；`settlement_status='CANCELED'` 仅用于历史存量数据 |
| 玩家自助撤单的审计痕迹 | 管理员未结订单删除写 `sys_operation_log`；玩家自助撤单沿用既有链路，以钱包退款流水（`SETTLEMENT_REVERSAL`，含原注单号）和聊天室 `CANCEL_RESULT` 反馈作为痕迹，**不写 `sys_operation_log`**（该表按后台操作权限记录）。若需要玩家自助撤单的独立审计行，应另立小计划补齐 |
| 代理改赔率的写入入口 | BY220 `UpdatePeiLv` 使用动态列名，代理可改自己 `score/isOpen/uid/password`；xupan 只接受白名单字段 + 类型/范围/归属校验 + 审计 |
| 清空数据的关联清理 | `PlatformSettingsService` 以 `related_bet_id IN (SELECT id FROM game_bet ...)` 关联清理；注单物理删除后该分支不再匹配，这类钱包流水只按自身时间清理。属保留金额事实的取舍 |
| 返水两处历史不一致 | 按用户确认原样保留：单边特码 `本金×teFanshui` 不除 100；双边特码 `本金×tePeilv×fanshui/100` 用普通返水 |
| 报表数字变化 | 双边流水由原「净收益」改为 BY220 的「有效投注额（本金）」口径，双边返水为新增指标，因此本记录的报表数字与 [报表双边流水与反水验收记录](2026-10-02-BY220超级管理后台报表双边流水与反水验收记录.md) 的旧值不可直接比较 |
