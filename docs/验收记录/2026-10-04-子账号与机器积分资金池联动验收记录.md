# 子账号与机器积分资金池联动验收记录（2026-10-04）

> 对应范围：BY220 `application/admin/controller/Rb.php`、`application/common.php::rbUpdown`、`application/admin/controller/Users.php`
> 当前结论：**已完成本机实现 + H2 全量 + 本机 MySQL 运行态验证**；服务器与生产未验证。
> 本文是「子账号按 BY220 补齐」的第 1 条（资金联动）；第 2~7 条仍待做，见文末。

## 1. BY220 行为（为什么要联动）

BY220 里子账号（`x_admin.score`）就是名下机器的**上游资金池**，三处证据：

| # | BY220 代码 | 行为 |
| --- | --- | --- |
| 1 | `Rb.php` 子账号建机器分支 | 插入 `x_robot` 后 `db('admin')->setDec('score', 机器初始积分)`：机器积分从子账号扣 |
| 2 | `common.php::rbUpdown` | 给机器**上分**：`robot.setInc(score)` + `admin.setDec(score)`；**下分**：反向。并写 `folder_record` 流水「为 X 上分 N」 |
| 3 | `Users.php` 编辑子账号 | 超管用 `up`/`down` 给子账号上下分，下分不足报「该子帐号积分不足以下分！」 |

超管直接建的机器没有 `uid`（不挂子账号），因此不涉及资金池；机器删除时 BY220 **不退回**积分（`Rb.php::UpdatePanStatus` 直接 DELETE，无 `setInc`）。

## 2. xupan 实现

- 新增 `AgentLedgerService#assignMachineScore(agentId, fromGroupId, toGroupId, target, directEntryType, reason, operator)`：
  把「机器目标积分」翻译成资金池动作——① 归属变化时先把机器现有积分退回原池；② 再从新池按差额划出（或把差额退回池）；
  ③ 没有子账号（超管直连机器）时保持原来的「直接设定」语义。
- 划拨在同一个事务内完成，加锁顺序固定为「子账号（按 id 升序）→ 机器」，与其它账本路径一致，避免交叉死锁。
- 每次划拨写**成对流水**：子账号侧与机器侧各一条、方向相反；新增两种类型 `MACHINE_ALLOCATE`（子账号 → 机器）
  与 `MACHINE_RETURN`（机器 → 子账号），迁移 `V71` 扩展 `ck_agent_ledger_entry_type`。
- 子账号池不足时返回 409 `SUB_ACCOUNT_SCORE_INSUFFICIENT`，文案对齐 BY220：「该子帐号积分不足以为机器分配积分！」，且**不产生任何余额变动**。
- 前端机器表单补了一行说明（积分从「所属子账号」划出／退回，池不足会拒绝保存），并把这两个错误码映射成中文提示。
- 只影响超管在「机器管理」建机器/改机器积分；**机器给玩家上下分不涉及子账号池**（与 BY220 `rbUpdown` 的适用对象一致）。

## 3. 行为对照

| 操作 | 子账号池 | 机器积分 | 流水 |
| --- | --- | --- | --- |
| 建机器（挂在子账号下） | −N | +N | `MACHINE_ALLOCATE` 成对 |
| 机器积分调高 | −差额 | +差额 | `MACHINE_ALLOCATE` 成对 |
| 机器积分调低 | +差额 | −差额 | `MACHINE_RETURN` 成对 |
| 机器改挂到另一个子账号 | 原池 +现有积分、新池 −目标积分 | 目标值 | 先 `MACHINE_RETURN`，再 `MACHINE_ALLOCATE` |
| 机器改为「未设置」子账号 | 原池 +现有积分 | 目标值（直接设定） | `MACHINE_RETURN` + `MACHINE_ADJUST`/`MACHINE_INIT` |
| 池余额不足 | 不变 | 不变 | 无（409 拒绝） |
| 删除机器 | **不退回** | 随机器一起物理删除 | 与 BY220 一致 |

## 5. 已知边界与后续项

- **删除机器不退回积分**：与 BY220 完全一致（BY220 删机器直接 DELETE，没有 `setInc` 回子账号）。若希望「删机器把积分退回子账号」，那是**偏离 BY220**的新需求，需要使用者确认后再改。
- **子账号自身余额不校验名下机器占用**：超管把子账号积分直接设低（甚至设为 0）是允许的，机器已持有的积分不受影响。BY220 `Users.php` 的下分校验只比较子账号自己的余额，同样不考虑机器占用，因此这里与 BY220 一致。
- **子账号上下分仍是「设定目标值」**：BY220 是 `up`/`down` 增量语义并校验余额（第 2 条待做）。
- 其余待做（按 BY220 补齐子账号）：③「开启飞单」联动名下机器上游状态 + 统一飞单真正生效；④`online` 启用/在线开关；
  ⑤批量创建子账号；⑥多级子账号 level 口径；⑦子账号菜单可见性逐项核对。

## 6. 影响范围与回滚

- 影响的入口：`POST /api/admin/machines`、`PUT /api/admin/machines/{id}`（仅当机器挂有子账号时产生资金池动作）。
