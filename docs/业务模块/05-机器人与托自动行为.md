# 业务模块 05：机器人与托自动行为

> **2026-11-03 新决定，已实施待验收：**托下注继续参与本地钱包和开奖结算，但完全不参与飞单、中心接单、风险额度占用和第二层结算。托级“飞单”配置、API 字段和数据库列已删除；自动化、浏览器及完整结算验收未执行，见[修复计划与本机实施状态](../plans/2026-11-03-托单隔离中心报网与结算修复开发计划.md)。

> 本页描述当前托生命周期实现。需求依据为 [托生命周期严格对齐 BY220 确认](../需求基线/2026-10-09-托生命周期严格对齐BY220确认.md)；实施方案与验证记录见 [实施计划](../plans/2026-10-09-托生命周期严格对齐BY220实施计划.md)。BY220 运行态不可用，本页不把静态源码/本地种子结论写成线上观察。

## 1. 范围和账户边界

代理后台 `/console` 创建并管理自己机器名下的托。托保留会员 ID、昵称、拉黑、换名记录、玩家链接和有效期。托使用独立玩家虚拟钱包；人工或自动上下分只改变托钱包并写账本，不扣、不返还机器积分，也不建立代理审批申请。

平台聊天室唯一服务端机器人与托玩家是两种身份：本模块的自动下注、上下分及查询行为均以托玩家身份执行；产生的注单和钱包流水仍走托的正式业务链路，聊天室反馈统一由唯一机器人发出。机器人身份固定为“机器人”，头像使用随应用发布的绿色 Android 静态资源，不读取环境数据库中的自定义头像键（使用者确认 2026-10-22）。

回复格式及场景的本机实现证据见[机器人回复补齐验收记录](../验收记录/2026-10-30-Xupan机器人回复格式与场景补齐本机验收记录.md)。

## 2. 代理创建及配置

- 新托默认处于“自动”状态，默认下注范围为 30–300。
- 下注范围固定为五档：30–300、300–1000、1000–3000、3000–10000、10000–30000。
- 代理可切换自动/手动，修改下注范围，并操作托级“追”状态；设置即时保存。托没有飞单配置。
- 开通追受机器账号的追单权限门禁。托下注不进入中心报网和第二层结算；普通玩家中心报网规则见[11 中心上游](11-中心上游.md)。
- 界面和接口不再提供下注整十、托级玩法白名单、活跃比例、每期注单数、随机上分概率/金额范围、托闲聊参数、额外 RANDOM 档和托全局注单/积分上限。

## 3. 自动生命周期

下注派发器每秒检查当前投注期：先筛出机器已开启、未过期、托和玩家账号有效、自动模式且持有有效完整玩家链接的候选托，再按机器和期号选取约 90% 的托（向上取整，至少 1 托）。每个被选托每期生成一笔持久化动作，下注时间落在本期投注窗口。执行前再次校验状态；动作使用幂等键、租约和结果状态，失效动作保留原因，不补执行已经关闭期号的动作。

> 机器手动封盘（本机已实施，见[开发计划及实施记录](../plans/2026-10-28-机器手动封盘开盘控制恢复开发计划.md)）：封盘机器不得新建或执行托下注；执行前复检避免计划生成后才封盘的竞态。若动作到期时机器仍关闭，则将该动作记为 `SKIPPED/MACHINE_MANUALLY_CLOSED`，以后重新开盘不补发；机器手动封盘不改变托的非下注行为、既有注单结算或聊天室开奖播报。H2 Spring 上下文受 V83 迁移 SQL 阻断，相关服务测试未执行。

下注文本由单一 13 叶子玩法池生成：番、角、加、车、念、正、通、无、单、双、大、小、特。抽取权重为：

| 玩法 | 权重 |
| --- | ---: |
| 特、无 | 各 27% |
| 车、念 | 各 9% |
| 角、番、正 | 各 4.5% |
| 单、双、大、小 | 各 1.125% |
| 加、通 | 各 5% |

“特”始终在候选池中。除“加/通”沿用 Xupan 原参数生成外，其余按 BY220 AU8 玩法语义生成；最终通过玩家聊天室解析、正式注单、虚拟钱包扣分和结算链路。

上下分和查询由约 15 秒一次的独立行为派发器处理，每批最多抽取 6 个自动托。余额低于下注范围下限且本期尚未自动上分时，从 BY220 固定金额表中抽取金额直接上分；余额高于 2000、本期尚未下分且过去 30 分钟未自动下分时，按余额一半四舍五入到千位执行下分。上下分立即记入托钱包账本；现存“待审批”措辞只是历史模板文本，不代表等待代理审批，聊天室中的相关通知以唯一机器人身份发布。余额、流水、历史查询通过托的玩家消息链路执行。

自动下注回执使用正式已受理注单批次、完整期号、实际扣除积分及钱包余额快照；托自动上/下分仅在正式钱包操作成功后建立机器私有通知意图。通知意图以稳定幂等键派发至唯一机器人，不把托账号伪装成机器人，也不因重试重复记账。

## 4. 代码与数据库落点

- 自动行为和注单文本：`TestPlayerBehaviorService`、`BotBetTextGenerator`。
- 定时派发：`TestPlayerBehaviorScheduler`，受 `xupan.test-player.behavior-enabled` 控制；`application.yaml` 默认开启，可用环境变量关闭。
- 代理托配置：`PlayerDeskAdminController`、`PlayerDeskAdminService`、`PlayerDeskRepository` 和 `PlayerWorkbenchModule.vue`。
- 数据库变更：Flyway V79 收敛旧托行为字段、默认值、追/飞状态和旧待执行动作；V80 修复 `BET_TEXT` 动作类型约束；V81 加入数据保留清理所需索引，均已在本机 MySQL 8.4 应用。
- 注单经正式 `ChatMessageService`、下注解析与结算服务；上下分经 `VirtualWalletService` 与钱包流水。

## 6. 托动作历史保留（使用者确认 2026-10-09）

托自动行为记录中 `SUCCEEDED` 与 `SKIPPED` 只保留 5 天，超过期限后分批清理；`PENDING`、`PROCESSING`、`FAILED` 保留并继续用于恢复/排错。已完成机器人聊天派发记录和旧机器人事件也在 5 天后清理；超过 5 天仍未派发的旧事件不再补发，已有失败/处理中派发继续重试。
