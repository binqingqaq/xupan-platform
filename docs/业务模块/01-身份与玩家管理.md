# 业务模块 01：身份与玩家管理

> 当前状态：本机收口完成，服务器/生产未验收。
>
> 当前代码基线：`3f7d7e4`
>
> 详细链接规则：[玩家链接生命周期与影响矩阵](../玩家链接生命周期与影响矩阵.md)

## 1. 模块职责

负责管理员、普通玩家、TEST 玩家、BOT 和服务端机器人的身份区分、认证入口、权限边界、玩家资料、链接登录和玩家生命周期。

## 2. 身份模型

| 身份 | 数据标识 | 认证入口 | 能力边界 |
| --- | --- | --- | --- |
| 管理员 | `sys_user` + ADMIN 角色 | 密码登录 | 管理后台和授权运营操作 |
| 普通玩家 | `user_type` 普通用户 + `player_kind=NORMAL` | 管理员签发链接 | 完整玩家前台，不能进后台 |
| TEST 玩家 | `user_type=TEST` | 不走普通登录 | 联调、手工操作和审计 |
| BOT 玩家 | `TEST` + `player_kind=BOT` + `PLAYER_LINK`/服务端行为 | 管理员签发链接或服务端行为 | 通过链接进入完整玩家前台，也可自动/手动聊天和下注 |
| 服务端机器人 | `chat_robot`、`ROBOT` 消息 | 服务端调度 | 发布系统事件，不拥有玩家钱包和注单 |

## 3. 主要业务事实

- `sys_user`：用户、状态、认证模式、安全版本和昵称。
- `demo_user_account`：玩家账户、玩家分类、TEST 标识和钱包关联。
- `player_access_link`：链接哈希、密文、范围、过期、撤销和最近使用时间。
- `player_link_expiration_config`：每个普通玩家下次生成/刷新链接使用的有效期天数，默认 7 天；保存配置不改写当前链接，刷新链接才按新配置生成新 URL 和新 `expires_at`。
- `auth_session`：访问会话、刷新会话和撤销状态。
- 身份审计：创建、状态变更、角色变化、链接签发/撤销/恢复/刷新、软删除。

## 4. 核心流程

```text
管理员登录
  -> 创建普通玩家或 BOT
  -> 普通玩家生成 PLAYER_FULL 链接
  -> 玩家兑换链接并创建 PLAYER_LINK 会话
  -> 认证过滤器恢复玩家身份和权限
  -> 玩家访问 /room 的聊天、钱包和已开放游戏能力
```

软删除流程：

```text
删除确认
  -> sys_user 和 demo_user_account = DELETED
  -> security version 递增
  -> 撤销链接和会话
  -> 停用 BOT 行为
  -> 保留钱包、注单、结算、聊天和审计历史
```

## 5. 权限与安全规则

- 默认拒绝；管理员后台使用 `USER_MANAGE` 等明确权限。
- 普通玩家会话使用 `PLAYER_LINK` + `PLAYER_FULL`，不注入管理员权限。
- 链接 Token 不进入日志、历史详情或前端持久化存储。
- 数据库存储 Token 哈希和受控显示密文，原始链接只在受控响应中返回。
- 普通玩家和 BOT 均可签发链接；拉黑、刷新、停用、删除都必须让后续认证失败；旧会话是否立即失效以具体操作规则为准。
- 管理员刷新 Cookie 与玩家链接刷新 Cookie 分离；刷新请求声明使用端并校验会话认证模式。
- 标签页使用端提示可保存在 `sessionStorage`，但刷新 Token 和访问 Token 不得写入浏览器持久化存储。
