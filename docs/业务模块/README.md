# 业务模块基线维护规则

本目录是当前项目的业务模块长期基线。它不是一次性实施计划，也不是接口实现清单。

## 当前维护规则

- 一个核心业务模块保留一份基线文档，不按 Java 包、Vue 组件或单个接口拆分。
- 模块文档必须同时描述后端、前端、数据库、权限、状态、联动和验收边界。
- 新需求先更新模块归属、影响流程和待确认项，再创建 `docs/plans/` 里的实施计划。
- 代码完成后，先更新模块状态和证据等级，再把专项计划从当前入口移除或结项。
- 已完成计划不能继续作为当前规则来源；当前行为以源码、迁移、测试、模块基线和最新验收记录为准。

## 每份模块文档必须回答

1. 模块负责什么，不负责什么？
2. 有哪些参与者、状态和权限？
3. 哪些数据库事实由本模块写入？
4. 前后端通过什么入口联动？
5. 成功、失败、重复执行和服务重启如何处理？
6. 会影响哪些其他模块？
7. 当前已实现、已验证、未验证和待确认分别是什么？
8. 下一次需求应该从哪里开始补充？
