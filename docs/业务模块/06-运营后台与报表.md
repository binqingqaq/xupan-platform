# 业务模块 06：运营后台与报表

> 当前状态：统一后台已移除顶部功能导航，加入汇盈博式欢迎栏、状态赔率栏和线路域名栏；玩家工作台、上下分确认、最近记录、下注榜已形成；顶部赔率、特码赔率和限额已接入可持久化配置，报网控制仍为静态占位；服务器与生产待验收。

## 1. 当前入口

| 入口 | 职责 | 当前定位 |
| --- | --- | --- |
| `/console` | 统一后台壳体和模块导航 | 当前正式主入口 |
| `/console/players` | 玩家工作台 | 当前入口，复用统一工作台 |
| `/console/users` | 用户和管理员基础管理 | 当前入口 |
| `/console/robots` | 服务端机器人管理 | 当前入口 |
| `/console/operations` | 旧赔率、钱包、期号和注单运营 | 兼容入口，后续收敛 |
| `/admin/*` | 旧后台地址 | 自动跳转到 `/console` 对应路径 |

`/console` 已接入区域为：

- 左侧“上下分确认”：显示持久化待处理申请、同意、取消和两种提示音。
- 右侧“最近上下分记录”：按玩家/托查看当天实际生效的管理员上下分。
- 左侧导航下方“下注榜”：当前期普/托统计和明细、空白上期、最近 18 期开奖和倒计时。
- 顶部当前期状态下方“报网控制静态区域”：复刻报网类型、账号操作、押注、网盘余额、报网状态、自动退单、自动上报、超时订单和刷新按钮的视觉布局；当前不绑定接口、状态或点击逻辑。
- 顶部“欢迎与状态赔率区域”：欢迎人、托数量、过期时间、剩余积分和修改密码仍为静态占位；当前状态、赔率、限额、特码赔率和特码返水已按后台配置读取，其中赔率、特码赔率和特码返水可编辑自动保存，限额通过弹窗配置。
- 底部“线路域名静态区域”：复刻线路域名、开放注册和登录链接、复制链接的视觉布局。
- 底部“封盘与显示控制区域”：复刻预留封盘、取消、返水三个可编辑数字，显示右角和倒计时两个开/关开关，以及`↑移上`按钮；数字和开关只保存在当前页面，`↑移上`在本页交换该区域与线路域名区域的显示顺序。

## 2. 玩家工作台职责

- 普通玩家和 BOT 共用列表和详情结构。
- 展示内部编号、会员编号、昵称、头像、状态、余额和玩家分类。
- 创建普通玩家或 BOT。
- 执行软删除、上分、下分、链接管理和 BOT 行为配置；`停用玩家`入口已按运营要求从工作台移除，后端状态接口和前端处理函数保留备用。
- 查看普通玩家积分记录或托积分记录。

所有写操作都必须经过后台权限和服务端事实链路，前端不能自行聚合或修改业务状态。

## 3. 报表与对账

当前积分记录接口：

```text
GET /api/admin/player-desk/points-records?kind=NORMAL|BOT&date=yyyy-MM-dd
```

规则：

- 业务日按 `Asia/Shanghai` 每天 06:00 切换。
- 总流水取已有注单 `stake` 合计。
- 总盈亏取已结算注单 `net_profit` 合计。
- 上分/下分来自钱包流水。
- BOT 动作来自动作表。
- 报表只读现有事实，不建立第二套余额或盈亏事实。
- 抽水、飞单和代理分成暂不纳入。

### 3.1 上下分审批与最近记录

规划接口：

```text
GET  /api/admin/player-desk/point-requests
POST /api/admin/player-desk/point-requests/{requestId}/approve
POST /api/admin/player-desk/point-requests/{requestId}/reject
GET  /api/admin/player-desk/point-operations/recent?kind=NORMAL|BOT
```

规则：

- 前后台申请以 `player_point_request` 为待审批事实源。
- 实际积分变化以 `demo_balance_ledger` 为唯一事实源。
- 最近记录只读取 `ADMIN_GRANT` 和 `ADMIN_ADJUST`。
- 拒绝和待处理申请不进入最近记录。
- 审批成功后，前台申请和玩家工作台手动上下分进入同一列表。
- 默认按玩家显示，可切换到托。
- 继续使用 `USER_MANAGE` 权限并保留操作审计。

### 3.2 下注榜

当前只读接口：

```text
GET /api/admin/player-desk/bet-board?kind=NORMAL|BOT&limit=500
```

规则：

- 使用 `USER_MANAGE` 权限。
- 普通玩家和托按 `demo_user_account.player_kind` 区分。
- 当前期数量和总积分排除 `CANCELED` 注单。
- `普`/`托` 展示当前期下注明细，并重建玩法文本。
- `上期` 当前空白。
- `开奖` 读取最近 18 个已结算期号，展示 8 个位置的番值和状态，并使用服务端时间校准倒计时。
- `×` 保留显示但禁用，当前不提供管理员撤单。
- 不新增数据库迁移；后续撤单、上期榜单和报表扩展必须单独定义事实和验收。

### 3.3 赔率与限额配置

当前接口：

```text
GET /api/admin/player-desk/betting-config
PUT /api/admin/player-desk/betting-config/display
PUT /api/admin/player-desk/betting-config/limits
```

规则：

- 使用 `USER_MANAGE` 权限，普通玩家返回 403。
- Flyway V30 新增单行配置表 `game_betting_config`，保存展示字段和 13 项限额，并用 `CHECK` 约束保证展示值非负、限额为正、最小注额不大于最高注额。
- `特码赔率`同时写入 `game_odds` 的 `SPECIAL` 行，作为特玩法实际赔率；`赔率`和`特码返水`当前只保存和展示，不参与赔率或积分计算。
- 顶部输入不设确认按钮，`change`、回车或失焦时自动保存；保存失败时前端回滚到已保存值并显示原因。
- 限额弹窗 13 个字段全部必填，必须是大于 0 的整数，且最小注额不能大于最高注额；服务端独立复核，不依赖前端校验。
- 限额实际生效位置在下注入口，按单个玩家当前期累计判断，取消注单不占额度；一次组合下注只拒绝超限的那一项。
- 并发口径：聊天室下注路径由 `chat_room` 数据库行锁串行；直连下注接口由实例内 `PlayerBetLock` 按玩家串行，多实例部署前仍需数据库行锁或分布式锁。
- 配置读取和写入都走服务端事实，前端不缓存为业务事实源。

## 4. 权限边界

- 玩家工作台和积分报表使用 `USER_MANAGE`。
- 服务端机器人读取、修改、模板和重试使用独立机器人权限。
- 普通玩家不能访问后台报表接口。
- 后台接口的返回值不能包含原始 Token、密码或不必要的敏感信息。

## 5. 当前证据和风险

统一后台、玩家工作台、上下分审批、最近记录、下注榜、赔率限额配置和汇盈博式区域已有前端类型检查、构建、H2/Flyway、本机 MySQL 和浏览器验证。下注榜当前为只读能力；欢迎栏、报网控制和线路域名区域仍为视觉占位，不参与业务事实；状态赔率栏中的赔率和限额已经接入后端配置。真实多管理员并发、多实例额度竞争、服务重启、撤单专项、服务器和生产验收仍待补。

## 6. 新需求入口

新增后台菜单或报表时，必须先定义权限、数据事实源、筛选口径、业务日/时区、分页排序、脱敏和验收数据，不允许只增加一个前端入口。
