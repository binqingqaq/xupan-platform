## 3. 报表与对账

当前积分记录接口：

```text
GET /api/admin/player-desk/points-records?kind=NORMAL|BOT&date=yyyy-MM-dd
```

规则：

- 业务日按 `Asia/Shanghai` 每天 06:00 切换。
- `turnover` 是业务日内未撤销注单的下注本金合计；`singleFlow`/`doubleFlow` 分别按现有 BY220 对齐计算器统计单边/双边有效流水，`effectiveFlow` 按所属机器的 `rebate_mode` 选择。
- `singleRebate`/`doubleRebate` 分别按注单保存的返水比例快照计算，`effectiveRebate` 按机器 `rebate_mode` 选择；这是虚拟积分返水，不是抽水、现金扣成或代理分成。
- `netProfit` 汇总业务日已结算注单盈亏；已撤单注单排除，未结算注单不计入已结算盈亏及有效流水。`turnover` 仍包含未结算注单本金。
- 上分/下分来自钱包流水。
- BOT 动作来自动作表。
- 总计从业务日全量注单和积分流水计算；每个玩家卡片的注单、积分操作和托动作明细仍受 `detailLimit` 限制（默认 500，最大 1000），明细上限不会截断总计。
- 报表只读现有事实，不建立第二套余额或盈亏事实；普通玩家和托通过 `kind=NORMAL|BOT` 分别查询。BY220 源码仅能证实普通玩家积分汇总，托的独立筛选按本项目现有数据分类实现。
- 不实现抽水、飞单和代理分成。

### 3.1 上下分审批与最近记录

规划接口：

```text
GET  /api/admin/player-desk/point-requests
POST /api/admin/player-desk/point-requests/{requestId}/approve
POST /api/admin/player-desk/point-requests/{requestId}/reject
GET  /api/admin/player-desk/point-operations/recent?kind=NORMAL|BOT
```

规则：

- 前后台申请以 `player_point_request` 为待审批事实源。
- 实际积分变化以 `demo_balance_ledger` 为唯一事实源。
- 最近记录只读取 `ADMIN_GRANT` 和 `ADMIN_ADJUST`。
- 拒绝和待处理申请不进入最近记录。
- 审批成功后，前台申请和 `/console` 玩家工作台手动上下分进入同一列表。
- 默认按玩家显示，可切换到托。
- **权限现状（2026-10-08 使用者拍板后**已执行**）**：`/console` 上的审批与工作台走机器账号权限（`AGENT_CONSOLE_READ` + `AGENT_PLAYER_MANAGE`）；`/api/admin/player-desk` 与 `/api/admin/player-desk/**` 在 `SecurityConfig` 中**已收紧为仅 `PERM_AGENT_CONSOLE_READ`**——超管 `USER_MANAGE`、子账号 `AGENT_PLAYER_MANAGE` 一律 403，数据范围在服务层收敛为 `MACHINE`；**`PERM_AGENT_PLAYER_MANAGE` 在 `SecurityConfig.java` 的授权规则中已 0 命中（唯一出现是说明该角色被 403 的注释）**，`/api/admin/test-players` 死匹配器与 `betting-config` 读取豁免均已删除（定向用例 73 例全部通过）。**"超管不碰玩家"现在在服务端也成立**，不再只靠"前端不留入口"（BY220 依据：玩家运营动作全部在机器登录态下的代理后台：BY220: application/rbt/controller/Login.php:55、BY220: application/rbt/controller/Index.php:610）。两个遗留项见 [缺口表 §4.1 D1/D2](../对齐基线/BY220对齐缺口表.md)。审计保留。


### 3.3 赔率与限额配置

当前接口：

```text
GET /api/admin/player-desk/betting-config
PUT /api/admin/player-desk/betting-config/display
PUT /api/admin/player-desk/betting-config/limits
```

规则：

- 使用 `USER_MANAGE` 权限，普通玩家返回 403。
- Flyway V30 新增单行配置表 `game_betting_config`，保存展示字段和 13 项限额，并用 `CHECK` 约束保证展示值非负、限额为正、最小注额不大于最高注额。
- `特码赔率`同时写入 `game_odds` 的 `SPECIAL` 行，作为特玩法实际赔率；`赔率`和`特码返水`当前只保存和展示，不参与赔率或积分计算。
- 顶部输入不设确认按钮，`change`、回车或失焦时自动保存；保存失败时前端回滚到已保存值并显示原因。
- 限额弹窗 13 个字段全部必填，必须是大于 0 的整数，且最小注额不能大于最高注额；服务端独立复核，不依赖前端校验（BY220 对应 `robot.php` 的限额弹窗 `limitForm`：13 项限额均带必填 `*` 且输入框只许数字，BY220: application/rbt/view/index/admin_list.html:1180-1252；写入动作 BY220: application/rbt/controller/Index.php:712）。
- 限额实际生效位置在下注入口，按单个玩家当前期累计判断，取消注单不占额度；一次组合下注只拒绝超限的那一项。
- 并发口径：聊天室下注路径由 `chat_room` 数据库行锁串行；直连下注接口由实例内 `PlayerBetLock` 按玩家串行，多实例部署前仍需数据库行锁或分布式锁。
- 配置读取和写入都走服务端事实，前端不缓存为业务事实源。

- 玩家人工上下分、玩家工作台与积分报表只存在于机器端 `/console`，走 `AGENT_CONSOLE_READ` + `AGENT_PLAYER_MANAGE`（`MACHINE` 范围，只操作自己那台机器的玩家/托）。

- 平台侧与玩家相关的只有「在线玩家」：`ONLINE_PLAYER_READ`，**只读列表 + 强制下线 + 发消息**，不做积分、资料或建删。
- 服务端机器人读取、修改、模板和重试使用独立机器人权限。
- 普通玩家不能访问后台报表接口。
- 后台接口的返回值不能包含原始 Token、密码或不必要的敏感信息。
