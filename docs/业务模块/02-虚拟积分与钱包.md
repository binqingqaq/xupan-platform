# 业务模块 02：虚拟积分与钱包

> 当前状态：虚拟积分、钱包、聊天上下分申请、后台审批、提示音和最近记录已形成本机闭环；服务器与生产待验收。

## 1. 模块边界

本模块只处理虚拟积分，不处理现实资金。系统中的余额、下注额、返还、盈亏和流水不能兑换现金，也不代表充值、支付、提现、转账或代理分成。

## 2. 事实源

| 事实 | 来源 | 说明 |
| --- | --- | --- |
| 当前余额 | `demo_user_account` 钱包余额 | 只能由服务端事务更新 |
| 余额流水 | `demo_balance_ledger` | 不可用前端计算替代 |
| 下注扣分 | `game_bet` + 钱包流水 | 与注单关联、可幂等重试 |
| 结算返还/盈亏 | 结算服务 + 钱包流水 | 使用注单赔率快照 |
| 管理员上下分 | 管理员钱包接口 + 流水 | 必须记录操作人、原因和前后余额 |
| 上下分申请 | `player_point_request` | 聊天指令创建的待审批事实，审批通过后才写钱包流水 |

## 3. 核心流程

```text
管理员上分/下分
  -> USER_MANAGE 或钱包专用权限
  -> 玩家状态和金额校验
  -> 事务更新余额
  -> 写入流水和幂等标识
  -> 返回服务端最新余额
```

```text
玩家聊天申请上分/下分
  -> 创建 player_point_request(PENDING)
  -> 不改变余额
  -> 管理员同意
       -> 事务锁定钱包
       -> 写 ADMIN_GRANT / ADMIN_ADJUST 流水
       -> 申请标记 APPROVED
  -> 管理员拒绝
       -> 不改变余额
       -> 申请标记 REJECTED
```

```text
下注
  -> 校验玩家身份和期号
  -> 锁定/校验余额
  -> 保存注单和赔率快照
  -> 扣减虚拟积分
  -> 写流水
```

```text
结算
  -> 读取注单快照和开奖结果
  -> 幂等判定 WIN/DRAW/LOSE
  -> 更新注单状态和净盈亏
  -> 派彩或退回虚拟积分
  -> 写流水
```

## 4. 必须保持的规则

- 余额变化不能只改余额字段，必须有流水。
- 重试、重复请求和服务重启不能重复扣分或派彩。
- 软删除玩家保留历史钱包和流水，但不能继续上下分或下注。
- BOT 使用同一套钱包事实，不能用独立内存余额。
- 报表读取钱包流水，不能再建第二套统计余额。
- 待审批申请不是余额事实；当前余额仍以钱包表和服务端流水为准。
- 审批使用稳定幂等键，重复或并发审批不能重复加减积分。
- 拒绝申请保留 `REJECTED` 审计事实，但不产生钱包流水。
