## 1. 模块职责

负责平台、渠道组、代理、代理账号、玩家/托归属，以及平台超级管理端和代理端的数据隔离。

本模块不负责：

- 玩家钱包、下注、开奖和结算的金额计算。
- 代理钱包、信用、冻结和结算。
- 上游适配器的**实现**（本模块只负责机器的报网配置：`report_type`/`report_username`/盘口/线路域名 与 `center_agent_id` 绑定；适配器与中心侧逻辑在 [11 中心上游](11-中心上游.md)）。
- 代理赔率、封盘和取消的**结算公式**已按 BY220 接入（2026-10-02）：机器赔率参与下注赔率快照，封盘与取消秒数参与下注和撤单判定，规则见 [03 期号玩法下注与结算](03-期号玩法下注与结算.md) 第 2.1 节和 [代理赔率返水封盘取消结算映射实施计划](../plans/2026-10-02-代理赔率返水封盘取消结算映射实施计划.md)。
- 代理钱包、信用额度、冻结和**第二层账本**（二层结算已由 [11 中心上游](11-中心上游.md) 实现，本模块只负责机器的报网配置与 `center_agent_id` 绑定）。
- 玩家在代理之间转移。
- 现实资金、代理分成或外部投注平台（**永久不做**）。

## 2. 组织模型

第一版固定为：

```text
平台超级管理员
  └─ 可选渠道组
       └─ 代理
            └─ 玩家 / 托
```

同时支持代理不挂渠道组，直接归平台管理（BY220 侧对应"机器 `x_robot.uid` 为空"，即超管直接建机器、不挂子账号：BY220: local/schema-base.sql:546）。

> **组织模型核对（BY220 事实）**：BY220 的实际层级是「子账号 `x_admin` → 机器 `x_robot.uid` → 玩家/托 `x_rbuser.isrobot`」三层，**没有"渠道组"这一层**（BY220: local/schema-base.sql:11、BY220: local/schema-base.sql:516、BY220: local/schema-base.sql:546）；BY220 里"代理"就是机器（`x_robot`），用自己的 `UserName`/`password` 登录 `robot.php`（BY220: application/rbt/controller/Login.php:55）。
>
> **未对齐核对**：本项目的"渠道组 / 代理 / 玩家"三层是 xupan 自组织模型，尚未与 BY220 逐项核对。

### 角色

| 角色 | 说明 |
| --- | --- |
| 平台超级管理员 | 使用正式 BY220 超级管理后台 `/platform-admin`。可管理渠道组、代理和玩家归属；与玩家相关的页面**只有 BY220 本来就有的在线玩家 `/platform-admin/online-players`（只读列表 + 强制下线 + 发消息）**。**不碰玩家积分/资料/建删，也没有玩家运营面**（BY220 `admin/controller/*` 查 `db('user')` 零命中）。**不再进 `/console`**（2026-10-08）；上一批越界新增的 `/platform-admin/player-workbench` 已按方案 A 删除 |
| 渠道组 | 可选管理分组，不拥有玩家、不建立钱包、不承载登录 |
| 代理 | 实际运营主体，通过**机器账号登录 `/console`**（BY220 `robot.php`，机器隔离）。**`/console` 只接受机器账号**：路由门禁 `requiredRoles: ['AGENT']` + `excludeRoles: ['ADMIN','SUB_ACCOUNT']`，平台管理员/子账号进入另一入口 |
| 玩家/托 | 归属代理，继续使用现有玩家、钱包、下注、聊天和托行为能力 |

## 3. 业务事实

### `agent_group`

- 渠道组编码和名称。
- 状态只允许 `ACTIVE`、`DISABLED`。
- 渠道组停用前必须没有启用代理（BY220 没有"渠道组"表，只有 `x_admin` 子账号与 `x_robot` 机器：BY220: local/schema-base.sql:11、BY220: local/schema-base.sql:516）。
- 本条属 xupan 自组织模型校验，尚未核对：未对齐核对。
- 不做物理删除。

### `agent`

- 代理编码、名称、所属渠道组。
- 可绑定一个 `sys_user` 代理账号。
- `PLATFORM_DIRECT` 是系统内置平台直属代理，不允许停用，也不绑定登录账号。
- 普通代理必须绑定账号（BY220 侧机器自带 `UserName`/`password` 并据此登录：BY220: local/schema-base.sql:532、BY220: local/schema-base.sql:547、BY220: application/rbt/controller/Login.php:55）。
- 不做物理删除。

### `demo_user_account.agent_id`

- 玩家和托的当前代理归属。
- 存量玩家和托迁移时全部归入平台直属代理。
- 新玩家和托通过数据库默认归属平台直属代理。
- 第一版只允许把平台直属玩家一次性分配给普通代理，不允许代理间转移。

## 4. 权限与认证

新增权限：

| 权限 | 用途 |
| --- | --- |
| `AGENT_MANAGE` | 平台管理员管理渠道组、代理和玩家归属 |
| `AGENT_CONSOLE_READ` | 代理读取自己的代理后台。**自迁移 V76（2026-10-08，版本沿革标识）起只由 `AGENT` 持有**，已从 `ADMIN`/`SUB_ACCOUNT` 撤销（BY220 `robot.php` 只认 `x_robot`：BY220: application/rbt/controller/Login.php:55；`x_admin` 不含此域；权限码本身保留） |
| `AGENT_PLAYER_MANAGE` | **玩家与托的唯一运营权限**：代理（机器账号）创建玩家和托、上下分、上下分申请审批，以及玩家链接查看/刷新/拉黑/恢复；`/api/admin/player-desk/**` 的放行集合里也含它（`SecurityConfig`，见 §9 未执行项）。**注意**：本权限**不再**对应任何平台侧玩家运营页面（`/platform-admin/player-workbench` 已删除） |

新增角色：

- `AGENT`：拥有 `AGENT_CONSOLE_READ` 和 `AGENT_PLAYER_MANAGE`；**`/console` 仅此角色可进**。
- `ADMIN`：拥有 `AGENT_MANAGE` 和 `AGENT_PLAYER_MANAGE`；**自迁移 V76（版本沿革标识）起不再持有 `AGENT_CONSOLE_READ`**。其 `AGENT_PLAYER_MANAGE` 现仅用于 `/api/admin/player-desk/**` 的放行集合（无对应平台侧页面，见 §9 未执行项）。

代理账号使用普通密码登录模式。代理停用时会同步将账号置为 `DISABLED`、提升安全版本并撤销已有会话。

会话按**入口**隔离（迁移 V75，2026-10-08，版本沿革标识）：`auth_session.entry` = `PLATFORM`/`CONSOLE`；三个刷新 Cookie（`xupan_refresh` 平台 / `xupan_console_refresh` 代理 / `xupan_player_refresh` 玩家链接）；跨入口刷新 401 且只清该入口 Cookie、不撤销会话；退出只清当前入口。服务端纵深防御：显式 `CONSOLE` 头登录要求账号含 `AGENT`，否则 403 `AUTH_ENTRY_FORBIDDEN`「该入口只接受机器账号」且不签发任何 Cookie。

## 5. 核心流程

### 创建渠道组

```text
平台管理员
  -> AGENT_MANAGE
  -> 创建渠道组
  -> 写审计日志
```

### 创建代理

```text
平台管理员
  -> 校验代理编码、登录名和渠道组
  -> 创建 sys_user
  -> 分配 AGENT 角色
  -> 创建 agent 并绑定账号
  -> 写审计日志
```

任一步失败时整个事务回滚。

### 玩家归属

```text
平台管理员
  -> 选择平台直属玩家
  -> 选择启用中的普通代理
  -> 更新 demo_user_account.agent_id
  -> 写审计日志
```

如果玩家已经不属于平台直属代理，更新被拒绝。

### 代理后台

```text
代理账号密码登录
  -> AGENT_CONSOLE_READ
  -> 查询自己的代理资料
  -> 只查询 agent_id 等于自己的玩家/托
  -> 创建玩家/托时校验 AGENT_PLAYER_MANAGE
  -> 普通玩家创建后自动归属当前代理并签发 PLAYER_FULL 链接
  -> 托创建后归属当前代理、启用托行为并签发玩家链接
  -> 托数量不能超过 agent.bot_count
  -> 普通玩家上分时扣减代理积分并增加玩家余额；下分时反向处理
  -> 托上下分只调整玩家钱包，不改变代理积分（BY220 规则）
  -> 上下分使用现有 demo_balance_ledger 和请求幂等键
  -> 玩家链接支持查看、刷新、拉黑和恢复；所有操作先校验 player 属于当前 agent
  -> 运营数据按业务日汇总当前代理下注笔数、流水、净盈亏、待结算和活跃玩家
  -> 可从当前代理玩家下钻查看注单和积分流水明细
```

代理后台当前支持玩家和托创建、普通玩家/托上下分、玩家链接查看/刷新/拉黑/恢复、机器范围运营汇总和玩家注单/积分流水明细；这些查询按当前机器 `agent_id` 隔离。玩家前台现已在本地实现同一 `/room` 内按消息机器快照过滤，普通玩家与托同机互见，跨机隔离；玩家个人当期注单仅本人可见。机器运营汇总新增 BY220 单边/双边与配置选择流水，保留总投注额、净盈亏和普/托金额统计。后端全量测试、前端测试/类型检查/构建通过；V78 已在本机 MySQL 8.4.11 迁移。浏览器人工验收未执行，服务器/生产未操作。详情见[澳8番摊专项计划](../plans/2026-10-09-澳8番摊代理玩家隔离严格对齐计划.md)。代理赔率/返水/封盘/取消的结算映射已完成（2026-10-02）。**代理钱包、信用额度和冻结仍未完成**；第二层结算已由[11 中心上游](11-中心上游.md)实现。逐项 BY220 落点：BY220: application/rbt/controller/Index.php:677（建玩家/托，托数量上限 `tuoNum`）、BY220: application/rbt/controller/Index.php:610（`UpDownScore` 上下分）、BY220: application/rbt/controller/Index.php:252、`:258`、`:298`（上下分申请与审批）、BY220: application/rbt/controller/Index.php:992（`getUserLink` 链接）、BY220: application/rbt/controller/Index.php:151（`SetBlack` 拉黑）、BY220: application/rbt/controller/Index.php:1062（`Getalltongji` 运营汇总）、BY220: application/rbt/controller/Index.php:330、`:388`（注单与积分流水明细）。

### 子账号是机器的上游资金池（BY220，2026-10-04 实现）
