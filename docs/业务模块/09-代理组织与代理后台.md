# 业务模块 09：代理组织与代理后台

> 当前状态：代理组织底层、代理账号、代理后台列表、“创建玩家/托”“上下分”“玩家链接管理”、基础运营数据和玩家注单/流水明细已完成。正式 BY220 超级管理后台入口 `/platform-admin` 已恢复独立“子账号”和“机器管理”；`/console/agents` 仅保留为临时兼容/内部辅助页，不再作为 BY220 正式菜单。服务器与生产未验收。

> 当前实现基线：Flyway V54；当前全量证据为后端 `320/320`、前端 `126/126`、`typecheck`/生产构建、本机 MySQL 8.4.11 V54 运行态。

## 1. 模块职责

负责平台、渠道组、代理、代理账号、玩家/托归属，以及平台超级管理端和代理端的数据隔离。

本模块不负责：

- 玩家钱包、下注、开奖和结算的金额计算。
- 代理钱包、信用、冻结和结算。
- 报网类型、盘口线路和上游适配器。
- 代理赔率/返水/封盘/取消设置的最终结算公式验证；当前只在结构化结算链路中保存部分配置，不能宣称已按 BY220 公式生效。
- 代理钱包、信用额度、冻结和二层结算。
- 玩家在代理之间转移。
- 现实资金、代理分成或外部投注平台。

## 2. 组织模型

第一版固定为：

```text
平台超级管理员
  └─ 可选渠道组
       └─ 代理
            └─ 玩家 / 托
```

同时支持代理不挂渠道组，直接归平台管理。

### 角色

| 角色 | 说明 |
| --- | --- |
| 平台超级管理员 | 使用正式 BY220 超级管理后台 `/platform-admin`；`/console` 保留为现有详细运营工作台。可管理渠道组、代理和玩家归属 |
| 渠道组 | 可选管理分组，不拥有玩家、不建立钱包、不承载登录 |
| 代理 | 实际运营主体，通过独立账号登录 `/agent` |
| 玩家/托 | 归属代理，继续使用现有玩家、钱包、下注、聊天和托行为能力 |

## 3. 业务事实

### `agent_group`

- 渠道组编码和名称。
- 状态只允许 `ACTIVE`、`DISABLED`。
- 渠道组停用前必须没有启用代理。
- 不做物理删除。

### `agent`

- 代理编码、名称、所属渠道组。
- 可绑定一个 `sys_user` 代理账号。
- `PLATFORM_DIRECT` 是系统内置平台直属代理，不允许停用，也不绑定登录账号。
- 普通代理必须绑定账号。
- 不做物理删除。

### `demo_user_account.agent_id`

- 玩家和托的当前代理归属。
- 存量玩家和托迁移时全部归入平台直属代理。
- 新玩家和托通过数据库默认归属平台直属代理。
- 第一版只允许把平台直属玩家一次性分配给普通代理，不允许代理间转移。

## 4. 权限与认证

新增权限：

| 权限 | 用途 |
| --- | --- |
| `AGENT_MANAGE` | 平台管理员管理渠道组、代理和玩家归属 |
| `AGENT_CONSOLE_READ` | 代理读取自己的代理后台 |
| `AGENT_PLAYER_MANAGE` | 代理创建玩家和托、上下分以及玩家链接查看/刷新/拉黑/恢复 |

新增角色：

- `AGENT`：拥有 `AGENT_CONSOLE_READ` 和 `AGENT_PLAYER_MANAGE`。
- `ADMIN`：拥有 `AGENT_MANAGE`、`AGENT_CONSOLE_READ` 和 `AGENT_PLAYER_MANAGE`。

代理账号使用普通密码登录模式。代理停用时会同步将账号置为 `DISABLED`、提升安全版本并撤销已有会话。

## 5. 核心流程

### 创建渠道组

```text
平台管理员
  -> AGENT_MANAGE
  -> 创建渠道组
  -> 写审计日志
```

### 创建代理

```text
平台管理员
  -> 校验代理编码、登录名和渠道组
  -> 创建 sys_user
  -> 分配 AGENT 角色
  -> 创建 agent 并绑定账号
  -> 写审计日志
```

任一步失败时整个事务回滚。

### 玩家归属

```text
平台管理员
  -> 选择平台直属玩家
  -> 选择启用中的普通代理
  -> 更新 demo_user_account.agent_id
  -> 写审计日志
```

如果玩家已经不属于平台直属代理，更新被拒绝。

### 代理后台

```text
代理账号密码登录
  -> AGENT_CONSOLE_READ
  -> 查询自己的代理资料
  -> 只查询 agent_id 等于自己的玩家/托
  -> 创建玩家/托时校验 AGENT_PLAYER_MANAGE
  -> 普通玩家创建后自动归属当前代理并签发 PLAYER_FULL 链接
  -> 托创建后归属当前代理、启用托行为并签发玩家链接
  -> 托数量不能超过 agent.bot_count
  -> 普通玩家上分时扣减代理积分并增加玩家余额；下分时反向处理
  -> 托上下分只调整玩家钱包，不改变代理积分（BY220 规则）
  -> 上下分使用现有 demo_balance_ledger 和请求幂等键
  -> 玩家链接支持查看、刷新、拉黑和恢复；所有操作先校验 player 属于当前 agent
  -> 运营数据按业务日汇总当前代理下注笔数、流水、净盈亏、待结算和活跃玩家
  -> 可从当前代理玩家下钻查看注单和积分流水明细
```

代理后台当前支持玩家和托创建、普通玩家/托上下分、玩家链接查看/刷新/拉黑/恢复、基础运营汇总和玩家注单/流水明细；玩家范围始终按当前代理 `agent_id` 隔离。代理赔率/返水/封盘/取消的真实结算映射、代理钱包、信用和二层结算尚未完成。

## 7. 页面

| 路由 | 页面 | 权限 |
| --- | --- | --- |
| `/console/agents` | 临时兼容/内部辅助页，不是 BY220 正式菜单 | `AGENT_MANAGE` |
| `/agent` | 代理后台 | `AGENT_CONSOLE_READ` |

登录完成后：

- 有 `USER_MANAGE` 的管理员默认进入 `/console`。
- 只有代理权限的账号默认进入 `/agent`。
- 明确指定安全的站内 `redirect` 时优先使用该路径，再由路由权限二次校验。

## 8. 审计和失败恢复

- 创建渠道组、创建代理、启停代理和玩家归属都会写操作审计。
- 代理账号创建、角色分配和代理记录创建处于同一事务。
- 代理停用是幂等状态更新；重复停用不会重新创建业务事实。
- 玩家归属更新带当前代理条件，归属已变化时返回冲突，不静默覆盖。
- 系统内置平台直属代理受保护，不能被普通管理操作停用。

## 10. 当前限制和下一步

当前限制：

- 玩家不能在代理之间转移。
- 没有代理钱包、信用额度、冻结和二层结算。
- 代理赔率、返水、封盘和取消设置尚未证明已按 BY220 公式影响下注/结算；禁止只做“可保存但不生效”的页面。
- 代理级报表目前是基础运营汇总和玩家明细，尚无完整日期/期号/状态筛选、导出和长期统计。
- 没有代理聊天室、托自动行为的代理范围可见性。
- 没有报网、盘口、中心上游和外部适配。

下一步应作为独立计划处理：

1. 先读 BY220 `rbt/Index.php` 的赔率、返水、封盘、取消控制器和 `common.php` 的 `peilv`/`tePeilv` 结算公式，建立字段/公式/状态映射。
2. 将代理配置接入当前 `SettlementService`、`game_bet.odds_snapshot` 和 `game_odds`，以自动化和本机 MySQL 证明实际生效，再补页面。
3. 代理级明细筛选、区间统计和导出。
4. 代理聊天室、托自动行为和可见性。
5. 代理钱包、信用和冻结。
6. 报网、盘口、上游和二层账。
