# 业务模块 09：代理组织与代理后台

> 当前状态：代理组织底层、代理账号和只读后台已形成本机闭环；**但“代理组织管理”是临时合并名称，不符合用户确认的 BY220 严格平移规则，最终必须拆回“子账号”和“机器管理”两个独立页面。** 服务器与生产未验收。
>
> 当前实现基线：Flyway V34。
>
> 本文描述代理组织的第一阶段能力，不包含代理钱包、报网、盘口、二层结算和外部上游。

## 1. 模块职责

负责平台、渠道组、代理、代理账号、玩家/托归属，以及平台超级管理端和代理端的数据隔离。

本模块不负责：

- 玩家钱包、下注、开奖和结算的金额计算。
- 代理钱包、信用、冻结和结算。
- 报网类型、盘口线路和上游适配器。
- 代理创建玩家、上下分或修改赔率。
- 玩家在代理之间转移。
- 现实资金、代理分成或外部投注平台。

## 2. 组织模型

第一版固定为：

```text
平台超级管理员
  └─ 可选渠道组
       └─ 代理
            └─ 玩家 / 托
```

同时支持代理不挂渠道组，直接归平台管理。

### 角色

| 角色 | 说明 |
| --- | --- |
| 平台超级管理员 | 使用现有 `/console`，拥有全部平台权限，可管理渠道组、代理和玩家归属 |
| 渠道组 | 可选管理分组，不拥有玩家、不建立钱包、不承载登录 |
| 代理 | 实际运营主体，通过独立账号登录 `/agent` |
| 玩家/托 | 归属代理，继续使用现有玩家、钱包、下注、聊天和托行为能力 |

## 3. 业务事实

### `agent_group`

- 渠道组编码和名称。
- 状态只允许 `ACTIVE`、`DISABLED`。
- 渠道组停用前必须没有启用代理。
- 不做物理删除。

### `agent`

- 代理编码、名称、所属渠道组。
- 可绑定一个 `sys_user` 代理账号。
- `PLATFORM_DIRECT` 是系统内置平台直属代理，不允许停用，也不绑定登录账号。
- 普通代理必须绑定账号。
- 不做物理删除。

### `demo_user_account.agent_id`

- 玩家和托的当前代理归属。
- 存量玩家和托迁移时全部归入平台直属代理。
- 新玩家和托通过数据库默认归属平台直属代理。
- 第一版只允许把平台直属玩家一次性分配给普通代理，不允许代理间转移。

## 4. 权限与认证

新增权限：

| 权限 | 用途 |
| --- | --- |
| `AGENT_MANAGE` | 平台管理员管理渠道组、代理和玩家归属 |
| `AGENT_CONSOLE_READ` | 代理读取自己的代理后台 |

新增角色：

- `AGENT`：只拥有 `AGENT_CONSOLE_READ`。
- `ADMIN`：拥有 `AGENT_MANAGE` 和 `AGENT_CONSOLE_READ`。

代理账号使用普通密码登录模式。代理停用时会同步将账号置为 `DISABLED`、提升安全版本并撤销已有会话。

## 5. 核心流程

### 创建渠道组

```text
平台管理员
  -> AGENT_MANAGE
  -> 创建渠道组
  -> 写审计日志
```

### 创建代理

```text
平台管理员
  -> 校验代理编码、登录名和渠道组
  -> 创建 sys_user
  -> 分配 AGENT 角色
  -> 创建 agent 并绑定账号
  -> 写审计日志
```

任一步失败时整个事务回滚。

### 玩家归属

```text
平台管理员
  -> 选择平台直属玩家
  -> 选择启用中的普通代理
  -> 更新 demo_user_account.agent_id
  -> 写审计日志
```

如果玩家已经不属于平台直属代理，更新被拒绝。

### 代理后台

```text
代理账号密码登录
  -> AGENT_CONSOLE_READ
  -> 查询自己的代理资料
  -> 只查询 agent_id 等于自己的玩家/托
```

代理后台当前为只读，不提供创建玩家、上下分、赔率或注单操作。

## 6. 接口

平台超级管理端：

```text
GET    /api/admin/agent-groups
POST   /api/admin/agent-groups
PATCH  /api/admin/agent-groups/{groupId}/status

GET    /api/admin/agents
POST   /api/admin/agents
PATCH  /api/admin/agents/{agentId}/status

GET    /api/admin/agent-player-assignments
PUT    /api/admin/agent-player-assignments/{userId}
```

代理后台：

```text
GET /api/agent/me
GET /api/agent/players
```

## 7. 页面

| 路由 | 页面 | 权限 |
| --- | --- | --- |
| `/console/agents` | 平台代理组织管理 | `AGENT_MANAGE` |
| `/agent` | 代理后台 | `AGENT_CONSOLE_READ` |

登录完成后：

- 有 `USER_MANAGE` 的管理员默认进入 `/console`。
- 只有代理权限的账号默认进入 `/agent`。
- 明确指定安全的站内 `redirect` 时优先使用该路径，再由路由权限二次校验。

## 8. 审计和失败恢复

- 创建渠道组、创建代理、启停代理和玩家归属都会写操作审计。
- 代理账号创建、角色分配和代理记录创建处于同一事务。
- 代理停用是幂等状态更新；重复停用不会重新创建业务事实。
- 玩家归属更新带当前代理条件，归属已变化时返回冲突，不静默覆盖。
- 系统内置平台直属代理受保护，不能被普通管理操作停用。

## 10. 当前限制和下一步

当前限制：

- 代理后台只读。
- 代理不能创建玩家或托。
- 代理不能执行上下分。
- 玩家不能在代理之间转移。
- 没有代理钱包、额度、风险、报网和结算。
- 没有代理级报表、聊天室和数据导出。

下一步应作为独立计划处理：

1. 代理创建玩家和托。
2. 代理上下分与审批边界。
3. 代理级注单、积分和报表。
4. 代理聊天室、托自动行为和可见性。
5. 代理钱包、信用和冻结。
6. 报网、盘口、上游和二层账。
