# BY220 报网业务与订单全流程代码梳理

> 本文回答两个问题：BY220 的“报网”实际怎么跑；一笔玩家订单从下注到本地结算，各环节由什么代码和数据承接。
>
> **证据范围**：依据只读参考仓库 `D:\codes\liuhecai\_github-by220-cp` 当前源码静态梳理，未在本轮启动 BY220 做运行验证。文中“源码行为”描述代码现状；“业务解释”帮助理解字段，不代表外部网盘一定返回成功。

## 1. 一句话说明报网

BY220 的报网（代码中也叫“飞单”）是：**代理机器把本地已受理的玩家订单，通过某一种网盘适配器主动发送到所配置的网盘账号/盘口。**

报网不是玩家下注本身，也不是 BY220 中心接单。BY220 本地保存玩家注单并负责玩家积分及开奖结算；目标网盘若接受了订单，则该订单在网盘侧形成另一份订单。当前源码没有显示 BY220 从网盘取回开奖结算结果并据此结算本地玩家。

```text
玩家下注 -> BY220 校验/扣本地积分 -> 写本地 record 注单
                                      |
                                      +-> 满足条件时调用网盘适配器 -> 写回 flyers_status
                                      |
                                      +-> 本地封盘/开奖 -> jiesuan -> 更新本地玩家积分和 record.status

网盘订单 -> 由网盘侧自行处理/结算；BY220 当前未见把该结果导回本地玩家账的代码
```

## 2. 角色、配置和登录

### 2.1 谁提供什么

| 角色 | BY220 中的职责 | 对应代码/数据 |
| --- | --- | --- |
| 平台超级管理员 | 配置网盘名称、网盘代码、站点地址 | `application/admin/controller/Index.php:37-98` 的网盘配置动作；数据表 `rbwp` |
| 代理机器账号 | 选择已配置网盘，填写网盘账号/密码、盘口等选项，保存后登录 | `application/rbt/view/index/admin_list.html:900-980` 报网栏；`application/rbt/controller/Index.php:752` `flyersSave()`、`:784` `flyersLogin()`；数据表 `rbfly` |
| 玩家 | 在代理机器名下下注 | `application/chat/controller/Index.php:800-810` 普通下注调用；本地玩家 `rbuser` 与注单 `record` |
| 网盘 | 校验登录并接收适配器发送的订单，返回结果和账户信息 | `extend/Flyers/` 下的网盘适配器；目标站点取自 `rbwp.websiteUrl` |

账号/密码是代理在“设置账号”中填写、保存给 BY220 使用的网盘凭据。BY220 源码能证明“这些凭据被发起登录/报单的适配器使用”，但不能证明凭据由谁申请、网盘如何给代理开户，那部分属于外部网盘自己的业务。

### 2.2 配置到登录的实际顺序

1. 超级管理员先在 BY220 网盘设置中配置一项 `rbwp`：网盘名称、代码和 `websiteUrl`。
2. 代理在报网栏选择网盘/盘口，填写用户名、密码，设置“自动上报网盘”和“失败退单”。勾选框状态变化会分别调用 `flyersAuto()` / `flyersDraw()`。
3. 勾选框变化走 `changewp()`，它先调用 `flyUpdate()` 更新 `rbfly`，再调用 `rbUpdate()` 更新当前机器 `robot`。点击“保存账号”则另走 `flyersSave()`：写入/更新 `rbfly`、将 `flyers_online`/`money`/`betting` 置 0，并更新机器所选网盘类型；接口响应“保存成功,请登录”。所以“保存账号”不等于“已登录”。
4. 代理点击登录。`flyersLogin()` 按 `rbwp.code` 选择适配器，再把配置的账号密码交给适配器；需要验证码的页面还会传验证码参数。
5. 适配器返回成功时，代码把在线状态写为 1。后台 WebSocket 定时轮询网盘账户信息，并更新在线状态、网盘余额和押注/未结金额。

**报网代码执行时必须同时满足两个条件**：机器 `robot.flyers_online == 1`，并且 `robot.flyers_auto == 1`。已登录不代表自动上报开启；勾选自动上报也不代表已登录。

**同名字段的位置要注意**：`rbfly` 保存网盘账户配置时也有 `flyers_auto` / `flyers_withdraw`；页面状态查询 `flyersInfo()` 返回的开关值取机器会话 `$user`，而 `feidan()` 读取机器 `robot`。页面勾选框变化时 `changewp()` 会同步写 `rbfly` 和 `robot`；单击“保存账号”的 `flyersSave()` 只写 `rbfly` 的两个开关值，不显式同步 `robot` 对应开关。维护或排查时不能只查一张表，应以报网执行实际读取的 `robot` 字段判断，并核对页面/`rbfly` 是否一致。

### 2.3 源码现状中的登录问题

`flyersLogin()` 的失败分支也会调用 `rbUpdate(['flyers_online' => '1'])`；另外，代码在没有账号密码时预置的 `$login['bOK']` 是 `'0'`，可能走到成功响应分支。因此当前“在线”字段不能单独作为外部登录真实成功的可靠证据。这是源码问题，不是应该保留的业务规则。

`BY220_LOCAL_MODE=1` 是本地模拟登录分支：它直接把在线写为 1、余额/押注写为 0，并返回“本地模拟登录成功”，不等于外部账号校验、订单已发送或外部订单已结算。

## 3. 从玩家下注到本地注单：数据如何形成

下面以普通玩家发来 `单 10`、当前期为 `Q1001` 为例。具体游戏玩法文本因彩种而异，报网主链路相同。

1. 玩家聊天消息进入 `application/chat/controller/Index.php`。控制器/公共下注函数解析玩家、机器、期号、玩法文本和金额，检查当前期、限额和玩家余额。
2. `application/common.php::xiazhu()` 等下注函数执行玩法限额检查；通过后对 `rbuser.score` 扣除 10。
3. `xiazhu()` 调用 `addDan3()`（特殊玩法/分盘也有 `xiazhu4()` → `addDan4()` 路径）。`addDan3()` 往 `record` 插入一条下注记录，保存期号、生成时间、玩法文本、金额、玩家/机器标识、赔率/返水快照、`status=0` 等信息。
4. `addDan3()` 对“普通玩家、非吃单、非托、且彩种不是 75/5”的记录会直接调用 `feidan()`。`addDan4()` 也有对应的直接调用条件。注单插入和本地扣分先发生，报网是之后的处理。

核心数据可以这样读：

| 数据 | 表/字段 | 用途 |
| --- | --- | --- |
| 玩家可用积分 | `rbuser.score` | 下注时扣减；本地中奖/和局/取消时按结算规则返还或增加 |
| 本地下注事实 | `record` | 玩家、机器、期号、玩法、下注积分、下注时间、赔率/返水快照、开奖结算状态 |
| 注单本地结算状态 | `record.status`、`record.ying` 等 | `status` 表示本地未结/已结；`ying` 等保存输赢结果/金额 |
| 注单报网状态 | `record.flyers_status` | 网盘发送结果；报网状态与本地结算状态分开 |
| 机器网盘配置 | `rbfly` | 网盘账号/密码、选定网盘和盘口、自动上报、失败退单、在线及账户信息 |
| 网盘类型/站点 | `rbwp` | 适配器代码和目标站点地址 |

注意：`record.flyers_status` 在 `local/schema-base.sql` 中是可空字段，创建注单的 `addDan3()` 本身没有显式写它；不能仅根据“新单一定初始为 0”推断数据库缺省值。代码读取时会把 0/1 作为未报、2 作为已报、3 作为失败来显示。

## 4. 从本地注单到网盘：发送和回写

### 4.1 `feidan()` 的处理顺序

主要入口是 `application/common.php::feidan($value, $str, $id, $xiaList)`：

1. 确认注单所属玩家存在，且玩家配置 `isFeidan` 允许报网；未允许时直接返回，不向适配器下单。
2. 读取 `record` 注单、本机 `robot` 与对应 `rbfly`、`rbwp` 配置。
3. 对 `type=3` 的记录检查等待窗口：订单生成后需经过 `robot.cancel + 5` 秒；未到时间时将 `flyers_status` 写成 3 并返回，等待后续重试。
4. 仅当 `flyers_online=1` 且 `flyers_auto=1` 时，按网盘代码创建适配器，将本地玩法/金额转换成目标格式，再调用相应的 `make()` 或 `subMake()` 下单。
5. 适配器返回值 2 被写为已报；返回值 3 被写为失败。其他返回码的实际含义需要按各适配器核对，不能一概解释为成功。
6. 若结果为失败且机器开着失败退单，代码给玩家加回注单金额、发取消消息并删除这条 `record`；若关闭失败退单，则保留订单并写失败状态。

`extend/Flyers/K28.php` 有登录、账户查询、`make()`、`subMake()` 等实现；其他平台适配器位于同目录（文件名以仓库实际清单为准）。适配器负责网盘协议转换和请求，`feidan()` 负责选择配置、调用适配器并处理本地状态。

### 4.2 定时重试与人工重报

- `application/console/Websocket.php` 每约 2.4 秒扫描 `record.type=3`、`record.status=0`、`isTuo=0`、`flyers_status=3` 的记录，再调回 `feidan()`。
- 这会同时扫描“发送失败”和“还没到等待时间”的记录，因为两者都用状态 3。当前源码中没有看到把两种原因拆开。
- `application/rbt/controller/Index.php::reFeidan()` 允许代理对 `flyers_status` 为 0 或 3 的订单手动重报，并检查是否临近封盘。

当前源码证据只能说明会再次调用发送适配器；未发现基于稳定订单号的网盘幂等保障或请求超时后先查网盘订单的完整逻辑。若请求超时但网盘已经收单，自动/手动重试可能造成重复，因此“超时”不能直接当成“网盘肯定没收到”。

## 5. 本地开奖结算：与报网并行但独立

1. 开奖流程 `openKj()` 读取当前彩种/期号下 `record.status=0` 的本地下注记录。
2. 对每条记录调用 `application/common.php::jiesuan($value, $kj)`，按玩法、开奖结果以及订单保存的赔率等计算结果。
3. `xzjs()` 写入本地订单输赢字段；对中奖或和局等需要返分的结果，增加 `rbuser.score`。未中奖订单之前下注时已扣分，结算后不再返还本金。
4. `jiesuan()` 最后把 `record.status` 改为 1，表示本地结算已完成。

开奖查询的筛选条件是本地 `record.status=0`，并不以 `flyers_status` 是否为 2 作为筛选条件。因此从源码看，报网失败但未被退单删除的订单，仍可能进入 BY220 本地开奖结算。**报网成功不是本地结算成功；报网失败也不自动取消本地订单。**

BY220 没有在上述链路中读取目标网盘的开奖/结算结果并回写本地玩家积分。所谓“最后闭环”是两条并行链：

```text
本地链：玩家下注 -> 扣本地积分 -> record -> BY220 开奖 -> 本地玩家结算
报网链：同一 record -> 适配器发送 -> 网盘接受/拒绝 -> flyers_status
                                   网盘侧之后自行处理，本地未见结算结果回流
```

## 6. 一笔订单的完整例子

### 前置配置

平台管理员在 `rbwp` 配置网盘类型 W 和站点地址。代理机器 M01 在 `rbfly` 保存网盘账号、盘口、自动上报=开、失败退单=关。代理登录后若适配器确认成功，理想状态为 `flyers_online=1`。机器/玩家允许报网，当前期尚未封盘。

### 正常成功路径

玩家小林余额 100 分，下注 `单 10`：

1. 本地规则通过，`rbuser.score` 从 100 扣到 90。
2. `record` 新增订单 O1001：期号 Q1001、玩法 `单`、金额 10、`status=0`，并带上本次赔率/返水等本地结算所需信息。
3. `addDan3()` 对符合条件的普通玩家订单调用 `feidan()`。
4. 若距离生成时间还不足 `cancel+5` 秒，先将报网状态写 3，WebSocket 轮询稍后再试。
5. 等待窗口满足后，适配器把 O1001 转换为 W 的下注格式并提交。适配器回 2 后，`record.flyers_status=2`。这只表示 BY220 适配器将本次调用识别为成功。
6. Q1001 开奖，`openKj()` 找到 O1001（本地 status 仍为 0），`jiesuan()` 计算本地结果。若中奖，`xzjs()` 按本地规则把应返积分加回玩家；若未中奖则不返。最后 `record.status=1`。
7. W 网盘里的对应订单由 W 自己开奖/结算。BY220 不会因此自动更新小林的本地积分。

## 7. 不同情况的结果

| 情况 | BY220 当前可确认的结果 | 本地订单/玩家积分后续 |
| --- | --- | --- |
| 自动上报关闭 | `feidan()` 的在线+自动条件不满足，不调用自动下单适配器 | 本地注单仍可继续走开奖结算；是否有后续自动补报取决于订单状态和触发路径，不能保证关闭期间漏报的每笔都会补发 |
| 未登录/掉线 | 正常业务意图应不报；但登录代码存在失败也置在线的缺陷，应以适配器调用/日志而非 UI 在线字样判断 | 若本地订单保留，开奖仍可能结算 |
| 还在取消等待窗口 | 写 `flyers_status=3`，约 2.4 秒扫描任务再试；此时尚不代表网盘拒单 | 本地注单不变，照常等待开奖 |
| 网盘明确返回失败，失败退单关 | `flyers_status=3`，定时任务/人工入口可重试 | 本地注单保留；只要仍是 `status=0`，可被本地开奖流程结算 |
| 网盘明确返回失败，失败退单开 | 返还本地玩家下注积分、发取消消息、删除本地 `record` | 已删除注单不会进入后续 `openKj()` 的记录查询；源码未见保留原单的独立退单审计事实 |
| 请求超时但网盘可能已收单 | 本地结果可能被当失败并再次调用适配器；是否已收单无法仅由本地超时判断 | 自动退款可能导致本地撤单、网盘仍有单；重试也可能重复单。当前源码未见完整查单/幂等闭环 |
| 报网成功但本地输 | `flyers_status=2`，本地开奖按自己的开奖结果结算 | 玩家本地积分扣款保留；网盘单独处理 |
| 报网失败但本地赢 | 只要订单没因失败退单而删除，本地开奖仍照常结算 | 本地中奖返分逻辑由 `jiesuan()` / `xzjs()` 完成，与网盘是否接单分离 |
| 使用 `BY220_LOCAL_MODE=1` | 登录接口返回本地模拟成功、在线=1、余额/押注=0 | 只能证明模拟登录分支运行，不能证明真实网盘已收单或结算 |

## 8. 图中“超时、押注、余额”如何理解

| 页面字段 | 数据来源与含义 | 当前源码边界 |
| --- | --- | --- |
| 在线状态 | `rbfly.flyers_online`，由登录/轮询逻辑更新 | 登录分支有错误地置在线的路径，值可能失真 |
| 自动上报网盘 | 页面状态读 `robot.flyers_auto`；开关变更同时写 `robot` 与 `rbfly`，保存账号接口写 `rbfly` | `feidan()` 执行时检查 `robot.flyers_auto`；不是订单已报成功状态 |
| 失败退单 | 页面状态读 `robot.flyers_withdraw`；开关变更同时写 `robot` 与 `rbfly`，保存账号接口写 `rbfly` | `feidan()` 执行时读取 `robot.flyers_withdraw`；不是确认网盘撤单 |
| 押注 | 适配器账户信息返回的 `betting` 或对应未结金额，写入 `rbfly.betting` 后在 `flyersInfo()` 返回 | 目标网盘账户侧的占用/未结快照，不是 BY220 本地玩家下注总额 |
| 余额 | 适配器账户信息返回的余额，写入 `rbfly.money` 后在 `flyersInfo()` 返回 | 目标网盘账户侧快照；本地模拟登录显示 0 |
| 超时 | 页面 `admin_list.html` 中 `.csrecord` 默认文本为 0 | 对主模板检索未找到该计数的动态赋值；当前不能据此断定存在真实超时订单统计 |

## 10. 阅读这段业务时不要混淆

1. `record.status` 是 **BY220 本地注单是否开奖结算**；`record.flyers_status` 是 **向网盘报单的状态**。一个订单可“报网失败但本地仍结算”，也可“报网成功但本地尚未开奖”。
2. `rbfly.money`、`rbfly.betting` 是网盘适配器取得的账户快照；玩家积分是 `rbuser.score`。不是同一个余额，也没有源码证据表明两者会自动互相结算。
3. “失败退单”是 BY220 给本地玩家返积分并删除本地订单的分支；它不等于向网盘发出撤单成功，也不保证网盘那边没有该单。
4. 网盘配置/适配器是 BY220 主动连接外部的出站逻辑。源码中没有由 BY220 充当中心端、接收另一个系统订单并做平台代理结算的这条入站业务。
5. 本文梳理的是 BY220 源码现状。Xupan 的报网适配器和中心上游是另一套实现边界，不能用 Xupan 当前的内部模拟闭环反向证明 BY220 已有中心接单功能。
