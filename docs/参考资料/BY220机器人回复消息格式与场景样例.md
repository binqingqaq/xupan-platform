# BY220 机器人回复消息格式与场景样例

> 核对日期：2026-10-20  
> 范围：BY220 玩家聊天室中以“机器人”身份持久化或广播的文本、图片和开奖结构化消息。本文是源码静态分析与虚构数据演示，不是 BY220 线上运行验收，也不表示这些业务已在 Xupan 全部实现。

## 1. 结论与统计口径

BY220 的机器人回复不是前端根据玩家输入临时拼出来的。主要消息内容由 PHP 后端业务代码生成并写入 `record` 表：下注回执由 `addDan*()` 写入；机器人文本、图片和系统播报由 `addMsg()`、`addMsg2()`、`addMsg3()` 写入。聊天接口再把记录转换成 `name`、`type`、`content`、`atUser` 等字段，前端按这些字段渲染气泡、图片、颜色和时间标签。

按业务场景归纳，本文分为 **6 组、约 30 个可区分模板/分支**。这个数量是便于逐条核对的归类数，不是系统中所有可能文本的数学总数：下注错误有多个玩法分支，动态名字、期号、金额、余额、流水和开奖结果会组合出大量不同文本；每笔玩法下注原文也会随用户输入变化。

本文口径包括：

- 机器人身份发出的玩家反馈和全房间开奖/封盘播报。
- 用户输入被解析后由机器人返回的结果。
- 开奖后台生成、写入聊天记录并由玩家端展示的消息卡片/文本。

本文不把玩家自己发送的原始下注指令、后台网页弹窗、服务端控制台日志或前端仅作样式用途的 `atUser` 标签算作机器人回复种类。

## 2. 消息结构与前端展示

`addMsg()` 把文本写入 `record.cmd`，设置 `NickName='机器人'`、`wxid=0`、`isShow=1`。`addMsg3()` 用于积分申请反馈，并附带上下分类型及申请 ID。`addMsg2()` 用于图片、开奖卡片、历史、系统标记等消息，额外保存 `sys`、`kaijiang` 等字段。下注成功回执由 `addDan()`、`addDan3()`、`addDan4()` 在下注记录本身写入 `cmd`，因此成功下注反馈同时也是注单记录。

客户端 `official-player-runtime.js` 对消息对象的 `type`、`content`、`atUser` 做展示分支：纯文本以文本节点显示；`type=2` 等消息内容可按 HTML/图片块展示；`kai*`、`stop`、`last` 等标记控制开奖卡片、样式或时间标签。上述标记是消息表现/分类元数据，不应简单视为业务回复种类。

## 3. 玩家下注与解析反馈

以下金额和用户均为虚构值，文案结构依 BY220 源码。旧源码出现“元”“粮草”等措辞；Xupan 面向用户必须保持“虚拟积分”边界，不得将积分解释为现实货币。

### 3.1 成功下注回执

`addDan()` 的格式：

```text
@{昵称}, {期号末三位}攻击成功，使用粮草{本次金额}, 剩余粮草：{下注后余额}
```

示例：

```text
玩家甲发送：第3球/12正/50
机器人：@玩家甲, 318攻击成功，使用粮草50, 剩余粮草：950.00
```

`addDan2()`、`addDan3()`、`addDan4()` 使用“回合攻击成功”格式：

```text
@{昵称}, {期号末三位}回合攻击成功，使用粮草{本次金额}, 剩余粮草：{下注后余额}
```

示例：

```text
玩家乙发送：第5球/红波/30
机器人：@玩家乙, 318回合攻击成功，使用粮草30, 剩余粮草：470.00
```

是否展示由下注路径传入的 `isShow` 影响；有些机器人/内部注单仍会记录回执但设置为不展示。`addDan*()` 的不同实现还承载不同玩法/下注入口，不应据函数名推断用户能看到多种完全不同的成功文案。

### 3.2 下注失败与限制提示

| 触发条件 | 源码文案格式 | 虚构输出 |
| --- | --- | --- |
| 余额低于下注额 | `@{昵称}, 您当前积分不足{金额}!` | `@玩家甲, 您当前积分不足500!` |
| 下注低于代理最低限额 | `@{昵称} "{下注文本}" 最低下注{下限}元` | `@玩家甲 "第3球/12正/5" 最低下注10元` |
| 下注高于代理最高限额 | `@{昵称} "{下注文本}" 最高下注{上限}元` | `@玩家甲 "第3球/12正/9000" 最高下注5000元` |
| 超过单玩法限额 | `@{昵称} "{玩法文本}" 超出此玩法最大投注限额，{分支编号}最多可下{剩余额度}` | `@玩家甲 "12特" 超出此玩法最大投注限额，5最多可下80` |
| 超过整场限额 | `@{昵称} "{下注文本}" 超出总场最大投注限额，剩余可下{剩余额度}` | `@玩家甲 "第3球/12正/100" 超出总场最大投注限额，剩余可下40` |
| 同一号码重复下注 | `@{昵称}, 不能下注相同号码!` | `@玩家甲, 不能下注相同号码!` |
| 当前期停止/封盘 | `@{昵称}, 已停止下注!` 或 `@{昵称}, 已停止!` | `@玩家甲, 已停止下注!` |
| 投注扣分失败 | `@{昵称}, 下注失败!` | `@玩家甲, 下注失败!` |
| 通用无效下注分支 | `@{昵称}, 下注无效!` / `@{昵称}, 下注无效2!` | `@玩家甲, 下注无效!` |
| 通用格式错误 | `@{昵称}, 指令格式不正确!` | `@玩家甲, 指令格式不正确!` |
| 特定解析阶段错误 | `@{昵称}, 指令格式不正确({阶段号})!` | `@玩家甲, 指令格式不正确(2)!` |
| 某条拆分下注项错误 | `@{昵称}, "{子项文本}" 指令格式不正确!` | `@玩家甲, "第3球/12正" 指令格式不正确!` |

同类提示会因玩法、拆单位置、限额分支不同而重复出现，不应按源码调用行数重复计数。对于 `.`、`=`、`+`、空格等非法格式及多行/逗号拆分解析失败，控制器会进入相应格式错误分支。

## 4. 查询与展示指令

### 4.1 查询余额：`查`

源码经 `cha()` 生成：

```text
@{昵称}  剩余：{余额保留一位小数}
```

示例：

```text
玩家甲：查
机器人：@玩家甲  剩余：950.0
```

### 4.2 查询历史：`历史`

`lishi()` 对支持的游戏生成 HTML 历史开奖结果卡片，通过 `addMsg2(..., sys='ck', wxid=1)` 记录。

虚构内容示意：

```text
┌──────┬──────────┬────────────────┬────┐
│ 期数 │ 时间     │ 结果           │ 番 │
├──────┼──────────┼────────────────┼────┤
│ 318  │ 20:05:00 │ 03 11 18 26 32 │ 小双 │
│ 317  │ 19:55:00 │ 01 08 17 23 35 │ 大单 │
└──────┴──────────┴────────────────┴────┘
```

真实输出是按游戏配置生成的 HTML 表格/走势块，条目数量和列会受游戏 `hasKey`、`hasSelect`、玩法配置影响。UI 对应 `.card2` 历史卡片，不是一句固定纯文本。

### 4.3 查询走势：`走势`

`zoushi()` 只在特定游戏分支写入 `getZoushi()` 生成的 HTML 卡片，并使用 `sys='ck'`。页面内容是走势/路图数据，因当前期历史变化而变，不存在稳定固定文本；不支持的游戏分支不返回这条机器人消息。

### 4.4 查询流水：`流水`

`get_Liushui()` 依据机器流水设置选择文案：

```text
@{昵称}:
累计单边流水:{金额}
盈亏:{金额}
期数:{期数}
```

或：

```text
@{昵称}:
累计双边流水:{金额}
盈亏:{金额}
期数:{期数}
```

澳8等玩法可能显示“累计有效流水”。虚构示例：

```text
@玩家甲:
累计双边流水:1250.00
盈亏:85.00
期数:6
```

### 4.5 查询玩法：`玩法`

记录玩家输入后，机器人消息内容为玩法图片资源路径，由前端作为图片显示。示意：

```text
[机器人发送玩法说明图片]
```

图片资源具体玩法由站点静态资源提供；这里不伪造源码中没有的图片文字。

## 5. 取消注单

### 5.1 取消成功

成功取消有效时间窗口内的一笔或多笔当前期下注时，后端会发明细消息，再发总结消息：

```text
@玩家甲
取消 第3球/12正/50，返回50
取消 第5球/红波/30，返回30
剩余 980.0
```

随后：

```text
@玩家甲, 30秒内有效指令已全部取消!
```

### 5.2 取消失败/禁止

| 条件 | 示例机器人回复 |
| --- | --- |
| 已达到本期停止下注时间 | `@玩家甲, 本期已停止，禁止取消!` |
| 机器配置禁止取消 | `@玩家甲, 禁止取消!` |
| 时间窗口内没有可取消有效指令 | `@玩家甲, 30秒内无有效指令!` |

## 6. 上下分及审批通知

普通玩家通过聊天申请时，机器人先发待审批消息；后台批准/拒绝后，`application/rbt/controller/Index.php` 再发最终结果。

| 操作与结果 | 源码格式 | 虚构输出 |
| --- | --- | --- |
| 玩家申请上分 | `@{昵称}, 上分{金额},待审批!` | `@玩家甲, 上分100,待审批!` |
| 玩家申请下分 | `@{昵称}, 下分{金额},待审批!, 剩{申请后余额}` | `@玩家甲, 下分50,待审批!, 剩900` |
| 申请重复/无效上分 | `@{昵称}, 上分无效!` | `@玩家甲, 上分无效!` |
| 申请重复/无效下分 | `@{昵称}, 下分无效!` | `@玩家甲, 下分无效!` |
| 余额不足 | `@{昵称}, 您当前积分不足{金额}!` | `@玩家甲, 您当前积分不足1000!` |
| 后台批准上分 | `@{昵称}, 成功上分{金额}, 剩{更新后余额}` | `@玩家甲, 成功上分100, 剩1050.0` |
| 后台批准下分 | `@{昵称}, 成功下分{金额}` | `@玩家甲, 成功下分50` |
| 后台拒绝申请 | `@{昵称}, 您的上分请求被拒绝！` / `@{昵称}, 您的下分请求被拒绝！` | `@玩家甲, 您的下分请求被拒绝！` |

托在代理后台直接上下分另有“待审批”与“成功”消息组合；其中“待审批”字符串可能只是复用的历史模板，不表示托的业务真的等待审批。玩家普通申请、后台审批和托直接操作必须作为不同触发场景理解。

## 7. 期号、封盘和开奖播报

此部分由 `common.php` 的期号/开奖任务生成并通过 `addMsg2()` 写入，前端依据 `sys` 标记渲染。播报按机器/游戏配置及幂等检查生成，部分开奖组件为公开消息，机器核对或中奖列表则按机器记录。

### 7.1 封盘前 60 秒

```text
距离318期封盘还剩60秒!
```

触发条件是当前期结束时间进入配置的封盘阈值加 60 秒范围；通过缓存标记避免同一期重复通知。

### 7.2 封盘与核对列表

同一封盘场景会先后生成期号停止提示和核对列表：

```text
318期停止
```

```text
-----------
318
核对列表:(80)
(玩家甲) "第3球/12正/50，第5球/红波/30"
(玩家乙) "第1球/单/20"
-----------
以核对列表为准
不在列表都无效
```

金额为该期下注合计；同一玩家的多笔记录按昵称归组展示。若无人下注，仍有标题、合计和有效性说明，但无玩家明细行。

### 7.3 开奖结果卡片

每期首次结算时生成“开盘结果”结构化 HTML 卡片，包含期号、开奖时间、号码球及游戏配置允许的附加结果（例如番、合计、龙虎、球位玩法结果/颜色）。这是消息内容，不是仅由前端当前期展示栏临时生成。

虚构数据示意：

```text
开盘结果
第318期                         2026-10-20 20:05:00
03  11  18  26  +  32
合计：90    番：小双
```

源码根据 `hasKey`、`hasTe`、`hasSelect` 等游戏配置决定号码分组、是否加号、合计、龙虎和球位结果；并非每种彩票都使用同一布局。旧版站点使用 HTML 片段作为 `addMsg2()` 内容，不能把以上纯文本排版误认作接口原始序列化格式。

### 7.4 历史开奖卡片

开奖结果卡片之后会生成最近若干期历史卡片，源码最多逐行生成前 15 条可视历史记录，并可能附号码属性、番路图等。示例见 §4.2。它是另一条机器人消息，触发于开奖结算流程。

### 7.5 非 `hasKey` 游戏：获奖排名

`hasKey=false` 时生成 `获奖排名:` 消息。源码会按玩家昵称归并注单，列出开奖后余额及中奖/未中奖玩法金额，末尾带生成时间。

虚构示例：

```text
获奖排名:
(玩家甲)  1,180.0  "第3球/12正/50 [-50]"  "第5球/32特/20 [-20]"
(玩家乙)    720.0  "第2球/大/30 [-45.0]"
--------------------
时间:2026/10/20 20:05:08
```

列表可包含输的注单金额；该消息不等同于“只列中奖者”。若本期无注单，标题和时间仍可能出现，名单为空。

### 7.6 `hasKey` 游戏：结果、球位属性、获胜名单

`hasKey=true` 时生成 `kai6` 结果消息，先列开奖号码及番/单双/大小/龙虎；若 `hasSelect=true`，继续列每球结果属性，再列获胜名单和中奖玩法盈额。

虚构示例：

```text
318结果:
03,11,18,26,32 => 小双,双,小龙
第1球/03=>红波, 小, 单
第2球/11=>绿波, 小, 单
第3球/18=>蓝波, 小, 双
第4球/26=>红波, 大, 双
第5球/32=>绿波, 大, 双
----------
获胜名单：
(玩家丙) "第1球/03正" 盈:90.0
(玩家丁) "18特" 盈:180.0
时间:2026/10/20 20:05:08
```

号码属性文字依游戏数据函数输出，以上只用于展示字段结构。若没有中奖注单，仍可能发送开奖结果和空的“获胜名单”。

### 7.7 `hasKey` 游戏：总榜

随后可能发送总榜消息，显示当期玩家积分/盈亏汇总：

```text
318结果:
03,11,18,26,32 => 小双,双,小龙
--------------------
总榜: 【135.0】
玩家丙   [80] (+120.0)
玩家丁   [55] (+15.0)
```

源码只把余额达到其筛选门槛的用户并入榜单；昵称过长会截短。榜单内容来自结算后的账户/注单汇总，不是开奖数字本身。

### 7.8 `hasKey` 游戏：走势消息

满足该游戏配置时，再发送历史走势 HTML 卡片（`sys='kai3'`）。这与玩家主动输入“走势”触发的 `sys='ck'` 响应是不同触发来源，消息形态都可以是走势图。

## 8. 注单被取消/退单通知

系统在飞单失败或相应结算处理路径中会通过 `addMsg()` 通知：

```text
@玩家甲 "第3球/12正/50" 注单取消
```

该消息可由 BY220 的飞单失败处理产生，不等于玩家主动输入“取消”。HBY019 客户端保存的 UI 代码会针对 `tuidan_notice` 或正文“退单通知”加红色样式，但本次对 BY220 后端全量消息调用点的静态搜索没有发现这两个词作为稳定的全局固定机器人模板。不能把 HBY019 的前端样式分类扩写成 BY220 的后端业务消息种类。

## 9. 触发流程总览

```text
玩家发文本
  ├─ 查 / 历史 / 走势 / 流水 / 玩法 -> 查询结果或展示卡片
  ├─ 上分 / 下分 -> 请求校验 -> 待审批/无效/余额不足 -> 后台批准或拒绝后再发结果
  ├─ 取消 -> 时间/开关/订单校验 -> 退回有效订单并发明细+总结，或发禁止/无有效提示
  └─ 下注文本 -> 期号/封盘/格式/余额/赔率限额校验
       ├─ 拒绝 -> 对应错误文本
       └─ 接受 -> 写下注记录并生成“攻击成功”机器人回执

定时开奖流程
  ├─ 临近封盘 -> 60 秒提醒
  ├─ 达到封盘点 -> “第N期停止” + 核对清单
  └─ 结果到达并结算 -> 开奖卡片 + 历史卡片
       ├─ 非 hasKey -> 获奖排名
       └─ hasKey -> 开奖结果/球位属性/获胜名单 + 总榜 + 配置允许的走势卡片
```
