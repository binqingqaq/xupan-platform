# Sub2API 前端移动端布局参考分析

> 用途：为后续修复 Xupan `/platform-admin/**` 手机适配提供源码级参考；本文只记录设计分析，不把 Sub2API 的业务、菜单、字段、权限或代码作为 Xupan 需求。
> 参考仓库：`D:\codes\禅道数据统计2.0\sub2api`（只读）
> 参考提交：`b650bdd6`，本机检出分支 `main`；检查时工作区干净。
> 前端基线：Vue `^3.4.0`、Vue Router `^4.2.5`、TypeScript、Vite `^5.0.10`、Tailwind CSS `^3.4.0`；另用 `@tanstack/vue-virtual`、`@vueuse/core` 等。版本为 `package.json` 声明范围，不等同于 lockfile 实际解析版本。
> 证据边界：下文基于当前检出提交的静态源码、组件文档与测试文件；本次没有启动 Sub2API，也没有做其真机运行验收。

## 1. 结论摘要

Sub2API 的移动后台不是把桌面界面缩小，也不是全站只靠一条 CSS 规则。它把响应式行为分在三个层次：

1. **应用外壳**：桌面侧栏在手机变成从左侧滑入的导航抽屉，顶部保留精简工具栏，页面内容保持单列自然纵向滚动。
2. **数据表**：共用 `DataTable` 在小屏切换成字段名/字段值卡片；桌面仍使用可横向滚动、首列和操作列可固定的宽表。
3. **页面骨架**：`TablePageLayout` 把操作区、筛选区、数据区和分页区分开；桌面把数据区限制在可用高度内滚动，手机改回整页纵向滚动。

对 Xupan 最值得借鉴的是**断点下真实切换呈现结构**与**行操作跟随对应记录**。固定右侧操作列在 Sub2API 也是一种桌面增强能力；它不应直接套用到 Xupan 手机宽表，因为用户的第二张截图已经显示这类固定列会挡住中间业务字段。

## 2. Xupan 两张实测图与当前源码核对

### 图一：子账号页顶栏文字叠在一起

截图里子账号卡片本身已按手机方式展示，卡片中的用户名、积分、失效日期、权限和操作大体可读；问题集中在顶栏：欢迎信息、横向菜单和安全退出重叠。

当前 [PlatformAdminNav.vue](../../web/src/components/platform-admin/PlatformAdminNav.vue) 同时渲染 `.platform-admin-desktop-nav` 和 `.platform-admin-mobile-nav`。桌面容器默认 `display:flex`，手机媒体查询只给手机容器设置 `display:grid`，没有在 `<768px` 隐藏桌面容器。因此两套导航在手机视口同时显示，截图中的重叠与这一源码缺口吻合。此结论是基于当前源码和用户截图的直接对应，不是对线上构建哈希或浏览器缓存的鉴定。

### 图二：开奖历史固定操作列遮住期号等列

当前 [PlatformAdminDrawHistory.vue](../../web/src/views/PlatformAdminDrawHistory.vue) 在所有视口都渲染同一个 `el-table`；操作列声明 `fixed="right"`，但页面没有手机卡片分支。平台公共移动 CSS 只约束表格最大宽度，没有把这张表转换成移动记录卡片，也没有在窄屏取消固定操作列。

因此在手机横向可视区域有限时，固定的“操作”列会覆盖/压住其它列，用户看到的是数据被操作列挡住，而不是完整的响应式行记录。这与截图相符。为保证同一条开奖记录、球号、状态和“投注记录/补齐结算”等操作有清楚归属，手机端应单条纵向展示，操作放在该记录卡片内部；不要只把滚动条藏起来或继续固定右列。

## 3. Sub2API 应用外壳

| 区域 | Sub2API 源码行为 | 可迁移原则 |
| --- | --- | --- |
| 视口 | `frontend/index.html` 使用 `width=device-width, initial-scale=1.0` | 让媒体查询拿到设备实际宽度；不使用桌面宽度 viewport 冒充手机布局 |
| 桌面侧栏 | `AppSidebar.vue` + `.sidebar` 固定在视口左侧；`AppLayout.vue` 的主内容按侧栏展开/收起增加 `lg:ml-64` / `lg:ml-[72px]` | 桌面导航和主内容由同一外壳管理，避免页面分别计算宽度 |
| 手机导航 | 侧栏默认 `-translate-x-full`，`lg` 以上常驻；手机汉堡按钮切换 Pinia `mobileOpen`，背景遮罩点击关闭；选择菜单后延迟关闭 | 手机只展示一个明确导航入口，打开后菜单在独立抽屉中完整浏览，不让一行菜单和账号操作争抢屏宽 |
| 顶部栏 | `AppHeader.vue` 为 sticky、64px 高；手机显示菜单按钮，余额转入用户下拉，文档文字缩成图标 | 将低频信息收到用户菜单，保留紧凑标题/菜单入口；Xupan 当前退出是高影响命令，仍需在明显、不会被挤掉的位置保留 |
| 主内容 | `AppLayout.vue` 使用 `p-4 md:p-6 lg:p-8`；桌面 `lg` 以上避开侧栏，页面主体仍自然纵向滚动 | 手机页不要给整个后台固定桌面 `min-width` 或整体 `zoom`；只让确有横向比较需要的数据区内部滚动 |
| 侧栏导航内容 | 管理员菜单与个人菜单分区；分组可展开；选中态、图标、收起提示；菜单主体独立 `overflow-y-auto` | 保持 Xupan 已有权限筛选和菜单顺序；菜单过长时让菜单区自己滚动，底部主题/收起操作不覆盖菜单项 |

## 4. 数据表和列表

### 4.1 DataTable 的桌面/手机两套结构

`frontend/src/components/common/DataTable.vue` 是参考项目最直接的可迁移模式：

| 状态 | 结构与行为 | 适用性 |
| --- | --- | --- |
| `<768px` | 每条数据渲染为一张记录卡；每个数据列以字段标签 + 字段值纵向列出；操作槽置于卡片末尾并与记录绑定 | 适合子账号、机器、开奖、订单等窄屏需要完整身份和操作的业务行 |
| Loading | 使用多张字段/值骨架卡，而不是桌面表格骨架挤进窄屏 | 保持加载期间的目标布局稳定 |
| Empty | 用清楚的空状态，不显示空白表格假象 | 空数据与加载失败仍须由 Xupan 页面分别表达 |
| `>=768px` | 语义化表格；表头 sticky；`min-width: max-content` 让宽列形成横向滚动；桌面大列表使用 TanStack 虚拟行 | 适合电脑端保留现有密集比较能力 |

移动卡片仍来自同一 `columns`、`data` 和 scoped slots，未另行请求数据。`dataColumns` 排除 `actions`，随后单独渲染 `cell-actions`，因此操作不会固定在表格右边压在字段上。

主要源码位置：

- `frontend/src/components/common/DataTable.vue:1-63`：移动端卡片、loading/empty 状态和记录操作槽。
- `frontend/src/components/common/DataTable.vue:65-202`：桌面表格、sticky 表头、虚拟行和单元格。
- `frontend/src/components/common/DataTable.vue:214-217, 337-349, 552-579`：以 `matchMedia('(min-width: 768px)')` 初始判断并监听断点变化、数据变化后测量可滚动状态。
- `frontend/src/components/common/DataTable.vue:365-404, 547-548`：数据表 props 默认首列与操作列 sticky、字段列定义。
- `frontend/src/components/common/DataTable.vue:658-699, 755-845`：桌面固定首列/操作列及层级、阴影分隔。
- `frontend/src/components/admin/UsersView.vue:254-267, 587-647`：真实用户列表复用表格组件，字段通过 slot 定制，操作槽仍留在该行。
- `frontend/src/components/common/__tests__/DataTable.spec.ts`：目前检索到的 DataTable 专项测试覆盖排序，不等于手机视觉/横向触控的完整验收。

### 4.2 可借鉴的操作列处理

- Sub2API 默认桌面 sticky 首列和操作末列，并给固定列配置不透明背景、表头/表体不同 `z-index`、横向滚动阴影提示。
- 用户管理页将低频操作收入行内“更多”菜单，同时把常用编辑、启停操作留作可见动作；菜单可以 Teleport，避免被表格滚动容器裁切。
- 但在手机结构中，操作位于卡片字段之后，不再使用 sticky 末列。这是本次对 Xupan 最重要的取舍：**桌面 sticky 可以保留，手机卡片必须关闭桌面固定列结构**。

### 4.3 Sub2API 本身的限制

1. `TablePageLayout.vue` 把视口小于 1024px 判为 `mobile-mode`，而 `DataTable.vue` 到小于 768px 才切换卡片。768–1023px 因而是页面纵向流动、数据仍使用桌面表格的过渡区；不能把它概括成一个统一断点。
2. `DataTable` 桌面固定操作列默认开启；固定列本身仍可能在窄表视口遮住相邻字段。Xupan 图二所示问题正是需要在手机避免固定右列的场景。
3. `TablePageLayout` 手机样式将其外层 table-scroll-container 还原为页面滚动；表格实际滚动仍受 `DataTable` 自身 `.table-wrapper` 管理。不同页面如直接使用原生 `<table>` 或自定义网格，未必自动得到同样行为。
4. `DataTable` 全字段卡片可能变得很长，尤其是机器配置/高列数报表。Xupan 应按字段优先级设计摘要与详情展开，不应把二十多个配置字段全部铺在默认首屏。
5. `checkActionsColumnWidth()` 会计算桌面操作列按钮宽度，但当前文件中 `actionsColumnNeedsExpanding` 的结果没有其它读取点；这段测量代码不应当作已验证有效的手机操作折叠机制。

## 5. 页面骨架、筛选、分页和表单

`TablePageLayout.vue` 使用四个命名槽：

```text
actions（固定区）
filters（固定区）
table（桌面剩余高度滚动）
pagination（固定区）
```

桌面表格区通过 `flex-1 min-h-0` 和内部 `overflow-x-auto overflow-y-auto` 留出独立滚动空间，筛选和分页不随表体滚走；手机移除定高/固定表格区，恢复普通页面纵向滚动。这能避免窄手机出现“整页滚动和表格嵌套滚动互相抢手势”。

`UsersView.vue` 的新建动作按钮用 `flex-1 md:flex-initial` 在手机充满可用宽度；筛选和动作作为独立槽不进入表格内部。其他页面仍有自己的筛选组件，需按页面字段逐项保证控件宽度、折行和按钮可达，不能因共享壳层而推断全部页面都已适配。

`BaseDialog.vue` 与全局 CSS 提供的表单弹层处理：

- Teleport 到 `body`，避免局部 `overflow` 裁切弹层。
- 统一宽度等级 `narrow/normal/wide/extra-wide/full`；最大高度为 `95vh`（sm+ 为 `90vh`），header/footer 不缩小，body `flex-1 overflow-y-auto`。
- 开启时锁住 body 滚动、聚焦第一个可聚焦元素；关闭时恢复之前焦点；支持 Escape；遮罩是否关闭由 `closeOnClickOutside` 决定且默认 false。
- 全局提供 `safe-top` 和 `safe-bottom` 工具类，但不能据此推断每个弹窗都自动处理安全区。当前默认最大高度是 `vh`，并非 `dvh`，因此移动浏览器动态工具栏仍需设备验收。

源码：`frontend/src/components/layout/TablePageLayout.vue:1-111`；`frontend/src/components/common/BaseDialog.vue:1-43, 57-100, 114-151`；`frontend/src/style.css:377-420, 757-764`。

### 5.1 全前端页面类型横向盘点

路由包含初始化/登录/注册/验证、公开首页、用户 dashboard/Keys/Usage/Profile、订阅和支付、管理员 dashboard/Users/Groups/Accounts/Channels/Subscriptions/Proxies/Redeem/Settings/Usage/Orders/Affiliates/运维监控等多种页面（`frontend/src/router/index.ts:23-365, 378-646`）。不是所有页面都使用同一种表格组件，当前代码可归纳为：

| 页面类型 | Sub2API 实际模式 | Xupan 后续可借鉴点 |
| --- | --- | --- |
| 登录/注册/初始化 | `AuthLayout` 使用 `min-h-screen`、`p-4`、单列 `max-w-md` 内容；输入项沿用卡片宽度 | 手机表单单列、留足边距；不要套用认证页渐变主题到运营后台 |
| 用户/管理员 Dashboard | Tailwind 网格从 `grid-cols-1/2` 过渡到 `lg:grid-cols-2/3/4`；指标卡堆叠或扩列 | 指标和开奖状态按层级重排；图表在小屏纵向排列，不保留桌面并排固定宽度 |
| Admin Users/Groups/Redeem/Accounts | `TablePageLayout` + `DataTable`；手机自动变记录卡；动作槽处于记录底部 | 适合 Xupan 子账号、机器、开奖历史和订单的手机信息层级；保留相同数据与命令处理器 |
| Usage、Keys、列表筛选 | 字段默认 `w-full`，到 `sm` 后变固定/最小宽度；列设置等低频文字在 `md` 以下隐藏为图标控件；工具栏折行 | 筛选控件逐项换行，操作组允许换行；图标化命令必须有可访问名称/tooltip，不能只隐藏按钮文字后失去含义 |
| Profile/订阅/支付 | 多用响应式卡片网格（单列，`sm` 双列，`lg` 三列）；支付方式在卡片内纵向/分栏切换 | 适合账户摘要、配置摘要；不适合把密集账务流水一律改成装饰性卡片 |
| 复杂表单/属性编辑 | 页面级表单按 `grid-cols-1 md:grid-cols-2/3` 折列；组内支持小型嵌套列表滚动 | 保留字段顺序和分组语义；长机器设置适合分段信息块，但需保证用户知道当前编辑对象和保存范围 |
| 详情/错误/监控 | 独立 Dialog、监控卡/详情弹层；图表组件独立响应式 | 弹层必须独立滚动，操作按钮不覆盖字段；详情卡应在手机以单列展开 |
| 长列表筛选与分页 | 操作、筛选、表格和分页由命名 slot 分区；手机页面可将各区自然堆叠 | 不要将筛选、固定底部工具条、表格和分页叠到同一窄条或挤在导航行 |

## 6. 断点与视口行为清单

| 断点/场景 | Sub2API 当前行为 | 给 Xupan 的建议 |
| --- | --- | --- |
| viewport | `width=device-width, initial-scale=1.0` | 保持真实设备宽度，保留双指缩放 |
| `<768px` | DataTable 改卡片；AppSidebar 抽屉；顶部显示汉堡 | 正式手机模式，所有业务列表根据页面使用记录卡片或专门的可读布局 |
| `768–1023px` | DataTable 为桌面表；TablePageLayout 已进入 mobile flow | Xupan 明确制定平板过渡区规则，避免壳层与表格各自换模式造成断层 |
| `>=1024px` | 桌面侧栏常驻；AppHeader 不显示汉堡 | 保留 Xupan 当前桌面导航和密集表格，不因手机修复而重排 |
| 窄屏弹层 | 响应式 max-width、最大高度、内部 body 滚动 | 对机器长表单可采用全屏模式；确认固定动作位不挡住字段/软键盘 |
| 长列表 | 桌面虚拟滚动，手机 cards + 正常 document scroll | 确认性能和分页契约；虚拟滚动需在桌面容器有有效尺寸后运行 |

Tailwind 配置没有覆盖默认 `sm/md/lg` breakpoint；实际 Tailwind 默认 md=768px、lg=1024px。除响应式工具类外，表格和页面骨架还自行监听 `matchMedia`/`window.innerWidth`，存在 breakpoint 双处维护风险。

## 7. 把参考模式映射到 Xupan

| Xupan 页面/问题 | 可借鉴的 Sub2API 模式 | 后续适配要求 |
| --- | --- | --- |
| 公共管理顶部导航 | 单一移动汉堡入口 + 权限菜单抽屉；桌面/手机不能同时可见 | 在 Xupan 手机媒体规则显式隐藏 `.platform-admin-desktop-nav`；抽屉内容独立纵向滚动，账号欢迎和退出不能与菜单项重叠；路由切换、遮罩关闭和 Escape 可测试 |
| 子账号 | 每条记录卡列字段标签和值；该行操作置于卡片末尾 | 保留用户名、状态、积分、失效时间、机器数和权限；动作固定在同一卡片，保留确认语义 |
| 机器管理 | 摘要卡 + 字段/值明细 + 行内动作 | 默认摘要展示账号、状态、开关、所属子账号、积分、失效日；配置明细折叠；复制、玩家、启停/解锁和删除可见且不遮内容 |
| 开奖历史（用户图二） | 手机上的数据卡片代替固定操作宽表 | 每条记录按彩种/期号、号码、时间、确认状态、待结算数/注单数、该期操作分组；号码允许多行；不使用固定右操作列 |
| 首页历史表、路字图 | DataTable 按窄屏变卡片，或对紧凑路字图定义独立横向查看区 | 历史列全字段可查看；路字图若横向滚动，要把滚动限制在路图自身并提供可见边界 |
| 报表、订单、中心上游 | 按列定义生成摘要卡/详情展开；筛选、分页独立区 | 先保留记录识别字段、状态、金额和业务动作；长命令/明细放详情，不固定宽操作列盖住主字段 |
| 长表单、确认弹层 | Teleport、内部滚动、固定 header/footer、焦点管理 | 逐一核对机器长表单日期控件、软键盘、危险操作确认和 safe-area；不要只改宽度 |

必须保持 Xupan 与 BY220 的既有边界：仅重新组织呈现，不改菜单顺序/字段含义/权限/机器隔离、积分语义、接口或操作链；`/platform-admin` 和 `/console` 仍是两个业务面。Sub2API 的业务数据和权限模型不得带入。

## 8. 推荐迁移顺序与验收

1. **先修公共导航**：在手机断点显式隐藏桌面导航，仅保留一个汉堡入口和当前页面/账号命令；核查滚动、重叠、安全区、键盘焦点、切路由关闭和权限菜单。
2. **将开奖历史/订单等剩余宽表改为手机记录卡**：保留桌面表格；手机字段与动作绑定同一行数据；取消手机固定操作列。先修截图二直接涉及的开奖历史。
3. **核查子账号与机器卡片**：保留已做的卡片，但用实机检查顶栏修复后卡片操作未被遮挡，机器所有字段均能展开并阅读。
4. **对所有 `/platform-admin/**` 页面按页面类别走查**：dashboard、表格页、长表单、设置、报告和高复杂中心扩展；不要把静态宽表规则误当作全部适配完成。
5. **对齐 breakpoint**：项目选择明确的手机/平板/桌面策略并由公共 token 或共享 helper 驱动 CSS 和 JS，避免 768/1024 多处分散且含义不一致。
6. **验收矩阵**：360×800、390×844、430×932、768×1024、900×900、1024×768、1280×720、1440×900；Android 浏览器/用户实际内置浏览器至少各验一次。检查页面 `scrollWidth` 与 `clientWidth`、菜单单一可见、卡片字段完整、操作不覆盖数据、表单键盘/日期弹层和缩放后位置。

验收要取实际 `/platform-admin/**` 已部署资源的浏览器截图与路由/viewport 证据，不能只用本机 Vite 成功或单测 DOM 断言推断生产页面已修复。服务器业务写操作须单独授权；本参考分析不执行服务器操作。

## 9. 参考模式的边界

- Sub2API 是 Vue + Tailwind 管理型应用；Xupan 使用 Vue + Element Plus。应迁移交互和布局约束，不复制 Tailwind 类、组件依赖或无关设计系统。
- Sub2API 菜单远多于 Xupan，权限/路由语义不同；只参考抽屉、状态管理和折叠行为，不搬它的路由或菜单。
- Sub2API 的 DataTable 默认仍支持桌面首列/操作列 sticky，且页面骨架和表格断点不一致。Xupan 的使用证据表明手机需要免遮挡优先，不能将 sticky action 作为手机方案。
- Sub2API 桌面表格使用虚拟化，手机卡片不虚拟；Xupan 当前机器/子账号分页数据规模和接口语义需单独核对后再决定性能实现。
- 本文只证明参考仓库该提交中的源码方案，不证明其每一页在真机上都无缺陷；最终仍需 Xupan 实际 Android/iOS 视觉与触控验收。
