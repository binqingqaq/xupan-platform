## 参考仓库技术基线

从当前浅克隆的根 `pom.xml` 可确认：

- Spring Boot：`4.1.0`
- Java：`17`
- Spring Security
- MyBatis Spring Boot
- Redis
- JWT
- Druid
- SpringDoc OpenAPI
- Quartz
- 代码生成器

当前项目使用 Java `21`、Spring Boot `4.0.8`、MySQL `8.4 LTS` 和 Flyway，因此不能直接复制若依根 POM 或全部依赖版本。

## 模块参考建议

| 若依模块 | 参考内容 | 当前项目使用策略 |
| --- | --- | --- |
| `ruoyi-common` | 统一响应、异常、分页、工具类、注解、基础领域对象 | 优先参考设计，按当前命名和依赖重新实现 |
| `ruoyi-framework` | JWT/Redis Token、Spring Security、权限校验、数据权限、过滤器和全局配置 | 用户认证和权限方案确定后选择性迁移 |
| `ruoyi-system` | 用户、角色、部门、岗位、菜单、字典、参数、通知、操作日志 | 后台基础能力优先参考，业务表不直接照搬 |
| `ruoyi-generator` | 根据数据库表生成后端和前端基础代码 | 表结构稳定后按需使用，不作为首期必选依赖 |
| `ruoyi-quartz` | 定时任务管理和调度任务 | 确认开奖、结算或同步任务后再评估 |
| `ruoyi-admin` | 应用启动、Controller 组织和 Web 配置入口 | 只参考组织方式，不整体复制 |
| `sql` | 系统表和初始化数据 | 只做结构参考，改写为当前项目 Flyway 迁移脚本 |

## 当前不直接采用的内容

- 不直接合并若依整套多模块工程。
- 不直接复制若依系统表、菜单和权限数据到生产库。
- 不因为参考若依就自动引入 Redis、Quartz、代码生成器或微服务。
- 不直接把若依的用户、角色和权限模型当作彩票业务模型。
- 不使用 `RuoYi-Cloud` 微服务版作为当前首期架构；当前项目尚未有拆分微服务的需求。

## 后续复用流程

1. 在当前项目方案中确认需要的能力，例如认证、后台用户、角色权限或操作日志。
2. 指定若依参考模块、类、配置和 SQL 文件位置。
3. 检查版本、许可证、依赖、数据结构和安全边界。
4. 设计当前项目自己的接口、表结构和 Flyway 迁移。
5. 先写测试，再选择性实现，不把参考代码当作已验证的当前实现。
