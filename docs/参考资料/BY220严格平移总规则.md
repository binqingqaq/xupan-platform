## 0. 项目本质（用户再次确认，2026-10-02）

`xupan-platform` 不是另做一个相似产品，而是用现代技术栈重建 BY220 的同业务系统。

```text
BY220 业务流程
  -> 保持基本一致
  -> 替换技术栈
  -> xupan-platform
```

三大业务面必须同时存在并保持一致：

| 业务面 | BY220 对应 | xupan 目标 |
| --- | --- | --- |
| 玩家前台/下注 | 玩家访问链接进入、期号、开奖、聊天、下注 | 现有玩家前台按 BY220 流程收敛 |
| 代理后台 | `robot.php` | `/agent`，代理创建玩家和托并执行代理操作 |
| 超级管理后台 | `admin.php` | `/platform-admin`，平台超级管理员的全部业务菜单 |

为什么要做 xupan-platform：

- 不是因为业务要变。
- 而是因为 BY220 的 PHP、ThinkPHP、旧前端和旧运行方式不适合继续作为长期技术底座。
- 所以应当保留 BY220 的业务结果和操作习惯，替换底层技术和工程实现。

如果 BY220 已有页面或流程，未经用户确认不得改掉、合并或重新设计。只有合规、安全、数据库和现代工程约束造成的差异可以单独记录。

## 1. 总原则

用户要求：

> BY220 的业务规则和界面逻辑直接严格平移到 xupan，先照着 BY220 有的界面实现一遍，不要开发者自行改流程、改菜单或重新发明业务。

“平移”指：

- 业务名称、菜单结构、操作路径、字段含义、操作顺序和状态结果与 BY220 一致。
- 使用 xupan 的 Java 21、Spring Boot、Vue、MySQL 8.4 重新实现。
- 不是复制 PHP 代码、模板、数据库配置、密码、Token 或外部地址。
- 若受虚拟积分合规、安全或技术栈限制必须调整，先记录偏差并取得用户确认。

## 2. 后台入口强制分离

| `admin.php` | `/platform-admin` | 平台超级管理员 | 平台级菜单、子账号、机器管理、报表、开奖、订单、设置 |
| `robot.php` | `/agent` | 代理/机器账号 | 创建玩家和托、玩家运营、下注和流水相关操作 |

## 4. 子账号规则

BY220 `子账号`不是代理账号，也不是玩家账号。

核对源码：

- 菜单：`application/admin/view/public/head.html`
- 控制器：`application/admin/controller/Sub.php`
- 列表：`application/admin/view/sub/list.html`
- 表单：`application/admin/view/sub/form.html`
- 数据表：`x_admin`，典型 `type=0`

当前已观察到的字段和操作用于今后严格实现，包括：

- 用户名、密码、积分、失效日期。
- 子账号权限 `subxiugai`。
- 机器人权限 `rbxiugai`。
- 统一飞单、飞单账号、飞单密码、飞单网盘、飞单盘口。
- 添加、编辑、删除、刷新。
- 子账号状态、网盘/盘口信息展示。

xupan 实现时必须先建立字段映射，不能只做“渠道组”名称后结束。

当前 xupan 已通过 `agent_group.sys_user_id` 建立登录账号映射，并限制子账号只能访问自己的机器和报表范围；菜单按最小权限裁剪。
BY220 子账号在 `Sub.php` 中被 `isAdmin()` 拒绝，而当前项目也禁止子账号进入子账号管理；其余可见菜单以实际权限复核结果为准。

## 5. 机器管理规则

BY220 `机器管理`中的机器账号才是实际代理后台账号。

核对源码：

- 控制器：`application/admin/controller/Rb.php`
- 列表：`application/admin/view/rb/list.html`
- 表单：`application/admin/view/rb/form.html`
- 玩家列表：`application/admin/view/rb/user.html`
- 数据表：`x_robot`
- 代理登录后台：`application/rbt/controller/Index.php`

当前已观察到的字段和操作包括：

- 账户、密码、积分、失效日期、所属子账号。
- 彩种、托数量、追功能、机器人权限。
- 开盘、封盘、取消秒数、返水、赔率、特码返水、特码赔率。
- 单场总限额、正/角/念/通/车/单码/单双/大小/番/加限额。
- 玩家最高注额、玩家最低注额。
- 添加、编辑、删除、玩家列表、开盘/闭盘、刷新。
- 飞单/网盘及后续上报字段先按参考记录，接入现实资金前必须停止并评审。

## 6. 代理后台规则

BY220 代理后台入口是 `robot.php`，对应控制器 `application/rbt/controller/Index.php`，主要页面参考 `application/rbt/view/index/admin_list.html`。

必须逐步平移的能力：

- 创建玩家、创建托。
- 玩家列表和玩家详情。
- 上下分申请、审批和流水。
- 赔率、返水、封盘、取消等玩家配置。
- 登录链接、二维码和复制链接。
- 下注榜、流水、盈亏、账变。
- 玩家密码、昵称、用户名和状态操作。
- 报网、盘口、飞单等配置按 BY220 页面继续逐项核对。

当前 `/agent` 已完成创建玩家、创建托、代理范围列表和玩家链接签发；其余上下分、赔率、链接管理、注单和报表仍需逐项平移，不能称为 BY220 代理后台已经完成。

## 7.1 当前实施顺序（用户已确认）

当前第一优先级：

```text
完整实现 BY220 admin.php 超级管理后台
```

实现要求：

1. 先逐菜单调查 BY220 的控制器、模板、数据库、权限、按钮和状态变化。
2. 输出功能映射和数据库设计。
3. 用 Java 21、Spring Boot、Vue 3、MySQL 8.4 LTS 和 Flyway 实现。
4. 完成页面、接口、权限、审计、并发、幂等、测试和运行态验收。
5. 超级管理后台框架完成后再讨论报网、盘口、中心上游和二层结算。

不允许在超级管理后台框架未完成时先扩张报网或中心上游，否则会形成叠加返工。

## 8. 禁止事项

- 禁止把 BY220 多个菜单随意合并。
- 禁止使用“代理组织管理”等自造名称替代 BY220 的原菜单。
- 禁止先做自认为更现代的交互再让用户修改。
- 禁止用占位假数据冒充已完成业务。
- 禁止复制敏感配置、密码、Token、真实外部地址。
- 禁止把未实现的菜单跳到一个内容不匹配的页面后宣称完成。

## 10. 完成判定

只有当某一 BY220 页面满足以下条件时，才能标记完成：

1. 菜单名称和位置一致。
2. 页面主要结构一致。
3. 操作按钮和流程一致。
4. 字段含义一致。
5. 数据结果和状态变化一致。
6. 权限边界一致。
7. 已记录必要偏差。
8. 已完成本机运行态验证。
