# GitHub 传统运营后台界面调研

> 调研日期：2026-09-29
>
> 调研目标：寻找与当前后台参考图相近的“单页、密集、高信息量、老式桌面运营软件”界面，用于减少后续逐项布局调整，而不是照搬业务代码。

## 1. 调研方法

使用已登录的 GitHub CLI 进行仓库、代码和许可证检索，重点包括：

- 中文界面特征词：`报网类型`、`报网状态`、`预留封盘`、`上下分确认`、`修改积分`、`下注榜`、`链接二维码`
- 业务词：`lottery admin`、`彩票 后台`、`番摊`、`开奖 后台`
- 界面词：`layui admin`、`H-ui.admin`、`legacy admin ui`、`classic admin template`
- 对命中项目进行浅克隆，阅读模板、CSS、许可证和提交时间
- 对最接近的 `by220/cp` 做只读静态渲染，确认实际布局

## 2. 结论摘要

GitHub 上**没有找到一个高星、活跃、明确授权、并且界面与参考图高度一致的完整开源运营后台**。

最接近参考图的项目是 [by220/cp](https://github.com/by220/cp)：

- 界面字段和布局几乎与参考后台同源。
- 使用固定约 `900×800` 的工作窗口、密集控件、左侧下注榜/积分榜、右侧状态与用户操作区。
- 技术栈为 ThinkPHP + jQuery + 旧版 Element UI 样式 + jQWidgets。
- 只有 1 star、3 forks，没有 LICENSE，包含大量备份文件、vendor、配置和部署残留，不能安全复制。
- 适合作为**视觉结构参考**，不适合作为依赖或复制来源。

其次可以参考 [MaGua-Bishop/bot](https://github.com/MaGua-Bishop/bot)：

- 业务字段高度相似，包含下注榜、预留封盘、上下分确认、修改积分、报网类型和后台积分管理。
- Django 后台、Layui + Bootstrap 5，属于同业务形态的另一套实现。
- 没有 LICENSE，0 star，代码同样不适合直接引入。
- 适合参考信息架构和交互流程。

如果只需要一个可合法复用的传统后台基础样式，优先参考 MIT 项目：

- [H-ui.admin.page](https://github.com/jackying/H-ui.admin.page)：老式中文后台，表格、表单、弹层和小按钮风格接近，但整体是左侧菜单式后台，不是单页运营台。最后推送约 2020 年。
- [layuimini](https://github.com/zhongshaofa/layuimini)：MIT，约 4.2k stars，Layui 后台壳层，组件丰富、维护记录较好，但视觉偏现代左菜单后台，不是参考图那种桌面软件布局。
- [AdminLTE](https://github.com/ColorlibHQ/AdminLTE)：MIT，高活跃、高质量，但属于通用 Bootstrap 后台，只能借鉴组件和布局语义，视觉差异较大。

## 4. `by220/cp` 的界面特征

从源码中的 `application/rbt/view/index/admin_list.html` 和 `public/static/xz/admin/home.css` 可确认：

- `.topframe` 固定约 `900×800`，黑色边框，整体像老式桌面软件窗口。
- 顶部为欢迎、账号、积分和退出操作。
- 左列固定约 `300px`，集中放登录、链接、下注榜或积分榜。
- 右侧和中部放当前状态、赔率、限额、封盘、上下分确认、积分和用户操作。
- 大量使用绝对定位、固定高度、小尺寸输入框和按钮。
- 字体尺寸普遍在 `12–14px`，控件高度约 `22–35px`。
- 视觉核心不是“现代卡片”，而是“窗口、边框、状态栏、面板和密集操作区”。

可借鉴的内容：

- 工作窗口尺寸和左右列比例。
- 顶部状态条和模块标题条。
- 1–2px 边框、浅色面板、紧凑控件。
- “状态在上，列表和编辑操作并列，不影响相互高度”的结构。
- 表格、输入框、单选按钮和动作按钮的密度。

不建议复用的内容：

- 固定写死坐标和大量历史内联样式。
- 老版 Element UI、jQuery、jQWidgets 混合栈。
- 旧版依赖、未维护的浏览器兼容代码。
- 无许可证的业务代码、图片、音频和模板。
- 参考仓库中的账号配置、数据库配置、外部地址和备份文件。
- 支付、代理分成、现实资金或可兑换资产相关业务。

## 5. 对本项目的建议

1. **继续使用现有 Vue 3 工程，不引入参考仓库的 PHP 或旧 jQuery 框架。**
2. **把 `by220/cp` 当作视觉蓝图，而不是代码来源。** 按项目现有组件重新实现布局、边框、颜色、尺寸和密度。
3. **通用交互组件可参考 MIT 项目。** 例如 H-ui 的紧凑表单/表格、layuimini 的组件行为，但不要引入整套旧框架。
4. **保留当前的后端和权限边界。** 参考项目只用于看界面，不把彩票、代理、支付、现实资金或未知业务规则带入本项目。
5. **建立自己的运营台主题层。** 用一个共享样式文件和少量基础组件统一窗口、面板、状态条、表格和紧凑按钮，避免后续继续逐个页面手调。
6. **需要进一步节省时间时，最有效的方式不是复制整仓库，而是从 `by220/cp` 提取一套布局骨架和尺寸规范，再映射到现有 Vue 组件。**

## 6. 建议的下一步

- 以 `by220/cp` 为视觉基准，整理一份“运营台布局坐标和尺寸映射表”。
- 只保留本项目需要的模块，例如期号、状态、赔率、上下分、玩家列表、聊天记录、机器人管理。
- 用现有 Vue 组件实现统一的 `ops-window`、`ops-toolbar`、`ops-panel`、`ops-statusbar`、`ops-compact-table` 和 `ops-action-button`。
- 保留当前项目的虚拟积分边界，不引入参考项目的支付、代理和现实资金代码。
