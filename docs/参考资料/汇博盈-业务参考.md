## 已形成的玩法模型（部分确认）

### 参考页已直接观察到的事实

对单个位置的号码 `n`，页面显示的 `番` 与 `n % 4` 一致：余数 `1/2/3` 分别显示为 1/2/3 番，余数 `0` 显示为 4 番。观察样例中 `18 -> 2 番`、`20 -> 4 番`、`04 -> 4 番`、`19 -> 3 番`，与此关系一致。

页面把 1、3 番归为 `单`，2、4 番归为 `双`；`大小`则按实际号码判断，`01～10` 为 `小`，`11～20` 为 `大`。页面内嵌的玩法说明明确写成“大于等于 11 为大，小于等于 10 为小”，这与观察到的 `18 -> 大`、`04 -> 小`、`19 -> 大` 一致。首期结算引擎至少需要先计算：

```text
番 = n % 4；余数为 0 时按 4 番处理
单双 = 1/3 番为单，2/4 番为双
大小 = 01～10 为小，11～20 为大
```

### 参考页内嵌的玩法说明（已直接读取）

页面源码中的“玩法规则”对首期需要的玩法给出了明确文本，当前可以作为参考页规则的直接证据：

- `番`：投注一个番数；开出该番为赢，其余三番为输。
- `角`：投注两个番数；开出任一所选番数为赢，其余为输。页面示例为 `12角`。
- `车`：投注三个番数；开出三个番数之一为赢，剩余一个为输。
- `严`：投注两个番数；第一个为赢号，第二个为和号，剩余两个为输号。`1严2` 与 `1念2` 的规则相同。
- `加`：投注三个番数；第一个为赢号，后两个为和号，剩余一个为输号。
- `正`：以 1 正为例，开 1 番为赢、开 3 番为输、开 2/4 番为和；其他正玩法按相同的相对关系处理。
- `通`：投注两个赢号，剩余两个番数一个为输、一个为和；例如 `3通12` 表示 1/2 赢、3 输、4 和。
- `无`：页面把 `12无3` 作为 `3通12` 的另一种下注格式，即 1/2 赢、3 输、4 和。
- `单双`：1/3 番为单，2/4 番为双。
- `大小`：实际号码 11～20 为大，01～10 为小。
- `特`：按实际开奖号码直接命中，页面支持 `01特` 至 `20特`，也支持用斜线组合多个特定号码。

页面同时给出了可识别的下注文本格式，例如：`1番100`、`12角100`、`124/100`、`1严2/100`、`1加23/100`、`1正100`、`3通12/100`、`12无3/100`、`单100`、`大100`、`01特100`。当前演示应先把这些文本解析为结构化下注对象，再进入结算，不建议直接以字符串参与结算。

### 通用番摊资料可用于解释的玩法

公开资料对传统番摊的通用定义与页面中的 `番/念/角/通/正/单双` 命名基本一致：

- `番`：选择一个番数，开出该番为赢，其余为输。
- `念`：前一个番数为赢号，后一个番数为和号，另外两个为输号；顺序不能交换。
- `角`：选择两个番数，任一命中为赢，另外两个为输。
- `通`：选择两个赢号，再指定一个输号，剩下一个为和号。
- `正`：选择一个主番；通用资料通常定义一个相对番为输，另两个为和，实际返还需以页面赔率为准。
- `单双`：1、3 番为单，2、4 番为双。

这些是外部通用资料的解释，不能替代参考页自身的结算协议。首期实现应把“赢、和、输”作为明确的结算结果，而不是只保存一个布尔值。
