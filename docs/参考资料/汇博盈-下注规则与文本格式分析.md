## 1. 资料范围和结论边界

本文件整理两类资料：

- 用户提供的汇博盈页面“玩法说明”截图。
- 当前项目 `web/汇盈博每期的下注情况.txt` 样本，记录了 `31393303` 至 `31393313` 共 11 期的下注核对列表。

截图中的玩法说明是目标页面的直接规则证据；下注文本是页面实际输出样本，可用于识别语法、别名和省略写法。两者都是外部页面参考，不能自动等同于当前项目已经确认的生产规则。对于样本无法唯一确定的内容，本文件标记为“待确认”或“强推断”，不能直接写死到结算代码。

## 3. 基础概念

### 3.1 番值

页面开奖结果的基础结果是 1、2、3、4 番。当前项目已经按以下关系计算号码对应番值：

```text
1、5、9、13、17 -> 1 番
2、6、10、14、18 -> 2 番
3、7、11、15、19 -> 3 番
4、8、12、16、20 -> 4 番
```

等价公式是 `number % 4`，余数 0 按 4 处理。除 `特` 以外，下注代码中的 1、2、3、4 都应优先按番值理解，而不是按实际开奖号码理解。

### 3.2 金额和两种书写方式

截图直接给出了两种常见金额写法：

```text
玩法描述金额       例如：1番100、2番269、大10
玩法描述/金额       例如：1严2/51、124/216、07特219
```

金额在样本中表现为每个下注项最后的整数。样本没有证明金额是否允许小数、负数、千分位或其他货币格式；当前项目金额校验仍以自身接口和结算方案为准。

### 3.3 位置前缀

此前页面观察到完整输入还可以带位置前缀，例如：

```text
第8球/3番15
第8球/13角15
第4球/2无4/983
第6球/2通1/968
第2球/02特548
```

本次 `下注情况.txt` 的核对列表没有出现 `第N球/` 前缀，因此只能推断它是去掉位置后的汇总文本，不能从该文件推断某一笔下注对应第几球。当前项目是 8 球模型，后续解析时应把位置作为独立字段，不要从下注代码中猜测位置。

## 4. 截图直接确认的玩法

| 玩法 | 截图规则 | 页面格式 | 结果解释 |
| --- | --- | --- | --- |
| `番` | 投注一个番号 | `1番100` | 开出所选番为赢，其他三番为输 |
| `角` | 投注两个番号 | `12角100` 或 `12/100` | 开出任一所选番为赢，另外两番为输 |
| `车` | 投注三个号码，开出其中之一中奖 | 截图示例 `1车100`、`124/100` | 三个所选番任一开出为赢，未选番为输；“1车”语义需单独确认，见第 6 节 |
| `严` | 两个番号，一个赢、一个和 | `1严2/100` | 第一个为赢号，第二个为和号，其余为输 |
| `念` | 与 `严` 相同的两号顺序玩法 | `1念2/100` | 第一个为赢号，第二个为和号，其余为输 |
| `加` | 三个番号，一个赢、两个和 | `1加23/100` | 第一个为赢号，后两个为和号，剩余番为输 |
| `正` | 一个主番 | `1正100` | 以 `1正` 为例：1 赢、3 输、2/4 和；其他主番按相对关系处理 |
| `通` | 两个赢号，剩余两个一输一和 | `3通12/100` | 3 为输号，1/2 为赢号，剩余 4 为和号 |
| `无` | 截图给出两赢一输一和写法 | `12无3/100` | 1/2 为赢号，3 为输号，剩余 4 为和号；与 `3通12` 结果结构等价 |
| `单、双` | 1、3 为单；2、4 为双 | `单100`、`双100` | 按开奖番值的奇偶命中 |
| `大、小` | 第八位号码大于等于 11 为大，小于等于 10 为小 | `大100`、`小100` | 这是按实际号码判断，不是按番值判断 |
| `特` | 开奖结果按实际号码直接命中 | `01特100`、`02/03/04特100` | 选择一个或多个 01～20 实际号码，开出所选号码为赢 |

截图顶部还给出三个非下注命令：

```text
上100   上分
下100   下分
查      查询分数
```

这三个命令不应进入下注结算解析器。

### 5.2 省略玩法字的两位和三位写法

截图给出了省略玩法字的格式，样本验证了这些格式确实被使用：

| 形态 | 样本示例 | 当前可推断含义 |
| --- | --- | --- |
| 两位数字`/金额` | `13/52`、`12/42`、`14/50`、`23/53`、`34/17` | 等价于两位 `角`，两个数字是番值 |
| 三位数字`/金额` | `124/216`、`134/52`、`234/133`、`123/167` | 等价于三位 `车`，三个数字是番值 |
| 两位数字加显式 `角` | `12角114`、`23角44`、`34角259` | `角` 的完整写法 |
| 三位数字加显式 `车` | `3车151` | 页面确实出现，但该项只有一个数字在 `车` 前，语义仍待确认 |

按当前样本，数字长度为 2 或 3 的省略写法只在金额前带 `/` 时容易识别；解析器不能把任意连续数字直接当作下注代码，否则会与金额发生歧义。

### 5.3 `特` 的号码写法

`特` 与其他玩法不同，前面的数字是实际号码，不是番值。样本出现了：

```text
单号：01特、02特、05特、07特、09特、10特、20特
多号：3/7特、3/7/11特、1/5/9特、12/16特
```

样本同时出现 `1特`、`07特`、`20特` 等不同补零方式。页面截图偏好 `01` 至 `20` 的两位展示，但输入规范是否强制补零，当前资料不能确定。建议解析时允许 1～20，保存结构化号码时统一为整数，展示时再统一两位格式。

## 6. 仍然存在的关键歧义

### 6.1 单数字 `无` 形式

样本中有 23 项形如：

```text
1无2/120
2无4/249
3无1/161
4无2/39
```

截图只明确说明了 `12无3/100`：前面两个番为赢号，后面一个番为输号，剩余番为和号。它没有说明 `1无2` 这种只有一个数字在 `无` 前、一个数字在 `无` 后的含义。

因此当前结论是：

- `12无3` 这类“两赢一输一和”规则已确认。
- `1无2` 这类写法确实存在，但它可能是另一种“三赢一输”的无组合，也可能有平台专用的顺序含义。
- 仅凭样本文本，没有开奖后的逐笔结算结果，无法确定 1 和 2 哪个是输号，也无法确定另外两个番是赢、和还是其他状态。
- 当前项目不能把所有 `无` 都按同一个三参数结构接收；应至少预留 `NONE_TWO_WIN_ONE_LOSE` 和待确认的另一变体，待拿到实际结算结果后再启用。

### 6.2 `车` 的“1车”形式

截图文字同时出现了“投注三个号码”和 `1车100` 示例，而样本出现 `3车151`，与三位省略写法 `124/216` 并不完全一致。现有资料能够确认三位 `车` 组合，例如 `124/100`，但不能确认单数字 `1车100` 或 `3车151` 是否：

- 页面快捷语法，由一个数字展开成预设组合；
- 页面说明中的笔误或显示截取；
- 另一种“车”玩法。

在没有实际开奖结算对应记录前，单数字 `车` 不应自动转换成三位组合。

### 6.3 位置、赔率和订单口径

本文件不能从核对列表确定以下内容：

- 每笔下注对应第几球；
- 同一用户同一期同一玩法的重复下注是合并、覆盖还是分开结算；
- `核对列表` 的统计口径；
- 赔率是否包含本金；
- `和` 是否退回本金，以及不同玩法的和局金额处理；
- `特` 多号码组合的赔率和本金扣除方式；
- 单笔最低/最高金额、单玩法限额和封盘后的处理；
- 下注失败、网络故障、重试造成重复提交时的订单规则。

截图底部声明“若遇网络故障、网络攻击等造成的数据丢失，以后台备份数据为准”，这只是参考页面的提示文案，不能当作当前项目已经实现的备份或争议处理能力。

## 7. 对当前项目解析器的适配建议

后续如果实现文本下注入口，建议先将原文解析为结构化对象，再交给现有结算服务：

```text
BetText {
  ballPosition: 1..8 或空
  playType: FAN / ANGLE / CAR / STRICT / ADD / POSITIVE / TONG / NONE / ODD_EVEN / BIG_SMALL / SPECIAL
  parameters: 番值列表或实际号码列表
  stake: 金额
  syntax: 显式 / 省略 / 别名
  rawText: 原始下注片段
}
```

建议的归一化规则：

1. `念` 归一化为与 `严` 相同的顺序玩法，但保留原始字样供订单展示。
2. 两位纯番数字归一化为 `角`，三位纯番数字归一化为 `车`；只接受不重复的 1～4 番。
3. `特` 的参数按 1～20 实际号码解析，支持斜线多个号码，不按番值转换。
4. `通` 按“输号在 `通` 前、两个赢号在 `通` 后”解析；`无` 的两赢一输形式按“两个赢号在前、输号在后”解析。
5. `1无2` 等单数字 `无` 形式先进入待确认分支，不参与正式结算。
6. 金额、位置和原始文本独立保存；不要把位置前缀、玩法参数和金额重新拼成唯一业务键。
7. 解析失败时返回明确格式错误，不把未知写法默认为 `番`、`角` 或 `无`。

## 8. 当前结论

可以根据截图和 11 期下注样本，较完整地推出 `番、角、车、严/念、加、正、通、单双、大小、特` 的主要玩法和下单格式，也可以确认两位/三位省略字的实际使用。当前最重要的未决项是单数字 `无`、单数字 `车`、位置前缀在核对列表中的去向，以及金额和核对列表数字的统计口径。

因此，本资料可以作为当前项目下注文本解析和后台规则配置的设计依据，但在 `无` 的另一变体和单数字 `车` 取得真实开奖后逐笔结算样本前，不应宣称已经完整复刻汇博盈全部订单规则。
