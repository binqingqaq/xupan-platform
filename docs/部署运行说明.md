# 聊天室 WebSocket 部署运行说明

## 当前边界

当前实现是单实例 WebSocket：连接注册表和房间广播位于单个 Spring Boot 进程内。它支持多个用户和多个浏览器连接，但不支持多台应用服务器之间的实时广播，也不代表生产高可用。

服务端常驻机器人、Redis/MQ 跨实例广播、聊天治理后台和正式故障演练属于后续阶段。本说明不包含任何数据库密码、Token、ticket 或完整会话 URL。

## 本地运行

后端需要 Java 21 和可用的 MySQL 8.4 LTS 配置：

```powershell

.\mvnw.cmd spring-boot:run
```

数据库连接使用以下外部环境变量，值保存在受控本地或服务器配置中，不提交到 Git：

- `XUPAN_DB_URL`
- `XUPAN_DB_USERNAME`
- `XUPAN_DB_PASSWORD`
- `XUPAN_CHAT_WS_ALLOWED_ORIGINS`

前端开发服务器：

```powershell
Set-Location D:\codes\liuhecai\xupan-platform\web
npm install
npm run dev
```

Vite 已将 `/api` 和 `/ws` 代理到 `http://127.0.0.1:8080`。用户页面为 `http://127.0.0.1:5173/room`，生产静态页面由 Spring Boot 提供。

## WebSocket 契约

- 票据：登录后调用 `POST /api/auth/ws-ticket?roomCode=main`，票据短期有效且只能消费一次。
- 连接：`ws://<host>/ws/chat/main?ticket=<短期票据>`；生产 HTTPS 使用 `wss://`。
- 客户端建立连接后发送 `subscribe`，携带房间和最后接收序列。
- 发送消息使用 `message.send`，必须提供稳定的 `clientMessageId` 和纯文本 `content`。
- 断线补偿使用现有 REST `GET /api/chat/rooms/{roomCode}/messages?afterSequence=...`。
- 未订阅连接不能发送消息；用户身份、昵称、头像和权限不接受客户端自报。

## Nginx 反向代理

在现有站点的 API location 同级增加 WebSocket location。`proxy_pass`、域名和 TLS 参数必须结合服务器当前配置确认，不能直接覆盖整个站点配置：

```nginx
location /ws/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 75s;
}
```

修改后先执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

生产 Origin 通过 `XUPAN_CHAT_WS_ALLOWED_ORIGINS` 配置明确来源，禁止使用 `*`。Nginx 日志和应用日志不得记录 ticket 原文。

## 故障排查

- 页面显示“实时连接不可用，已切换普通模式”：检查浏览器 Network 中 `/api/auth/ws-ticket` 是否成功、WebSocket 是否返回 101、Origin 是否在白名单中。
- ticket 失败：确认用户登录态、会话未注销、用户为 ACTIVE、用户拥有聊天室查看权限；不要重用旧 ticket。
- 连接成功但不能发消息：确认客户端已发送 `subscribe`，用户拥有发言权限且未被禁言；服务端消息仍应通过现有 `ChatMessageService` 落库。
- 消息重复：检查客户端是否同时启动了 WebSocket 和 REST 轮询；正常 READY 状态不应运行聊天室降级轮询，消息合并按 ID/序列去重。
- 多节点部署：当前实现不支持直接扩容；必须先完成 outbox 可靠发布和 Redis/MQ 跨实例设计，再接入负载均衡。
