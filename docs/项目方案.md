### 3. 结算规则

对单球号码 `n`：（未对齐核对：以下番/单双/大小口径与玩法判定尚未与 BY220 源码逐行核对）

```text
fan = n % 4；余数 0 映射为 4
parity = fan 为 1 或 3 时为单，否则为双
size = n 在 01～10 时为小，在 11～20 时为大
```

玩法判定返回 `WIN`、`DRAW` 或 `LOSE`：（未对齐核对）

| 玩法 | 结构 | 判定（未对齐核对） |
| --- | --- | --- |
| 番 | 一个番数 | 命中为赢，其余为输（未对齐核对） |
| 角 | 两个番数 | 任一命中为赢，其余为输（未对齐核对） |
| 车 | 三个番数 | 任一命中为赢，未选番为输（未对齐核对） |
| 严 | 赢号、和号 | 赢号为赢，和号为和，其余为输（未对齐核对） |
| 加 | 赢号、两个和号 | 赢号为赢，两个和号为和，余号为输（未对齐核对） |
| 正 | 一个主番 | 主番为赢，相对番为输，另外两个为和（未对齐核对） |
| 通/无 | 两个赢号、一个输号 | 赢号为赢，输号为输，剩余番为和（未对齐核对） |
| 单双 | 单或双 | 按番的奇偶命中为赢，否则为输（未对齐核对） |
| 大小 | 大或小 | 按实际号码 11～20/01～10 命中为赢，否则为输（未对齐核对） |
| 特 | 一个或多个实际号码 | 号码直接命中为赢，否则为输（未对齐核对） |

赔率结算采用可配置口径：（未对齐核对）

```text
LOSE: -stake
WIN: stake * (odds - 1) 作为净盈亏
DRAW: drawPolicy 配置，首期默认退回本金，净盈亏为 0
```

页面当前观察到的默认赔率为：番 3.850、角 1.950、念 2.900、单双/大小 1.950、正 1.950、车 1.316、两赢一输一和的无组合 1.950、三赢一输的无组合 1.475、特 18.00。实现中必须保存赔率快照，不能依赖开奖后的当前赔率。（未对齐核对：参考页观察值，未与 BY220 赔率配置核对）

### 4. 技术架构

首期使用单体 Spring Boot 服务，浏览器页面由同一服务的静态资源提供，减少前后端联调成本：（技术选型）

```text
浏览器静态页面
    -> REST API：当前期、轮期状态、玩法赔率、下注、演示后台控制
    -> Spring Boot Controller
    -> 领域服务：期号、玩法解析、结算
    -> Repository/JDBC
    -> MySQL 8.4 LTS；测试使用 H2
```

首期暂不引入 Redis、Quartz、WebSocket、MyBatis 和微服务。自动轮期使用 Spring `@Scheduled` 每秒推进，前台使用 REST 轮询；后续若确认多人实时消息需求，再评估 SSE/WebSocket。（技术选型；"暂不引入 WebSocket"已被 2026-09-13 单实例 WebSocket 实现取代，时点记录见冻结历史层）

### 5. 数据边界
