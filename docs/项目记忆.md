## 2026-09-10 自动轮期与随机开奖

- 用户已确认：8 个球号分别在 01～20 内随机生成，允许重复，不做去重；首期期号从 `3000000` 开始。
- 每期固定 300 秒：前 180 秒为 `BETTING`，到时自动封盘并进入 `DRAWING`；后 120 秒开奖中，期满生成最终号码、结算待结注单并自动创建下一期。
- 服务端使用 Spring `@Scheduled(fixedDelay = 1000)` 推进状态，前台通过 `/api/demo/game/current` 每秒轮询；服务端返回阶段、服务端时间、两个阶段截止时间和轮期事件。
- 随机开奖使用 `SecureRandom` 生成最终 8 个号码；开奖中的滚动预览使用按期号和秒数稳定的伪随机值，避免同一秒不同客户端显示不同结果。
- Flyway 新增 V3 轮期字段和 V4 轮期事件表；自动轮期状态转换、最终开奖和事件写入均有幂等条件。
- 已验证：`自动轮期服务Test` 能从 `3000000` 推进到开奖中，期满将旧期置为 `SETTLED` 并创建 `3000001`；前端 `npm run typecheck`、`npm run build` 已通过。

## 2026-09-24 管理员自助重置密码锁等待修复

- 现象：在用户管理里重置当前登录管理员的密码会卡住约 50 秒后失败，刷新后仍只能用旧密码登录。
- 根因：`UserAdminService.resetPassword` 在业务事务里持有操作人 `sys_user` 行的排他锁，而 `OperationAuditRepository.record` 用 `REQUIRES_NEW` 另开事务写 `sys_operation_log`；插入子表记录的外键检查需要对同一父行加共享锁，形成跨连接自等待，直到 `innodb_lock_wait_timeout`（50 秒）超时并回滚整笔事务。同类风险存在于管理员上传自己头像、修改自己角色等「改自己这行 + 写审计」的操作。
- 修复：审计改为显式管理事务——业务事务存在时登记 `TransactionSynchronization`，在业务事务提交或回滚、锁释放之后用独立事务写入；没有业务事务时直接写入。保留「业务回滚也写失败审计」的语义，审计失败不再回滚业务操作。
- 验证：新增 `UserPasswordResetIntegrationTest`（H2，2 个用例）与 `MySqlSelfPasswordResetVerification`（本机 MySQL，仅在提供 `XUPAN_DB_PASSWORD` 时运行，用临时管理员复现同一场景）。后端全量 `287/287` 通过，本机 MySQL 验证确认无锁等待、密码与审计均已写入，修复后后端已重启。
