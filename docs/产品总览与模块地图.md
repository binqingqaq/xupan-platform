## 2. 产品边界

### 2.1 已确认边界

- 产品定位为合法合规的虚拟积分娱乐产品。
- 余额、下注额、返还、盈亏、积分流水和结算全部表示虚拟积分。
- 不接入充值、支付、提现、转账、代理分成或现实资金结算。
- TEST 玩家和 BOT 必须有可见、可查询、可审计的身份标记，不能伪装成普通真实用户（**未对齐核对**：BY220 没有 REAL/TEST 身份维度，托就是玩家行上的 `isrobot`——application/rbt/controller/Index.php:622/:637/:684，全仓查 测试玩家|试玩|isTest|ceshi 零命中；收敛计划见 docs/文档索引.md）。
- 数据库是业务事实源；前端计算、浏览器状态、内存状态和临时文件不能作为唯一事实。
- 关键操作必须考虑权限、事务、幂等、审计、失败恢复和重复执行（工程基线）。

### 2.2 当前范围

- 一个单体 Spring Boot 服务。
- 一个单服务器、单实例运行基线。
- 一个当前游戏和期号流，已有期号、玩法、下注、开奖、结算和虚拟积分链路。
- 三大业务面：玩家前台 `/room`、**代理后台 `/console`（对应 `robot.php`，只接受机器账号（`AGENT` 角色）登录、机器隔离，玩家与托的全部运营都在这里）**、超级管理后台 `/platform-admin`（对应 `admin.php`）。**平台侧没有玩家运营面**，与玩家相关的只有 BY220 本来就有的**在线玩家 `/platform-admin/online-players`**（只读列表 + 强制下线 + 发消息）；上一批越界新增的 `/platform-admin/player-workbench` 已按方案 A 删除。另有聊天室和展示端页面；`/agent` 已确认收敛（BY220 三面入口对应：application/chat/controller/Index.php:14、application/rbt/controller/Index.php:677/:610/:252/:258/:298、application/admin/view/public/head.html:170-193）。
- 服务端常驻机器人和 TEST/BOT 自动行为。

### 2.3 当前不纳入或尚未确认

- 现实资金能力和可兑换资产。
- Redis、多实例协调、分布式调度锁和跨节点 WebSocket 广播。
- 第三方开奖接口或未经确认的生产开奖源。
- 代理钱包、信用额度、代理间玩家转移、代理赔率/返水/封盘/取消的真实结算映射、抽水、飞单、代理分成和现实资金语义。代理创建玩家/托及普通上下分已实现（BY220: application/rbt/controller/Index.php:677 AddMember、:610 UpDownScore；此前在 `/agent`，2026-10-02 确认收敛进 `/console`；2026-10-08 平台侧 A1 上下分改为扣/回玩家归属机器积分池、托不联动，**该平台侧链路现已无 UI 入口**），但尚未完成服务器/生产浏览器验收。
- 总结果聚合、特玩法金额口径、和局返还等仍需确认的业务规则。

## 3. 技术与部署基线

```text
Vue/Vite 前端
    -> REST API / WebSocket
Spring Boot 单体服务
    -> 领域服务、权限、调度、消息和审计
    -> JDBC Repository
MySQL 8.4 LTS（正式事实源）
    -> Flyway 迁移
```

- Java：21。
- 后端：Spring Boot，静态资源可由同一服务托管。
- 前端：Vue 3、TypeScript、Vite。
- 数据库：正式基线为 MySQL 8.4 LTS，测试可使用 H2，但 H2 结果不能替代 MySQL、服务器或生产证据。
- 当前运行决策：单服务器、单实例；扩容、Redis 和分布式能力必须以真实容量或故障证据为依据另行评估（工程基线）。**注意区分：定时任务互斥不是扩容问题**——单实例滚动重启（新旧进程并存数十秒）同样会重复开奖，该项属于上线前置，见 [上线可用收口与阶段 C 至 D 实施规划](plans/2026-10-02-上线可用收口与阶段C至D实施规划.md) §4 P0-1。

## 5. 模块依赖关系

```text
平台基础
  -> 身份与权限
       -> 机器端玩家/托工作台（/console，BY220 robot.php）
       -> 普通玩家前台
       -> TEST/BOT 自动行为
  -> 虚拟积分
       -> 下注与结算
       -> 积分报表
  -> 游戏核心
       -> 聊天反馈
       -> 服务端机器人
       -> TEST/BOT 自动行为
  -> 聊天与实时通信
       -> 玩家前台和机器人消息
       -> 代理组织与代理后台
            -> 代理管理、代理数据隔离和后续代理运营能力
```

关键原则：

- 钱包余额和流水由服务端交易链路产生，不能由页面直接计算或写入。
- 下注必须依赖当前期号、玩家身份、玩法校验和钱包余额；不能把下注做成单独页面假数据（BY220: application/chat/controller/Index.php:206 send 下注入口、application/common.php:454 wfuser 玩法校验、:1101-1134 addDan 扣分写注单）。
- 机器人消息是聊天事实或系统事件反馈，不能替代注单、钱包、结算等业务事实。
- 报表只能读取已有业务事实，不能再建一套与钱包、注单相冲突的统计事实源（BY220: application/rbt/controller/Index.php:388 GetScoreHis、:395 GetScoreHisDetail、:1062 Getalltongji 都是从 `record` 只读聚合）。
- 删除玩家不删除业务历史；必须撤销会话、链接和后续行为，并保留可审计关联（**与 BY220 不一致，未对齐核对**：BY220 application/rbt/controller/Index.php:235-243 DelMember 是物理删除 `rbuser` 行并把积分退回机器，本项目改为软删除+历史保留，尚未登记为有意偏离）。
