BY220 是用户确认的第一业务和界面基准。未列出映射表的新页面不得开始实现；不得将 BY220 独立菜单自行合并或改名。当前“代理组织管理”和 `/console/agents` 标记为临时偏离实现。
## 1. 状态定义

| 状态 | 含义 |
| --- | --- |
| 待确认 | 业务规则、范围或口径尚未由用户确认 |
| 已规划 | 已有方案或计划，但尚未形成可验收实现 |
| 开发中 | 当前工作区或分支正在实现 |
| 代码完成未验证 | 代码存在，但缺少对应自动化或运行态证据 |
| H2 已验证 | 测试数据库迁移、单元或集成测试通过 |
| 本机 MySQL 已验证 | 本机 MySQL 8.4 LTS 迁移或接口链路通过 |
| 服务器已验证 | 已在目标服务器现场验证 |
| 生产已验证 | 已在正式生产环境验证 |
| 暂不纳入 | 当前阶段明确不做，不代表需求已完成 |

## 3. 当前优先级

### P0：影响后续所有功能

- 继续维护身份、权限、虚拟积分和数据库事实源边界。
- 新功能必须更新模块归属、依赖关系和验收证据。
- 对“代码完成”“本机 MySQL 通过”“服务器通过”“生产通过”保持严格区分。

### P1：适合作为下一批业务功能

- 服务器生产硬化与补验：HTTPS、Secure Cookie、登录后浏览器/WebSocket、备份恢复、回滚和监控告警。
- 多实例部署前的强一致控制：玩家限额与「所有托每期总注单/总积分」需要数据库行锁或分布式锁。
- 下注榜后续能力：管理员撤单和 `上期` 榜单，必须另立计划并补齐权限、幂等、退款和审计。
- 代理组织后续能力：代理创建玩家/托、代理上下分、代理级报表、数据隔离复验和玩家转移专项。
- 报表与对账的现场复验，以及托行为的长周期统计观察。
- 后台仍是静态占位的区域收敛：报网控制、线路域名、封盘与显示控制。
- 玩家工作台新托行为面板的 375px 与桌面截图专项。

### P2：暂不抢先实现

- Redis、多实例、MQ、分布式调度。
- 现实资金和支付相关能力。
- 未确认的抽水、飞单、代理和资产兑换规则。

## 4. 使用方式

新需求进入时，先在本表找到所属模块：

1. 如果模块不存在，先在《产品总览与模块地图》中增加模块。
2. 如果模块存在但规则不清，先标记为“待确认”，不要直接写代码。
3. 如果模块存在且规则明确，建立跨模块影响清单，再创建实施计划。
4. 开发和验收结束后，只更新实际证据对应的状态，不提前提升环境等级。
