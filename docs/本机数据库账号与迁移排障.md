# 本机数据库账号与迁移排障

> 范围：仅说明当前 Windows 开发机的 Xupan MySQL 8.4 和本机应用。此文不包含密码；用户名对应的密码保存在被 Git 忽略的 `docs/本地环境密钥.md` 中。生产服务器须按生产数据库权限和 DBA 流程单独处理。

## 账号用途

| 账号/服务 | 用途 | 密码来源 |
| --- | --- | --- |
| MySQL 管理账号 `root` | 本机备份、创建测试库、维护 MySQL 设置；不能作为 Spring Boot 数据源账号 | `docs/本地环境密钥.md` 的「MySQL 8.4 / root 管理账号」 |
| MySQL 应用账号 `xupan_app` | Spring Boot 连接 `xupan_platform` 并运行 Flyway | 同文件的「MySQL 8.4 / 应用账号」 |
| 超级后台账号 `admin` | 登录 `/platform-admin` | 同文件的「本地应用首个管理员」 |
| 机器账号 `localadmin` | 登录代理后台 `/console` | 同文件的「本地机器账号」 |

这些账号分属数据库管理、应用数据库访问、平台管理和代理后台四类，不能用其中一个账号替代另一类。`xupan_app` 没有 `SUPER` 权限是预期的最小权限设计，不要为了迁移报错直接给应用账号加 `SUPER`。

## 本机服务定位

- Xupan 使用 Windows 服务 `MySQL84`，连接地址为 `127.0.0.1:3307`，业务库为 `xupan_platform`。
- 本机 `mysqlzt` 服务/3306 是另一套数据库，不是 Xupan 数据源。检查 JDBC 地址和监听端口后再连库。
- Spring Boot 本机默认端口为 8080；Vue/Vite 开发页通常为 5173，并把 `/api` 代理到 8080。
- 本机服务密码只从上述密钥文件加载。不要把真实密码放进 Git、普通文档、命令行参数或聊天记录。

## V95 触发器错误

### 原因

2026-11-10 本机 MySQL 状态为 `log_bin=1`、`log_bin_trust_function_creators=0`。Flyway V95 创建保护已确认开奖结果的数据库触发器时，MySQL 要求迁移连接拥有 `SUPER` 或允许低权限的触发器创建者。Spring Boot 使用 `xupan_app`，它只有数据库级权限，因此报 MySQL 1419。

应用账号没有 `SUPER` 是正确的安全边界；应修复本机 MySQL 的触发器创建策略，不应扩大应用账号权限。

### 本机修复

已于 2026-11-10 在本机 MySQL 8.4 执行并持久化：

```sql
SET PERSIST log_bin_trust_function_creators = ON;
```

该设置作用于本机 MySQL84，不是生产配置；应用账号仍没有 `SUPER`。确认方式：

```sql
SELECT VERSION(), @@GLOBAL.log_bin, @@GLOBAL.log_bin_trust_function_creators;
SHOW GRANTS FOR 'xupan_app'@'127.0.0.1';
```

当前本机变量应为 `log_bin=1`、`log_bin_trust_function_creators=1`。未来若 MySQL 重装或清理持久变量，V95 等创建触发器的迁移会再次报 1419；生产环境应由 DBA 按生产策略审批，不要直接照搬本机设置。

## Flyway 检查顺序

1. 先确认 JDBC URL、目标库、MySQL 版本和应用账号；Xupan 本机数据库是 3307，不是 3306。
2. 按 `installed_rank` 检查真实迁移进度，不能用字符串列 `MAX(version)` 判断版本；例如 V99 在字符串排序下可能大于 V112。

   ```sql
   SELECT installed_rank, version, description, success
   FROM flyway_schema_history
   ORDER BY installed_rank DESC
   LIMIT 10;
   ```

3. 检查待执行迁移的 DDL、数据回填、约束条件、Java Migration 和 Flyway checksum；`flyway repair` 不能用缺少 Java migrations 的不完整 classpath 执行。
4. 共享本机业务库升级前先做逻辑备份并计算 SHA-256，记录数据库名、迁移前后 `installed_rank`、升级错误和恢复路径。不要清空共享库来绕过迁移问题。
5. 确认本机 MySQL 允许 V95 触发器创建后，再由 `xupan_app` 启动 Spring Boot/Flyway。启动后检查 health、迁移版本、目标 API、SPA 路由和静态资源。
6. 把本机 MySQL、单元/隔离 H2、浏览器、服务器和生产验收分开记录；一次本机 HTTP 200 不能代替其余层级。
