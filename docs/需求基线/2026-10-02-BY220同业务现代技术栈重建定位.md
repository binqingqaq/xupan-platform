# BY220 同业务现代技术栈重建定位

> 确认日期：2026-10-02
>
> 权威细则：`docs/参考资料/BY220严格平移总规则.md`

## 1. 项目本质

`xupan-platform` 不是 BY220 的“相似参考项目”，也不是重新设计的新产品。

它是：

```text
BY220 同业务系统
+ 现代技术栈重新实现
+ MySQL 8.4 LTS 和 Flyway
```

即：

- 业务流程基本一样。
- 三大入口一样。
- 页面菜单和操作逻辑按 BY220 逐项平移。
- 只是因为 BY220 的 PHP/ThinkPHP/旧前端/旧运行方式太老，所以换成 xupan-platform 的技术栈。

## 2. 必须一致的三大业务面

| 业务面 | BY220 | xupan-platform |
| --- | --- | --- |
| 玩家前台/下注端 | 玩家链接、期号、开奖、聊天、下注 | 保持相同业务流程 |
| 代理后台 | `robot.php` | `/agent` |
| 超级管理后台 | `admin.php` | `/platform-admin` |

三方不能互相替代：

- 玩家前台不是代理后台。
- 代理后台不是超级管理后台。
- 超级管理后台不是代理后台。

## 3. 平移要求

- BY220 有页面，就先按对应页面实现。
- BY220 有菜单，就保留对应菜单名称和位置。
- BY220 有操作按钮，就保留对应操作和结果。
- BY220 有字段，就先建立字段映射。
- BY220 有状态，就保持状态流转。
- 不先做自己的“更合理”设计。
- 不把子账号和机器管理合并为“代理组织管理”。
- 不把代理后台的玩家/托创建搬到超级管理后台。
- 不把未实现菜单跳到内容不匹配的页面后宣称完成。

## 4. 允许差异

只允许以下原因产生差异：

1. PHP 旧技术栈替换为 Java/Vue/MySQL。
2. 数据库结构改为 Flyway 管理的 MySQL 8.4 LTS。
3. 安全、权限、审计和幂等工程基线增强。
4. 用户确认的虚拟积分合规边界。
5. 用户明确批准的产品调整。

所有差异必须记录在实施计划和验收记录里，不能静默改变业务结果。

## 5. 完成标准

只有当一个 BY220 页面在 xupan-platform 中达到以下条件时才算完成：

- 菜单一致。
- 页面结构和主要字段一致。
- 操作按钮和行为一致。
- 状态流转一致。
- 权限和入口一致。
- 数据结果一致。
- 本机运行态已验证。
- 必要偏差有记录并经用户确认。
