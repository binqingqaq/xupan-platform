# 澳门四分彩独立开奖业务需求草案

> 状态：本次业务口径已由使用者于 2026-11-10 确认，本文作为本功能实施需求依据。功能实现和验收状态以开发计划及后续验收记录为准。
>
> 范围：梳理澳门四分彩独立开奖、后台逐球预设和开奖页展示。截图用于说明当前展示样式及开奖历史表格的参考形态；业务规则以本次文字描述为准。现有澳门四分彩占位行目前镜像快乐8展示数据，不能视为澳门四分彩的真实独立开奖结果。

## 1. 业务目标

为“澳门四分彩”建立独立的开奖数据和每日开奖流程：后台管理员可以为下一期的七个球位分别预设号码；每天约定开奖时间到达后，服务端保留已预设号码，并为未预设球位生成随机号码；开奖后生成下一期。移动开奖页的澳门四分彩行读取并展示这套独立数据，不再把快乐8结果当作澳门四分彩结果。

澳门四分彩在本需求中仅用于开奖展示，不开放下注，不参与玩家结算、机器人消息、代理后台或中心上报。

## 2. 已明确的业务规则

| 项目 | 本次描述整理出的规则 |
| --- | --- |
| 彩种名称 | 澳门四分彩 |
| 开奖频率 | 每天一期 |
| 计划开奖时间 | 每天晚上 20:30，北京时间（Asia/Shanghai） |
| 期号 | 从 100 期开始，每天进入下一期；开奖页面只显示期号末三位 |
| 球位数量 | 每期 7 个球位 |
| 号码范围 | 每个球位为 1 至 40 的整数；页面展示可补零为 `01` 至 `40` |
| 同期号码 | 七个号码互不重复 |
| 管理员预设 | 管理员可以分别指定任意球位的号码；未指定的球位留空 |
| 开奖取值 | 到期开奖时，指定球位使用管理员保存的号码；空球位由系统随机生成 |
| 部分预设 | 只指定部分球位时，保留指定号码，并为其余球位随机补足；全部未指定时，七球均随机生成 |
| 开奖后 | 保存本期完整开奖结果，状态变为“已开奖”，并进入次日 20:30 的下一期；下一期状态为“待开奖” |
| 状态 | 仅有“待开奖”和“已开奖”；不设置“开奖中”状态 |
| 展示数据 | 开奖页澳门四分彩行读取澳门四分彩自己的后端开奖结果和期次，不复用快乐8开奖结果 |

由于同期开奖号码不得重复，管理员预设号码之间不得重复；随机补出的号码也不得与预设号码或同一期已生成号码重复。

## 3. 管理后台页面

### 3.1 菜单与页面

- 在超级管理后台 `/platform-admin` 增加独立的“澳门四分彩”菜单。
- 菜单页面提供澳门四分彩期次及开奖记录表格，不把此功能放入代理后台 `/console`。
- 页面字段和操作按下表收敛；不显示截图中与本需求无关的查询区、补期区、待结算数量、下注数量等列或操作。

### 3.2 表格字段

| 列 | 展示内容 |
| --- | --- |
| 彩票名称 | 固定显示“澳门四分彩” |
| 期号 | 本期唯一的期号 |
| 开奖球号 | 已开奖期显示七个最终号码；待开奖的下一期显示已预设球位的号码，未预设球位显示 `-` |
| 开奖时间 | 已开奖期显示实际开奖时间；待开奖期显示计划开奖时间 |
| 当前状态 | 显示本期当前状态，例如待开奖、已开奖；最终状态名称需确认 |
| 操作 | 仅保留“编辑”按钮 |

表格默认展示 20 条：一条未来待开奖期，以及 19 条历史开奖记录。待开奖期排在最前，其后展示最近的历史记录。待开奖行用于显示下一期预设；号码已预设则显示号码，未预设显示 `-`。

### 3.3 编辑和保存

1. 管理员点击待开奖期的“编辑”按钮，进入该期的开奖号码编辑界面。
2. 编辑界面提供 7 个球位输入项，每个球位可单独填写 1 至 40 的号码，也可保持未指定。
3. 管理员点击“确认”后保存预设；确认只保存预设号码，不提前开奖。
4. 保存成功后回到或更新表格：已预设球位显示号码，未预设球位显示 `-`。
5. 同一期预设号码重复、超出 1 至 40 或格式无效时，不允许保存，并提示具体球位或原因。
6. 已开奖期不可再作为下一期预设进行编辑。管理员是否需要修正已开奖结果，本次未提出，草案不提供该能力。

编辑界面采用弹窗、抽屉还是独立页面未指定；确认交互形态时再定。

## 4. 每日自动开奖与轮期

1. 服务端按澳门四分彩自己的每日计划，在北京时间（Asia/Shanghai）每天 20:30 执行开奖。
2. 开奖时读取当前待开奖期已保存的七个球位预设。
3. 保留所有有效预设号码，再从 1 至 40 的可用号码中，为每个空球位随机生成一个号码，保证最终七球互不重复。
4. 一次性保存完整开奖结果、实际开奖时间和本期最终状态；不得只保存部分开奖结果后就进入下一期。
5. 本期完成后立即创建或切换至次日 20:30 的下一期，状态为“待开奖”。状态只从“待开奖”转为“已开奖”，不经过“开奖中”。
6. 期号从 100 开始，逐期递增；开奖页面仅显示期号末三位。
7. 开奖页读取后端澳门四分彩当前期和已开奖记录；每天 20:30 开奖后立即刷新澳门四分彩这一行。页面刷新或重新加载后仍应显示相同期号和开奖结果。

如果服务在 20:30 时不可用或开奖执行失败，如何补跑、是否延迟开奖、是否告警，以及重启后如何避免重复开奖，需要在实施方案中定义并验收；业务上不得静默跳过该期或重复创建开奖结果。

## 5. 开奖页展示

- 保留现有开奖页澳门四分彩展示行的位置与基本视觉结构，展示名称、期号、七个球号、开奖状态/倒计时和下一期计划时间等现有对应信息。
- 下一期尚未开奖时，开奖页面继续展示上一期的七个开奖号码，不留空；管理员预设号码只在后台显示，不提前公开。
- 到每天 20:30 后，开奖完成时立即获取并展示本期七个最终号码，不展示“开奖中”；同时进入下一期待开奖期，并显示次日 20:30 的计划开奖时间。
- 澳门四分彩页面数据必须来自澳门四分彩后端数据。快乐8仍读取自身数据，两者期号、号码、时间和刷新状态互不影响。
- 本草案不规定颜色、球号布局细节；图一仅供对照现有视觉区域和七球呈现方式。

## 6. 权限、数据与审计约束

- 仅有相应开奖管理权限的超级后台管理员可以查看或编辑预设；具体角色授权沿用或扩展现有开奖管理权限，由实施方案确认。
- 预设号码、开奖结果、期号和开奖时间应由服务端作为持久化业务数据保存，不能只保存在浏览器或临时内存中。
- 保存预设时记录操作者、目标期号、变更前后各球号码和操作时间，供问题追查。
- 每期自动开奖应具备幂等保护；同一期最多产生一份最终开奖结果并只创建一个下一期。
- 全部号码及相关积分若后续接入业务，仍遵守项目已确认的虚拟积分边界，不新增现实资金能力。

## 7. 本次不包含

- 接入快乐8或其他第三方作为澳门四分彩开奖源。
- 下注玩法、赔率、注单、玩家输赢结算、机器人播报、代理操作、中心上报和报表接入。
- 管理员手动立即开奖、开奖后改号、历史补期、强制结算或删除开奖记录。
- 修改快乐8既有开奖周期和业务规则。

以上是本次描述未明确要求的功能，不表示未来禁止扩展；需要另行确认后再纳入范围。

## 8. 本轮确认记录

以下业务口径已由使用者确认：

1. 每天晚上 20:30 开奖，使用北京时间（Asia/Shanghai）。开奖时间到达后立即开奖并刷新展示。
2. 期号从 100 期开始递增；开奖页面只显示末三位。
3. 后台表格默认 20 条：1 条未来待开奖期、19 条历史记录。
4. 状态只有“待开奖”和“已开奖”，不设置“开奖中”。
5. 仅允许编辑下一期待开奖期的预设号码。
6. 澳门四分彩只用于开奖展示，不接入下注或结算。
7. 下一期未开奖前，开奖页面继续显示上一期的开奖号码，不留空；管理员预设号码不提前显示在开奖页面。
