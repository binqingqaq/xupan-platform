# 当前需求基线：汇博盈页面复刻

## 1. 文档状态

- 状态：当前有效
- 确认日期：2026-09-10
- 确认来源：用户当前明确要求
- 适用范围：用户前台页面的视觉、结构和交互设计
- 替代内容：此前“聊天室前台与演示后台改造”中自行设计的用户前台方案
- 代码状态：本基线建立时尚未开始新的页面复刻实现

本文件是当前用户前台改造的第一依据。旧方案和项目交接记录继续保留用于追溯，但不能覆盖本文件中的当前要求。

## 2. 当前已确认要求

1. 用户前台以汇博盈真实页面为主要复刻对象，不再自行设计一个“类似聊天大厅”的页面。
2. 页面不能只复刻余额、期号、8 个球位和下注功能等业务元素，还必须对齐参考页面的视觉和交互表现。
3. 复刻范围至少包括页面布局、区域层级、颜色、字体层级、间距、按钮和输入控件、消息展示、球位选择、下注入口、状态反馈和移动端表现。
4. 当前已有的 Vue 聊天室式页面只能视为上一阶段演示实现，不代表本需求已经验收通过。
5. 在没有足够的参考页面证据前，不能声称已经做到“一模一样”，也不能继续用自定义样式补齐未知部分。

## 3. 参考资料和事实边界

### 3.1 已有参考资料能证明的内容

`docs/参考资料/汇博盈-业务参考.md` 记录了此前只读观察到的业务元素和部分交互，包括余额、期号、8 个位置、消息流、输入区、玩法区、开奖结果和获胜名单。

这些内容可以作为页面区域和业务信息的参考，但不能证明真实页面的完整视觉细节，也不能替代当前页面截图、合法访问结果或用户确认的设计基准。

### 3.2 不能从旧资料推断的内容

- 旧观察记录不能直接推断当前页面的最新布局和样式。
- 旧期号、号码、余额、用户名、赔率和消息不能作为页面固定数据。
- “聊天室式”只能描述部分业务表现，不能作为新的页面设计结论。
- 当前 Vue 页面已经实现的样式不能反过来成为汇博盈页面的参考标准。

## 4. 新实现前必须具备的参考证据

2026-09-10 用户已提供当前可访问的汇博盈参考页面地址。该地址含随机访问标识，完整地址不写入仓库；后续分析以当前会话中用户提供的地址为准，并将观察结果转换为可追溯的截图、结构和交互记录。

在开始页面复刻前，至少需要整理出以下可核对资料之一：

- 用户提供的汇博盈页面桌面端和移动端截图；
- 用户提供的页面录屏或逐区操作说明；
- 合法可访问的参考页面及其可核对的页面状态；
- 用户明确确认的页面线框、设计稿或标注图。

如果只能看到部分页面，应把未看到的部分列为“待确认”，不得自行补成最终设计。

## 5. 页面复刻验收标准

新的用户前台计划必须逐项对照参考证据验收：

1. 页面整体布局和主要区域顺序一致。
2. 顶部用户信息、余额、期号和状态展示的位置及层级一致。
3. 8 个球位、号码结果、选择状态和切换方式一致。
4. 消息流的内容类型、排列方向、头像或标识、时间和状态样式一致。
5. 下注输入区的控件组成、默认值、选项组织、提交方式和反馈方式一致。
6. 桌面端和移动端的尺寸、折叠、滚动、固定区域和键盘遮挡行为一致。
7. 不以“功能能用”替代“页面表现一致”；每个差异都必须有参考依据或明确记录为待确认。

## 6. 文档使用规则

- 本文件：记录当前有效的页面复刻要求。
- `docs/参考资料/汇博盈-业务参考.md`：记录外部页面观察，只是参考证据，不是项目需求。
- `docs/项目方案.md`：记录总体技术和业务边界；其中旧的聊天室页面方案已标为历史。
- `docs/plans/`：记录基于当前需求基线制定的实施计划；旧计划不得直接继续执行。
- `docs/项目记忆.md`：记录交接事实和历史决策，不作为永远有效的需求来源。

每次参考页面、用户要求或项目目标发生变化时，应新建或更新带日期的需求基线，并明确“替代了什么”。不要只修改旧文档中的一段文字而丢失变更边界。

## 7. 当前待确认项

- 汇博盈页面的最新桌面端和移动端参考证据；
- 用户前台是否需要复制参考页中的全部入口、历史区域、快捷操作和消息类型；
- 管理后台是否只沿用现有演示控制功能，还是也需要按参考后台页面复刻；
- 页面复刻与当前玩法规则、账号权限和真实运营功能之间的边界。
