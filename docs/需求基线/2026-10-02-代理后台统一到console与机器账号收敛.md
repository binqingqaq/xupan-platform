## 3. 为什么之前会走偏（留档，防止复发）

- `/console` 是先建的运营台（2026-09-20 统一后台、09-28 复古运营台重构），页面构成与 BY220 `robot.php` 高度一致：顶部状态/赔率/限额、报网控制、下注榜、上下分确认、最近上下分记录、玩家工作台、底部封盘与显示控制、线路域名。
- 2026-10-01 的代理组织计划把它定位成"平台管理员的运营工作台"，以"缺少代理组织和代理侧数据隔离"为立项前提，**另建 `/agent`**（当时只读），10-02 又扩成创建玩家/托、上下分、链接、运营数据、明细。
- 结果同一个 `robot.php` 出现两份：**`/console` 是功能超集，`/agent` 是子集**（下注榜、上下分确认、积分榜、报网栏 `/agent` 都没有），且全部文档把 `robot.php` 指向 `/agent`。
- 本次确认即是对该定位错误的纠正。**任何后续 Agent 不得再以"robot.php 必须有独立入口"为由新建代理后台页面。**

## 4. 报网/盘口的范围边界（合规强制）

用户要求"参考 BY220 把报网/线路域名/盘口补全"。同时项目合规基线不变（虚拟积分、不接现实资金、不接真实外部上游）。两者的交点按 **BY220 自己的本地运行方式**处理：

- BY220 本地参考库里 `x_rbwp` 只有一条 `code=k28 / name=本地盘口 / websiteUrl=http://127.0.0.1:9999`，该地址**没有真实服务**；本地通过 `BY220_LOCAL_MODE=1` 绕过真实登录，即"登录成功"不等于连上外部平台。
- 因此 xupan 实现：**报网类型、飞单账号、登录/退出状态、在线状态、自动上报、失败退单、超时订单、押注、余额、盘口线路（A-D）全部内部持久化 + 本地模拟适配器**，状态机完整，但**不发起任何真实外部网络请求、不保存真实凭据、不接现实资金**。
- 真实外部上游、中心上游 API、第二层账本仍**不在本次范围**；将来若要做，必须单独评审（合规 + 安全 + 运维）。
