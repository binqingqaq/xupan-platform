## 2. 分析结论

1. 该首页可以先做桌面端静态复刻，页面布局、颜色、栏目、菜单、悬停、轮播、标签切换和展开收起等内容不依赖后端业务即可实现。
2. 第一阶段不需要先完成开奖、投注、余额、用户、赔率或机器人等后端交互；这些属于业务逻辑，可以在静态页面验收后再接入。
3. 按用户当前确认，第一阶段不预留正式 API、数据库结构、DTO 或数据适配层；静态展示内容可以直接写入展示页面，后续正式化时再根据评审后的内容重新定义。
4. 当前项目不需要新建一套后台或数据库。展示端应与 `/room` 用户前台、`/admin` 管理后台保持页面和权限边界，但后续可以共用当前 Spring Boot 服务和 MySQL 数据。
5. 第一阶段应使用独立的 `/display` 路由，保留当前 `/` 到 `/room` 的行为；展示端稳定后，再决定是否由域名首页指向展示端。
6. 参考站点包含多个未确认的彩种、第三方链接和投注入口，不能因为视觉复刻就扩展当前项目的玩法、开奖源、支付或真实资金范围。
7. 当前不锁定最终 API 路径、响应字段、数据库表或实时通信方式；这些只能在静态首页经过用户确认后，根据确定的展示内容和数据来源设计。

## 5. 实现边界

### 3.1 第一阶段纳入

- 展示端独立路由和页面组件。
- 桌面宽屏布局和静态展示内容。
- 公告、当前期号、开奖状态、号码摘要、推荐内容、广告和新闻等预置展示信息。
- 主导航悬停、下拉、轮播、标签切换、展开/收起和演示倒计时等前端本地交互。
- 页面刷新入口、桌面截图检查、DOM 可访问性检查和构建验证。

### 3.2 第一阶段不纳入

- 复制参考站点的后台、账号、第三方数据源或外部投注入口。
- 真实支付、充值、提现、代理分成或生产资金功能。
- 未经确认的多彩种玩法、赔率、预测算法和第三方开奖接口。
- 展示端直接访问 `/api/admin/**` 管理接口。
- 因视觉复刻而修改当前已确认的 8 球玩法、结算、权限和机器人领域规则。
- 任何正式 API、数据库表、DTO、WebSocket 消息协议和数据适配层。
- 移动端 `m.16894913.com` 的独立布局和响应式适配。

## 6. 技术方向

- 当前阶段继续使用现有 `web/` Vue 3 + TypeScript + Vite 工程，在前端工程内新增展示端路由和组件目录。
- 第一阶段继续使用同一 `web/` Vue 3 + TypeScript + Vite 工程，展示页面通过公开的 `/display` 路由运行。
- 第一阶段不调用 Spring Boot API，不新增数据库；当前后台、MySQL、用户身份和管理权限保持原边界。
- 后续正式化时再决定是否共用当前 Spring Boot 服务、是否新增公开只读接口以及是否独立部署。

## 7. 页面验收标准

1. 桌面端主要区域顺序、宽度层级、导航和内容卡片与参考截图/页面一致。
2. 静态图片、文字、期号、号码和倒计时无需后端即可显示，不抓取或依赖参考站点运行接口。
3. `/display` 可被未登录访客访问；`/room`、`/admin` 和后台接口仍按现有权限规则运行。
4. 移动端、正式数据来源和业务接口属于后续阶段，不因本阶段完成而视为已实现。
5. 参考站点未观察到或未确认的内容标记为待确认，不自行补成已实现需求。
