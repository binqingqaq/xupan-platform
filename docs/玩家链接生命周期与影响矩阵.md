# 玩家链接生命周期与影响矩阵

> 文档类型：身份认证专项业务规则
>
> 当前基线日期：2026-09-23
>
> 代码基线：`3e431d2`（工作区另含托自动行为改造等未提交改动）
>
> 证据规则：标记为“当前代码事实”的内容来自当前源码和测试；标记为“待确认/未验证”的内容不能当作产品承诺。

## 1. 先看结论

当前项目中有三种容易混淆的操作：

1. **拉黑**：撤销当前玩家访问链接，不等于停用玩家账号。
2. **拉白**：恢复该链接的 `revoked_at`，恢复的是链接兑换能力，不会自动恢复已经被撤销的旧会话。
3. **刷新链接**：撤销旧链接和现有会话，生成全新的 Token 和 URL；只有这个操作会更换链接地址。

补充：**停用玩家**是账号级操作，不是链接级操作。2026-09-24 起玩家工作台按运营要求不再提供`停用玩家/启用玩家`入口，日常改用`拉黑`（只废链接）或`删除玩家`（软删除），但后端状态接口和机制继续保留，需要时可直接恢复界面入口。

当前已经验证的行为：

- 拉黑后，原链接记录和 URL 仍然保留，可以在后台查看。
- 拉黑后，原 Token 不能再次兑换，已经建立的玩家会话会失效。
- 拉白后，原链接可以再次兑换，但玩家需要重新兑换，旧会话不会自动恢复。
- 刷新后，旧 Token 失效，新 Token 和 URL 改变。
- 普通玩家和 BOT 创建时自动生成链接，产品默认有效期为 7 天。
- 会员 ID 旁的天数是“下次生成/刷新链接使用的有效期配置”；保存后立即回显配置，但不改写当前链接的到期时间。
- 刷新链接才会使用已保存的新天数生成新 URL，并同步更新新链接的到期时间。
- 玩家软删除后，链接、会话和后续 BOT 行为失效；钱包、注单、结算、流水、聊天和审计历史保留。
- 管理员和玩家链接使用独立刷新 Cookie，可在同一浏览器的不同标签页同时保持会话。

## 2. 对象和状态不是一回事

### 2.1 玩家账号状态

玩家账号状态在 `sys_user` 和 `demo_user_account` 中管理，常见状态包括：

- `ACTIVE`：允许正常身份链路。
- `DISABLED` / `LOCKED`：账号停用或锁定，不能继续使用玩家身份。
- `DELETED`：软删除，只能查询历史，不能产生新的业务行为。

玩家账号状态影响玩家整体能力；它不是“拉黑链接”的同一个状态。

### 2.2 玩家链接状态

玩家链接记录在 `player_access_link` 中，状态主要由以下字段计算：

- `revoked_at IS NULL`：没有被撤销。
- `expires_at > 当前时间`：没有过期。
- 关联用户和钱包账户为 `ACTIVE`。
- 关联玩家分类为 `NORMAL`。
- `scope = PLAYER_FULL`。

因此“链接有效”不是只看一个 `active` 字段，而是链接记录、时间、玩家状态、账户状态和玩家分类共同决定。

## 3. 链接状态矩阵

| 状态 | 形成原因 | 原 URL 是否保留 | 新兑换 | 已有会话 | 聊天/下注/钱包 | 拉白/恢复 | 历史记录 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 有效 `VALID` | 未撤销、未过期、玩家和账户均 ACTIVE | 保留 | 允许 | 正常，直到会话失效 | 按普通玩家权限执行 | 不适用 | 全部保留 |
| 已拉黑 `REVOKED` | 管理员点击“拉黑” | 保留，可在后台查看 | 拒绝 | 当前代码会全部撤销 | 会话失效后不能继续 | 清除 `revoked_at`，原 Token 可重新兑换 | 链接和审计保留 |
| 已过期 `EXPIRED` | 当前时间超过 `expires_at` | 当前记录保留 | 拒绝 | 新兑换必然失败；已有会话即时失效策略尚未单独确认 | 依赖现有会话是否仍有效，不能假定 | 拉白不能延长过期时间 | 链接记录保留 |
| 已刷新旧链接 `ROTATED` | 管理员点击“刷新链接” | 旧 URL 记录保留 | 旧 Token 拒绝 | 旧会话全部撤销 | 旧会话不能继续 | 不作为恢复旧链接的主流程 | 旧链接和新链接均保留 |
| 玩家停用/锁定 | 修改玩家或用户状态 | 链接记录保留 | 拒绝 | 停用操作会撤销现有会话 | 不能继续产生玩家业务行为 | 不能仅靠拉白恢复 | 历史保留 |
| 玩家软删除 `DELETED` | 管理员确认删除 | 链接记录保留但撤销 | 拒绝 | 全部撤销 | 不能聊天、下注、上分、下分或执行 BOT | 不能恢复为 ACTIVE 玩家链接 | 钱包、注单、结算、流水、聊天、审计保留 |
| BOT 玩家 | `player_kind=BOT` | 与普通玩家一样生成并保留链接 | 允许 `PLAYER_FULL` 兑换 | 可进入房间，也可继续走 BOT 行为链路 | 支持拉黑/拉白/刷新 | BOT 动作独立保留 |

## 4. 管理操作影响矩阵

| 操作 | 数据变化 | Token/URL | 会话 | 业务影响 | 审计 |
| --- | --- | --- | --- | --- | --- |
| 创建/首次生成 | 新增 `player_access_link`，保存 Token 哈希和加密密文，设置 `expires_at` | 生成 URL；同一有效链接重复生成时可复用当前链接 | 撤销该玩家已有会话 | 玩家可兑换 `PLAYER_FULL` | 记录签发操作，不记录完整 Token |
| 查看当前链接 | 读取最新链接记录 | 可能返回原 URL，不生成新 Token | 不改变 | 不改变玩家业务能力 | 当前接口为查询，不产生新链接 |
| 拉黑 | 设置 `revoked_at`，撤销该玩家所有活跃会话 | URL 保留，Token 不变 | 立即失效 | 新兑换、聊天、下注、钱包接口拒绝 | 记录 `revoked=true` |
| 拉白 | 设置 `revoked_at = NULL` | URL 保留，Token 不变 | 不恢复已撤销会话 | 允许原 Token 再次兑换 | 记录 `revoked=false` |
| 刷新链接 | 撤销旧链接，新增一条链接，撤销所有会话 | 旧 URL 失效，新 URL 改变 | 立即失效 | 玩家必须使用新链接重新进入 | 记录轮换操作 |
| 修改有效期 | 更新玩家的链接有效期配置 | 当前链接的 `expires_at` 不直接改写；后台立即显示新配置 | 不改变现有会话 | 影响下一次生成/刷新 | 记录配置变更 |
| 玩家停用/锁定（工作台已隐藏入口，接口保留） | 修改账号状态 | 链接记录仍在，但不能兑换 | 撤销会话 | 禁止后续玩家业务行为 | 记录状态变更 |
| 软删除玩家 | 用户和账户置为 `DELETED`，撤销链接，提升安全版本，停用 BOT | 原 URL 保留为历史数据但不可用 | 全部失效 | 禁止登录、聊天、下注、上下分和 BOT 行为 | 记录身份快照和删除操作 |

## 5. 关键流程

### 5.1 拉黑流程

```text
管理员点击“拉黑”
  -> 校验 USER_MANAGE 权限
  -> 校验玩家仍是 ACTIVE 的 NORMAL 玩家
  -> player_access_link.revoked_at 写入时间
  -> 撤销该玩家全部活跃会话
  -> 写 USER_MANAGE 操作审计
  -> 后台显示“已拉黑（链接保留）”
```

拉黑不会：

- 修改 `sys_user.status` 为 `DISABLED`。
- 修改 `demo_user_account.status`。
- 删除玩家、钱包、注单、聊天或流水。
- 生成新的 URL。
- 停用独立的 `chat_robot`。

### 5.2 拉白流程

```text
管理员点击“拉白”
  -> 校验 USER_MANAGE 权限
  -> 校验玩家仍是 ACTIVE 的 NORMAL 玩家
  -> player_access_link.revoked_at 清空
  -> 写 USER_MANAGE 操作审计
  -> 后台显示“原链接已恢复”
  -> 玩家重新使用原 Token 兑换新会话
```

拉白不会：

- 恢复拉黑前的旧会话。
- 修改 `expires_at`。
- 自动刷新 Token。
- 处理已软删除玩家。

### 5.3 刷新链接流程

```text
管理员点击“刷新链接”
  -> 撤销当前玩家全部未撤销链接
  -> 撤销该玩家全部活跃会话
  -> 按当前有效期配置生成新 Token
  -> 保存新链接的哈希和加密密文
  -> 返回新的完整 URL
```

刷新后必须确认：

- 新旧 URL 不相同。
- 旧 Token 不能兑换。
- 旧玩家会话不能访问聊天室。
- 新 Token 可以兑换完整 `PLAYER_FULL` 会话。
- 新链接的有效期使用刷新时的配置。

前端提示约定：

- 保存天数：`设置成功`。
- 复制链接：`复制成功`。
- 刷新链接：弹出 `获取成功，请用新链接登录（已自动续期X天）`，其中 `X` 为保存后的配置天数。

管理台会员 ID 旁按当前配置直接显示“剩余 X 天”；保存 6 天后立即显示“剩余 6 天”。该区域不再展示“当前链接剩余/刷新后续期”等技术解释，避免干扰运营操作；服务端仍按已保存配置约束后续链接生成和刷新。

管理台成功和失败提示统一使用右上角自动消失的 Toast 浮层，不再把提示插入业务内容流中。保存、复制、刷新、删除、状态变更和积分操作等后续管理动作沿用同一提示形式。

### 5.4 玩家删除流程

```text
管理员确认删除
  -> 用户和钱包账户置为 DELETED
  -> 安全版本递增
  -> 撤销全部链接
  -> 撤销全部玩家会话
  -> 停用 BOT 行为
  -> 写不含 Token/完整 URL 的身份审计
  -> 默认列表隐藏，历史查询显式 includeDeleted
```

## 6. 兑换和前台能力

玩家使用 URL 兑换时，服务端必须同时检查：

1. Token 格式有效且无空白。
2. Token 哈希匹配链接记录。
3. `scope = PLAYER_FULL`。
4. `revoked_at IS NULL`。
5. `expires_at > 当前时间`。
6. 用户状态为 `ACTIVE`。
7. 钱包账户状态为 `ACTIVE`。
8. 玩家分类为 `NORMAL`。

兑换成功后：

- 创建 `PLAYER_LINK` 认证模式的玩家会话。
- 会话范围为 `PLAYER_FULL`。
- 只能使用普通玩家前台能力。
- 不能访问管理员后台和管理员权限接口。
- 玩家昵称、会员编号、内部编号和头像以服务端身份为准，不能由客户端覆盖。

### 6.1 同浏览器多标签会话共存

- 管理员刷新会话使用 `xupan_refresh`。
- 玩家链接刷新会话使用 `xupan_player_refresh`。
- `/api/auth/refresh` 根据 `X-Xupan-Auth-Audience` 选择对应 Cookie，并校验会话认证模式。
- 每个标签页只在 `sessionStorage` 记录当前使用端，不保存 Token。
- 管理员标签页刷新不会恢复成玩家身份；玩家标签页刷新也不会恢复成管理员身份。
- 管理员退出只清管理员 Cookie，玩家退出只清玩家 Cookie。

## 8. 当前已验证和未验证

### 已验证

- 链接签发、兑换和完整 `PLAYER_FULL` 前台权限。
- 过期、撤销、重复兑换、停用玩家、托玩家和无权限管理员边界。
- 拉黑后原 Token 不能兑换，已有玩家会话失效。
- 拉白后原 Token 可以再次兑换，URL 不变。
- 刷新后旧 Token 失效，新 URL 改变。
- 软删除后链接和会话失效，历史详情和业务历史保留。
- 本机 MySQL 8.4.11 迁移和 HTTP 运行态。

证据见：[玩家身份模型与聊天室链接登录验收记录](验收记录/2026-09-21-玩家身份模型与聊天室链接登录验收记录.md) 和 `PlayerLinkAuthControllerTest`。

### 尚未完成或未单独证明

- 两个并发拉黑/拉白/刷新请求的最终状态和幂等行为。
- 拉黑、拉白、刷新与玩家删除同时发生时的最终状态。
- 链接过期时，已经兑换成功的玩家会话是否必须立即失效。
- 拉白一个已经过期的链接，当前实现不会延长 `expires_at`；产品是否允许该操作需要确认。
- 当前链接剩余天数和下次刷新配置天数已明确拆分：前者看 `expires_at`，后者看 `player_link_expiration_config.days`。
- 过期和撤销链接元数据的保留期限及清理任务。
- 服务器和生产环境的 HTTPS、Cookie、代理和浏览器现场验证。

## 9. 后续修改规则

任何涉及玩家链接的需求，必须先更新本文件至少一项：

- 状态定义。
- 操作影响矩阵。
- 前台能力矩阵。
- 接口和数据变化。
- 并发、幂等和失败恢复规则。
- 测试和环境证据。

不得只修改按钮文案或接口实现而不更新生命周期记录。若“拉黑”未来要改成停用整个玩家，必须明确写成新的业务操作，不能继续复用 `revoke` 名称造成语义混淆。
